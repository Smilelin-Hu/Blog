# 项目二：Heterogeneous Inference Workload Benchmark Platform

按到达时间重放五类工作流（Reasoning、Agentic、Structured、Multimodal、Compound），分别核算端到端 SLO。混合负载平台的陷阱是「 Handler 没真跑」：五类 handler 都必须执行、到达顺序保持、structured 输出真校验、compound/agentic 路径真发生多次链接调用——否则「混合负载 SLO」只是单类负载的数字换了名字。

## 1. 项目闭环

```bash
python project/02-workload-platform/run.py --check-only
python project/02-workload-platform/run.py --output results/project-02-fixture.json
python project/02-workload-platform/run.py --real --endpoint http://serving:8000 --trace workload.jsonl \
  --output results/gpu_result.json
```

- **输入**：五类工作流 trace（含到达时间）、serving 端点、SLO 阈值。
- **输出**：逐类端到端 SLO 核算、到达顺序记录、链接调用 trace。
- **验收**：五类 handler 都运行；到达顺序保持；structured 输出被校验；compound/agentic 多次链接调用。

## 2. 判读纪律

- 逐类 SLO 分开报：混合聚合会掩盖单类违约。
- 到达顺序重放是负载真实性的前提：乱序重放会改变批处理与缓存行为。
- 只有 `source=measured` 的报告可用于性能或发布结论。
