# 面向训练的数据湖、资产目录与血缘架构

数据湖以资产目录与血缘把原始层到训练层串成可追责链路。

## 1. 机制要点

- 分层（raw/clean/curated）+ 资产目录使每份训练输入可溯源
- 血缘闭包支持检查点反查与数据退出

## 2. 实验闭环

```bash
python lessons/lesson-03/run.py
python lessons/lesson-03/run_gpu.py
```

- **输入**：固定 Fixture 场景集（可修改阈值/状态/样本观察验收变化）
- **输出**：结构化报告（状态/原因/检查项）与运行产物
- **验收**：分层（raw/clean/curated）+ 资产目录使每份训练输入可溯源；血缘闭包支持检查点反查与数据退出

## 3. 判读纪律

- 默认 Fixture/模拟只验证控制逻辑与合同；真实路径（`--real`/GPU）才产生可用于性能或发布结论的测量。
- 前置条件不足时返回 SKIPPED/precondition_failed 并说明原因，不以模拟或 CPU 结果冒充实测。
- 报告区分 PASS/FAIL/SKIPPED 并附原因与证据（trace/快照/哈希）；负例与失败注入对照必做。
