# AI 原生应用的新阶段：形态谱系与成熟度判断

一年前企业构建 AI 应用的起点是「如何把模型接入业务」：Prompt + RAG + Workflow，应用代码掌握完整执行路径。现在模型正成为能维持状态、分解目标、调用工具、操作环境并按反馈调整行为的执行主体。本文提炼新阶段的形态谱系、定义边界与成熟度判据——核心决策原则只有一条：**自主性与任务风险相匹配，选择成本与风险可接受的最低充分架构**。

## 1. 生产拐点：从生成内容到完成任务

上一阶段应用的三个特征：以「请求—回答」为交互单元、执行路径由代码/Workflow 预定、输出是内容而非环境中可验证的结果。Coding Agent 构成拐点，不只因研发是高价值场景，更因它集中暴露了进生产必须处理的六类工程问题：

1. 仓库超窗口 → 信息检索、筛选、摘要与外置存储；
2. 跨步骤多次调用 → 计划、进度与待办维护；
3. 工具真实改环境 → 权限控制、环境隔离、不可逆操作审批；
4. 中间尝试会失败 → 错误观测、重试、检查点与恢复；
5. 结果不能模型自评 → 测试、构建、静态检查、Diff 或独立评估器验证；
6. 人无法逐 Token 监督 → 关键节点 Steering 与 Human-in-the-Loop。

Anthropic 的 Session/Harness/Sandbox 分离与 OpenAI 的 Durable Thread/外部记忆/Skills 指向同一结论：**长任务不是延长一段对话，而是把认知、状态、执行与控制分层**。这些能力在研究、数据分析、IT 操作、客服工单等场景反复出现，逐步从业务应用抽离为通用 Harness 与 Agent Platform。

## 2. 形态谱系：共存而非替代链

| 形态 | 任务路径 | 状态与跨度 | 人的角色 | 适用条件 |
|---|---|---|---|---|
| Chat/RAG | 应用预定 | 单轮/短会话 | 提问、阅读、判断 | 结果是内容，不改外部系统 |
| Workflow | 设计时预定 | 步骤有限、状态明确 | 设计与审批 | 路径可穷举、错误代价高 |
| Copilot | 人持续决定 | 跨多轮、控制权在人 | 驾驶、验收、负责 | 专业判断难全自动 |
| Single-Agent | 运行时动态决定 | 多步骤有状态、有界闭环 | 定目标/约束/审批点 | 路径难预知、环境有反馈、结果可验证 |
| Long-Horizon / Multi-Agent | 长期反馈调整 / 多主体编排 | 跨会话可恢复 / 多角色状态 | 检查点与例外 / 角色权限边界 | 单 Agent 受时间或角色复杂度限制 |

根本区别不在是否对话界面，而在**任务循环由谁掌握、路径何时确定、对环境的影响程度、是否跨会话或多主体**。Workflow 与 Agent 长期共存：资格校验/账务入账走确定性流程，材料理解/异常调查交给 Agent；主流是 Hybrid——Workflow 中嵌 Agent 把不确定性限在边界内，或 Agent 调用 tested Workflow/Skill 把成熟做法从重复推理中抽离。

Long-Horizon 与 Multi-Agent 是**两个正交维度**：前者解决跨时间持续（核心不是「跑得久」而是目标/状态/责任/结果的一致性），后者解决多主体协作（价值不在调用数量而在分工/隔离/校验成为可设计结构）。可独立采用或组合，都不是必经升级阶段。

## 3. 定义与判定：Agent = Model + Harness

Agentic Application：以 Model + Harness 构成的执行主体为核心，结合业务逻辑/数据/工具/环境/交互，围绕目标维护上下文与状态、动态规划、采取行动，在确定性边界内交付可验证结果。公式强调**责任边界**：Model 提供理解/推理/生成/决策，但不能独立承担上下文准备、状态维护、工具执行、权限控制、故障恢复与结果验证；Harness 在落地中拆为 Agent Loop、Context/State/Memory、Tool/Skill/Protocol、Runtime/Sandbox、Observability/Evaluation、Security/Governance。

六个判定特征（是判据不是功能清单）：目标与结果为中心、运行时决定部分路径、能作用于外部环境、维持跨步骤跨请求状态、自主行为受确定性机制约束（模型不能自行绕过）、通过可观测与评估持续改进。

三个易混边界：Agent ≠ Agent 框架（框架给开发抽象，不自动形成持续执行交付结果的系统）；Long-Horizon/Multi-Agent ≠ 天然更高成熟度（各自增加状态漂移/通信开销/责任划分难度）；应用形态 ≠ 平台形态（形态描述任务如何执行，Platform 提供共享能力）。

## 4. 成熟度 L1–L4 与升级判断

| 级别 | 典型状态 | 核心能力 | 升级门槛 |
|---|---|---|---|
| L1 辅助生成 | Chat/RAG/基础 Copilot | 生成、检索、简单工具 | 可复用 Prompt/知识/基础评测 |
| L2 受控自动化 | Workflow + 局部 Agent | 预定流程、结构化输出、审批 | 明确自主边界，引入 Harness/工具策略/轨迹评估 |
| L3 Agentic Execution | Agent 持有任务循环 | 动态规划、环境操作、持久状态、恢复 | Runtime/Sandbox/Observability/Security/Evaluation |
| L4 规模运营 | 规模化 + 统一治理 + 持续优化 | 多任务多租户、策略控制、灰度 | 共享平台 + 组织知识 + 自动化降治理成本 |

成熟度不由产品名称决定，从任务循环/执行跨度/环境影响/生产治理四维判断。**不必依次升级**：知识助手可长期 L1，交易审批可停在 L2，路径难预知的研发/运维进 L3，规模化多租户才需 L4。L4 是能力水平不是新形态，Single/Long-Horizon/Multi 都可处于 L3 或 L4。升级只在「当前架构无法以可接受风险成本交付、新增能力有明确价值」时才必要。

架构决策先于构建，依次回答五问：如何设计（形态与边界）→ 如何构建（能力组合）→ 如何运行（调度/状态/隔离/恢复）→ 如何治理（身份/审批/审计）→ 如何调优（质量判定/回归/灰度/回滚）。

## 5. 操作系统视角：被改写的管理假设

多 Agent 长期并发运行时，调度/隔离/授权/恢复/审计这些 OS 职责重新浮现，但前提被「运行时决定路径」改写：执行单元从进程变为 Run（可跨进程副本）、状态外置持久、能力运行时动态接入、授权每次高影响操作强制判定且可撤销、恢复以任务为单位（需检查点/幂等/补偿，重启 ≠ 正确恢复）、审计是意图—调用—反馈—结果的关联链路。

其中不归属任何单个 Harness 的公共职责（沙箱创建回收、高影响操作强制拦截、跨会话记忆快照、预算授权派生与撤销）正收敛为一个新层次——Agentic OS（34 篇展开）。云与 K8s 是底座而非替代：它们管 Pod 不管 Run，调和基础设施却不判断任务是否真正且安全完成；缺的是把容器/配额/IAM 翻译成 Run/预算租约/操作记录的 Agent 原生抽象。
