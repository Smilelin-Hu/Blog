# Agent 运行时与沙箱：三类负载、状态分层与恢复验证

模型生成计划与操作指令，文件读写、程序运行、页面交互与结果验证由执行环境完成。Sandbox 是按任务需要配置、具有隔离边界和明确生命周期的可编程工作空间：计算资源、文件系统、语言依赖、终端/浏览器/桌面入口，加上网络、数据挂载、凭证、观测与状态保留。Agent Runtime 则把环境的创建、连接、等待、恢复与回收纳入任务生命周期。本文提炼运行篇第一站的工程要点——沙箱让模型判断获得可检查的运行依据，但**业务结果是否正确仍由测试、规则、评测器或用户验收确认**。

## 1. 两种部署关系与三类典型负载

**Agent use sandbox**：编排逻辑在沙箱外，通过接口调用其中的代码/浏览器/工具，便于为已有应用增加执行能力；**Agent in sandbox**：Agent 进程与主要工具链共同运行在沙箱内（模型推理仍可远端），适合完整项目环境、持续进程与复杂工具协作。加上面向批量交互、轨迹采样、重置与重复实验的 **Agent RL/Eval**，构成三类典型负载——是观察维度不是互斥架构：工具沙箱也可维持长会话，沙箱内 Agent 也可只处理短任务。

| 负载 | 首要价值 | 主要关注点 |
|---|---|---|
| 工具执行（use） | 为已有 Agent 增加真实操作与结果验证 | 首次可用时延、工具能力、任务间隔离 |
| 长时任务（in） | 延续项目状态，支持多轮修改 | 会话连续性、恢复效果、等待成本 |
| 训练评测（RL/Eval） | 并行探索、复用环境准备、稳定比较 | 环境吞吐、重置与分叉、可复现性 |

参数明确、行为固定的业务动作直接调已有 API，无须为每次查询创建沙箱；操作路径需在执行中逐步确定的任务才用可编程环境。

## 2. 工具执行：环境类型与产物验收

五类环境各有任务价值：**Code**（清洗数据/跑脚本/构建测试，按任务组织程序复用依赖）、**Browser**（页面交互/下载/预览检查，直接验证真实页面效果）、**Computer**（桌面软件与图形流程，覆盖缺少 API 的路径）、**AIO**（浏览器+代码+终端共享文件工作区，下载→计算→生成→预览连续任务免反复上传下载与路径对齐）、**MCP/Skill 环境**（把只在某台开发机上能跑的本地依赖工具变成可分配可维护的运行环境——stdio MCP Server 随沙箱启动，适配层/网关做协议转换，沙箱承载进程依赖工作区，无人用时回收休眠、请求增加时扩容）。

代码沙箱的典型闭环：检查样本 → 生成转换脚本 → 安装解析库 → 按运行结果修正脚本。**命令执行成功只表示程序正常退出**，还要核对数据范围、输出文件、关键统计结果；输入版本、执行脚本与必要日志随任务保留供复核复用。高频稳定的计算沉淀为固定工具，变化多需探索的留给沙箱。共享范围与任务匹配：同任务工具可访问协作文件，不同租户项目分开，并行分支改同一文件要有明确合并规则；只用代码的简单任务选轻量模板，组合环境的收益要能覆盖镜像体积、启动与维护成本。

## 3. 长时任务：连续性、休眠与故障恢复

长任务围绕项目展开：取得仓库、装依赖、改代码、跑测试、起预览、等用户反馈，下次修改时前次成果必须仍可用。**仅维持进程存活承担不了连续性**——若成果只存在实例内部，平台因 CPU 低就回收实例，下次只能从头开始。连续性靠两类映射：**会话亲和**（稳定会话标识 → 路由层查找已有环境或启动恢复）与**工作区挂载**（已验证的租户/用户/项目关系 → 挂载对应数据目录）。两者不必一一对应：可复用环境，也可释放后新建实例重挂文件；**把用户编号拼进目录名不能代替服务端对归属与访问权限的检查**，调用方不应把容器临时地址当长期入口。工作区存源码/下载/中间制品，任务事实（目标/已完成步骤/待确认项/外部操作结果）归状态存储——恢复内存磁盘后编排层仍要确认进度，避免重复提交。运行期新增依赖要有恢复方式：可预知的固化进版本化模板，临时的装进持久化项目目录，系统路径改动保留可重建步骤或环境快照；**工作区挂载只恢复其覆盖的文件，不代表全部环境变化已恢复**。恢复检查未通过应保持失败或等待态，不能把空工作区当恢复结果交付；状态与工作区保留期独立于计算实例设置。

长会话计算需求不连续（等模型/等确认/等事件），持续保留完整资源成本随时间增长，每次等待都销毁又增加恢复开销——休眠在保留必要状态的前提下降占用。三个关键点：**唤醒入口在休眠沙箱之外**（定时器/消息入口/路由组件先收事件再恢复环境，休眠中的 Agent 自己不跑任务循环）；能否休眠不只看「没有新请求」，还要检查在跑工作与未完成操作，进入等待前保存继续点与等待条件，重要增量随执行及时保存而非等终止信号；**恢复后重查可用性**——文件保住了但外部连接、临时凭证、远端登录态、服务端口可能已变（E2B 暂停会中断外部连接），恢复成功以任务能否继续执行为依据，接口返回成功只是一个环节。

实例故障恢复三条纪律：区分执行环境故障与依赖服务故障（存储不可用要暂停读写恢复存储，反复重建实例消不掉存储故障）；**失去心跳只表示观察不到，旧进程可能还在跑**——串行修改同一任务/工作区时，先确认旧实例已停或使其写权限失效再让新实例写入，用执行代次 + 受保护存储拒绝旧代次（围栏 fencing），仅更新控制面编号阻止不了旧进程；已提交外部系统的操作要核对结果（提交构建后失联，新实例按原构建标识查状态再决定等待/读结果/重试），不能安全重复且结果不明的保持待核对、必要时转人工。

## 4. 训练与评测：并行探索的环境供给

一次从初始状态经多步动作得到结果的交互构成一条 rollout 轨迹。并行运行时环境准备、文件读写、测试执行与回收都影响有效轨迹产出——模型推理有余量，任务仍可能在等环境。四项能力各解决一个问题：**Template** 让重复任务有一致起点（OS/工具版本/依赖/启动参数）、**Snapshot** 保存已完成的准备（文件系统或内存）、**Fork** 从同一快照并行展开多次尝试、**Reset** 防上一轮改动污染下一轮。典型用法：仓库检出+依赖安装+基础测试后存快照，多沙箱分叉各跑不同策略再汇总补丁与轨迹；收益取决于准备成本、快照大小、分叉次数与恢复开销。

两个易错点：**沙箱快照不能自动回退外部数据库、已发送消息、已完成业务操作**——评测要用独立数据副本/测试租户/明确外部重置机制，分支写入进各自可写空间，避免共享挂载把一次修改传播给其他分支（沙箱快照也不同于保存权重优化器的训练检查点）；**评分规则与关键验证材料要独立保护**，防止会改代码文件的执行者通过修改评分环境获得失真结果（reward hacking）。训练追求足够多有效探索，评测强调可比较条件，都要记录模板数据依赖版本、限定预算，并**区分「Agent 没完成任务」与「环境本身没正常服务」**——否则环境故障被误计为模型能力变化。评估平台收益时分阶段记录耗时与失败原因，区分环境能力与模型缓存/推理调度/训练算法各自的贡献。

## 5. 状态分层与弹性容量

状态保留策略决定等待期占用与恢复开销，四档取舍：

| 策略 | 保留/释放 | 适用 | 代价 |
|---|---|---|---|
| 持续运行 | 进程与执行资源全保 | 连续计算、即时交互、在跑服务 | 等待仍占资源 |
| 浅层暂停 | 保内存与文件，减活跃计算 | 等待短、恢复敏感 | 仍占内存 |
| 深度休眠 | 状态持久化，释放执行资源 | 等待长、要延续运行上下文 | 存储与恢复开销，外部连接重建 |
| 保留文件后重建 | 仅工作区与任务记录 | 进程易重启、文件是主要状态 | 重启服务、补未持久化上下文 |

各产品对浅/深休眠的实现与计费不同，**不能把某个 pause 接口等同于所有平台的同一种休眠**，按实际状态语义设计。按完整任务周期评估：保留长执行短的项目降等待占用收益大；频繁恢复且每次等待短的任务，反复保存加载反而增时延成本。结合活跃时间、等待时长、恢复频率与状态大小设休眠阈值与保留期，清理无业务用途的快照工作区。

首次可用时延从环境申请算到命令通道、依赖、工作区、所需服务全就绪：冷启动含资源分配/镜像准备/进程初始化，镜像缓存预热减镜像时间，实例预热以资源池持续占用换短等待——**预热只能提前完成与任务无关的准备，身份、挂载与恢复检查仍计入时延**。突发工具调用用适量预热池承接常见流量，大批量评测按队列提前备容量，长项目优先复用恢复；防止创建提速后瓶颈转移到共享存储、出口网络或控制接口。容量按代表性任务实测（含内存/工具子进程/连接数/伴生组件），分别设单实例并发与资源池上限，耗尽时有界排队或明确拒绝。**CPU 使用率低不能单独作为回收依据**；缩容先停接新工作，再等在途任务完成或到可恢复点。

## 6. 分工、隔离后端与接入方式

Harness 持有任务语义（目标/上下文/下一步决策），Runtime 组织可启动可等待可取消可恢复的运行过程，Sandbox 提供计算与工具环境——是职责边界不要求三个独立服务，但**平台不应根据进程是否存活猜测任务是否完成**。三平面落位：执行面承载任务循环与沙箱实例，数据与资源面保存镜像/工作区/任务记录/快照/制品，控制面管身份/模板准入/权限/配额/生命周期策略；任务结束可释放计算环境，已交付结果与必要运行记录按业务要求保留。

隔离后端按代码可信度、租户边界、OS 能力、设备需求与运维成本选：容器（镜像运维生态成熟，常见实现共享宿主内核）、用户态内核如 gVisor（减少直接接触宿主内核的范围，需验证系统调用兼容性）、MicroVM 如 Firecracker（硬件虚拟化独立内核边界，仍需配套资源网络存储身份管理）。**对外提供 SDK 或 K8s 接口不能单独说明底层隔离强度**；浏览器自身进程沙箱只覆盖应用边界。共享池纪律：预热环境分配前不带用户数据凭证，重新分配前清理进程/文件/挂载/网络规则，阻断获取宿主机广泛权限的路径。接入两入口可指向同一底座：SDK/API 面向应用开发者（创建/连接/命令/文件/生命周期），Kubernetes CRD 面向平台团队（模板/实例/预热池/存储/控制器统一治理）。接口兼容减少迁移代码量，但模板、超时、暂停恢复、网络、持久化、错误处理要逐项验证——**同名参数在不同实现中支持范围可能不同**，生产迁移用代表性任务验证完整生命周期。

## 7. 落地验证：基线、成本与恢复场景

实施顺序：先把单任务的环境准备与反馈闭环做完整，再优化状态复用，最后扩并发；每项新增机制对应已观察到的运行问题（短任务从按需创建+明确清理开始，长任务加会话关联与恢复，高并发评测再上预热/批量调度/快照分叉）。基线覆盖完整任务链并分阶段计时：环境侧（排队/分配/镜像/挂载/初始化/恢复）、执行侧（模型等待/工具运行/重试/验收）、结束侧（结果保存/释放/清理）；P95/P99 要明确从哪个事件计到哪个事件、给出并发量与缓存条件，**不能用空环境启动数据代表完整业务响应**。成本口径：**单位成功任务成本 = 测量窗口内归属该负载的计算+状态存储+网络+预热费用 ÷ 成功完成任务数**，失败尝试与重试计入总费用——用于判断休眠收益是否被恢复开销抵消、加并发是否带来更多无效尝试。

上线前围绕同一项目验证五场景：执行中实例退出（新实例接回记录/文件/依赖从保存位置继续）、挂载失败或归属不符（阻断执行，不把空目录或他人数据当恢复成功）、旧实例失联后重现（旧执行者不能再改受保护状态，外部操作结果得到核对）、等待期取消或触发资源上限（停新增、保结果、回收资源）、新版本上线后恢复旧任务（状态与环境版本兼容、文件权限正确）。**环境升级要同时验证新建与恢复路径**——旧快照可能保留旧依赖与凭证状态，只验新模板证明不了全部环境已升级；状态格式或挂载方式变化先验迁移路径再逐步切换。
