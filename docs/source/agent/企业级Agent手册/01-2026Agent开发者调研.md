# 2026 Agent 开发者调研：生产化卡点与能力诉求

来源调研回收有效问卷 1906 份，受访者以企业技术决策者、架构师、一线工程师与产品经理为主，覆盖北京、深圳、广州、上海、杭州等地的线下沙龙。本文提炼数据结论与工程含义，作为全系列的选题依据——后续各篇回应的正是这里暴露的卡点。

## 1. 总判断：投入成共识，生产化是少数派

- 暂无开发计划者从 22% 降至 15%，调研/计划中从 47% 降至 25%，已开发完成或开发中合计 46%（上年 36%）；**真正部署到生产的只有 18%，持续迭代的不到 10%**。
- 上线率差距普遍大于开发率差距（上海大型企业 45% vs 小微 16%）。卡点不是意愿也不是模型能力，而是持续演进 Agent 的工程能力储备：组织协作、治理、优化与沉淀。
- 对照 L1–L4 成熟度分级：L1 辅助生成、L2 受控自动化已普遍，L3 Agentic Execution 仅部分场景成立，L4 Managed & Optimizing 尚属少数。构建/运行/治理/调优各篇本质上都在回答「如何从 L2 演进到 L3、L4」。

## 2. 架构选型：共存而非替代

单 Agent 为主的企业占 40%，多 Agent 为主 42%，15% 把 Human-in-the-Loop 当作架构原则（关键步骤必须人确认）而非附加审批开关。**自主度是可调参数，混合形态是长期状态而非过渡阶段**；Chat/RAG、Workflow、Copilot、Agent、Managed Agentic Application 在同一家企业内并存，选型取决于任务确定性与容错空间，而非技术新旧。

多 Agent 痛点排序：状态与上下文在协作中衰减（60%）居首，其次是死锁雪崩与成本失控——本质都是调用链与状态缺乏约束。最期待补齐的能力：端侧与开源运行底座（73%）、研发—测试闭环（65%），前者指向运行底座自主可控，后者说明多 Agent 验证成本已成主要负担。

## 3. 场景与工具链：编码先行，标准未收敛

- AI Coding 是唯一规模化落地的付费场景：采购 Coding 工具的企业占 57%，用通用 Agent 框架的占 78%，近四成两者并用。能先行是因为三个前提齐备——**反馈信号明确（编译/测试）、环境边界清晰（仓库/工作区）、错误代价可控（可回滚）**。
- 供应商碎片化，前十份额平缓下降而非陡峭长尾，无事实标准。围绕单一框架建企业内标准风险高，**可迁移的工程抽象比押注厂商更有价值**；编程 Agent 沉淀的范式（Skill 组织、工作区隔离、工具权限、上下文分层）正向办公场景渗透。
- 落地场景排序：员工效能、代码工程、数据分析居前；进入核心业务流程的不足 40%——Agent 优先进容错空间大、能人工兜底的场景，严肃场景需要更完整的治理配套。

## 4. 上下文、工具与协议层瓶颈

- 上下文痛点不在窗口大小：检索不准（54%）、记忆更新与遗忘机制缺失（48%）居前，窗口限制只排第三。扩窗解决不了写入、淘汰与检索策略问题。
- 工具侧：工具过多选择困难（52%）、幻觉调用（50%）。**工具的组织方式与描述质量比数量更决定调用成功率**。
- MCP：关注或已落地合计 37%，完成企业内私有部署仅 9%。差的是企业级配套——私有注册中心、统一身份鉴权、版本灰度、审计留痕、网关集成，这些都不是协议规范本身提供的。

## 5. 网关与可观测诉求

多模型路由与自动降级被 63% 的企业列为最需要的网关能力，是比例最高的单项需求：不同任务匹配不同模型、主模型不可用降级、按成本延迟动态选择——无法在应用代码里逐个解决，需要统一流量入口承接。可观测诉求里**成本归因（50%）仅次于全链路追踪，高于审计合规与语义质量监控**，是规模上来之前先建成本可见性的预防性诉求。

## 6. 评估：可靠性必经之路

- 评估手段：人工抽查 55% 稳居第一，基于运行轨迹自动评估仅 6%，公开 Benchmark 不足 5%，28% 尚无系统性评估；LLM-as-Judge/A-B 实验/离线回归任一用上的仅 34%。
- 后果体现在成功率：任务成功率 ≥90% 的企业仅约一成，≥70% 约 55%，**16% 根本没量化过成功率**——这部分企业无法判断 Agent 是否在正常工作。
- 相关性：用了评估手段的企业成功率 ≥70% 的比例约为无评估者的两倍，已上线持续迭代者达 84%。评估支撑迭代、迭代提升可靠性、可靠性使持续评估成为可能；缺评估的团队既无法定位问题也无法证明改动有效，长期停在试点。

## 7. 工程含义

调研结论收敛为三条：卡点在 Harness 层开箱即用的工程配套而非模型；形态与工具链碎片化是既定事实，统一入口与可迁移抽象是应对方式；评估基建不成熟是生产可靠性的最大短板。全系列按此组织：架构篇定形态与成熟度，构建篇给不绑定框架的 Harness 抽象，运行篇回应基础设施诉求，治理篇把质量从人工兜底转为机制，调优篇沿 Trace → Trajectory 建立持续变好的能力。
