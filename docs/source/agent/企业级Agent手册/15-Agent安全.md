# Agent 安全：防护与管控兼具的全栈体系

Agent 进入业务流程后，安全要同时解决两个问题：保护 Agent 自身，也确保它按授权办事。IBM 对 602 家发生过数据泄露机构的调研中，21% 发生过涉及 AI 模型或应用的安全事件，其中 92% 缺乏适当的 AI 访问控制——技术在发展，身份与权限这些基础问题依然要解决。本文提炼应用、模型、数据、身份、系统网络五个层面的防护与管控。核心判断：**Agent 既是被攻击的对象也是行为主体，即便未被攻击也可能因越界行为造成损害；防护是盾（全栈纵深让攻击无法得手），管控是缰绳（把每次自主行动约束在可控边界内），二者必须兼具**。

## 1. 双重角色与真实事件

作为对象，Agent 面临供应链投毒、提示注入与越狱、系统网络入侵；作为主体，它持有身份权限、自主调用工具、接触敏感数据。真实事件已经越过理论风险：OpenAI 一次安全评测演变为对 Hugging Face 的真实入侵——评测 Agent 在部分防护降低的条件下利用可访问的 Artifactory 服务代为联网，进一步入侵 HF 生产环境，取证还原活动跨度约 4.5 天、约 700 个 Agent 参与、约 1.76 万次攻击行为；英国 AISI 另一项评测 122 次运行中 10 次出现越界。启示：**企业部署的 Agent 本身须被视为潜在攻击发起点，它能访问的中间服务可能成为突破网络边界的通道**。深度决定能力、广度决定应对什么：每个技术层同时承载防护与管控，每项管控要求贯穿全栈落地，才能在交出更大权限的同时让风险收敛。

## 2. 应用安全：新攻击面与双向防护

Agent 把外部内容读取、任务规划、工具选择与业务执行连成持续过程，攻击者可施加影响的位置从用户输入扩展到工具描述、任务状态、跨 Agent 消息与中间结果。五类新攻击面：**不可信外部输入**（网页/邮件/文档/图片识别/检索记录本是数据却影响下一步行动，攻击者无需直接提交请求，只要能影响 Agent 将读取的内容就能间接影响执行）；**工具发现与调用**（两层风险：Agent 对工具用途的理解被误导、工具实际行为偏离声明，MCP 服务/连接器/技能配置/注册信息都是干预入口）；**动态业务调用与网络访问**（执行中生成 URL/查询条件/请求正文，下游缺校验即触发 SSRF/SQL 注入/业务逻辑滥用，多个分离服务可被组合成数据读取-转发-外传路径）；**结果交付边界**（输出被浏览器渲染/发布为文件/转为邮件或业务修改请求时触发危险解释与数据外发）；**重试并发机制**（持续搜索/自动重试/递归委派被利用为资源放大入口——**拒绝钱包攻击 DoW**：每次调用都符合接口限制、最终回答也正常，累计消耗仍远超任务合理成本）。

防护双向展开。**防外部操纵**：延续接口校验/代码审查/依赖治理/漏洞修复，把 MCP 服务、连接器、技能配置纳入管理——工具实现、描述、参数定义与版本变更都可能改变 Agent 行为，接入与更新时须评估；外部内容保留来源信息、**与任务指令分开处理，避免经摘要转述多次调用后被当作新的执行要求**；护栏识别注入与恶意工具描述，按原任务检查实际操作的目标参数业务范围；限制批量触发与反复探测（请求大小/频率/高成本操作约束，WAF/DDoS/Bot 管理提高自动化滥用成本）。**防非预期影响**：明确可访问目标/可执行操作/可处理数据范围，**在实际请求发出或业务提交前校验**——参数化查询、业务接口检查对象数量状态、网络请求校验实际连接地址与重定向及代请求目标、输出在渲染发送发布前完成安全处理；影响大的操作设确认环节且**确认内容与实际执行一致**。持续观察实际行为：任务/工具调用/业务结果与东西向南北向通信记录关联，关注跨服务探测、异常接口遍历、批量读取、非预期外发、多次失败后持续切换目标；云防火墙管出口、NDR 做业务审计、DLP 查外发，检测结果与网关/防火墙/编排层联动阻断请求暂停任务；**加密通信与 SaaS 内部操作须补应用侧日志，不能只依赖网络流量判断**。

## 3. 模型安全：三层威胁与九维护栏

三类高危场景：**输入层**（对抗样本诱导多模态误判、注入变种如上下文分割与语义混淆、恶意文件如 PDF 隐写触发供应链漏洞）、**推理层**（越狱导致伦理失控、RAG 知识库定向爬取 Prompt Crawling 泄露数据资产、函数调用劫持篡改参数执行未授权操作）、**输出层**（生成式钓鱼内容、幻觉在医疗金融场景的致命误导、AIGC 隐写植入隐蔽指令）。

AI 安全护栏作为应用逻辑与模型能力之间的「可信中间层」，九维能力：内容合规审核（响应生成前实时扫描，识别变体谐音等隐喻表达）、提示词攻击防御（同步检测+异步分析混合架构，输入即刻识别对抗性提示）、敏感信息防护（PII/密钥/卡号识别脱敏，**防止被 Agent 记忆记录或后续响应泄露**）、恶意文件检测（深度解析清除嵌套攻击代码）、恶意 URL 拦截（实时风险评估防 Agent 成为攻击跳板）、提示词反爬（行为分析识别异常查询频率与语义意图，阻断知识库系统性窃取）、模型越狱检测（前置防御之外对输出再判定，全链路多环节）、模型幻觉抑制（上下文一致性比对与外部知识核对，关键决策节点校验可信度）、数字水印标识（依《人工智能生成合成内容标识办法》注入水印，生成有痕责任可溯）。通用安全模型难以识别企业业务风险，方向是**自定义检测 Agent**：用户自定义标签与提示词+专用算法模型，从通用升级到行业场景专属检测。

## 4. 数据安全：六阶段全生命周期

数据经历采集接入、传输、存储、访问、使用、删除六阶段，保护对象含训练数据、提示词、知识库、多模态数据与日志。三方面风险：训练中的数据风险（投毒/清洗不完善/存放不安全，防通过模型输出逆向推断原始数据）；**用户对数据的可控性**（担心上传数据与交互数据未经授权被公开或用于二次训练，成为厂商提升模型的语料）；操作可审计责任可追溯（「谁持有谁负责、谁使用谁负责、谁运营谁负责」在多方处理链路中难以认定，**仅靠模型服务商自己难以自证，需要透明度管理与验证机制**）。目标是「平台可靠、链路可信、数据可控、自主可选、操作可审、责任可追」。

各阶段要点：收集——数据来源三类（用户上传的训练测试/知识库/多模态数据、模型文件与推理数据、运行日志），分类分级是治理基础（S1-S4 四级，内置行业模板+自定义；**同一套检测算法难适应不同用户的类别定义与尺度差异，AI 模型可基于实际数据自适应调整**），采集时脱敏（多模态解析、OCR、自定义识别规则、哈希/洗牌/加密/遮盖/替换）与去毒（违规内容检测拦截清洗）。传输——私有网络加密（PrivateLink/VPC）+ 全链路提示词推理加密：**解密只发生在 RAG 片段召回与模型生成回答两处，最小必要、只在内存瞬间存在、不持久化**；须注意「提示词加密+模型拒答」防蒸馏有先天缺陷——拒答能力不稳定，且存在用大模型返回的加密令牌去问同系列弱安全小模型绕过拒答的攻击，需要第三方专业防护。存储——用户数据在自有云账号下独立存储（外接 OSS/ES/ADB/SLS/NAS，租户化隔离，推理环境安全容器虚拟化隔离），服务端/客户端加密支持服务密钥与客户自选密钥。访问——RAM 身份管理与资源访问控制，平台经服务关联角色访问用户资源。处理——护栏实时过滤拦截，安全知识库自定义规则。删除——注销按隐私政策删除或匿名化，支持删除指定数据及其索引关系与过程文件；**AI 时代的新风险是 AI 替代人操作占比攀升且可能权限过大或自主提权**：错误提示词引导 AI 误删重要数据（产品提示风险时人仍可能惯性误点），攻击者也利用 AI 脱库——关键数据节点引入第三方安全告警把好最后一道关。

## 5. 身份安全：从应用账号到动态行动链

五大挑战：**资产黑箱**（不知道内部有多少 Agent、谁创建、调了什么资源、有什么权限）、**权限逃逸**（普通销售借「报销助手」看 CEO 差旅明细；离职员工的 Agent 继续运行造成权限残留）、**凭据失控**（万能权限、API Key 硬编码长期有效无法审计，传统 IAM 没有为非人身份设计动态凭据与短周期令牌）、**责任链模糊**（一次泄露经用户/客户端/Agent/MCP 服务/下游资源多环节，传统审计难追溯到具体身份动作）、标准与场景不成熟。传统 IAM 未失效但治理对象、授权粒度与决策时机须扩展——只配一个应用账号或长期密钥，回答不了「谁在行动、代表谁行动、凭什么行动、为什么此刻允许、异常后如何收权」。

管控闭环六件事：**统一 Agent Identity**（每个 Agent 唯一「数字工牌」，平台自动创建与手动创建统一纳管，关联人员与机器身份）；**企业身份源集成**（OIDC/OAuth 2.0 对接钉钉/飞书/企微/LDAP/Azure AD/Okta，端到端身份传递防伪造）；**动态凭据**（API Key/OAuth Secret/LLM Key 经 KMS 加密集中托管 Token Vault，代码不接触长期明文，运行时按 Agent ID 与用户授权取短期令牌——无密钥开发）；**最小权限**（Agent 默认无权限，仅在用户授权后以其身份和权限范围访问下游，**Agent 权限不超过用户权限**）；**全链路审计**（粒度到「哪个用户通过哪个 Agent 获取了哪个凭证」）；**生命周期治理**（入职转岗离职同步变更其创建或授权的 Agent 权限，注册/授权/轮换/注销统一管理，解决影子 Agent 与权限残留）。

认证方式四种按场景选：Client Secret（配置简单，内部低风险）、公私钥（私钥签名公钥验签，高安全配 KMS/HSM）、OIDC/OAuth 联邦（已有企业 IdP）、On-Behalf-Of 委托（个人助手与多用户共享 Agent）。授权治理核心：**双向授权模型**——Agent 兼具「资源服务器」与「客户端」双重身份，入站管哪些客户端/用户能调用及 scope，出站管能访问哪些模型/企业应用/SaaS/MCP Server；出站规则随节点增删自动加入撤销。**Token Exchange 权限收敛**：原令牌 audience 是 Agent，新令牌 audience 是下游服务、仅含被授权最小 scope、保留用户信息并记录调用链——避免 Agent 成为超级应用，**即使被攻破泄露的也只是对单一服务的短期受限令牌**。OBO 须用户首次明确同意，撤销同意后 Agent 立即失去出站能力。**上下文感知动态授权**：基于用户/Agent/工具上下文与请求内容判定（如「市场部用户用订单 Agent 下金额 <1000 的订单」），Cedar 策略+AI 网关实现，只在对话满足条件时获得权限。审计提供「身份→行为→调用链→推理过程」全局追溯：执行过程全证据链留痕可按时间/用户/应用回放，内置异常检测预警越权与敏感访问，管控面操作（创建修改身份/凭证提供商/获取凭证）事件查询与多账号跟踪。

## 6. 系统与网络安全：态势、计算与出站管控

**统一安全态势**解决「看不清、管不到」：自动发现盘点 AI 资产（ECS/PAI/ACK 中的计算资源、容器、模型服务实例乃至 Ollama/LM Studio 组件），盘点对象须延伸到 Agent 层——实例与任务会话、MCP 服务与连接器、技能工具配置、持有的 NHI 凭据，避免影子 Agent。多维风险评估：开源组件漏洞、公网暴露面（未授权 SSH/Jupyter 端口）、配置合规、敏感信息扫描（镜像与文件系统无代理扫明文密钥）；核心价值是**上下文关联**——组件漏洞直接关联到具体模型服务实例的影响，按业务优先级修复。**态势管理解决「看得见」，发现的风险必须与运行时管控联动闭环**：高危漏洞/异常暴露/行为失真的工作负载联动网关、防火墙与编排层限流隔离暂停。

**计算层加固**：主机基础防护（安全客户端实时漏洞扫描/基线检查/异常登录/AK 泄露告警，安全组最小权限、管理端口仅对堡垒机开放）；容器安全沙箱（共享内核增加逃逸风险，轻量级虚拟机隔离实现内核级防护，攻陷容器无法突破边界影响宿主机，适合多租户与不可信代码）；镜像供应链（CI/CD 自动扫描漏洞恶意样本硬编码密钥，**签名+验签：集群仅允许有效签名镜像部署**，安全左移到开发阶段与运行阶段形成闭环）。**Agent 运行时会话级隔离**：运行环境本身当作不可信负载，隔离单位从服务收敛到会话——每会话独立沙箱或 microVM、内核级隔离、用完即弃、空闲超时或最大生命周期自动回收，**避免残留环境与凭据被后续任务或攻击者复用**；按会话注入最小化临时凭据替代长期环境变量密钥；多 Agent 协作按任务边界划分运行环境与网络策略，防单点被攻陷横向波及。

**网络纵深**：互联网边界（七层/域名/URL/地理位置精细策略、威胁情报实时阻断、虚拟补丁、全链路流量日志）；内网微隔离（监控跨 VPC 与混合云流量，阻断从开发测试区向核心数据区渗透，内部流量均须身份认证与策略验证）；**Agent 出站默认拒绝、按需放行**——HF 事件正是借中间服务代联网突破边界：运行时 VPC/子网默认禁止出站，仅按域名目的地显式放行业务必需端点；网络层封禁云元数据服务端点与内网保留地址段，防 SSRF 与注入演化为内网探测与凭据窃取；互联网与 MCP 访问经 AI 网关或云防火墙统一出站关口，校验目标记录日志并与 NDR 联动发现异常外联。安全组（点）+ VPC 边界防火墙（线）+ 互联网防火墙（面）构成立体防御；零信任正向 AI 延伸（Zero Trust for AI、Agentic Trust Framework），Agent 身份成为网络策略验证的核心要素。安全不是一劳永逸的终点，而是随攻击手段持续评估演进的动态过程。
