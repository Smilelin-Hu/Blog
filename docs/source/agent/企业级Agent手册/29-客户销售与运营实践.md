# 客户销售与运营实践：MiniMax、信永中和、哔哩哔哩与滔搏

客户、销售与运营一侧的 Agent 落地，考验的不是单点对话能力，而是支撑规模化业务的数据底座、治理平台与运营机制。本文按源章顺序整理四项实践：MiniMax 为亿级用户的 AI 角色对话构建海量长周期记忆数据底座，信永中和用 AgentCore 与 AI 网关把多智能体纳入统一治理，哔哩哔哩以「大模型 + 小模型」协同把社区内容变成商业洞察，滔搏体育把零售经验沉淀为可复用可运营的企业资产。四者共同指向一个判断：**单个 Agent 能工作，不代表多个 Agent 合在一起就能把事情做好**——规模化的意义不是企业里多出更多 Agent，而是让今天解决过的问题成为明天可以复用的能力。

## 1. MiniMax：海量长周期记忆的三重存储挑战

MiniMax（稀宇科技）成立于 2022 年，坚持文本、视频、语音全模态自研，旗下海螺 AI、星野、Talkie 等产品覆盖 200 多个国家及地区逾 2.36 亿用户。星野是基于多模态 AIGC 的 AI 智能体创作平台，用户定制具备个性化形象、声线、人设及技能的 AI 角色，核心价值在对话场景——依托自研大模型的上下文感知与表达能力实现高拟人化对话，构建用户与 AI 角色间的持续互动关系，而持续互动的前提是长周期记忆。用户规模与活跃度持续增长给底层存储带来三重挑战：**海量多模态数据的存储与性能瓶颈**——用户自定义角色模板、对话数据及视频音频图像等非结构化内容日均新增数亿条，整体规模超百 TB 且指数级增长，传统数据库处理数十 MB JSON 或 Blob 大字段时性能急剧下降，表超过 10 亿行后读写延迟显著上升，直接影响 AI 推理链路效率；**潮汐流量下的弹性与稳定性压力**——峰值并发相比日均基线扩大 10 倍以上，静态资源配置导致低谷期闲置、TCO 上升，高峰期水平扩展受限又引发性能衰减与端到端延迟增加；**架构边际成本持续攀升**——计算、存储、运维成本随业务指数增长，边际成本成为可扩展性的主要瓶颈。

## 2. MiniMax：PolarDB Limitless 的四项能力与业务收益

数据底座基于 PolarDB Limitless 构建，四项能力对应三重挑战：**分布式多主架构**打破单主节点性能瓶颈，支持高达 63 个计算节点同时写入，每日新增 xTB 级对话数据高效分散到多个 Shard，写入吞吐线性扩展；分布式 DDL 通过多阶段提交协议确保跨节点表结构变更的原子性，不停服即可完成 schema 变更，加快产品迭代。**秒级弹性扩缩容**应对流量潮汐：Serverless 实时监测 CPU/内存负载，5 秒内完成预测、1 秒内完成从 0 到千核的无感扩容，最大支撑十万级突发 QPS；基于 PolarStore 共享存储实现「零数据拷贝」弹性——扩容仅需切换分区的计算所有权而无需迁移物理数据，结合智能分区调度算法元数据与状态迁移量减少 30%-50%，全程连接不中断、事务不丢失、性能波动低于 5%，无需为峰值预留冗余资源，整体计算成本降低 50%。**大表与大字段优化**加速长上下文处理：针对含大 JSON/Blob 字段的千亿级对话表，列存布局与局部更新能力结合 RDMA 网络加速实现单节点 12GB/s 大字段吞吐，CRUD 性能提升超 3 倍，历史对话检索延迟稳定毫秒级；基于协程调度与上下文缓存的异步执行框架使「按用户 ID 拉取对话流」等高频点查 QPS 提升 50% 以上。**智能化数据底座**双轮驱动：冷热数据智能分离按访问热度自动分层，零代码改造实现毫秒级热数据响应与秒级冷数据检索；多模态统一引擎借助 RDMA 高速网络实现文本语音图像跨模态低延迟高精度召回，增强 Agent 长期记忆与上下文理解能力。目前 MiniMax 全系产品 100+ 数据库已部署在 PolarDB 上，收益四条：千亿级对话表读写性能提升超 3 倍、支撑日均数亿消息实时写入与毫秒级检索；秒级无感扩缩容应对 10 倍流量波动、计算成本降 50%；冷热自动分层归档使存储成本下降 75%、运维人力减少 80%；分布式 DDL 支持 7×24 在线 schema 变更、AI 功能上线周期显著缩短。这验证了云原生数据库与 AI 系统深度融合的价值——「湖库一体」智能数据底座与算法引擎协同，长记忆、多模态交互、实时响应的 AI 智能体生态得以规模化落地。

## 3. 信永中和：专业服务机构为什么需要企业级多智能体平台

信永中和源起 1981 年，是中国最早成立的会计师事务所之一，拥有审计鉴证、管理咨询、税务服务、工程管理四个平行业务板块，在全球 23 个国家和地区设立 110 个办公室、超 1.2 万名员工。随着 AI 应用场景逐步增多，企业级 AI 建设已不再局限于单一问答助手，而需要进一步解决**多智能体协同、模型统一管理、业务系统连接、安全管控及成本治理**等问题——这正是引入 AgentCore 多智能体治理与协作平台及 AI 网关的原因。分工清晰：信永中和负责整体业务规划、应用场景设计、知识体系梳理、内部系统集成及推广运营，阿里云提供平台产品与技术支持；双方围绕核心需求完成技术方案验证、应用场景配置、内部系统对接，在最终上线的关键阶段用一周时间完成系统联调、环境配置、应用接入、测试优化后正式上线，快速形成面向内部员工的多智能体 AI 服务能力。专业服务机构对信息安全、数据保护和业务合规有较高要求，安全、可控、可追溯始终是重要原则。

## 4. 信永中和：多智能体协同与 AI 资产统一管理

基于 AgentCore 构建面向不同业务场景的 AI 智能体，采用统一管理、协同调度方式：平台根据员工问题识别任务类型，分配给相应专业 Agent 处理；涉及多步骤的复杂任务由统一的**管理 Agent 进行任务拆解和结果汇总**，实现多 Agent 协同——既保留专业 Agent 在特定场景的能力，也为员工提供统一便捷的使用入口，员工不必逐一判断该用哪个 Agent，只需描述需求。AI 资产统一管理是规模化应用的重要基础：模型、MCP Server、Skill 及 Agent 模板集中管理，按不同 Agent 的业务需求和权限要求配置下发；通过 MCP Server 管理能力，企业内部现有系统和服务接口逐步转化为 Agent 可调用的标准能力，使 Agent 不仅能回答问题，还能在授权范围内查询信息、调用系统、执行任务；内部 Skill 统一沉淀、审核和复用，为快速构建更多业务 Agent 提供基础支撑。已构建四类智能体：**制度与流程问答 Agent**（对接内部知识库，自然语言查询制度流程与管理规范，减少人工找资料和跨部门咨询）、**OA 集成 Agent**（连接办公系统，对话式完成工时查询与填报）、**企业信息查询 Agent**（企业基本信息、股东情况、关联关系及风险查询，辅助客户了解与项目立项判断）、**文档处理和汇报辅助 Agent**（文档总结、材料提炼、内容整理、汇报框架生成，降低重复性文字工作量）。各类 Agent 服务化接入内部应用平台形成统一入口，为从「信息查询」走向「任务执行」奠定基础。

## 5. 信永中和：AI 网关四能力与全程可观测治理

模型调用层面通过 AI 网关统一接入管理，作为统一入口提供四项能力：**多模型调度保障服务稳定**——按场景任务特点选择合适模型，主模型延迟或异常时按预设策略切换备用模型；**精细化统计支持成本治理**——按部门、Agent、模型统计调用量和 Token 使用，为资源分配、使用分析和预算管理提供数据；**统一认证实现权限控制**——按 Agent 业务职责配置不同模型访问权限和调用策略，避免超范围调用；**安全防护降低数据风险**——请求和返回过程中结合敏感信息识别、内容安全检测及访问控制统一防护调用链路。全程可观测支撑企业级 AI 治理：Agent 调用过程、模型使用情况、任务执行记录及异常情况统一监控分析，员工在什么时间、通过哪个 Agent、调用了哪些能力、完成了哪些操作都形成调用和审计记录，为问题排查、安全管理及内部治理提供依据；统一身份认证、权限控制、凭证管理和资源隔离确保 Agent 在授权范围内调用企业系统和数据。成效有两层：表层是统一的企业 AI 服务入口，对话式交互降低员工使用 AI 和内部系统的门槛；深层是**建立了企业级 AI 应用的统一技术底座，后续新增 Agent 和业务场景可以在相对统一的标准下建设、接入和治理**。方向是从知识问答走向业务协同和任务执行——随着内部系统经 MCP 向 Agent 开放标准化能力，员工用自然语言描述需求，AI 自动完成信息查询、任务拆解、系统调用及结果反馈，企业 AI 从「回答问题」走向「完成工作」。核心经验：企业落地 AI Agent，关键不仅在于模型能力，更在于如何把不同 Agent、模型、知识、系统和工具统一组织起来，并在安全、合规和成本可控的前提下服务真实业务。

## 6. 哔哩哔哩：内容种草平台的三大痛点与大小模型协同

B 站内容生态涵盖视频、图文、直播、音频、互动内容等多种体裁，以「内容种草」为核心心智，是汽车、3C 数码、美妆、快消等行业品牌营销的重要阵地。与传统电商不同，B 站用户的消费决策源于内容互动形成的品牌认知与兴趣积累，而非站内直接转化，这对营销效果评估提出更高要求。商业化团队面临三大挑战：**营销效果难以量化**——品牌投放 UP 主种草视频后缺乏手段衡量用户群体是否被「种草」，如汽车品牌需从互动内容中识别用户群体对续航、外观、价格等属性的评价；**内容资产难以结构化**——视频含大量视觉语音文本信息、互动区充斥高信息密度长文本，传统关键词匹配或规则引擎难以准确提取品牌、类目、SPU 等商业实体及关联语义；**营销策略缺乏数据支撑**——品牌希望基于真实讨论反向指导新品定义与传播策略，如美妆品牌需了解用户讨论粉底液时最关注持妆度、遮瑕力还是肤感。所有分析基于**经过去标识化、匿名化处理的海量公开互动数据，开展群体层面的趋势分析**。解决方案依托 PolarDB for AI——PolarDB 内部的分布式机器学习组件，支持数据不出库前提下高效调用轻量化小模型实时推理，同时联动通义千问等大模型处理复杂语义任务。技术路径是「大模型 + 小模型」融合：依托 DeepSeek、Qwen 系列、B 站自研 Index 模型与 PolarDB for AI，构建 M×N 矩阵的全域内容洞察体系（M 为商业化标签维度、N 为内容体裁维度），架构三层——AI 基建层（百炼、PAI、GPU 资源及自研 Agent 平台提供训练推理调度）、数据与模型层（通用大模型 Qwen/Qwen-VL/Qwen-Audio 结合经 SFT 与强化学习微调的领域小模型）、应用服务层（PolarDB for AI 节点提供模型算子，数据不出库高效挂靠推理，稳定独享的实时在线服务）。分工兼顾效果与成本：**通用大模型用于标签体系挖掘与复杂语义分析，领域小模型在实体抽取等特定任务上实现更高精度与更低延迟**；定制化电商领域大模型结合阿里电商商品知识图谱，大幅提升类目、品牌、SPU 标签识别与品牌高精准匹配能力。

## 7. 哔哩哔哩：实体挂靠与「过滤-分析-挖掘」三级流水线

两个关键技术难点各有解法。**视频稿件内容提取**：信息分散于画面、语音与字幕，采用多模态融合策略——ASR 与关键帧 OCR 提取原始文本，Qwen-VL、Qwen-Audio 生成语义中间表示；基于大模型挖掘与行业维护建立 CPV「类目-属性-属性值」体系（如相机类目下防抖技术属性的值 IBIS）；大模型抽取〈类目, 品牌, SPU〉三元组后，难点是原始抽取结果与标准产品库命名不一致（「尼康Z5」vs「尼康Z5微单相机」），解法是在 PolarDB for AI 节点部署定制化挂靠模型，**通过 SQL 的 PREDICT 语句在数据库内直接调用精调大模型做实体对齐**，实现数据不出库的高并发挂靠，既保障数据安全又降低工程复杂度，再结合 BGE+RoBERTa 等 NLP 模型匹配进一步提升准确率。**互动内容分析**：评论区信息密度高但 90% 以上为非商业化内容，大模型全量处理成本高昂，采用三级流水线——第一级商业化过滤用轻量 NLP 模型（BGE+BiLSTM）快速筛除无关内容，仅保留可能涉及品牌产品讨论的部分；第二级实体与语义关联分析用 PolarDB for AI 的商品大模型识别类目品牌 SPU 并建立实体间语义关联；第三级意图与属性挖掘识别「种草」「购买意愿」等高阶语义，提取用户群体关注的具体属性（如「续航达成率高」「价格贵」）形成结构化洞察。体系已应用于哔哩指数、花火平台 AI 选 UP 主、哔哩必达洞察报告、引力计划爆文投放、经营号线索挖掘及品牌广告搜索词包等商业化场景，把社区公开互动数据转化为可行动的商业洞察，提升广告主投放确定性与 ROI，实现从内容洞察到营销转化的全链路提效。

## 8. 滔搏：为什么需要多个企业级 Agent 与统一运营底座

滔搏拥有 4360 家实体门店、超 3700 家小程序店铺，与 20 多个领先运动品牌长期合作，累计用户超 9000 万。单店经营问题可以找有经验的人商量，但面对几千家店不能只靠找到最懂的人——最有经验的人不可能同时出现在每一家店铺，目标是**让经过验证的专业经验及时服务更多门店**。岗位不同需要的帮助也不同：一线员工问商品怎么介绍、需要哪些培训；店长问问题出在哪、怎么调整运营、哪些顾客需要维护、怎么把分析落地成动作——目标相关，但所需知识、数据、权限不一样，因此需要不同能力的 Agent 解决不同岗位的具体问题。多做几个 Agent 并不自动解决问题，规模化运营有六个难点：**重复建设**（同样的知识数据工具每个项目重新接一遍）、**协作困难**（经营 Agent 做完后会员营销怎么接下一步）、**权限治理**（不同岗位能看什么能做什么要清晰界定）、**效果衡量、问题定位、共同运营**（上线后谁持续负责）。这些不可能让每个项目各自解决，需要统一运营底座——AgentCore 承担这一角色：模型连接、MCP 工具、Skill 和 Agent 统一管理，Workspace、团队、角色、凭证管理明确资源边界，Agent Team 让多个专业 Agent 围绕任务协作运行，出了问题能追溯，再结合 AgentLoop 评估和改进。目标是**做第二个 Agent 时不必从头开始，做第 10 个时也能管理清楚**。但平台不能代替业务回答所有问题：什么结果算合格、哪些动作需要人工确认，需要业务自己明确——底座有了，接下来是把零售经验变成可复用、能协作的专业能力。

## 9. 滔搏：三个协作场景，交付的是行动而不是报告

零售 Agent 体系自下而上：知识、业务数据、MCP 和 API 工具 → 可复用 Skill（商品查询、库存、会员分群）→ 专业 Agent（经营、商品、陪练、会员、营销）→ 围绕业务目标组成 Agent Team，用户经 AI 助手提需求，Team Leader 分解任务、调度能力、汇总结果，身份权限、运行观测、评估反馈贯穿全程。**一线练货**：经营 Agent 发现商品销售偏差，但不能把卖得不好直接翻译成员工学得不好——需结合现场反馈确认问题真实存在；确认训练需求后商品 Agent 提供资料卖点搭配，陪练 Agent 组织针对性互动练习，评分与建议回到 AI 助手安排补练并持续观察后续表现。分工是经营分析找问题、商品能力提供依据、陪练变成可练习的动作；单月练货商品超 5700 件、次数超 39 万，但使用规模之外真正值得关注的是训练有没有帮员工把能力用到实际服务中。**线索挖掘**：线上小程序店只有店长一个人，看数据、选顾客、挑商品、组织沟通全落在一人身上——**如果 AI 再生成一份报告，阅读任务增加了，经营任务却没有减少**，所以要把报告后面的准备工作连接起来：经营与会员 Agent 识别优先维护顾客，商品 Agent 匹配偏好与可售商品，营销 Agent 准备沟通建议，AI 助手汇总为店长当天可执行的任务，店长确认并亲自跟进，回访和成交记录反馈到下一轮维护——店长还是一个人，但交到手里的不只是一份洞察，而是一项准备充分的行动。**门店经营探索**：「周末怎么安排」没有现成按钮，店长提出的是目标和约束而非预设指令，AI 助手把经营表现、商品库存、会员情况整理成商品主推、陈列调整、顾客维护等建议，店长可追问、修改、最终确认执行；**复用能力不等于共享所有数据，店长使用的仍然只能是本店授权的数据**。单次经营分析案例中店长工作从耗时 2 小时缩短到约 20 分钟，更值得关注的是减少跨系统取数整理后，店长时间留给了经营判断。

## 10. 滔搏：四步复制与 SOP 型 Skill 沉淀

从做场景走向沉淀能力的转折点是回答「下一个店长再问，是不是还要重新再来一遍」。能力沉淀分四步：**选场景**——先找高频、刚需、可衡量的问题，明确原流程耗时与验收标准；**沉淀资产**——建设中把知识、工具、Skill、Agent 与测评数据沉淀下来，让下一次有东西可用；**共同运营**——上线后由业务、IT 与 AI 团队共同运营，持续看使用与价值；**持续进化**——有效能力继续优化复制，长期低价值场景及时调整退出。每做完一个场景回答两个问题：这次解决了什么？下一次可以复用什么？最值得留下的是**反复确认有效的处理方法**：同一类经营问题出现多次且业务验证过，就不需要让 Agent 重新灵机一动，把经过验证的方法沉淀为 **SOP 型 Skill**——讲清楚适用条件、输入处理、调用工具、输出，正常情况怎么走、异常怎么办、什么时候需要人确认。不是把经验写成文档就完成，而是要能被调用、被验证、随反馈更新；**Skill 需要版本化、负责人和测评标准，稳定的 Skill 进一步组合成专业 Agent**——留下来的不只是一次答案，而是一套已验证的解法。

## 11. 滔搏：三团队共同运营与双闭环持续调优

经验可以沉淀，业务规则还会继续变化，能力由谁持续维护？答案不是交给某一个团队：**业务最了解问题与判断规则，定义验收标准并持续承担场景负责人角色；IT 负责平台、系统集成、身份权限与运行稳定性；AI 团队负责 Agent 工程、公共能力、测评与版本优化**——各有分工，但不能各自验收、各自结束。上线后围绕共同的业务结果决定继续优化还是退出，否则就会出现「**Agent 上线了，责任却下线了**」；要改变的正是这种一次性交付关系——能力有人建设，也有人长期对它的有效性负责。共同负责需要共同的衡量办法：调用量大不等于业务价值，建议没被采纳或每次都要反复纠错，调用量就没有变成价值。指标四维：**使用与采纳**（不仅看有没有人用，还看建议是否被业务采纳）、**质量与可靠性**（正确率、异常情况、人工兜底）、**效率与成本**（耗时、节约时间、单次成本）、**业务价值**（方案有没有被执行、结果有没有被改善）。指标最终导向行动：入口是否调整、工具是否修复、Skill 是否更新——仪表盘告诉发生了什么，运营还要回答然后改什么，改进进入下一次循环闭环才真正开始。这是两个闭环讲同一件事的两个面：**AgentLoop 关心能力怎么变好，Business Loop 关心经营问题怎么解决**；关键不是运行次数多了 Agent 就自动变好，而是反馈有没有被接住、有没有转化为经过验证的改进——练货效果不理想就检查训练需求、内容与评估，顾客维护不达预期就分析人群筛选、商品匹配还是沟通内容需要调整，真实反馈进入 Skill 与 Agent 优化后，更新的能力帮助业务解决下一轮问题，关键决策和执行责任仍由人承担。总结成一句话：AgentCore 提供智能体构建和治理的底座，AgentLoop 提供数据飞轮的底座，滔搏把零售经验不断沉淀为可复用、可运营的企业资产。
