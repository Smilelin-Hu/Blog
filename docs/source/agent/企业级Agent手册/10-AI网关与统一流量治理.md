# AI 网关与统一流量治理：模型、工具与任务的策略执行点

LLM、MCP 与 Agent 的普及没有让 API 网关与服务网格的能力失效，而是引入新的治理语义：响应可能持续流式输出、费用按 Token 核算、工具调用产生业务副作用、任务跨越多轮交互与等待恢复阶段。AI Gateway 在模型、工具和 Agent 的访问路径上建立一致的策略执行点，并与任务执行系统协同。本文按治理对象提炼 LLM/MCP/Agent 三种可组合语义、统一治理与控制面联动，末尾附智能路由与 AI Coding 的智价比实践。核心判断：**网关只保证准入、转发与记录的一致性，不能仅凭请求成功断言任务完成，也不能替代执行系统保证状态恢复**。

## 1. 三种治理语义与 AI 流量的新约束

三种语义是分析框架而非成熟度阶梯，不要求依次建设三个独立产品：

| 治理语义 | 直接治理对象 | 主要问题 | 不承担的责任 |
|---|---|---|---|
| LLM Gateway | 模型调用及其实际尝试 | 选哪个模型/端点，限流、容灾、计量 | 判断输出是否满足业务成功标准 |
| MCP Gateway | MCP 请求及工具调用 | 协议代理，当前身份能否调指定工具及参数 | 把可发现等同于已授权、健康或可执行 |
| Agent Gateway | Agent 接入及任务关联流量 | 身份、路由、亲和、并发控制、跨调用关联 | 定义 Task、业务 State、Checkpoint 或恢复语义 |

可部署在同一数据面，统一的关键不是同一进程，而是**身份映射一致、策略边界清晰、调用记录可关联、同一次上游调用不因穿过多个组件被重复计费**。客服退款案例的完整链路：Agent 入口校验委托身份并按能力标签路由 → 模型调用经 LLM Gateway 路由降级 → 只读订单查询经 MCP Gateway 鉴权放行 → 退款挂起进审批，批准后按新准入条件重新校验委托范围/参数摘要/预算预留才执行 → 结果与用量回写任务账本，由业务系统判定 Outcome。

AI 流量四特征改变网关设计：**长连接流式**（HTTP 成功后仍有流内错误；TTFT 不等于 HTTP 首字节；SSE 字节切片可能含半个或多个事件，首个事件可能只是心跳）；**大请求体**（全量缓冲内存随并发放大，需增量解析与按路由控制缓冲）；**Token 计费**（准入估算≠实际用量，并发同时消耗余额）；**多轮长程**（亲和助缓存复用但不替代状态持久化，KV cache 复用是性能优化不是业务恢复，缓存未命中应表现为性能变化而非 Task 丢失）。与既有设施的边界：API Gateway 可承载 AI 插件、Mesh 提供 mTLS 与发现、Registry 只是目录不因集成而授权、业务应用保有 Task 权威、Verifier 需授权才判定 Outcome。Higress 的 Wasm 插件 + Envoy 数据面 + Istio 控制面是一种实现路线而非必须架构；生态比较要落到具体版本（原 Envoy AI Gateway 现称 Agent Router，v1.0.0 GA 不代表所有控制面 API 都进入 v1）。网关自身也要按关键基础设施设计：多副本不消除依赖单点，状态写入 Redis 不代表一致性要求自然成立。

## 2. LLM Gateway：路由、重试、超时与严格预算

统一接口须**声明能力子集**：工具调用、图像输入、推理内容、缓存用量、停止原因不总能无损映射，不支持的参数应显式报错而非静默忽略；记录适配器版本、实际 provider 与原始用量来源，避免协议转换后无法对账。**模型选择与端点选择分开**：静态映射权重（灰度主备，变更须能力质量回归）、成本感知路由（看总任务成本含重试返工而非单次价格）、语义路由（分类器须经评估且有回退，分类错误改变质量且自身有成本）、推理端点选择（队列/在途/缓存信号，时效与负载均衡权衡）。InferencePool v1 API 稳定，但调度算法属实现，前缀关联只是缓存可能可用的信号。

**错误分类先于重试**：限流看重置时间、认证错误应终止并修凭证、上下文超限不能由网关擅自截断——截断策略属 Harness 决策。「尚未收到响应体≠上游尚未执行」。**多层重试乘积放大**：SDK 3 次 × 网关 3 次 = 上游 9 次，尝试预算须跨层传递——绝对总截止时间、按 call_id 原子扣减尝试额度、call_id+attempt_id 关联、重试/摘除/切换分开记录。五种超时（连接/首字节/TTFT/流式空闲/总截止）不互相代替：心跳流可以不触发空闲超时却没有有效输出。usage 缺失不能记零消耗，客户端取消不证明上游已停止。

**预算四机制分开建模**：速率限制、Token 时间窗、余额配额、严格预算。「请求前检查响应后扣减」不保证硬上限——余额 100 时两个估算 80 的并发请求可同时通过，实际消耗 160。严格预算不变量：**可用额度 = 已授权 − 已结算 − 在途预留；准入条件 = 本次最大可计费消耗 ≤ 可用额度**，检查与预留须同一原子操作，结算幂等并释放多余预留，重试单独占额，流中断不能因租约到期无条件退款（上游可能已执行）。Token 配额与金额预算分开；现成插件（如 ai-token-ratelimit/ai-quota）多非严格并发预算，且缓存故障分支的放行/拒绝行为需逐版本验证。语义缓存键须区分租户/权限/模型版本/系统提示/知识版本，**有副作用的调用不能重放缓存结果**。

## 3. MCP Gateway：准入四步与不可绕过前提

版本基线影响治理语义：MCP 2025-03-26 确立 Streamable HTTP，2025-11-25 引入实验性 Tasks，2026-07-28 提供逐请求元数据与 server/discover、Tasks 移为可选扩展。准入四步「**认证 → 协议校验 → 授权 → 转发**」：逐请求元数据只服务第二、四步，**协议说明不是调用者身份证明**；Mcp-Name 镜像头按方法校验且须与正文一致，防止头部鉴权与正文执行不同对象。tools/list 过滤减少误选，但 tools/call 必须再次鉴权。有效权限 = 调用者原有权限 ∩ 工作负载限制 ∩ 任务委托范围 ∩ 资源侧限制，**不由 clientInfo 自称扩大**。

**网关不可绕过依赖五前提**：凭证不下发到客户端、出口网络受控、发现与 DNS 收敛到网关、直连被禁、旁路受审计——缺一项则策略只是建议。健康检查分层：连接可达≠协议兼容≠业务依赖可用；写入/支付类工具不为健康检查执行真实副作用。桥接方向须显式声明（如 Higress 仅支持 Modern 下游→Legacy 上游）；出口按上游 RPC 重构，默认不透传 Cookie/会话/内部头；REST-to-MCP 防 SSRF（限制可变主机与路径的出站），**用字符串前缀判断「只读 SQL」不可靠**。参数级治理按业务风险配置：数据查询限范围、支付走审批与额度、集群管理限环境、文件读取限路径。自然语言治理意图须转成结构化策略经验证后发布，**运行时不靠模型自由解释权限**；框架、网关、资源服务器三层纵深防御。

## 4. Agent Gateway：任务对象权威与分层账本

任务关联对象各有权威来源：Task 归业务应用、Session 归执行系统、Turn 归 Harness、State/Checkpoint 归业务模型+Runtime、Outcome 归业务或获授权 Verifier。网关可存亲和键、映射、在途计数、配额预留，但不解释业务 State；按能力标签选候选后仍须验证版本/授权/环境；**亲和失败不能转到空运行时声称「已续跑」**。协议成熟度不同：ACP v2 仍 Draft（IDE 客户端场景）、A2A v1.0.0 已 GA（Agent 间）。HiRoute 的任务路由案例：主 Agent 按「计划」（稳定调用名+用途+执行工作 Agent+候选模型）显式委派 Codex、DeepSeek Harness、Claude Code 等完整工作 Agent，任务有独立身份与幂等，保持受理时的计划版本。

**租户身份与财务归属正交**：配额绑认证主体而非 IP；入口在途并发≠Runtime 活动任务槽位。**Task 分层账本归因链：task_id → session_id → turn_id → model/tool call → attempt_id**，task_id 来自业务应用，客户端关联头须绑定认证主体校验租户，防止伪造头转移费用；关联缺失记「待归因」不编造。四层账本各答不同问题：Attempt 层答上游实际尝试、Call-Turn 层答本轮消耗、Session 层答会话成本、Task 层答任务总账。网关日志只是任务账本来源之一，**Trace 因采样/缺失/跨恢复不自动成为财务权威**；模型 tool_calls 是意图不等于工具已执行，工具费用以执行记录结算；请求成功率与业务完成率分开统计。

## 5. 统一治理：身份、委托、审批与审计

主体映射须清除伪造的内部头（不直接信 x-mse-consumer 之类）；委托可验证、可撤销、范围清晰、不超过委托者原权限；每次判定记录命中规则版本与拒绝原因。**审批是持久化业务状态，不是 HTTP 长挂起**，五状态各有明确语义：

| 审批状态 | 执行语义 |
|---|---|
| 待审批 | 不执行，连接可以结束 |
| 批准 | 重新校验身份/委托/参数摘要/预算后才转发 |
| 拒绝 | 终止，不隐式替换为其他操作 |
| 超时/撤销 | 保持未执行，**不自动降级为只读** |
| 结果未知 | 不盲目重试，交业务对账与补偿 |

审批记录绑定工具版本、参数摘要与任务上下文，回调须认证防重放。审计材料≠业务 Evidence；日志默认元数据为主，内容按需脱敏、限长、采样；DLP 检测服务失效时放行/拒绝/转人工按风险预先定义。**插件顺序须验证**：鉴权与预算在转发之前，敏感内容不因顺序失效被提前写入日志。FinOps 需要可核对的主体、用量与价格，实时准入账与财务报表之间要有对账规则，不「天然一致」。

## 6. 控制面联动：变更链路与可观测边界

Evaluation 不天然拥有发布权，完整链路六阶段：**观测诊断 → 候选建议 → 构建验证 → 治理授权门禁 → 灰度控制面发布 → 运行反馈**，各阶段有进入条件。低风险调参可在预批准范围与幅度内自动执行，但留版本、验证与回滚记录，超范围重新授权；缓存策略不因名称而被认定低风险。分发机制（xDS 的 LDS/RDS/CDS/EDS、CRD+OCI 制品）支持热更新，但仍须测试在途流式请求的行为；配置记录策略版本+插件制品摘要+发布批次。运行时自适应（如 AdaptiveScore EWMA）是已发布策略内部的端点选择，**不能自行扩大模型范围、地域、权限或预算**。

可观测五类数据各配常见误区：用量成本（usage 缺失记零）、时延（TTFT 混同首字节）、可靠性（请求成功当业务完成）、治理（拒绝无规则版本）、关联（缺 task_id 断链）。**指标控制基数**：Task/Session 标识进日志与 Trace，不进指标标签；OTel gen_ai.* 语义约定仍处 Development 状态，须固定版本使用。回滚不只恢复配置文本，还要处理已执行副作用、未结算额度与在跑任务。

## 7. 智能路由实践：智价比与 HiRoute

**智价比口径 = 同样验收标准下完成一件事的总花费**，不是 Token 单价。Epoch AI 数据：达到同一能力水平的成本 2023 年以来平均每季度降约 47%，低价模型只会越来越多，难的是怎么用好。关键观察：**难度是一步一步变化的，不是一个场景对应一个值**——技术选型任务里大部分工作是整理核验，真正需要强模型的只有少数判断；资料整理交经济模型、关键判断交主力模型，质量与全程主力一致而成本约为其十二分之一；全程经济模型则三次关键判断错两次。所以场景层决定「候选模型与验收标准」，每一步用哪个模型到这一步再判断。工程细节：**只在新用户消息、上下文压缩或重建时换模型，一轮之内保持不变**——轮内来回切换会白白丢掉上下文缓存（实测一轮 21 次调用同模型，缓存命中近九成）。

通用榜单只能初筛：SWE-Bench Pro 上，Verified 能解七成的头部模型公开题只剩约 23%，私有代码库再降到 17.8%——自己的代码库对模型正是这种未见过场景。落地思路是**边用边评**：先只把足够简单的步骤交新模型，每步看结果，出问题主力接手，证据够了再放手。判断证据就在用户下一条消息里：明确否定是失败证据，接着安排或沉默不能证明失败。信任度调整规则不对称——**放手门槛高于收回**：建议多放手需 ≥30 个评分步骤、≥3 个会话、评分覆盖六成以上且 85% 达标；建议收回只需 30 个步骤中达标不足 70%；每次调整先用历史记录回放确认影响面再生效。

决策机制上「**让模型回答问题，让程序做决定**」：直接问决策模型「该用哪个模型」结果不稳定（复合判断易想偏），拆成三个独立问题——上一步做得怎么样（胜任度评分）、这一步有多难（简单概率）、上一步的问题会不会带到这一步（已知未解决问题是否仍适用）——选组由程序按阈值组合。对比实验中两类决策模型的选组准确率从 50%-67% 提升到 89%-100%，且两种方向相反的偏差（偏大胆/偏保守）被同一拆法压下；每千次三问决策约 0.085 美元、耗时中位数半秒到一秒，每轮判断一次负担得起。

AI Coding 实践（一个月约 300 亿 Token、净增 31 万行 Rust）验证了四条抓手。其一，**按阶段分流**：受控复跑真实并发缺陷，全程主力 3/3 通过、17 分 46 秒、$6.45；按阶段分流 3/3 通过、32 分 25 秒、$2.65（省约 59%）；全程经济模型仅 1/3 通过。典型会话 56 次请求中，经济模型承担约 86% 的 Token 却只占约 5% 的费用。其二，**验收与人的判断接进闭环**：范围清楚的任务靠厚验收门禁守夜（5000+ 测试、60+ 界面场景脚本、14 条 Computer Use 端到端实操链路，单测全绿但界面点不通照样报错）；低分保护触发主力接管修根因。核心设计任务人在场把关，**对话中的明确否定与纠偏是高权重胜任度信号**——经济模型给出「调高内存上限糊弄单测」的方案被一句话否定后，下一轮自动切主力重做设计。其三，**管住 Harness 协作的隐形 Token 税**：强拆子 Agent 让每个子会话重读背景代码，父模型等待中反复唤醒重读几十万字主上下文却无新产出。收敛为「**主线不拆，旁支外包**」——核心改造留在同一主会话靠模型路由换模型；真正解耦、边界干净的支线（摸调用方、查资料、CI 日志定位首错）才委派给轻量 Harness+经济模型，后台静默等待，完成后只交回一页干净摘要。其四，**复盘与回放**：每单大活回看切换账本，把「哪类活可交常规组、哪类必须上主力」沉淀进难度判断；调信任度前先拿最近真实历史回放分配变化，再试跑验证。新模型先塞常规组接熟悉的活，新 Harness 先走任务委派跑独立旁支，用自己仓库的真实验收结果说话。
