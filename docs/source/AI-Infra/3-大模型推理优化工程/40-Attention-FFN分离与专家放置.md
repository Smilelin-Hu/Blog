# Attention-FFN 分离与专家放置

主题二 27 篇讲 PD 分离（按生成阶段切），本文讲另一种切法：**AF 分离在模型层内切**——注意力产生隐状态，前馈或选中专家处理后再送回，下一层等结果，小数据量交接因此反复发生。MoE 最适合这种分工：专家权重总量大、每 token 只用一部分，「搬权重给 GPU」还是「CPU 就地算、只传激活」成了可计算的选择题。再往外是专家分离（独立专家池）、大 EP 的副本与均衡。量化口径沿用主题二 40/41 篇。

## 1. CPU／GPU 协作：两条路径的交点

同一份专家输出可以两条路径交付：把 36 MiB 专家权重（Qwen3-235B-A22B 单专家 $3\times4096\times1536$ 参数 BF16）从主存搬给 GPU，或权重留主存、CPU 就地计算只往返激活（每次分派进出合计 16 KiB）。KTransformers 走第二条：GPU 做注意力与常驻专家，CPU 做分给它的专家，提交后 GPU 继续并行分支、最后汇合。设专家参数 $P_e$、权重字节 $W_e$、输入宽 $h$、本批收到 $m$ 个 token，交接带宽 $B_L$、每次启动 $\alpha$：

$$
T_C(m)=2\alpha+\frac{2mhb}{B_L}+\max\left(\frac{2mP_e}{C_C},\frac{W_e}{B_D}\right),\qquad T_G(m)=\alpha+\frac{W_e}{B_L}+\max\left(\frac{2mP_e}{C_G},\frac{W_e}{B_H}\right).
$$

代入 KTransformers 实验机（Xeon 8452Y 单插槽主存 220 GB/s，A100 40GB PCIe 按峰值 50% 计 156 TFLOP/s、778 GB/s，交接 25 GB/s、启动 5 μs）：八个热点专家各 1 token 时，CPU 路径约 1.46 ms，搬权重路径约 12.5 ms——**低复用时避免搬 288 MiB 权重比提高矩阵算力更有价值**。各 128 token 时计算量翻 128 倍：AVX-512 kernel（1.8 TFLOP/s）CPU 路径升到 22.2 ms 反慢于 GPU，交点在每专家 71→72 个 token；换 AMX kernel（21.3 TFLOP/s）128 token 只要 2.57 ms，交点推迟到 689 个——**同一台机器同一批请求，CPU 用哪套指令决定专家放哪一侧**。NUMA 再改一笔：跨插槽带宽只有 125 GB/s，AVX-512 计算受限放哪个插槽几乎无关，AMX 计算缩短后跨插槽读取反而成了较长项。量化同时改权重字节与 kernel 有效吞吐，两项都要重算。

## 2. 容量、并发与专家覆盖

装得下与来得及是两个问题：235B 每层 128 个 BF16 专家 4.5 GiB，每层驻留 32 个则 94 层约 106 GiB，单张 A100 80GB 全给专家也放不下；减到 16 个驻留降为约 53 GiB，但更多专家执行被推给主存侧——**容量选择直接改变执行路径**。批内访问多少专家另算：64 token 各选 8 共 512 次分派，均匀覆盖 128 专家与集中 8 专家的有效计算同为约 19.3 GFLOPs，权重读取却是 4.5 GiB 对 288 MiB（16 倍，220 GB/s 主存上 22.0 对 1.37 ms）。随机路由的活跃专家期望

$$
\mathbb{E}[U]=E\left[1-\left(1-\frac{K}{E}\right)^M\right],
$$

$E=128,K=8,M=64$ 时约 126 个、读取约 4.43 GiB，接近均匀情形；batch 再大 $U$ 封顶 128，新增 token 越来越多复用已读权重，瓶颈也逐渐从读取转向 CPU 算力。大主存少 GPU 的服务器因此适合每专家行数少的负载：V4-Flash 单张 5090 配置要至少 200 GB 主存，Kimi K2 Q4_K_M 配置约 600 GB。

## 3. 跨机 AF、专家分离与大 EP

专家分离把路由专家放进独立资源池：注意力 worker 保留 KV，一层之内四步——注意力＋路由、dispatch（4×4 All-to-All 把隐状态按专家所在卡分组发出）、专家按来源重排行执行、combine 沿原路送回加权求和。两处等待：B 卡等各来源输入到齐才算，A 卡等一个 token 的 8 份输出全回才能进下一层——**一张 B 卡收得多算得慢，同时推迟自己与所有等它的 A 卡**。

大 EP 指 EP 组跨较多卡，但**扩 EP 不自动扩每专家 batch**：$n=1024,k=8,E=256$ 均匀路由每专家平均 $nk/E=32$ 行，256 专家从 32 卡摊到 128 卡平均值仍是 32，减的只是每卡专家数，增的是通信与同步范围、还有卡间 skew（主题二 28 篇第 11 节的 EP8/32/256 量化）。DeepSeek-V3/R1 公开 prefill EP32、decode EP144 加冗余专家，证明大 EP 有用，但不证明注意力与专家已分到两套设备。独立专家池要当整体管理：只有多个 EP 组各存完整专家集合才是可分别接任务的服务副本，只加保存部分专家的卡不能让请求绕开繁忙专家；共享池的队列、显存、版本与接纳策略统一管。

跨机 AF 用 micro-batch 交错流水（MegaScale-Infer）：一个 micro-batch 做注意力时另一个做专家，理想双阶段流水 $t_A+t_F+(q-1)\max(t_A,t_F)$。2 ms＋3 ms、四个 micro-batch：串行 20 ms、流水 14 ms，省 6 ms——**拆小后每阶段服务时间变长、或不可重叠往返超过 6 ms，收益即消失**。论文在八节点 64 张 Ampere 上 Scaled-MoE 每 GPU decode 吞吐达 TensorRT-LLM 1.90 倍（TPOT≤150 ms 约束），但这是分离放置、并行选择、流水与通信库的合效果，不是「只开 EP 分离」的通用加速比。

## 4. PD 一次交接与 AF 每步交接

AF 传的是 4096 维隐状态，与 KV 头数、潜变量宽度无关：Qwen3-8B 稠密 AF 一步 decode 72 次交接共 576 KiB，25 GB/s 下纯载荷 23.6 μs、72 次 5 μs 启动 360 μs，串行约 0.384 ms；8192 token prefill 整批交接则是 4.5 GiB 约 193 ms。PD 每请求只交接一次但随上下文增长，AF 每步都交接且随步数重复。令两者串行时间相等解出临界启动时间：

$$
\alpha^*=\frac{V_{KV}-V_{AF}}{71B},
$$

GQA 状态 25 GB/s 下约 680 μs、紧凑 MLA 324 μs（50 GB/s 减半）——5 μs 启动远低于临界值，单看一步 AF 更快；但放到整条请求，1024 步 AF 累计约 393 ms，是 GQA 一次 PD 交接 48.3 ms 的 8.1 倍、紧凑 MLA 23.0 ms 的 17 倍。**MLA 把 PD 那一次代价减半，对 AF 一个字节不省**；输出越长差距越大。

## 5. 专家副本：回本批数与放置约束

副本让同一逻辑专家有多个物理副本，不改 top-k 规则（改选择规则会改变模型行为，要分开评价）；vLLM/SGLang 的 EPLB 按路由统计调副本位置与任务分配。副本占显存挤 KV：每卡每层加一个 36 MiB 专家、94 层要 3.30 GiB，只给最拥挤的 8 层各加一个则 288 MiB，差近 12 倍——CRAFT 的结论是把空间花在最能缩短等待的层（A100 集群 DeepSeek-R1/Kimi K2 实测端到端平均 1.14 倍、最高 1.2 倍，条件不能外推）。

复制要回本：128 token 全选中卡 0 的八个热点专家（1024 次分派），复制七个到卡 1-7 共 252 MiB，卡 0 每批从 0.550 降到 0.309 ms、省 0.240 ms；机内 NVLink 复制约 0.622 ms，$N_{\min}=\lfloor T_{copy}/\Delta t\rfloor+1=3$ 批回本，热点持续 64 批净省约 14.8 ms；**跨服务器经 50 GB/s 网卡复制要 5.32 ms，第 23 批才回本**，热点只持续 16 批反而净损失——频繁跟着热点迁移副本会推迟回本，机内复制的限制是显存、跨机的限制是热点持续时间。接收卡只有 32 MiB 时连一份都放不下，先改放置或释放容量。

池级稳定条件：$\lambda\mathbb E[F_j]<C_j$ 且每链路 $\lambda\mathbb E[V_\ell]<B_\ell$——平均满足只是必要，突发与重尾仍造长队；多个 attention worker 各自小 batch 均衡，汇合后仍可能超热点专家服务能力，**分离不自动消除 skew**。副本要放到同时有算力与链路余量的位置；dispatch 消息 8 KiB（FP8 4 KiB）远大于约 0.93 KB 的发起速率交点，热点卡先用尽的是带宽。动态调副本要保留当前 batch 的路由映射到 combine 完成、迁移前排空在途任务、给热点设接纳额度与单来源在途上限；丢溢出 token、改 top-k、换逻辑专家都改变模型行为，不能当透明均衡。

## 6. 补齐、重叠与等待传播

Grouped GEMM 按 tile 补齐行数：八个本地专家收到 [32,16,8,4,2,1,1,0] 共 64 有效行，非空专家各补到 32 行要 224 行、全按最大补要 256 行——**硬件执行的是补齐后的矩阵，实际行数是有效的 3.5-4 倍**，有效任务相同矩阵时间仍不同。三阶段重叠另算：跨机均衡分布 dispatch/计算/combine 下界 0.336/0.156/0.336 ms，串行 0.827 ms；均分两个 micro-batch 理想流水 0.581 ms，但若 DMA 与 GEMM 争用 HBM 使两次通信各慢约 49%，流水回到 0.827 ms——**通信确实重叠了，整批没变快**；补齐与争用正是 MFU 达不到峰值的两大实现层来源。

token 合并完成时刻按最长分支：$T_t=\max_{e\in\mathcal E(t)}L_{t,e}+T_{\mathrm{merge},t}$，两条分支 0.5 与 1.4 ms 返回就要等 1.4 ms，把快分支降到 0.3 ms 不改变完成时刻；逐 token 推进能让没选慢专家的 token 先走，整批屏障则一起等。$\max(t_A,t_F)$ 预测流水周期要求各阶段稳定、资源独立、工作持续供给，实际还受最忙专家、往返链路、返回缓冲与跨层依赖约束；首个 micro-batch 仍承受完整往返，稳态吞吐提高不等于单 token 响应缩短。通信库要记版本：DeepEP V2 用 ElasticBuffer 与 NCCL Gin，移除了 V1 不占 SM 的 RDMA 低延迟路径——库名相同不能省略版本条件。比较实现固定版本、形状、精度、拓扑，分别记发送/接收字节、GEMM 行数、padding、各阶段就绪与完成事件，再统计层与请求的 p50/p99；复算时先变分布、再变出口与精度、最后改一个来源的就绪时间，区分流量 skew、计算 skew 与单纯晚到（网络侧的逐阶段延迟与拥塞见主题四 39 篇）。
