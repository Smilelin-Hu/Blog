# 课程导览

《大厂 AI Infra 训练营（三）：大模型推理优化工程》面向具备 Python 和大模型推理基础、希望建立生产级推理系统能力的读者。内容从新一代生成加速进入长思考、Agentic、结构化与多模态工作负载，再延伸到 Gateway、路由、模型生命周期、GPU Fleet、可靠性和推理经济学。

## 1. 内容概览

整体包含 7 个阶段、30 个主题、30 个独立实验和 6 个综合工程项目。精简实验包的根目录只有 `lesson/` 和 `project/`；每个实验只保留一个独立 `run.py`。默认运行 Fixture，加 `--real` 才执行真实 CUDA、服务端点或实测容量路径；前提不足时报告 `status=precondition_failed` 并以退出码 2 结束。

这套约定值得先记住，因为它贯穿后面所有实验：

- **Fixture 默认**：没有 GPU、没有模型权重也能跑通机制与报告结构，便于先理解方法。
- **`--real` 显式开启**：真实路径需要硬件与制品前提，不会被默认触发。
- **预检失败即退出码 2**：与「实验失败」区分开。前提不足不是结果不好，而是结果不存在，报告中必须如实标注。

## 3. 六个综合工程项目

### 3.1 项目 1：新一代 Speculator Benchmark

比较 EAGLE-3、MTP、DFlash 系列及自适应验证策略，输出可复现 Pareto 前沿。验收重点是比较结果可复算，并能解释不同策略为何位于当前 Pareto 前沿。

### 3.2 项目 2：新型推理工作负载基准平台

统一重放 reasoning、agentic、structured、multimodal 与 compound workload。交付需要统一任务身份、重放五类工作负载，并保留端到端阶段证据。

### 3.3 项目 3：生产级 AI Gateway 与 Smart Router

实现多租户网关、Token 配额、负载与 KV locality 联合路由。验收覆盖身份、配额、计量、路由选择、取消传播和热点分流。

### 3.4 项目 4：Multi-Tenant、Multi-Model 与 Multi-LoRA Serving

实现模型和 Adapter 生命周期、缓存、热切换、预热与回滚。项目需要演示冷暖路径、版本绑定、缓存抖动、预热与回滚。

### 3.5 项目 5：GPU Fleet Planner 与 Autoscaler

实现异构 GPU 放置、碎片评估、容量预测与 SLA-aware 扩缩容。验收器检查硬约束、碎片、容量到达、扩缩容迟滞和安全余量。

### 3.6 项目 6：生产级 LLM Inference Platform

集成控制面、数据面、路由、生命周期、可靠性与推理经济学，形成可验收平台。最终项目以完整请求链、发布流程、故障演练和单位经济报告收口。

六个项目的递进关系是：先在算法层证明收益边界（项目 1），再在负载层建立统一口径（项目 2），然后在入口层做治理与路由（项目 3），在模型层做多路复用（项目 4），在资源层做放置与扩缩（项目 5），最后把五层合成一个可验收平台（项目 6）。

## 4. 实验环境

CPU 机制模拟可在普通个人电脑运行。真实路径需要 Python、兼容的 PyTorch 与 CUDA 环境，以及自行准备的本地模型或兼容制品。脚本在昂贵工作前执行预检，根据显存选择安全参数；多 GPU、Kubernetes 和多节点内容为可选扩展。

「在昂贵工作前执行预检」是一条重要的工程习惯：权重下载、显存分配与服务启动都可能耗时数分钟到数十分钟，预检失败应立即退出并说明缺什么，而不是跑到一半才报错。

## 5. 学习与验收方法

不要只记录最终吞吐或一张截图。每次运行保留工作负载、配置、环境、请求级事件、聚合指标、失败与限制。比较基线和候选时只改变一个研究因素，并同时检查正确性、服务等级、有效成本和恢复能力。完成全部主题后，通过 6 个项目把算法、运行时和平台控制连接成统一证据链。

这里的四类检查对应四个不同的失败模式：正确性防止「更快但输出错了」，服务等级防止「平均更快但尾部崩了」，有效成本防止「吞吐更高但单位成本更贵」，恢复能力防止「正常时很好但故障后起不来」。只测吞吐会同时漏掉后三者。
