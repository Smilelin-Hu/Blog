## 5. 知识串讲

### 核心直觉与基础关系

### 核心直觉：Packing 不是把显存塞满，而是在 Headroom 和重排成本下减少碎片

GPU Fleet 的目标不是 100% 显存占用，而是在满足 SLO、并行组和故障余量的约束下提高有效承载密度。

GPU 容量 $C$，Replica 显存需求 $s_i$：

$$\sum_{i\in GPU_j}s_i\le C$$

目标：

$$\min N_{GPU}$$

### First Fit

按顺序找第一个能放的 GPU。

### Best Fit

选择放完后剩余空间最小的 GPU。

### First Fit Decreasing

先按 size 从大到小排序，再 First Fit，通常比原序更好。

### 为什么 LLM 不是一维 Packing

两个 Replica 都只占 30GB：

- A 是高 QPS Embedding，计算很忙；
- B 是低 QPS LoRA 模型，计算很闲。

只按 VRAM 可以把两个都塞满同一 GPU，但计算可能过载。

因此资源向量：

$$s_i=(Memory_i,Compute_i,Bandwidth_i)$$

约束：

$$\sum Memory_i\le M$$

$$\sum Compute_i\le C$$

实际 Compute 不是静态百分比，需要基于 workload profile。

### Headroom

如果把 GPU 显存装到 100%：

- Runtime workspace 波动；
- KV/临时 buffer；
- 长尾请求；
- Fragmentation；

都可能触发 OOM。

所以实际可用：

$$C_{safe}=C\cdot(1-h)$$

$h$ 是 Headroom。

例如 80GB，预留 10%：

$$C_{safe}=72GB$$

Headroom 不是越大越安全越好，因为空闲资源有成本。

### Fragmentation

Fleet level fragmentation：

```text
GPU1 剩 12GB
GPU2 剩 10GB
GPU3 剩 8GB
```

总共 30GB 空闲，但一个需要 20GB 的 Replica 放不下任何一张。

定义碎片率可以近似：

$$F=1-\frac{LargestFeasibleCapacity}{TotalFreeCapacity}$$

实际还要考虑 GPU group 和 topology。

### Gang Placement

一个 TP=4 Replica 需要同时获得 4 张兼容 GPU：

```text
要么4张一起拿到
要么不启动
```

这叫 gang scheduling/placement 语义。

如果先占了 3 张再等第 4 张，会造成资源死锁/浪费。

所以 Planner 应以 group 为申请单元。

### Packing 与 SLO

为了节省 GPU，把太多服务 colocate：

- memory 可放下；
- 但竞争 HBM/compute；
- P99 变差。

因此真正问题：

$$\min Cost$$

subject to：

$$SLO(m,g,ColocatedSet)\le Threshold$$

需要 colocated profile 或保守 Headroom。

### Repacking 的代价

为了减少碎片，可以迁移 Replica：

```text
GPU1: A + B
GPU2: C
→
GPU1: A + C
GPU2: B
```

但模型迁移会：

- cold load；
- drain；
- cache loss；
- traffic shift。

因此不能每分钟追求数学最优 packing。

可以设置：

$$Benefit_{repack}>MigrationCost+SafetyMargin$$

才执行。

### 放置算法实验（第二部分）

实现：

- First Fit；
- Best Fit；
- FFD；
- cost-aware + headroom；
- gang group。

输入：

- GPU memory/cost；
- model memory；
- replicas；
- compute load；
- group size。

输出：

- GPU count；
- cost；
- utilization；
- fragmentation；
- unplaced replicas。
