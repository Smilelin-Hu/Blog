证据分为机制模拟和真实 CUDA 测量。前者用可控变量观察异构 GPU 怎样影响显存容量，后者把框架、Kernel、内存和硬件成本计入结果。两条路径使用不同来源标签，并保留异构 GPU 相关环境与限制；参数组合可以随版本改变，证据链仍要支持复现、定位和回退。

## 5. 知识串讲

### 核心直觉与基础关系

### 核心直觉：Placement 是“模型需求 × 硬件能力 × 迁移成本”的匹配问题

只看显存剩余会错过带宽、算力、互联、并行组和已有模型缓存等约束。

节点 $g$：

$$R_g=(VRAM,Compute,BW,Interconnect,Features,Cost)$$

模型 $m$ 需求：

$$D_m=(VRAM_{min},ComputeReq,FeatureReq,GPUCount,Topology)$$

可行条件：

$$D_m\preceq R_g$$

例如需要 FP8 特定路径、80GB 显存或 NVLink group，就属于 hard constraint。

### Hard Constraint 与 Soft Preference

### Hard

不满足就不能运行：

- 显存不足；
- Compute capability 不支持；
- 必须的 dtype/kernel 不支持；
- TP group 节点数不够；
- security/region 不允许。

### Soft

能运行，但不是最优：

- 更贵；
- 带宽较低；
- cache locality 差；
- 远离用户；
- 功耗高。

Placement 应先过滤 Hard，再优化 Soft。

### 同样1张 GPU 不等于同样容量

H100 和 L40S 不能简单计作：

```text
1 GPU = 1 capacity unit
```

应通过 profile 得到：

$$Capacity_{m,g}=\text{在模型 }m\text{ 和目标 SLO 下 GPU }g\text{ 可提供的 Goodput}$$

然后归一化：

$$CU_{m,g}=\frac{Capacity_{m,g}}{Capacity_{m,ref}}$$

同一张 GPU 对不同模型的 CU 也可能不同。

### TP/并行组 Placement

如果一个 Replica 需要 4 GPU TP：

不是“找 4 张空卡”就行。

还需要：

- 尽量同节点；
- 同高速互联域；
- 互联拓扑对称；
- 避免跨慢链路。

因此 Placement 的最小单元可能是 **GPU group**，不是单卡。

### Affinity

### Model Affinity

倾向放在已有权重 cache 的节点。

### Adapter Affinity

热门 LoRA 的节点优先。

### Region Affinity

靠近用户/数据。

### Hardware Affinity

Reasoning 长输出模型优先高带宽/大显存硬件等。

### Anti-Affinity

为了高可用：

```text
Replica A → rack1
Replica B → rack2
```

避免所有副本在同一故障域。

但 Anti-Affinity 太强也可能降低资源利用率，需按：

- node；
- rack；
- zone；

定义层级。

### Placement Score

过滤 hard constraints 后：

$$Score(g,m)=w_1Cost+w_2Latency+w_3Load+w_4ColdStartPenalty+w_5FailureRisk$$

选择低分位置。

注意不同项单位不同，需要归一化。

### 异构 GPU 的调度陷阱

### 陷阱1：按空闲显存放置

忽略实际 throughput 和 SLO。

### 陷阱2：把快 GPU 全给最大模型

可能让高 QPS 小模型在慢卡上成为系统瓶颈。

### 陷阱3：不考虑可迁移成本

模型换节点可能触发几十/上百 GB 权重加载，频繁 rebalance 很贵。

### 放置算法实验（第一部分）

定义不同 GPU：

```text
G1: 24GB, capacity=1.0, cost=1
G2: 48GB, capacity=1.8, cost=2
G3: 80GB, capacity=3.0, cost=4
```

定义模型需求和流量。

实现：

1. first-fit；
2. cheapest feasible；
3. capacity-aware；
4. affinity-aware。

比较 SLO violation 与 total cost。

工作负载一变，Placement Constraint 对系统的贡献也会变化。处理异构降级应覆盖长短输入、不同输出、并发、突发、采样与任务域，并保留低载、稳定高载和过载记录。容量判断不能从一次固定批量的短运行外推。

对 Placement Constraint 的优化只有在输出合同不变时才有效。Token 序列、采样分布、结构合法性、结束原因和错误传播均需对账。最优放置没有故障余量会触发停止与回退，系统恢复到已有证据支持的配置。
