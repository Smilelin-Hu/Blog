# 声明式分布式训练平台

本项目把前序工作负载 API、Kubeflow 组件、Trainer V2、KubeRay、Pipelines 与模型注册几篇组合成一套声明式分布式训练与实验平台。用户提交训练意图，平台选择经过审核的 Runtime，经队列和 JobSet 启动多角色任务，通过 Pipeline 保存参数、制品与元数据，最后把不可变模型版本与训练运行关联。

![声明式分布式训练平台](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y4_l33_01.png)

参考场景包含两个四节点八卡请求，其中一次注入 Worker 失败并从检查点恢复。模拟只证明合同、状态、指标、血缘与反例，不证明真实 GPU 性能、分布式通信、KFP 后端或模型质量。真实环境未提供时返回 SKIPPED。

## 1. 架构与原理

### 1. 工程边界

工程边界在本项目中的作用，是把用户训练意图转成可重复、可治理和可追踪的控制面事实。平台保存请求身份、Runtime、镜像、数据、代码、队列、资源、输出和 Owner，并将这些事实传递给下游对象。任一关键输入使用可变标签都会使运行无法复现。

工程边界的权威状态必须由负责控制器产生。平台入口不直接猜测 JobSet、Pod、Pipeline 或模型注册表的状态，而是聚合 ObservedGeneration、Condition、Reason、对象 UID 和时间。等待 Runtime、等待配额、Rendezvous 失败、初始化失败和训练代码失败具有不同恢复动作。

常见错误是只把最终模型文件保存下来，而没有数据摘要、代码版本、镜像、Runtime、Pipeline Run、TrainJob 和指标。这样即使模型能部署，也无法回答它如何产生、能否重训、是否通过门禁以及应回滚到哪一版。

设计工程边界时先定义正向合同，再定义最小反例和失败预算。输入非法返回 REJECTED，依赖尚未存在返回 PENDING，执行错误返回 FAILED，证据不足返回 INCONCLUSIVE，重复运行由租约 BLOCKED。状态语义稳定后，门户和自动化才能安全消费。

真实验收工程边界不能只看资源 Created。需要从 API 请求追踪到队列准入、JobSet 角色、Pod 分配、GPU 与网络、训练进度、检查点、输出 Digest、Pipeline Artifact、Metadata 和模型版本。模拟只证明这一证据链的结构。

对工程边界做上线评审时，还要验证权限、幂等、控制器重启、部分成功、重试、清理和成本归属。普通用户只能选择批准 Runtime 和允许参数，不能覆盖 ServiceAccount、安全上下文、队列或输出边界。运行结束后保留必要证据并按策略清理计算资源。
