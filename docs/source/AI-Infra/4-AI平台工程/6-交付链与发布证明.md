# 交付链：注册、声明式服务、GitOps 与发布证明

训练跑完不等于交付完成。一条可审计的交付链要回答四个问题：**这份制品是什么、谁批准它上线、线上正在跑的是不是同一份、出问题怎么退回。**

## 1. 模型注册：把「名字」变成「不可变身份」

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y4_l22_01.png" width="78%" alt="模型注册与血缘" />
  <p>图 1：模型名是别名，Digest 才是身份；血缘把代码、数据、参数与制品串起来</p>
</div>

三条规则：

1. **别名可动，Digest 不可动**：`latest` / `candidate` 只是发布入口，最终部署必须解析为不可变摘要；
2. **制品是集合**：权重 + Tokenizer + 配置 + Adapter + 量化信息一起构成一个版本，**单文件校验通过不等于模型完整**；
3. **血缘要能反查**：从一次部署能追到训练运行（代码提交、数据版本、超参、评测结论），否则「这个版本为什么上线」只能靠记忆。

推论：一旦某次部署引用了 Digest，后续所有证据（评测、扫描、签名）都必须绑定同一个 Digest——否则「验证过」和「上线了」可能是两个东西。

## 2. KServe：声明式服务的控制面

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y4_l23_01.png" width="78%" alt="KServe 声明式生命周期" />
  <p>图 2：InferenceService 声明期望，控制器生成 Deployment/Service/Route，Condition 暴露分层状态</p>
</div>

### 2.1 对象分工

| 对象 | 职责 | 平台要点 |
|---|---|---|
| InferenceService | 声明 Predictor（必需）+ Transformer / Explainer（可选） | 模板只开放业务必要字段，其余由策略补全 |
| Predictor | 加载模型、提供推理协议 | 模型 URI 必须来自注册表的固定版本与摘要 |
| Transformer | 前/后处理 | **只有需要独立扩缩、依赖或复用时才拆**，否则只是多一跳 |
| Explainer | 解释端点 | 视为可选合同：可能泄露敏感特征、显著放大成本 |
| ServingRuntime | 模型服务器容器模板 + 支持的格式/协议 | 由平台团队发布，镜像按 Digest 固定；**不要让每个用户复制一份** |

### 2.2 Condition 思维

`status` 是控制器对当前观察的汇总，**URL 只是入口声明，不等于端到端请求成功**。

排障顺序：先等 `observedGeneration` 追上目标，再看**第一个 False 的 Condition**，然后沿它的 Owner 与事件下钻。

两个反例：

- 旧一代的 `Ready=True` 在新 spec 提交后还会短暂保留——发布器可能提前宣布成功；
- 把所有失败都映射成 `PredictorNotReady`——团队无法快速分派责任，可操作性归零。

### 2.3 数据路径的四跳

```text
DNS → Gateway/Ingress → Service → Pod 端口 → Runtime
```

入口返回 503 时直接重启模型 Pod，可能掩盖 Gateway、Service 选择器或 Endpoint 故障。每一跳都要有 TLS、认证、超时、大小限制与遥测关联。

### 2.4 三个「验收陷阱」

1. **`kubectl apply` 成功 ≠ 服务完成**：后面还有拉取、调度、启动、路由；
2. **Pod Running ≠ 可服务**：容器可能未 Ready、模型未加载、路由未建立；
3. **对象存在 ≠ 通过**：必须检查 current Generation、第一处 False Condition、子资源状态与外部真实请求。

还有一条纪律：**人工热修要回写配置源**，否则下一次调和会覆盖。

## 3. GitOps：变更即提交，晋级即改引用

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y4_l24_01.png" width="78%" alt="GitOps 与环境晋级" />
  <p>图 3：环境之间的差别只应体现在「引用哪个 Digest」</p>
</div>

四条原则：

1. **配置源唯一**：集群状态由 Git 收敛，任何人工修改都会被下一次同步覆盖——所以要么改 Git，要么承认漂移；
2. **晋级 = 改引用**：dev → staging → prod 的差别是「引用哪个 Digest + 哪些参数」，而不是「重新构建」；
3. **回滚 = 改回旧 Digest**：不需要重新找某个路径下的旧文件；
4. **PR 即变更单**：审查看 diff，而不是看聊天记录。

工程要点：

- 环境差异用 overlay/参数表达，**不要 fork 出两套配置**；
- 同步窗口与 drift 检测要可见（否则「已经部署了」和「集群里是什么」不一致）；
- 密钥不进 Git，用外部密钥系统或 Sealed Secret；
- 晋级门禁在 PR 阶段执行，而不是靠部署后人工验证。

## 4. 供应链与发布证明

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y4_l25_01.png" width="78%" alt="供应链与发布证明" />
  <p>图 4：输入、执行者、输出、策略四者都要可追踪，证据要绑定同一个 Digest</p>
</div>

### 4.1 三条链用 Digest 交接

```text
源码提交 → 构建（Task/Builder）→ 镜像/模型 Digest → GitOps 引用 → 准入策略 → Pod
```

**可信不是一个布尔值。** 五种组合说明这一点：

- 来源可信，但评测失败；
- 模型质量通过，但镜像含严重漏洞；
- 透明日志可用，但 Signer 不在允许身份列表；
- 所有证据有效，但策略版本已被撤销；
- PipelineRun 成功、扫描零漏洞、签名验证成功——**但三者讨论的不是同一个 Digest**。

所以状态页要展示每个门禁的 Subject、版本、时间与 Reason，并定义过期与重算规则。

### 4.2 四者都要固定

| 要素 | 例子 |
|---|---|
| 输入 | 源码提交、远程 Task、基础镜像、依赖锁、数据引用、配置生成器 |
| 执行者 | ServiceAccount、工作负载身份、Builder ID |
| 输出 | 镜像 Digest、模型 Digest、SBOM |
| 策略 | 准入策略本身的版本或摘要 |

任何证据只引用 Tag、别名、任务名或可编辑 URL，都**不能**作为生产放行依据。

### 4.3 两条路径要闭合

- **反向**：从运行中的 Pod 追到镜像 ID → 模型 Digest → GitOps 提交 → 准入策略 → 签名 Bundle → Provenance → PipelineRun UID → 源码提交；
- **正向**：从 PR 追到最终请求。

两条都通，且反例能在有害状态发生前被拒绝，控制链才算成立。验收时要主动注入失败：未审查源码、未固定 Task、非 hermetic 网络、空 SBOM、严重漏洞、禁止许可证、错误 Subject、未受信 Builder、签名篡改、透明记录缺失、策略 Digest 漂移、无匹配策略——**拒绝必须发生在 GitOps 晋级或 Pod 创建之前**。

### 4.4 责任分离

危险模式是一个脚本同时拥有：源码合并、构建、签名、Registry 写入、生产仓库写入、集群管理员权限。一旦它被攻破或出错，所有边界同时失效。

正确做法：每个边界独立身份与最小权限，交接物是**不可变 Digest + 经过认证的 Attestation**，而不是共享目录里的临时文件或聊天里的结论。

### 4.5 Tekton 的对象语义

| 对象 | 语义 | 常见误用 |
|---|---|---|
| Task | 一组有序 Step，运行时通常对应一个 Pod | 在 Step 间靠共享可写目录隐式传值 |
| Pipeline | Task 的依赖图（result 依赖、runAfter、when、重试、超时、finally） | 用 finally 把失败「洗成」成功 |
| TaskRun / PipelineRun | 一次执行的事实对象 | 只保存名称，不绑定 UID |
| Workspace | 源码、缓存、凭据挂载 | 用共享可写目录替代 Result 接口 |
| Result | 小型结构化输出（应返回完整 Digest） | 返回可变 Tag |

两条纪律：**Run 的证据要绑 UID**；**Result 返回 Digest，不返回 Tag**。

### 4.6 触发入口

事件只能「提出构建请求」，不能直接获得发布权限。Webhook 必须先验签（签名、时间、事件 ID、仓库、目标提交），**再解析不可信字段并创建高权限对象**。

Pipelines as Code 的 PR 流水线仍然来自潜在不可信分支：必须限制可用的 Task、ServiceAccount、Workspace 与 Secret。

## 5. 一张交付门禁清单

- [ ] 制品以 Digest 引用，别名只作为入口
- [ ] 模型制品是集合，完整性校验覆盖全部必需对象
- [ ] 评测结论与部署引用同一个 Digest
- [ ] 镜像/模型均有 SBOM 与 Provenance
- [ ] 签名者身份在允许列表内，签名可验证
- [ ] 准入策略本身有版本，且不被静默替换
- [ ] GitOps 为唯一配置源，drift 可检测
- [ ] 晋级 = 改引用；回滚 = 改回旧 Digest
- [ ] 正向与反向追踪都能闭合
- [ ] 拒绝发生在晋级/Pod 创建之前

## 写在最后

交付链的核心是**同一性**：谁批准的东西，必须就是线上在跑的东西。Tag 会动、名字会重用、URL 会变——只有 Digest 与 UID 不会。
