# 长上下文训练优化

## 1. 长序列训练中的显存挑战

### 1.1 二次方复杂度：一个残酷的数学事实

理解长序列训练的挑战，首先要理解标准 Attention 的复杂度。对长度为 $N$ 的输入，标准 Self-Attention 需要计算一个 $N \times N$ 的注意力矩阵，其**显存占用是 $O(N^2)$**，**计算量也是 $O(N^2)$**。

这意味着：当序列长度从 4K 增长到 128K（32 倍），注意力矩阵的大小增长为原来的 **1024 倍**；当序列长度达到 1M 时，这个矩阵本身就需要约 **1 TB** 显存——还不包括模型参数、梯度和优化器状态。

实际训练中问题更严峻：**为了在反向传播中计算梯度，需要在前向传播时缓存中间激活值（如 Key 和 Value）**，这部分显存占用也与序列长度成线性甚至平方关系。

一个具体例子：Qwen2.5-3B 模型在不用任何序列并行优化时，单卡显存占用高达 **75.35 GiB**；在 8 卡上使用 Ulysses + Ring-Attention 组合优化后，显存降至 **17.92 GiB**——降低 **76%**。

### 1.2 三重瓶颈：显存、计算与通信

**显存瓶颈**：注意力矩阵 $O(N^2)$ 的显存消耗是「爆」得最快的一项。$N=128K$ 时，仅注意力分数矩阵就需要**超过 128 GB**（BF16），远超单卡容量；激活值的存储压力同样巨大——128K 上下文的激活值内存是 8K 的 16 倍。

**计算瓶颈**：$O(N^2)$ 的复杂度意味着序列长度翻倍时计算量增长 4 倍。在 1024 个 token 上训练，每个 token 需要「看」1024 个其他 token；在 100 万个 token 上训练，每个 token 需要「看」100 万个其他 token——计算量差异是 **1000 倍**。

**通信瓶颈**：通过分布式策略（如序列并行）把序列切分到多卡时，跨设备通信成为新瓶颈。在 64 卡上处理 100 万 token 序列时，通信量可能占总时间的 **40% 以上**。

### 1.3 为什么传统并行策略不够用

- **数据并行（DP）**：不解决单卡无法容纳长序列的问题——每张卡仍要处理完整序列。
- **张量并行（TP）**：能降低单卡显存，但通信频繁。序列很长时 TP 通信开销急剧增加，且随着 GPU 数量增加切分更细，通信时间可能无法被减小的计算时间掩盖。
- **流水线并行（PP）**：按层切分，不能解决单层内 Attention 的 $O(N^2)$ 问题。

这些策略的组合（3D 并行）可以在一定程度缓解问题，但无法从根本上解决 Attention 的二次方复杂度。**序列并行（Sequence Parallelism, SP）**应运而生——它不是替代上述并行策略，而是作为**第四种并行维度**，专门解决序列维度的扩展问题。

## 2. Ring Attention 与序列并行

### 2.1 序列并行：第四种并行维度

序列并行的核心思想非常直接：**将输入序列沿序列维度切分到多个计算设备上，每个设备只处理序列的一个片段**。

到 2023 年底，序列并行领域出现了两个里程碑式的工作：**DeepSpeed-Ulysses** 与 **Ring-Attention**，标志着 SP 技术的成熟。

- **DeepSpeed-Ulysses**：序列被切分为子序列后，在每个 Transformer 层的 Attention 计算之前进行**激活值交换（All-to-All 通信）**，使每张卡上组合成完整序列，但 Attention Head 被拆分到不同卡上。它的通信量在序列长度与设备数量成比例增加时保持恒定，但并行度受限于 Attention Head 的数量。
- **Ring-Attention**：利用 Attention 计算可分块进行的原理，把序列块切分到多张卡分别计算，再合并结果；通过**环形通信**在设备间传递 K/V 块，并把通信与计算重叠。

### 2.2 Ring Attention 的核心机制

设计灵感来自高性能计算中的**环状（Ring）通信模式**。工作流程：

**第 1 步：序列分块**。把长度为 $L$ 的序列均匀切分为 $N$ 块（$N$ 为 GPU 数），每个 GPU 负责一块，包含该块的 Q、K、V。

**第 2 步：本地注意力计算**。每个 GPU 用本地 K/V 为**本地 Q 块**计算注意力输出。

**第 3 步：环形传递 K 和 V**。把本地 K/V 传给环中的**下一个** GPU，同时从**上一个** GPU 接收 K/V。

**第 4 步：重复计算与传递**。每收到一个新的 K/V 块，立即用它对本地 Q 块计算注意力并累加，重复 $N-1$ 次直到所有 K/V 块都被处理。

**第 5 步：输出合并**。所有 GPU 完成全部 K/V 块处理后，每个 GPU 都得到完整的注意力输出（对应各自的 Q 块）。

### 2.3 通信与计算的重叠：核心优势

Ring Attention 最巧妙的设计在于**通信与计算的深度重叠**：每一步中，GPU 在**等待接收下一个 K/V 块的同时**，可以用**已经收到的 K/V 块**继续计算注意力。通信与计算在时间轴上并行，通信开销被「隐藏」在计算过程中。

这种重叠使得 Ring Attention 扩展到大量 GPU 时，**通信开销不会线性增长**。实验表明，在 2 个 8×A800 节点（共 16 卡）上用 SP 训练 LLAMA3-8B、序列长度 208K 时，可达到 **47% 的 MFU**。

### 2.4 Ulysses 与 Ring Attention 的融合

两者并非互斥，可以**组合使用**。常见的融合策略是：先用 Ulysses 在 Attention Head 维度切分（受限于 Head 数量），再用 Ring Attention 在序列维度进一步切分。

| 配置 | 单卡显存 | 相对训练时间 |
|---|---|---|
| 无序列并行 | 75.35 GiB | 1× |
| Ulysses（8 卡） | 约 30 GiB | 约 1.6× |
| Ulysses + Ring（8 卡） | 17.92 GiB | 约 3.4× |

**显存降低 76%**，代价是训练时间增加约 3.4 倍——这正是「用通信换显存」在长序列场景下的体现。

### 2.5 序列并行的最新进展

- **BurstAttention**：通过拓扑感知的环形通信充分利用网络带宽，结合细粒度通信-计算重叠，在超长序列（超过 1M token）上比 Ring Attention 表现更优。
- **Untied Ulysses**：在 Attention Head 级别做细粒度分块（Headwise Chunking），把 70B Transformer 的峰值激活显存**降低 82.5%**，同时保持与现有 SP 技术相当的训练速度。
- **MTraining**：引入动态稀疏注意力与平衡稀疏 Ring Attention，针对超长上下文的训练。
- **DCP（Dynamic Context Parallelism）**：关注训练数据的动态性——不同样本的序列长度与注意力模式差异巨大，静态并行配置无法适应。DCP 通过细粒度分块划分，在 256 张 GPU 上实现近线性可扩展性。

## 3. 上下文窗口从 4K 到 1M 的技术演进

### 3.1 演进的时间线

上下文窗口的扩展是一条指数级增长曲线：GPT-3.5 的 4K → GPT-4 的 32K/128K → Claude 的 200K → Gemini 1.5 Pro 的 1M。从 4K 到 1M，**不到两年时间增长了 250 倍**；Llama 4 Scout 的 10M 更是把这一数字推到新高度。

### 3.2 第一阶段：位置编码的扩展（4K → 32K）

在模型架构不变的前提下，第一个被突破的瓶颈是**位置编码的外推能力**。

早期 Transformer 使用绝对位置编码或 Sin/Cos 编码，在训练上下文长度之外几乎无法泛化。**RoPE（Rotary Position Embedding，旋转位置编码）**的出现改变了一切——它通过旋转矩阵编码相对位置信息，成为当前大模型最广泛使用的位置编码方案。基于 RoPE，发展出两种扩展方法：

- **位置插值（Position Interpolation, PI）**：均匀缩放所有 RoPE 维度（把位置索引 $m$ 调整为 $m \times L/L'$，$L'$ 为扩展后窗口）。实现简单，但会丢失高频信息，导致短上下文性能下降。
- **YaRN（Yet another RoPE extensioN）**：在插值基础上改进，通过**非均匀地缩放不同频率的 RoPE 维度**，在扩展窗口的同时**保持短上下文性能**。YaRN 可以在很少甚至零微调的情况下把 LLaMA 等模型的窗口扩展数倍。

### 3.3 第二阶段：系统级优化（32K → 128K）

当窗口从 32K 扩展到 128K，仅靠位置编码改进已经不够——**Attention 的 $O(N^2)$ 显存占用开始成为真正的瓶颈**。这一阶段的核心突破是 **FlashAttention** 与**序列并行**的结合：

- **FlashAttention** 通过 IO 感知优化，把 Attention 的 HBM 访问从 $O(N^2)$ 降到 $O(N^2/M)$（$M$ 为 SRAM 大小）。
- **序列并行**（Ulysses/Ring Attention）把序列切分到多卡，将 $O(N^2)$ 的显存压力**分摊到多张 GPU**。

两者结合，使 128K 上下文的训练成为可能。DeepSpeed-Ulysses 可以在 **64 个 A100 GPU 上处理长达 100 万 token 的序列**。

### 3.4 第三阶段：分布式突破（128K → 1M+）

- **更高效的序列并行**：BurstAttention、Untied Ulysses 等新一代 SP 技术在通信效率与内存效率上持续优化。
- **动态并行策略**：DCP 等框架根据输入序列的实际长度与注意力模式**动态调整并行配置**，而非静态配置。
- **更智能的位置编码扩展**：LongRoPE2 通过搜索最优 RoPE 缩放因子，在把上下文扩展到 128K 的同时**保持超过 97% 的原始短上下文性能**。
- **端到端的框架支持**：Arctic Long Sequence Training（ALST）提供开箱即用的多百万 token 序列训练能力，结合单 GPU 与多 GPU 的内存优化；BurstEngine 专门针对超过 1M token 的极长序列做全栈优化。

### 3.5 技术演进的启示

从 4K 到 1M+ 的演进揭示了一个规律：**上下文窗口的扩展从来不是单点技术的突破，而是算法、系统和硬件的协同进化**。

- **算法层**：从 RoPE 到 YaRN 到 LongRoPE，位置编码在不断进化。
- **系统层**：从 FlashAttention 到 Ring Attention 到 BurstAttention，计算模式在不断优化。
- **硬件层**：从单卡到多卡到超节点，互联带宽在不断提升。
