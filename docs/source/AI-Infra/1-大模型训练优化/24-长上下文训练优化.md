# 长上下文训练优化

### 1.1. 二次方复杂度：一个残酷的数学事实
要理解长序列训练的挑战，首先要理解标准Attention的复杂度。
对于序列长度为N的输入，标准Self-Attention需要计算一个N×N的注意力矩阵。这个矩阵的**显存占用是O(N²)** 的，**计算量也是O(N²)** 的。
这意味着什么？当序列长度从4K增长到128K（32倍），注意力矩阵的大小增长为原来的**1024倍**。当序列长度达到1M时，这个矩阵本身就需要约**1TB**的显存——这还不包括模型参数、梯度和优化器状态。
在实际训练中，问题更加严峻：**为了在反向传播中计算梯度，我们需要在前向传播时缓存中间激活值（如Key和Value）**，这部分显存占用也与序列长度成线性甚至平方关系。
一个具体的例子：在Qwen2.5-3B模型上，不使用任何序列并行优化时，单卡显存占用高达**75.35GiB**。而在8卡上使用Ulysses+Ring-Attention组合优化后，显存可降至**17.92GiB**——降低了**76%**。
### 1.2. 三重瓶颈：显存、计算与通信
长序列训练面临的是三重叠加的瓶颈：
**显存瓶颈**：注意力矩阵O(N²)的显存消耗是“爆”得最快的一个。当N=128K时，仅注意力分数矩阵就需要**超过128GB**的显存（BF16精度下），远超单卡容量。激活值的存储压力同样巨大——128K上下文的激活值内存是8K的16倍。
**计算瓶颈**：O(N²)的计算复杂度意味着，当序列长度翻倍时，计算量增长4倍。在1024个token上训练，每个token需要“看”1024个其他token；在100万个token上训练，每个token需要“看”100万个其他token——计算量的差异是**1000倍**。
**通信瓶颈**：当通过分布式策略（如序列并行）将序列切分到多卡时，跨设备的通信开销成为新的瓶颈。在64卡上处理100万token的序列时，通信量可能占到总时间的**40%以上**。
### 1.3. 为什么传统并行策略不够用
数据并行（DP）、张量并行（TP）和流水线并行（PP）——我们前几课学习的这些并行策略，在面对超长序列时都有各自的局限：
- **数据并行（DP）**：不解决单卡无法容纳长序列的问题——每张卡仍然要处理完整的序列
- **张量并行（TP）**：能降低单卡显存，但通信频繁。当序列很长时，TP的通信开销会急剧增加，且随着GPU数量增加，TP的切分更细，通信时间可能无法被减小的计算时间所掩盖
- **流水线并行（PP）**：按层切分，不能解决单层内Attention的O(N²)问题
这些策略的组合（3D并行）可以在一定程度上缓解问题，但无法从根本上解决Attention的二次方复杂度。**序列并行（Sequence Parallelism, SP）** 应运而生——它不是替代上述并行策略，而是作为第四种并行维度，专门解决序列维度的扩展问题。
### 2.1. 序列并行：第四种并行维度
**序列并行（Sequence Parallelism, SP）** 的核心思想非常直接：**将输入序列沿序列维度切分到多个计算设备上，每个设备只处理序列的一个片段**。
到2023年底，序列并行领域出现了两个里程碑式的工作：**DeepSpeed-Ulysses**和**Ring-Attention**，标志着SP技术的成熟。
**DeepSpeed-Ulysses**的思路是：在序列被切分为子序列后，在每个Transformer层的Attention计算之前进行**激活值交换（All-to-All通信）**，使每张卡上组合成完整的序列，但Attention Head被拆分到不同卡上。Ulysses的通信量在序列长度和设备数量成比例增加时保持恒定，但其并行度受限于Attention Head的数量。
**Ring-Attention**则采用了不同的路径：利用Attention计算可以分块进行的原理，将序列块切分到多张卡上分别计算，再将计算结果合并。它通过**环形通信**在设备间传递Key和Value块，并将通信与计算重叠。
### 2.2. Ring Attention的核心机制
Ring Attention的设计灵感来源于高性能计算中的**环状（Ring）通信模式**。其工作流程可以概括为以下步骤：
**第1步：序列分块**
将长度为L的序列均匀切分为N个块（N为GPU数量），每个GPU负责一个块——包含该块的Query（Q）、Key（K）和Value（V）。
**第2步：本地注意力计算**
每个GPU使用本地的K和V，为**本地的Q块**计算注意力输出。
**第3步：环形传递K和V**
将本地的K和V传递给环中的**下一个**GPU，同时从**上一个**GPU接收K和V。
**第4步：重复计算与传递**
每收到一个新的K/V块，立即用它对本地Q块计算注意力，并将结果累加。重复N-1次，直到所有K/V块都被处理。
**第5步：输出合并**
所有GPU完成全部K/V块的处理后，每个GPU上都有了完整的注意力输出（对应各自的Q块）。
### 2.3. 通信与计算的重叠：Ring Attention的核心优势
Ring Attention最巧妙的设计在于**通信与计算的深度重叠**。
在每一步中，GPU在**等待接收下一个K/V块的同时**，可以用**已经收到的K/V块**继续计算注意力。通信和计算在时间轴上**并行**进行——通信开销被“隐藏”在计算过程中。
这种重叠使得Ring Attention在扩展到大量GPU时，**通信开销不会线性增长**。实验表明，在2个8xA800节点（共16卡）上使用SP训练LLAMA3-8B模型、序列长度208K时，可以达到**47%的MFU**。
### 2.4. Ulysses与Ring Attention的融合
Ulysses和Ring Attention并非互斥——它们可以**组合使用**。
在实际工程中，常见的融合策略是：先用Ulysses在Attention Head维度做切分（受限于Head数量），再用Ring Attention在序列维度做进一步切分。
这种融合方案在Qwen2.5-3B模型上的效果令人印象深刻：
> [内嵌电子表格，分享态无法直接读取内容]
**显存降低了76%**，代价是训练时间增加了约3.4倍——这正是“用通信换显存”在长序列场景下的体现。
### 2.5. 序列并行的最新进展
Ring Attention之后，学术界和工业界仍在持续优化：
**BurstAttention**通过拓扑感知的环形通信充分利用网络带宽，并结合细粒度的通信-计算重叠，在超长序列（超过1M token）上表现出比Ring Attention更优的性能。
**Untied Ulysses**通过在Attention Head级别进行细粒度的分块（Headwise Chunking），将70B Transformer的峰值激活显存**降低了82.5%**，同时保持了与现有SP技术相当的训练速度。
**MTraining**引入了动态稀疏注意力和平衡稀疏Ring Attention，专门针对超长上下文（Ultra-Long Context）的高效训练。
**DCP（Dynamic Context Parallelism）** 则关注训练数据的动态性——不同样本的序列长度和注意力模式差异巨大，静态的并行配置无法适应这种变化。DCP通过细粒度的分块划分，在256张GPU上实现了近线性的可扩展性。
### 3.1. 演进的时间线
上下文窗口的扩展是一条指数级增长曲线：
> [内嵌电子表格，分享态无法直接读取内容]
从GPT-3.5的4K到Gemini 1.5 Pro的1M，**不到两年时间增长了250倍**。Llama 4 Scout的10M更是将这一数字推到了新的高度。
### 3.2. 第一阶段：位置编码的扩展（4K → 32K）
在模型架构不变的前提下，第一个被突破的瓶颈是**位置编码的外推能力**。
早期的Transformer使用绝对位置编码或Sin/Cos位置编码，在训练上下文长度之外几乎无法泛化。**RoPE（Rotary Position Embedding，旋转位置编码）** 的出现改变了一切——它通过旋转矩阵编码相对位置信息，成为当前大模型最广泛使用的位置编码方案。
基于RoPE，研究者发展出了两种扩展上下文窗口的方法：
**位置插值（Position Interpolation, PI）**：通过均匀缩放所有RoPE维度（将位置索引m调整为m×L/L'，L'为扩展后窗口）来实现扩展。但这种方法会丢失高频信息，导致短上下文性能下降。
**YaRN（Yet another RoPE extensioN）**：在插值的基础上进行了改进，通过**非均匀地缩放不同频率的RoPE维度**，在扩展上下文窗口的同时**保持短上下文的性能**。YaRN可以在很少的微调（甚至零微调）下，将LLaMA等模型的上下文窗口扩展数倍。
### 3.3. 第二阶段：系统级优化（32K → 128K）
当上下文窗口从32K扩展到128K时，仅靠位置编码的改进已经不够了——**Attention的O(N²)显存占用开始成为真正的瓶颈**。
这一阶段的核心突破是**FlashAttention**（后文）和**序列并行**的结合：
- **FlashAttention**通过IO感知的优化，将Attention的HBM访问从O(N²)降低到O(N²/M)（M为SRAM大小）
- **序列并行**（Ulysses/Ring Attention）将序列切分到多卡，将O(N²)的显存压力**分摊到多张GPU上**
两者的结合，使得128K上下文的训练成为可能。DeepSpeed-Ulysses可以在**64个A100 GPU上处理长达100万token的序列**。
### 3.4. 第三阶段：分布式突破（128K → 1M+）
从128K到1M乃至10M，需要的是**系统级的全面突破**：
**更高效的序列并行**：BurstAttention、Untied Ulysses等新一代SP技术在通信效率和内存效率上持续优化。
**动态并行策略**：DCP等框架根据输入序列的实际长度和注意力模式**动态调整并行配置**，而不是使用静态配置。
**更智能的位置编码扩展**：LongRoPE2通过搜索最优的RoPE缩放因子，在将上下文扩展到128K的同时，**保持了超过97%的原始短上下文性能**。
**端到端的框架支持**：Arctic Long Sequence Training（ALST）提供了**开箱即用的多百万token序列训练能力**，结合了单GPU和多GPU的内存优化。BurstEngine则专门针对超过1M token的极长序列进行了全栈优化。
### 3.5. 技术演进的启示
从4K到1M+的演进路径，揭示了一个深刻的规律：**上下文窗口的扩展，从来不是单点技术的突破，而是算法、系统和硬件的协同进化**。
- **算法层**：从RoPE到YaRN到LongRoPE，位置编码在不断进化
- **系统层**：从FlashAttention到Ring Attention到BurstAttention，计算模式在不断优化
- **硬件层**：从单卡到多卡到超节点，互联带宽在不断提升
