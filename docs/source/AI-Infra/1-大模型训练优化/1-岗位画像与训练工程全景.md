# 岗位画像与训练工程全景

AI Infra 不是一个岗位名称，而是一组围绕模型训练、推理与平台建设的工程能力。它把算法、框架、加速器、网络、存储、调度与可观测系统串起来，任务是让「论文里的模型」变成能稳定运行、能规模化扩展、能控制成本的生产系统。

## 1. 训练方向要回答的四类问题

大模型训练方向的工程问题可以归成四条，它们决定了日常工作的大部分内容：

1. **模型能不能装下**：参数、梯度、优化器状态、激活是否超过显存；该用 TP、PP、ZeRO 还是重计算。
2. **训练能不能跑快**：GPU 计算、HBM 访存、NCCL 通信、数据加载中谁是瓶颈；MFU 还有多少提升空间。
3. **任务能不能稳住**：Loss Spike、OOM、Hang、节点故障如何处理；长周期训练如何做到检查点可恢复。
4. **系统能不能规模化运维**：百卡到千卡集群如何调度、监控、告警、扩缩容与核算成本。

这四条不是并列的清单，而是一条证据链：**先测量，再定位，再优化，最后验证收益与副作用**。AI Infra 的工作不是背参数，而是让每个结论都能被数据支撑。

## 2. 岗位的四个工作面

### 2.1 分布式训练框架与并行策略

把一个模型映射到多张 GPU/NPU 上，首先要清楚 DP、TP、PP、EP、SP/CP 各自切分了什么、通信发生在哪里、怎样映射到节点内与节点间的拓扑。

常见工作包括：

- 为 Dense 或 MoE 模型设计 2D、3D、4D 并行配置；
- 维护 Megatron-LM、DeepSpeed、FSDP 等训练框架的定制分支；
- 依据层数、hidden size、head 数量与 GPU 拓扑选择 TP/PP/DP 的切分比例；
- 分析流水线气泡、专家负载不均与通信拖尾。

### 2.2 GPU 性能优化与算子开发

当 GPU 利用率或 MFU 偏低时，需要从 Profiler 时间线上分辨是计算、访存、通信还是数据等待。常见手段包括混合精度、FlashAttention、算子融合、`torch.compile`、Triton 与 CUDA 自定义内核。

算子层的收益往往是「局部但确定」的：融合掉一次 HBM 往返，就少一次全局内存访问；换一种布局，就让访存合并。这类优化容易验证，也容易被通信或数据瓶颈掩盖，所以必须先有全局时间线。

### 2.3 显存与通信的系统性设计

显存的账本决定了并行方案的下限，通信的拓扑决定了并行方案的上限。两者必须一起看：把 TP 放进单机 NVLink 域内，把 DP 放到跨机柜，是 3D 并行的基本约束，而不是调参技巧。

### 2.4 稳定性、可观测性与集群运维

大模型训练是长周期任务，故障不是异常而是常态。可观测性体系、健康检查、检查点策略、故障迁移共同决定了「有效算力」——集群标称算力与实际用于训练的算力之间的差距，往往就产生在这里。

## 3. 规模增长带来的三重压力

### 3.1 从 GPT-2 到 GPT-3

2020 年 GPT-3 以 1750 亿参数刷新了业界对模型规模的认知；2019 年 GPT-2 最大版本只有 15 亿参数——一年时间规模增长超过 100 倍。

一个被反复验证的现象是：当参数、数据与计算量同时扩大时，模型会表现出更强的少样本与上下文学习能力。规模扩展由此成为主线。

### 3.2 稀疏化：总参数与激活参数要分开看

GPT-3 之后，Dense 模型继续变大，MoE 则通过稀疏激活把**总参数**推到万亿级：Switch Transformer 的某些配置达到 1.6 万亿参数，GLaM、GShard 证明了条件计算与专家并行的可扩展性。

这里最容易出现的口径错误是拿「总参数」直接比较模型规模。Dense 模型每个 Token 激活全部参数；MoE 只激活少数专家。比较规模时必须同时给出**总参数、激活参数与训练 FLOPs**。

### 3.3 Scaling Law 的工程含义

Scaling Law 描述的是性能与参数量、数据量、计算量之间的幂律关系。只扩参数而数据不足，会导致训练不充分；只加数据而模型容量有限，收益同样受限。

工程上的含义很直接：训练方案必须把**模型结构、Token 数量、总 FLOPs、集群规模与训练时长**放进同一个规划里，而不是先定模型再临时找卡。

## 4. 三大核心挑战

### 4.1 显存

训练显存由参数、梯度、优化器状态、激活与临时缓冲共同占据。以混合精度 Adam 为例，若保留 FP32 主参数，模型状态可按每个参数 16 字节粗估：

```text
参数（FP16/BF16）   2Φ
梯度（FP16/BF16）   2Φ
FP32 主参数          4Φ
Adam 一阶动量        4Φ
Adam 二阶动量        4Φ
合计                16Φ bytes（Φ 为参数量）
```

175B 模型仅模型状态就约 2.8 TB，远超单卡 80 GB——而且还完全没有计算激活与框架开销。

需要注意：不同教材的默认口径不一致。若把「参数 + 梯度 + 优化器状态」写成 12Φ，那是因为没有单独计入 FP32 主参数副本；加上它才是 16Φ。两种口径都常见，比较数字前先对齐口径。

### 4.2 计算

Decoder-only Transformer 的训练量可以按一级近似估算：

$$
\text{Training FLOPs} \approx 6 \times \text{参数量} \times \text{训练 Token 数}
$$

系数 6 的来源是前向 2 次乘加 + 反向 4 次乘加（对每个参数每个 Token）。GPT-3 规模约需 3640 PF-days：单卡 A100 要跑 130 天以上，这就是为什么必须做并行。

### 4.3 通信

并行度上去之后，通信量随规模增长：DP 每步一次 AllReduce，TP 每层多次 AllReduce，EP 是 All-to-All。通信一旦没有被拓扑与算法安排好，就会把前面所有计算优化的收益吃掉。

## 5. 硬件与性能指标

### 5.1 GPU 为什么适合深度学习

CPU 用复杂控制与大缓存追求单线程低延迟，GPU 用大量并行执行单元追求高吞吐。深度学习的矩阵乘法可以分解成大量独立的乘加，天然适合 GPU。

一个 GPU 由多个 SM（Streaming Multiprocessor）组成，SM 内部包含：

- **CUDA Core**：执行通用浮点与整数运算；
- **Tensor Core**：针对矩阵乘加做硬件加速，支持 TF32、FP16、BF16、FP8 等格式；
- **Warp 调度器**：以 32 线程为一个 Warp 调度。

只有当矩阵维度、数据类型和布局都符合 Tensor Core 的要求时，训练吞吐才可能远高于普通 FP32 路径。

### 5.2 内存层次

从快到慢大致是寄存器、共享内存/L1、L2、HBM、主机内存，越快容量越小。高性能算子的通行做法是 **Tiling**：把数据从 HBM 分块搬进片上存储并重复使用。FlashAttention 与高性能 GEMM 都遵循这一原则。

### 5.3 FLOPS 口径与「峰值陷阱」

FLOPS 表示每秒浮点运算次数，1 TFLOPS = \(10^{12}\) FLOPS。厂商标注的峰值通常对应特定数据类型、Tensor Core 路径与理想形状，因此比较算力必须说明四件事：FP32、TF32、FP16、BF16 还是 FP8；Dense 还是 Sparse 峰值；是否走 Tensor Core；是否按稀疏加速折算。

理论峰值不等于实际性能，常见损耗来源有：算子无法充分利用 Tensor Core、HBM 带宽不足导致计算单元空转、通信与同步等待、Kernel 启动与小算子碎片化。
