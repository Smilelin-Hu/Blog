# 激活值重计算（Activation Recomputation）

激活值是什么？在前向传播过程中，每一层都会产生输出张量，这些输出需要在反向传播时用于计算梯度——因此它们必须被保存下来，直到对应的反向传播完成。对于 Transformer 模型，激活值的显存占用与**批量大小（Batch Size）**和**序列长度（Sequence Length）**成正比。

有多夸张？训练一个 GPT-3 175B 模型时，如果使用较大的 batch size，**激活值可能占用超过 30% 的显存**；而在长序列训练（如上下文窗口达到 128K）中，这个比例甚至会超过 50%。

**激活值重计算（Activation Recomputation，也称为梯度检查点 Gradient Checkpointing）**的核心思想是：**以时间换空间**——不再保留所有激活值，而是在反向传播需要时重新计算它们。这是一项经典的显存优化技术，在 Transformer 训练中尤其有效。

## 1. 原理：时间换空间

### 1.1 为什么激活值占用这么多显存

在标准的前向-反向传播中，每一层的激活值必须被保留，直到反向传播完成。对于一个 N 层的 Transformer 模型：

- **前向传播**：第 1 层 → 第 2 层 → … → 第 N 层，每层产生激活值并存储在显存中。
- **反向传播**：第 N 层 → 第 N-1 层 → … → 第 1 层，逐层读取对应的激活值计算梯度。
- **释放时机**：某一层的反向传播完成后，该层的激活值才能被释放。

这意味着，在反向传播的早期（从最后一层开始），**所有层的激活值都还驻留在显存中**——这就是激活值显存占用的峰值。

对于 Transformer 模型，单层激活值的显存占用为：

$$
\text{每层激活值} \approx \text{batch\_size} \times \text{seq\_len} \times \text{hidden\_dim} \times 4\ \text{字节}
$$

系数 4 大致对应 Q/K/V/中间结果这几份需要保留的张量。当 `batch_size = 64`、`seq_len = 2048`、`hidden_dim = 4096` 时，**单层激活值就可能超过 1 GB**；70 层的模型就是 70 GB 以上——这比模型参数本身还要大。

### 1.2 核心思想：丢弃并重新计算

激活值重计算的思路非常直接。

**传统方式（存储所有激活值）**：

```text
前向: 计算Layer1→保存A1→计算Layer2→保存A2→...→计算LayerN→保存AN
反向: 读取AN→计算梯度→读取A(N-1)→计算梯度→...
峰值显存: A1 + A2 + ... + AN（全部保留）
```

**重计算方式（不保存激活值）**：

```text
前向: 计算Layer1→丢弃A1→计算Layer2→丢弃A2→...→计算LayerN→丢弃AN
反向: 重新计算Layer1→得到A1→计算梯度→丢弃A1→重新计算Layer2→...
峰值显存: 仅1层激活值（或0层，取决于实现）
```

这就是「时间换空间」的含义：**前向传播时不保存激活值，反向传播时重新计算它们**。代价是**额外的前向计算时间**——每一层在反向时都被重新计算了一次。

### 1.3 重计算的数学模型

记单层前向时间为 $T_f$、单层反向时间为 $T_b$、单层激活值显存为 $M$，模型共 $N$ 层。

**传统方式**：

- 时间：$T = N(T_f + T_b)$
- 显存峰值：$N M$

**全重算方式**（所有层都不保存激活值）：

- 前向：$N T_f$
- 反向：每层先重算前向再算反向，共 $N(T_f + T_b)$
- 总时间：$2N T_f + N T_b$
- 时间增加：$N T_f$，相对增幅为

$$
\frac{N T_f}{N(T_f + T_b)} = \frac{T_f}{T_f + T_b} \approx 30\% \sim 33\%
$$

- 显存峰值：$M$（仅 1 层）

**关键洞察**：重计算以**约 33% 的计算时间增加**，换取了 **N 倍的显存节省**。当 N 很大时，这个交换非常划算。

### 1.4 为什么在 Transformer 中尤其有效

Transformer 的架构特点使得激活值重计算特别有效：

1. **层数深**：GPT-3 有 96 层，Llama 3 405B 有 126 层。层数越深，保存所有激活值的显存压力越大，重计算的相对收益越高。
2. **计算密集**：Transformer 的每一层主要由矩阵乘法（Attention 和 FFN）构成，计算速度远快于显存访问。重计算增加的是「计算」而不是「显存访问」——对 GPU 利用率反而是有利的。
3. **激活值占比高**：在长序列训练中，激活值显存占用超过模型参数。重计算可以将这部分显存开销降低到可忽略的水平。

实践经验表明，启用激活值重计算后，**显存占用可以减少 30%–50%**，而**训练时间仅增加 15%–25%**——这是一个非常划算的交易。

## 2. Checkpointing 的策略选择：全重算 vs. 选择性重算

### 2.1 全重算（Full Recomputation）

**策略描述**：在反向传播过程中**重新计算所有层的激活值**。前向传播时不保存任何激活值（除了最后一层的输出）。

**优点**：

- **显存节省最大**：激活值显存占用从 $NM$ 降至 $M$。
- 实现最简单。

**缺点**：

- 时间开销最大：约增加 33%–40% 的训练时间。
- 在某些极端场景下，重计算可能与反向传播形成串行依赖，导致 GPU 利用率下降。

**适用场景**：显存极度受限、无法容纳完整激活值；模型极深（层数 > 100）；训练目标受限于显存而非计算（例如需要更大批量大小或更长序列）。

### 2.2 选择性重算（Selective Recomputation / Checkpointing）

**策略描述**：仅对模型的一部分层进行重计算，其他层的激活值仍然保存，即在特定「检查点」（Checkpoint）层之间进行重计算。

具体做法是：在前向传播时每隔 K 层**保存**一次激活值（称为 Checkpoint），然后丢弃这两次保存之间的所有激活值。反向传播时，从最近的 Checkpoint 开始，重新计算这 K 层的激活值。

**图示**（以 K=2 为例）：

```text
前向传播:
Layer1→保存A1→Layer2→丢弃A2→Layer3→保存A3→Layer4→丢弃A4→...

反向传播:
从A1开始→重算Layer2→计算梯度→从A3开始→重算Layer4→计算梯度→...
```

此时显存峰值约为 $\frac{N}{K} M$，额外前向计算量为 $(N - \frac{N}{K}) T_f$。

**优点**：

- **可调节的权衡**：通过调整 K 值，在显存和时间之间平滑调节。
- **更灵活**：可以根据模型结构选择性地对计算密集的层启用重算。
- 时间开销可控：通常为 10%–20%。

**缺点**：实现比全重算复杂；需要手动选择 Checkpoint 的位置。

**适用场景**：显存有一定余量但不足以保存全部激活值；希望在显存节省和时间开销之间取得平衡。这是工业界最常用的策略。

### 2.3 Checkpoint 间隔的选择：K 值的影响

K 值（每 K 层保存一个 Checkpoint）是选择性重算的核心参数：

| K | 显存峰值 | 额外前向计算 | 典型训练时间增幅 |
|---|---|---|---|
| 1 | $NM$（≈ 不重算） | 0 | 0 |
| 2 | $NM/2$ | $N T_f / 2$ | 约 15% |
| 4 | $NM/4$ | $3N T_f / 4$ | 约 20% |
| 8 | $NM/8$ | $7N T_f / 8$ | 约 25%–28% |
| N（全重算） | $M$ | $N T_f$ | 约 33%–40% |

**实际调优建议**：

- 通常 K 取 **2–8** 之间是最优区间。
- 开始时 **K=4** 是一个不错的默认值。
- 如果显存充足，可以减小 K（保存更多激活值，减少重计算）。
- 如果显存紧张，可以增大 K（减少显存占用，增加重计算）。

### 2.4 基于模型结构的非均匀 Checkpoint

更精细化的策略是**根据层的重要性或计算量进行非均匀分配**：

- **Self-Attention 层**：激活值占用大（需要保存 Q/K/V 中间结果），但计算密集，重计算的时间开销相对较小 → 优先重计算。
- **FFN 层**：激活值占用也大，但计算相对简单 → 可根据情况选择。
- **Embedding 层**：激活值占用较小，且只在前向开始时使用 → 通常保存。

在这种策略下，激活值重计算的开销可以减少至 **15%–20%**。

## 3. 重计算的开销分析与调优

### 3.1 量化的时间开销分析

以 Transformer 训练为例，标准前向 + 反向的时间分配大约为：前向传播约占总时间的 30%，反向传播约占总时间的 70%。

重计算增加的是**额外的前向计算**。在选择性重算（K=4）下，需要重计算的层数占总层数的 3/4：

- 额外前向计算：$\frac{3}{4} N T_f$
- 额外时间占比：$\dfrac{\frac{3}{4} N T_f}{N(T_f + T_b)}$

代入 $T_f = 0.3T$、$T_b = 0.7T$（$T$ 为单步总时间），额外时间占比约为 $0.75 \times 30\% \approx 22.5\%$。但由于 GPU 在重计算时保持了较高的利用率，实际训练时间增加通常在 **15%–20%** 左右。

### 3.2 重计算对 MFU 的影响

**MFU（Model FLOPs Utilization）**的定义是模型理论所需计算量除以硬件理论 FLOPS。激活值重计算会增加**实际 FLOPs** 而不改变**模型 FLOPs**（模型本身的 FLOPs 不变，只是重复计算了前向部分）。因此：

- **MFU 降低**：分母（硬件 FLOPS）不变、分子（模型 FLOPs）不变，但实际执行时间增加 → MFU 下降。
- **HFU 不变或上升**：因为实际 FLOPs 增加了（重算的部分）。

**这意味着什么？** MFU 下降了，但硬件利用率（HFU）可能并没有下降——计算资源一直在忙。这是「时间换空间」在 MFU 指标上的体现。

### 3.3 重计算与 ZeRO 的协作

激活值重计算和 ZeRO 是**互补的**优化技术：

- **ZeRO**：解决**模型状态**（参数、梯度、优化器状态）的显存问题，通过分片存储。
- **激活值重计算**：解决**激活值**的显存问题，通过丢弃并重新计算。

两者组合使用，可以将大模型训练所需的总显存**降低到原来的 1/3 到 1/4**。在 DeepSpeed 中，可以同时启用：

```json
{
  "zero_optimization": {
    "stage": 3
  },
  "activation_checkpointing": {
    "partition_activations": true,
    "cpu_checkpointing": true,
    "contiguous_memory_optimization": true,
    "number_checkpoints": 4,
    "synchronize_checkpoint_boundary": false,
    "profile": false
  }
}
```

**关键参数**：

- `partition_activations`：将激活值分片到多张 GPU（与 ZeRO-3 配合）。
- `cpu_checkpointing`：将 Checkpoint 保存到 CPU 内存，进一步减少显存。
- `contiguous_memory_optimization`：优化显存布局，减少碎片。

### 3.4 调优实战：找到最佳 Checkpoint 配置

**步骤 1：基线测量**。用 `torch.profiler` 在不启用重计算的情况下测量训练的时间分布和显存占用。

```python
with torch.profiler.profile(activities=[...]) as prof:
    for batch in dataloader:
        loss = model(inputs)
        loss.backward()
        optimizer.step()
```

记录：每步训练时间（秒）、峰值显存占用（GB）、前向/反向的时间占比。

**步骤 2：启用重计算并逐步调整**。从 K=8 开始，逐步减小 K 值（8→4→2→1），观察：

- K=8 时，显存占用最低，但时间开销最大。
- K=4 时，显存和时间达到较好的平衡。
- K=2 时，显存占用接近全保存，时间开销较小。

目标是找到**满足显存约束的最小时间开销**的 K 值。

**步骤 3：验证精度**。重计算完全可复现（因为计算逻辑完全相同），不会影响模型精度；但需要验证实现是否正确——确保中间结果的数值误差在可接受范围内。

**步骤 4：性能分析**。启用重计算后用 profiler 检查：

- 重计算是否与反向传播重叠？理想情况下，重计算和梯度计算应尽量并行。
- 是否存在 GPU 空闲等待？检查是否有同步点导致性能下降。
- Checkpoint 的保存位置是否影响了通信效率（在多卡场景下）。

## 4. 量化补充：选择性重算的生命周期账

第 2 节的选择性重算可以算到具体张量。SwiGLU 的 $h=a\odot u$ 供下投影权重梯度使用：若已为非线性反向保留了 $a,u$，可在下投影反向前重新相乘，不必让 $h$ 从前向一直驻留到反向。128 token micro-batch、FP32 激活时 $h$ 形状 [128,12288] 占 6 MiB，重建约 157 万次乘法；同层两个归一化加权输出各 [128,4096] 占 2 MiB 也可重建——每层省 $6+2+2=10$ MiB，九层流水阶段从 135 MiB 降到 45 MiB（原为 GEMM 保存的输入每层 15 MiB，其中 Q/K/V 与注意力输出 5 MiB 仍保留）。

收益来自生命周期差别：四个 micro-batch 同时等反向时长期保存减 $4\times90=360$ MiB，而逐层重建只需反复使用同一块 6 MiB 工作区（上一层用完下一层复用）。**等待反向的 micro-batch 越多，长期保存越多；流水调度让反向更早开始，等待数又下降**——重计算与流水调度共同决定保存量（五种调度的激活峰值对照见 05 篇第 5 节）；新增计算是否延长每步时间，取决于它在时间线上的位置，而非重算倍数本身。
