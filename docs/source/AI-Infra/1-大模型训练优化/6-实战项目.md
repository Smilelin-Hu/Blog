## 1. 项目一：7B 模型的分布式训练

### 1.1 选型与硬件

7B 是开源模型最常见的一档（LLaMA-2-7B、Qwen-7B、DeepSeek-V2-Lite），2–8 张 A100/H100 就能完整跑通。

- 最低：2 × A100 80 GB；
- 推荐：4–8 × A100/H100 + NVLink；
- 替代：24 GB 卡 + ZeRO-3 + CPU Offload（能跑，吞吐大幅下降）。

### 1.2 环境

```bash
conda create -n llm_train python=3.10 -y
conda activate llm_train
pip install torch==2.1.0 torchvision==0.16.0 torchaudio==2.1.0 \
    --index-url https://download.pytorch.org/whl/cu118
pip install deepspeed transformers accelerate datasets
ds_report   # 确认 CUDA / PyTorch / NCCL 版本匹配
```

### 1.3 显存估算决定并行方案

先算账（BF16 混合精度）：

```text
参数        7B × 2 = 14 GB
梯度        7B × 2 = 14 GB
优化器状态  7B × 8 = 56 GB
合计        约 84 GB（12Φ 口径）
```

单卡 80 GB 装不下 → 必须 ZeRO-3 或模型并行。

若用 Megatron 风格切分（2 节点 × 8 卡 = 16 卡）：**TP=2、PP=4、DP=2**，校验 \(2 \times 4 \times 2 = 16\)。此时单卡显存可降到约 25–35 GB（含激活）。

### 1.4 配置与启动

DeepSpeed 侧核心就三组：总 batch、ZeRO 阶段、精度。

```json
{
  "train_batch_size": 64,
  "gradient_accumulation_steps": 8,
  "zero_optimization": {
    "stage": 3,
    "offload_optimizer": { "device": "none" },
    "stage3_gather_16bit_weights_on_model_save": true
  },
  "bf16": { "enabled": true }
}
```

```bash
# 单机 8 卡
deepspeed --num_gpus=8 train.py --deepspeed ds_config.json

# 2 节点 × 8 卡
deepspeed --num_gpus=8 --num_nodes=2 --master_addr=<node0_ip> train.py --deepspeed ds_config.json
```

用 `SFTTrainer` 时只需 `deepspeed="ds_config.json"` 与 `bf16=True`，训练循环几乎不改。

Megatron 侧的关键参数是 `--tensor-model-parallel-size 2 --pipeline-model-parallel-size 4`，与 `--num-layers 32 --hidden-size 4096 --num-attention-heads 32 --seq-length 2048 --micro-batch-size 4 --global-batch-size 64` 一起调，注意 global batch = micro batch × DP × 梯度累积。

### 1.5 监控与验收

TensorBoard 看 Loss 与 LR，`nvidia-smi` 看利用率与显存，每 500 步存一次 checkpoint，训练结束在验证集上评 PPL 与下游准确率。

五类高频失败：

1. **OOM 但账算得下**：碎片化或反向刚开始的激活峰值；
2. **卡在第一步**：NCCL 初始化超时（网卡名、`NCCL_SOCKET_IFNAME`、防火墙）；
3. **Loss 立即 NaN**：`fp16` 与 `bf16` 配置冲突，或数据里有空标签；
4. **MFU 个位数**：`num_workers` 太小、数据在机械盘、micro batch 小到启动开销占主导；
5. **多机不行单机正常**：跨机带宽不足，或把 TP 放到了节点外。

## 2. 项目二：端到端性能分析与 MFU 优化

### 2.1 MFU 的口径

$$
\text{MFU} = \frac{\text{每步模型 FLOPs}}{\text{每步耗时} \times \text{GPU 数} \times \text{单卡峰值 FLOPS}}
$$

以 A100 BF16 峰值 312 TFLOPS 为例，若 7B 模型单步约 \(1.8\times10^{14}\) FLOPs、8 卡、每步 0.85 s：

$$
\text{MFU} = \frac{1.8\times10^{14}}{0.85 \times 8 \times 3.12\times10^{14}} \approx 8.5\%
$$

（这个数字偏低，通常说明 micro batch 太小或数据/通信没喂饱——正好是优化的起点。）

理论 FLOPs 用 \(6 \times \text{参数量} \times \text{Token 数}\) 估，峰值必须声明精度与是否稀疏。MFU 从 71% 提到 89%，相当于省下约 20% 的训练时间与算力成本。

### 2.2 采集基线

```python
with profile(activities=[ProfilerActivity.CPU, ProfilerActivity.CUDA],
             record_shapes=True, profile_memory=True, with_stack=True) as prof:
    for step in range(100):
        train_step()
        if step == 50:
            prof.export_chrome_trace("baseline_trace.json")

print(prof.key_averages().table(sort_by="cuda_time_total", row_limit=20))
```

系统级再用 nsys：

```bash
nsys profile -o baseline --trace=cuda,nvtx,cudnn,cublas --cuda-memory-usage=true \
    deepspeed --num_gpus=8 train.py --deepspeed ds_config.json
```

基线要记的五项：step time、tokens/s、峰值显存（allocated/reserved）、NCCL 通信耗时、数据等待时长。

### 2.3 三类瓶颈与对应手段

| 瓶颈 | 判据 | 手段 |
|---|---|---|
| 计算 | Top kernel 是 `aten::mm/bmm` | 混合精度、更好的 Attention、算子融合、加大 micro batch |
| 访存 | Top 是 `layer_norm`/`add`/`mul`，带宽接近饱和 | 算子融合、减少中间张量、`torch.compile` |
| 显存 | 占用 > 90% 且利用率不高 | 激活重计算、ZeRO、`PYTORCH_CUDA_ALLOC_CONF` 调碎片 |
| 通信 | AllReduce 占 step 比例高 | 调 NCCL 通道/算法、梯度分桶重叠、层次化 AllReduce |
| 数据 | GPU 利用率周期性掉坑 | 加 worker、`pin_memory`、预取、本地 NVMe |

### 2.4 报告怎么写

每项优化必须写清四件事：**改了什么、改善了哪个区间、损害了哪个区间、如何验证**。只报峰值吞吐提升的报告是不合格的——按教科书案例，MFU 提升 10 个百分点就算达标，但前提是同一口径下可复现。

## 3. 项目三：千卡集群通信方案设计

### 3.1 规模跃迁的质变

8 卡时通信是次要矛盾，1024 卡时是主要矛盾。NCCL 默认拓扑探测可能把 32 卡的 pipeline group 塞进同一个 Spine，导致 AllReduce 频繁跨 Spine、尾延迟飙升。

一个可引用的复盘：1024 张 H800A 跑 Megatron-LM（DP=8 / TP=4 / PP=32），首次上线 MFU 只有 71%（预期 85%），Profiler 显示 25% 的时间在 AllReduce，P99 尾延迟是 P50 的 4 倍；按拓扑重排通信组后，训练效率从 71% 提升到 89%。

### 3.2 方案要素

1. **拓扑感知放置**：TP/EP 留在节点或超节点内，PP 可跨机，DP 最外层；
2. **层次化 AllReduce**：节点内先归约（NVLink/NVLS），跨节点只传代表，通信量从 \(2G\) 降到 \(2G/N\)；
3. **算法/协议选择**：小消息 Tree/LL，大消息 Ring/NVLS/Simple，按消息大小设阈值；
4. **通信与计算重叠**：梯度分桶、反向即通信、减少同步点；
5. **梯度压缩的适用性判断**：量化（FP8/INT8/1-bit）、Top-K 稀疏、低秩近似 + 误差补偿；先算「省下的带宽是否大于压缩计算与精度风险」；
6. **可验收指标**：MFU、AllReduce 占 step 时间比、P99/P50 尾延迟比、集合通信带宽利用率、有效训练时间比（ETTR）。

### 3.3 交付物

- 拓扑与并行的映射图（哪个维度落在哪层网络）；
- 瓶颈证据（时间线、带宽曲线、尾延迟分布）；
- 优化清单：预期收益、风险、回滚方式；
- 验收标准与复现脚本。
