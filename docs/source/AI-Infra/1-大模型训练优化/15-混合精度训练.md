# 混合精度训练（Mixed Precision Training）

## 1. FP16、BF16、TF32 的原理与适用场景

### 1.1 从 FP32 说起：精度与范围的权衡

要理解混合精度训练，首先要理解浮点数格式的底层逻辑。一个浮点数由三部分组成：**符号位（Sign）**、**指数位（Exponent）** 和**尾数位（Mantissa）**。这三个部分的位数分配，决定了该格式的两个核心属性：

- **动态范围（Dynamic Range）**：能表示的最大值和最小值，由指数位决定。
- **精度（Precision）**：数值的精细程度，由尾数位决定。

FP32（单精度浮点数）的位分配为：1 位符号位 + 8 位指数位 + 23 位尾数位，动态范围约为 ±3.4×10³⁸，精度可达约 7 位有效数字。

问题在于：FP32 的精度对很多深度学习任务来说是**过剩的**，但计算和存储成本却是实打实的。如果能在保持足够动态范围和精度的前提下，把数据从 32 位压缩到 16 位，就能**直接减半显存占用和内存带宽消耗**。混合精度训练正是基于这一思路。

### 1.2 FP16（半精度）：最早的低精度方案

**位分配**：1 位符号位 + 5 位指数位 + 10 位尾数位。

**动态范围**：约 6.10×10⁻⁵（正规数）到 65504。

**关键特点**：FP16 的尾数位（10 位）比 BF16（7 位）多，因此**精度更高**——能更精细地表示小数值。但它的指数位只有 5 位，动态范围远小于 FP32（约 ±6.5×10⁴ vs ±3.4×10³⁸）。

这个**狭窄的动态范围**是 FP16 的核心问题。在训练中，梯度值可能非常小（如 10⁻⁶），超出了 FP16 的可表示范围，就会**下溢（Underflow）** 变为 0。这就是为什么 FP16 混合精度训练**必须配合损失缩放（Loss Scaling）**。

**适用场景**：

- NVIDIA Volta、Turing、Ampere 架构上的加速训练。
- 需要**较高精度**但可以接受额外调参（损失缩放）的场景。
- 小模型或对数值稳定性要求不苛刻的任务。

### 1.3 BF16（Brain Floating Point）：为深度学习而生

**位分配**：1 位符号位 + 8 位指数位 + 7 位尾数位。

**动态范围**：与 FP32 相同，约为 ±3.4×10³⁸。

**关键特点**：BF16 是 Google Brain 提出的格式，核心设计是**保留 FP32 的 8 位指数位，仅将尾数位从 23 位截断到 7 位**，使 BF16 拥有与 FP32**完全相同的动态范围**。

这意味着在 BF16 下**不会发生 FP16 常见的上溢/下溢问题**：梯度值无论多小或多大都仍在可表示范围内，**无需损失缩放**。代价是尾数位只有 7 位，精度低于 FP16。

但深度学习实践表明：**训练中动态范围比精度更重要**。梯度的大小（指数）决定了是否溢出，而梯度的精细程度（尾数）对最终收敛性的影响相对较小。BF16 正是抓住了这个核心洞察。

**适用场景**：

- **大模型训练的首选**：A100/H100 等现代 GPU 上的 LLM 训练常用 BF16。
- 训练**超大规模模型（参数 ≥ 10B）**，需最大化利用 GPU 算力。
- Transformer 类模型，BF16 比 FP16 更稳定。
- TPU 上 bfloat16 是原生支持的格式。

### 1.4 TF32（Tensor Float 32）：Ampere 架构的「即插即用」

**位分配**：1 位符号位 + 8 位指数位 + 10 位尾数位。

**关键特点**：TF32 是 NVIDIA 在 Ampere 架构（A100）上引入的格式。它不是一种存储格式，而是 **Tensor Core 内部的计算格式**——数据以 FP32 存储在显存中，但在 Tensor Core 计算时以 TF32 精度执行。

TF32 的指数位与 FP32 相同（8 位），因此动态范围与 FP32 一致，**无需损失缩放**。尾数位从 FP32 的 23 位截断到 10 位，精度有所降低但计算速度大幅提升。

**TF32 的最大优势是兼容性**：使用 TF32 时**不需要修改任何代码**。在 A100 上，TF32 相比 Volta GPU 上的 FP32 可提供**高达 10–20 倍的加速**；如果进一步切换到 FP16 混合精度，还可以再获得**约 2 倍的加速**。

**适用场景**：

- **从 FP32 迁移到 A100 的「第一步」**：无需改代码即可获得显著加速。
- 对代码修改有限制、希望快速提升性能的场景。
- **注意**：TF32 **不节省显存**（数据仍以 FP32 存储），只加速计算。

### 1.5 三种格式的对比总结

| 格式 | 符号/指数/尾数 | 动态范围 | 精度 | 需损失缩放 | 节省显存 |
|---|---|---|---|---|---|
| FP32 | 1/8/23 | ±3.4×10³⁸ | 约 7 位十进制 | 否 | 基准 |
| TF32 | 1/8/10 | ±3.4×10³⁸ | 约 3 位十进制 | 否 | 否（仅计算格式） |
| FP16 | 1/5/10 | 约 ±6.5×10⁴ | 约 3 位十进制 | 需要 | 是（减半） |
| BF16 | 1/8/7 | ±3.4×10³⁸ | 约 2 位十进制 | 不需要 | 是（减半） |

**选型建议**：

- **新项目/大模型训练**：直接使用 **BF16**——范围足够大、无需调参、显存省一半。
- **从 FP32 迁移到 A100**：先用 **TF32**（零代码改动）获得加速，再考虑切换到 BF16/FP16 获得额外 2 倍加速。
- **Volta/Turing 等老架构**：只能用 **FP16**（这些架构不支持 BF16/TF32）。

## 2. 损失缩放（Loss Scaling）与梯度裁剪

### 2.1 为什么需要损失缩放：FP16 的「下溢」困境

如前所述，FP16 的动态范围仅为 ±6.5×10⁴。在深度学习中，**梯度值往往非常小**——尤其在训练早期或深层网络中，梯度可能小到 10⁻⁶ 甚至 10⁻⁸。当这些极小梯度用 FP16 表示时会**下溢**变成 0；一旦梯度变为 0，对应参数就**不再更新**，模型无法正常收敛。

**损失缩放（Loss Scaling）** 正是为解决这个问题而提出的。

### 2.2 损失缩放的工作原理

核心思想非常简单：**在反向传播之前，将损失值乘以一个缩放因子 S**。

1. **前向传播**：正常计算损失 `loss`。
2. **缩放**：`scaled_loss = loss × S`（S 通常为 2 的幂，如 128、256、512、1024）。
3. **反向传播**：对 `scaled_loss` 计算梯度 → 得到 `scaled_gradients`。
4. **反缩放**：`gradients = scaled_gradients / S`。
5. **参数更新**：使用反缩放后的梯度更新模型参数。

**为什么有效？** 假设原始梯度为 $g = 1\times10^{-6}$，在 FP16 中会下溢为 0；如果乘以 $S = 1024$，则 $1.024\times10^{-3}$ 落在 FP16 的可表示范围内（≥ 6.10×10⁻⁵），反向传播后再除以 1024 即恢复原值。关键在于**缩放发生在反向传播之前**，梯度计算的中间结果都被放大，从而避免了计算过程中的下溢。

![混合精度训练一步：FP16 计算、反缩放后裁剪、FP32 更新](https://raw.gitcode.com/weixin_42917352/image-host/raw/main/images/aiinfra_y1_l15_01.png)

### 2.3 动态损失缩放（Dynamic Loss Scaling）

实践中，缩放因子 S 的选择至关重要：

- **S 太小**：仍然存在下溢风险。
- **S 太大**：可能导致梯度**上溢（Overflow）**——超出 FP16 的最大可表示范围（65504）。

**动态损失缩放**（PyTorch 的 `GradScaler` 默认使用）会自动调整 S：

1. **初始化**：设置一个较大的初始 S（如 $2^{16} = 65536$）。
2. **每轮迭代**：检查梯度中是否出现 `inf` 或 `nan`（上溢标志）。如果出现 → S 减半，**跳过本轮参数更新**（因为梯度已损坏）；如果连续若干轮没有溢出 → S 倍增。
3. **收敛**：S 最终稳定在既不导致下溢也不导致上溢的值。

```python
from torch.cuda.amp import GradScaler, autocast

scaler = GradScaler()  # 自动管理缩放因子

for inputs, labels in dataloader:
    optimizer.zero_grad()

    with autocast():  # 自动混合精度上下文
        outputs = model(inputs)
        loss = criterion(outputs, labels)

    scaler.scale(loss).backward()  # 缩放loss → 反向传播
    scaler.step(optimizer)         # 反缩放梯度 → 更新参数
    scaler.update()                # 动态调整缩放因子
```

**最佳实践**：浮点异常（溢出）的发生次数应控制在 **0.5% 以下**，global batch size 较大时建议在 **0.1% 以下**。

### 2.4 梯度裁剪与混合精度的配合

![动态损失缩放：溢出减半跳过、连续稳定倍增](https://raw.gitcode.com/weixin_42917352/image-host/raw/main/images/aiinfra_y1_l15_02.png)

**梯度裁剪（Gradient Clipping）** 通过限制梯度的最大范数来防止**梯度爆炸**。在混合精度训练中，梯度裁剪需要**特别注意顺序**——必须是「反向传播 → 反缩放 → 裁剪 → 更新参数」：

```python
scaler.scale(loss).backward()
scaler.unscale_(optimizer)                                        # 先反缩放
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)  # 再裁剪
scaler.step(optimizer)
scaler.update()
```

为什么必须先反缩放再裁剪？因为梯度裁剪基于梯度的**实际大小**。如果对缩放后的梯度进行裁剪，裁剪阈值需要同步缩放，容易出错。

## 3. 混合精度训练的精度问题与解决方案

### 3.1 常见精度问题

**问题一：训练不收敛或 loss 异常**。

- **现象**：loss 不下降、突然变为 `nan`/`inf`、或最终准确率远低于 FP32 基线。
- **FP16 下的可能原因**：梯度下溢（太小变成 0）或上溢（太大变成 inf）。
- **BF16 下的可能原因**：尾数精度不足（7 位尾数），在某些需要高精度的操作中累积误差。

**问题二：模型精度低于 FP32 基线**。

- **现象**：训练顺利完成，但验证集准确率比 FP32 低 1%–2%。
- **可能原因**：损失缩放因子设置不当；某些操作（如 Softmax、LayerNorm）在低精度下数值不稳定；梯度累积误差。

**问题三：训练不稳定、loss 震荡**。

- **现象**：loss 大幅波动，偶尔出现 `nan`/`inf` 但能恢复。
- **可能原因**：缩放因子在动态调整过程中产生短暂的不稳定。

### 3.2 解决方案

**方案一：选择合适的精度格式**。如果 FP16 遇到频繁溢出问题 → **切换到 BF16**（如果硬件支持），其指数位与 FP32 相同，从根本上**避免了下溢/上溢问题**。

**方案二：调整损失缩放策略**。检查 `GradScaler` 的溢出统计：溢出率过高（>1%）时尝试降低初始缩放因子；溢出率极低（<0.01%）时可尝试提高初始缩放因子以获得更好的下溢保护。浮点异常次数建议控制在 **0.5% 以下**。

**方案三：关键操作保持 FP32**。某些操作对精度极其敏感，应**强制使用 FP32**：

- **Loss 计算**：在 `autocast` 上下文之外计算 loss，或用 `autocast(enabled=False)` 包裹。
- **Softmax**：特别是 attention 中的 softmax，对数值范围敏感。
- **LayerNorm / BatchNorm**：归一化操作需要较高精度。
- **优化器更新**：始终在 FP32 下进行。

```python
with autocast():
    # 大部分操作自动使用FP16/BF16
    logits = model(inputs)
    # 但loss计算强制用FP32
    loss = criterion(logits.float(), labels)
```

**方案四：使用随机舍入（Stochastic Rounding）**。传统的**四舍五入（Nearest Rounding）** 在低精度下会产生系统性偏差；**随机舍入**以一定概率向上或向下舍入，使**舍入误差在期望上为 0**，是一种无偏估计，能有效减少低精度训练的精度损失。

**方案五：Kahan 求和补偿**。对于需要累加的操作（如梯度累积），**Kahan 求和**通过补偿项补偿累积的舍入误差。虽然增加少量计算开销，但在精度敏感场景下能显著改善收敛性。

### 3.3 调试混合精度问题的实用技巧

**技巧一：对比实验**。先跑一个 **FP32 基线**确认模型本身没问题，再切换到混合精度对比 loss 曲线和最终准确率；如果差距明显 → 问题在精度策略上。

**技巧二：监控溢出统计**。

```python
print(f"Overflow count: {scaler._overflow_count}")
print(f"Total steps: {scaler._scale_update_count}")
overflow_rate = scaler._overflow_count / scaler._scale_update_count
print(f"Overflow rate: {overflow_rate:.2%}")
```

**技巧三：逐层检查梯度**。在训练初期打印各层梯度范数，确认没有层出现梯度消失（全 0）或梯度爆炸（inf/nan）；若某一层异常，可针对该层单独提高精度。

**技巧四：分阶段启用**。初次使用混合精度可以分阶段推进：先用 TF32（零代码改动）→ 再切换到 BF16（无需损失缩放）→ 最后考虑 FP16（如果硬件限制）。
