# 混合精度训练（Mixed Precision Training）

### 1.1. 从FP32说起：精度与范围的权衡
要理解混合精度训练，首先要理解浮点数格式的底层逻辑。
一个浮点数由三部分组成：**符号位（Sign）**、**指数位（Exponent）** 和**尾数位（Mantissa/Fraction）**。这三个部分的位数分配，决定了该格式的两个核心属性：
- **动态范围（Dynamic Range）**：能表示的最大值和最小值，由指数位决定
- **精度（Precision）**：数值的精细程度，由尾数位决定
FP32（单精度浮点数）的位分配为：1位符号位 + 8位指数位 + 23位尾数位，动态范围约为±3.4×10³⁸，精度可达约7位有效数字。
问题在于：FP32的精度对很多深度学习任务来说是**过剩的**，但计算和存储成本却是实打实的。如果能在保持足够动态范围和精度的前提下，将数据从32位压缩到16位，就能**直接减半显存占用和内存带宽消耗**。混合精度训练正是基于这一思路。
### 1.2. FP16（半精度）：最早的低精度方案
**位分配**：1位符号位 + 5位指数位 + 10位尾数位
**动态范围**：约6.10×10⁻⁵（正规数）到65,504
**关键特点**：
FP16的尾数位（10位）比BF16（7位）多，因此**精度更高**——能更精细地表示小数值。但它的指数位只有5位，动态范围远小于FP32（约±6.5×10⁴ vs. ±3.4×10³⁸）。
这个**狭窄的动态范围**是FP16的核心问题。在训练中，梯度值可能非常小（如10⁻⁶），超出了FP16的可表示范围，就会**下溢（Underflow）** 变为0。这就是为什么FP16混合精度训练**必须配合损失缩放（Loss Scaling）**。
**适用场景**：
- NVIDIA Volta、Turing、Ampere架构上的加速训练
- 需要**较高精度**但可以接受额外调参（损失缩放）的场景
- 小模型或对数值稳定性要求不苛刻的任务
### 1.3. BF16（Brain Floating Point）：为深度学习而生
**位分配**：1位符号位 + 8位指数位 + 7位尾数位
**动态范围**：与FP32相同，约为±3.4×10³⁸
**关键特点**：
BF16是Google Brain提出的格式，其核心设计是：**保留FP32的8位指数位，仅将尾数位从23位截断到7位**。这使得BF16拥有与FP32**完全相同的动态范围**。
这意味着什么？在BF16下，**不会发生FP16常见的上溢/下溢问题**。梯度值无论多小或多大都仍在可表示范围内——**无需损失缩放**。代价是尾数位只有7位，精度低于FP16。
但深度学习的实践表明：**在训练中，动态范围比精度更重要**。梯度的大小（指数）决定了是否溢出，而梯度的精细程度（尾数）对最终收敛性的影响相对较小。BF16正是抓住了这个核心洞察。
**适用场景**：
- **大模型训练的首选**：A100/H100等现代GPU上的LLM训练常用BF16
- 训练**超大规模模型（参数≥10B）**，需最大化利用GPU算力
- Transformer类模型，BF16比FP16更稳定
- TPU上bfloat16是原生支持的格式
### 1.4. TF32（Tensor Float 32）：Ampere架构的“即插即用”
**位分配**：1位符号位 + 8位指数位 + 10位尾数位
**关键特点**：
TF32是NVIDIA在Ampere架构（A100）上引入的格式。它不是一种存储格式，而是**Tensor Core内部的计算格式**——数据以FP32存储在显存中，但在Tensor Core计算时以TF32精度执行。
TF32的指数位与FP32相同（8位），因此动态范围与FP32一致，**无需损失缩放**。尾数位从FP32的23位截断到10位，精度有所降低但计算速度大幅提升。
**TF32的最大优势是兼容性**：使用TF32时，**不需要修改任何代码**。在A100上，TF32相比Volta GPU上的FP32可提供**高达10-20倍的加速**。如果进一步切换到FP16混合精度，还可以再获得**约2倍的加速**。
**适用场景**：
- **从FP32迁移到A100的“第一步”**：无需改代码即可获得显著加速
- 对代码修改有限制、希望快速提升性能的场景
- **注意**：TF32**不节省显存**（因为数据仍以FP32存储），只加速计算

**选型建议**：
- **新项目/大模型训练**：直接使用**BF16**——范围足够大、无需调参、显存省一半
- **从FP32迁移到A100**：先用**TF32**（零代码改动）获得加速，再考虑切换到BF16/FP16获得额外2倍加速
- **Volta/Turing等老架构**：只能用**FP16**（这些架构不支持BF16/TF32）
### 2.1. 为什么需要损失缩放：FP16的“下溢”困境
如前所述，FP16的动态范围仅为±6.5×10⁴。在深度学习中，**梯度值往往非常小**——尤其是在训练的早期阶段或对于深层网络，梯度可能小到10⁻⁶甚至10⁻⁸。
当这些极小梯度值用FP16表示时，它们会**下溢（Underflow）** ——变成0。一旦梯度变为0，对应的参数就**不再更新**，模型无法正常收敛。
**损失缩放（Loss Scaling）** 正是为了解决这个问题而提出的。
### 2.2. 损失缩放的工作原理
损失缩放的核心思想非常简单：**在反向传播之前，将损失值乘以一个缩放因子S**。
**完整流程**：
1. **前向传播**：正常计算损失 `loss`
2. **缩放**：`scaled_loss = loss × S`（S通常为2的幂，如128、256、512、1024等）
3. **反向传播**：对 `scaled_loss` 计算梯度 → 得到 `scaled_gradients`
4. **反缩放**：`gradients = scaled_gradients / S`
5. **参数更新**：使用反缩放后的梯度更新模型参数
**为什么有效？**
假设原始梯度为 `g = 1×10⁻⁶`，在FP16中会下溢为0。如果乘以缩放因子 `S = 1024`，则 `scaled_grad = 1.024×10⁻³`——这个值在FP16的可表示范围内（≥6.10×10⁻⁵）。反向传播后，再除以1024，恢复为原始梯度值。
关键点在于：**缩放发生在反向传播之前**，梯度计算的所有中间结果都被放大了，从而**避免了在计算过程中出现下溢**。
### 2.3. 动态损失缩放（Dynamic Loss Scaling）
实践中，缩放因子S的选择至关重要：
- **S太小**：仍然存在下溢风险
- **S太大**：可能导致梯度**上溢（Overflow）** ——超出FP16的最大可表示范围（65504）
**动态损失缩放**（PyTorch的`GradScaler`默认使用）会自动调整S：
1. **初始化**：设置一个较大的初始S（如2¹⁶ = 65536）
2. **每轮迭代**：
- 检查梯度中是否出现`inf`或`nan`（上溢的标志）
- 如果出现 → S减半，**跳过本轮参数更新**（因为梯度已损坏）
- 如果连续若干轮没有溢出 → S倍增（逐步增大）
1. **收敛**：S最终稳定在一个既不会导致下溢也不会导致上溢的值
在PyTorch中，动态损失缩放由`torch.cuda.amp.GradScaler`自动管理：
```text
from torch.cuda.amp import GradScaler, autocast

scaler = GradScaler()  # 自动管理缩放因子

for inputs, labels in dataloader:
    optimizer.zero_grad()

    with autocast():  # 自动混合精度上下文
        outputs = model(inputs)
        loss = criterion(outputs, labels)

    scaler.scale(loss).backward()  # 缩放loss → 反向传播
    scaler.step(optimizer)         # 反缩放梯度 → 更新参数
    scaler.update()                # 动态调整缩放因子
```
**最佳实践**：浮点异常（溢出）的发生次数应控制在**0.5%以下**，global batch size较大时建议在**0.1%以下**。
### 2.4. 梯度裁剪与混合精度的配合
**梯度裁剪（Gradient Clipping）** 是另一种防止梯度异常的技术——它通过限制梯度的最大范数来防止**梯度爆炸**。
在混合精度训练中，梯度裁剪需要**特别注意顺序**：
**错误顺序**（❌）：
```text
scaler.scale(loss).backward()
scaler.unscale_(optimizer)  # 必须先unscale才能裁剪
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)
scaler.step(optimizer)
```
**正确顺序**（✅）：
1. 反向传播（使用缩放后的loss）
2. **反缩放梯度**（`scaler.unscale_(optimizer)`）——**必须先反缩放，再裁剪**
3. 裁剪梯度
4. 更新参数（`scaler.step(optimizer)`）
为什么必须先反缩放再裁剪？因为梯度裁剪基于梯度的**实际大小**。如果对缩放后的梯度进行裁剪，裁剪阈值需要同步缩放，容易出错。
```text
scaler.scale(loss).backward()
scaler.unscale_(optimizer)                    # 先反缩放
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)  # 再裁剪
scaler.step(optimizer)
scaler.update()
```
## 3. 混合精度训练的精度问题与解决方案
混合精度训练虽然高效，但在实践中可能遇到各种精度问题。下文总结常见问题及解决方案。
### 3.1. 常见精度问题
**问题一：训练不收敛或loss异常**
- **现象**：loss不下降、突然变为`nan`/`inf`、或最终准确率远低于FP32基线
- **FP16下的可能原因**：梯度下溢（太小变成0）或上溢（太大变成inf）
- **BF16下的可能原因**：尾数精度不足（7位尾数），在某些需要高精度的操作中累积误差
**问题二：模型精度低于FP32基线**
- **现象**：训练顺利完成，但验证集准确率比FP32低1-2%
- **可能原因**：
- 损失缩放因子设置不当
- 某些操作（如Softmax、LayerNorm）在低精度下数值不稳定
- 梯度累积误差
**问题三：训练不稳定、loss震荡**
- **现象**：loss大幅波动，偶尔出现`nan`/`inf`但能恢复
- **可能原因**：缩放因子在动态调整过程中产生短暂的不稳定
### 3.2. 解决方案
**方案一：选择合适的精度格式**
- 如果使用FP16遇到频繁的溢出问题 → **切换到BF16**（如果硬件支持）
- BF16的指数位与FP32相同，从根本上**避免了下溢/上溢问题**
**方案二：调整损失缩放策略**
- 检查`GradScaler`的溢出统计：如果溢出率过高（>1%），尝试降低初始缩放因子
- 如果溢出率极低（<0.01%），可以尝试提高初始缩放因子以获得更好的下溢保护
- 浮点异常次数建议控制在**0.5%以下**
**方案三：关键操作保持FP32**
某些操作对精度极其敏感，应**强制使用FP32**：
- **Loss计算**：在`autocast`上下文之外计算loss，或用`autocast(enabled=False)`包裹
- **Softmax**：特别是attention中的softmax，对数值范围敏感
- **LayerNorm / BatchNorm**：归一化操作需要较高精度
- **优化器更新**：始终在FP32下进行
在PyTorch中，可以通过`autocast`的`enabled`参数或数据类型转换来控制：
```text
with autocast():
    # 大部分操作自动使用FP16/BF16
    logits = model(inputs)
    # 但loss计算强制用FP32
    loss = criterion(logits.float(), labels)
```
**方案四：使用随机舍入（Stochastic Rounding）**
传统的**四舍五入（Nearest Rounding）** 在低精度下会产生系统性偏差。**随机舍入（Stochastic Rounding）** 以一定的概率向上或向下舍入，使得**舍入误差在期望上为0**——这是一种无偏估计，能有效减少低精度训练的精度损失。
**方案五：Kahan求和补偿**
对于需要累加的操作（如梯度累积），**Kahan求和**通过补偿项来**补偿累积的舍入误差**。虽然增加了少量计算开销，但在某些精度敏感的场景下能显著改善收敛性。
### 3.3. 调试混合精度问题的实用技巧
**技巧一：对比实验**
- 先跑一个**FP32基线**，确认模型本身没问题
- 再切换到混合精度，对比loss曲线和最终准确率
- 如果混合精度效果明显差于FP32 → 问题在精度策略上
**技巧二：监控溢出统计**
```text
# 在GradScaler中查看溢出统计
print(f"Overflow count: {scaler._overflow_count}")
print(f"Total steps: {scaler._scale_update_count}")
overflow_rate = scaler._overflow_count / scaler._scale_update_count
print(f"Overflow rate: {overflow_rate:.2%}")
```
**技巧三：逐层检查梯度**
在训练初期，打印各层的梯度范数，确认没有层出现梯度消失（全0）或梯度爆炸（inf/nan）。如果某一层梯度异常，可以针对该层单独提高精度。
**技巧四：分阶段启用**
对于初次使用混合精度的项目，可以**分阶段启用**：
1. 先用TF32（零代码改动）
2. 再切换到BF16（无需损失缩放）
3. 最后考虑FP16（如果硬件限制）
