# 模型蒸馏与稀疏化训练

量化改的是数值表示（主题二 37），蒸馏与剪枝改的是模型本身：前者要学生训练循环与教师推理服务，后者要剪后愈合（healing）训练。两者都不是「跑个脚本」的一次性操作，而是需要数据、调度与验收配套的训练系统。本文按「方法 → 系统成本 → 工程取舍」整理。

## 1. 压缩谱系：蒸馏与稀疏化的位置

| 手段 | 改变什么 | 是否需训练 | 硬件收益来源 |
|---|---|---|---|
| PTQ 量化 | 数值表示 | 否（校准即可） | 低精度 Tensor Core |
| 知识蒸馏 | 学生参数 | 是（学生训练） | 模型变小 |
| 结构化剪枝 | 矩阵形状 | 是（愈合续训） | 稠密 kernel 直接变快 |
| 非结构化 / N:M 稀疏 | 稀疏模式 | 一次性或续训 | 稀疏 kernel / 2:4 Tensor Core |

实践中常串联使用：剪枝 → 愈合 → 蒸馏。Sheared LLaMA 的两阶段即「定向结构化剪枝 + 续训」，蒸馏可再叠在愈合之后回收能力。

## 2. 知识蒸馏：从离线 logits 到 on-policy

### 2.1 损失与数据形态

- **词级 KD**：学生对教师 logits 做带温度 $T$ 的 forward KL，$\mathcal{L} = T^2 \cdot KL(p_T^{teacher} \| p_T^{student})$。
- **序列级 KD**：教师生成文本、学生做 SFT，本质是合成数据路线（呼应主题五 20），不需要 logits 带宽。
- **特征级 KD**：对齐中间层表示，多用于视觉或跨架构蒸馏，LLM 场景较少。

forward KL 是 mode-covering：学生被迫覆盖教师所有模式，容易「平均化」；reverse KL 是 mode-seeking：集中到教师高概率模式，对幻觉更克制。这一差异是 on-policy 蒸馏的动机。

![知识蒸馏损失：软目标 KL + 硬标签 CE](https://raw.gitcode.com/weixin_42917352/image-host/raw/main/images/aiinfra_y1_l30_01.png)

### 2.2 On-policy 蒸馏：MiniLLM / GKD / DistiLLM

离线 KD 有 exposure bias：训练时学生看教师前缀，推理时看自己的前缀，误差累积。**GKD** 让学生自己 rollout 前缀、教师逐 token 给监督，并可选 reverse KL；**MiniLLM** 用策略梯度直接优化 reverse KL；**DistiLLM** 以 skew KL 与自适应 off-policy 缓解学生早期样本质量差带来的不稳定。2025 年后 on-policy distillation 被进一步看作「稠密奖励的 RL」：教师 logprob 即每步奖励，样本效率高于稀疏奖励 RL。

系统形态因此变成三件套：学生训练循环 + 教师推理服务（vLLM 一类引擎）+ rollout 缓冲。教师推理与学生训练的算力配比、部署拓扑（同机混部 vs 分离部署，呼应 23 的 OpenRLHF 分离案例）是主要调度问题。

### 2.3 logits 的系统成本

全量 logits 存储 = batch × seq × vocab × 字节数。128k vocab、4k seq、BF16 下单样本约 1 GB，离线缓存路线的存储与带宽先于算力成为瓶颈。常见压缩：

- **top-k 截断**（k=20~100）+ 重归一化，存储降两到三个数量级，KL 用截断分布近似；
- 只存教师采样 token 与 logprob（退化为序列级 + 重要性加权）；
- 在线蒸馏不落地 logits，用教师服务现算，省存储但教师 GPU 要与学生共调度。

离线缓存适合多 epoch、多学生复用同一教师；在线适合教师持续更新、学生单轮训练。选型先算存储账与教师推理账，再定路线。

## 3. 剪枝与稀疏化：从一次性到愈合训练

### 3.1 一次性剪枝：SparseGPT / Wanda

逐层重建、不穿全网反向：SparseGPT 用 Hessian 信息做逐层最优掩码与权重更新；**Wanda** 只用 $|W| \times \|X\|$ 作重要性分数，无需 Hessian，工程上更轻。两者在中等稀疏度（50% 非结构化、2:4）下 perplexity 损失有限，高稀疏度则显著退化——一次性剪枝的边界在于「不训练」，超过边界就要接愈合。

### 3.2 结构化剪枝与愈合：Sheared LLaMA / LLM-Pruner

直接删行/列/头/层，模型形状变小，稠密 kernel 上拿到真实加速（非结构化做不到）。Sheared LLaMA 的配方：定向结构化剪枝（按目标架构掩码搜索）+ 约 50B token 续训 + **dynamic batch loading**（按各域 loss 轨迹动态重配数据比例）。愈合训练系统与继续预训练同构：数据混合、学习率 re-warmup、loss 监控，复用主题五 18 的链路即可。

其核心论证是成本账：剪枝 + 愈合远低于同尺寸从零预训练，小模型生产路线因此从「从头训」转向「大模型剪下来」。

### 3.3 稀疏模式与硬件

- **非结构化**：只有稀疏 kernel 才有真实加速，通用 GPU 上常「省显存不省时间」，部署前必须实测。
- **2:4 半结构化**：Ampere 起 Tensor Core 原生支持，理论 2×；2026 年的对照证据显示 2:4 下从零稀疏训练可追平剪枝路线，非结构化下剪枝仍占优。
- **激活稀疏**（ProSparse、TEAL 一类）与权重稀疏正交，可叠加，但改变计算模式，需要 kernel 与调度配套。

## 4. 工程取舍与验收

- 决策入口是目标：端侧部署优先结构化剪枝 + 量化；云端降本优先蒸馏出小模型；能力保留优先 on-policy 蒸馏而非序列级 SFT。
- 成本模型把教师推理、愈合数据、稀疏 kernel 适配都计入，与「从零训小模型」对照，而不是只比 FLOPs。
- 验收双门禁：perplexity 与下游基准回归矩阵（评测体系见主题五 37）；延迟/吞吐实测。只看 perplexity 会掩盖能力塌缩。
- 常见坑：非结构化稀疏无 kernel 支持导致实测零加速；蒸馏数据与评测集重叠（去污染呼应主题五 12/21）；愈合续训沿用预训练学习率导致 loss spike。
