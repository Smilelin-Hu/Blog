# 强化学习训练（RLHF/DPO）

在前面课程中，我们学习了大规模训练的高可用和可观测性体系建设——这些技术确保训练任务能够稳定、高效地运行。但有一个根本性的问题始终没有涉及：**训练出来的模型，真的“好”吗？**
“好”是一个主观的概念。在预训练阶段，“好”意味着语言建模损失低——模型能准确预测下一个token。但这与“模型能生成有帮助、无害、诚实的回答”是两回事。GPT-3在预训练后可以续写任何文本，但它可能输出有害内容、编造事实、或者拒绝遵循用户指令。
**RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）** 正是为了解决这个问题而生的。它通过**人类偏好数据**来定义“好”的标准，然后用**强化学习**让模型学会生成符合人类偏好的回答。ChatGPT、Claude、DeepSeek-R1等模型都依赖RLHF来实现与人类价值的对齐。
然而，RLHF的训练极其复杂——它需要同时维护**四个大模型**，且训练流程包含**生成、评分、训练**三个串行阶段。这种复杂性使得RLHF的训练效率远低于普通的SFT（有监督微调），对AI Infra工程师提出了全新的系统挑战。
### 1.1. RLHF的三阶段流程
标准的RLHF训练流程包含三个步骤：
**步骤1：监督微调（SFT，Supervised Fine-Tuning）**
首先，使用精选的高质量人工标注数据（问题-答案对）对预训练语言模型进行有监督微调，得到一个能够遵循指令的基础模型（SFT模型）。这一步的目的是让模型从“续写文本”转变为“回答用户问题”。
**步骤2：奖励模型训练（Reward Modeling）**
这一步的目标是训练一个**奖励模型（Reward Model，RM）**，用于评估模型回答的质量。奖励模型的训练数据来自人类标注的**偏好对比数据**——标注者对同一个问题的多个候选回答进行排序或两两比较。奖励模型的任务是：给定一个prompt和一个response，输出一个标量分数，分数越高表示该回答越符合人类偏好。
**步骤3：强化学习微调（RL Fine-Tuning）**
使用**PPO（Proximal Policy Optimization）** 等强化学习算法，以奖励模型的分数作为优化目标，进一步微调SFT模型。在每一轮迭代中，模型生成回答 → 奖励模型打分 → PPO算法根据分数更新模型参数。

### 1.3. RLHF训练的系统挑战
RLHF的训练效率远低于普通SFT，主要面临三大系统挑战：
**挑战一：生成阶段的“长尾”瓶颈**
每个RLHF训练迭代分为三个串行阶段：【生成（Generation） → 评分（Scoring） → 训练（Training）】。在生成阶段，Actor模型需要为一批prompt生成回答。由于回答长度差异巨大（“长尾分布”），一些长回答会**严重拖慢整个批次**——GPU在等待少数长回答完成时处于空闲状态。现有的RLHF系统因此饱受低GPU利用率的困扰。
**挑战二：流水线气泡（Pipeline Bubbles）**
生成→评分→训练三个阶段之间存在**数据和权重的依赖关系**，导致阶段之间存在天然的“屏障”——上游阶段未完成时，下游阶段只能空闲等待。这类似于我们在后文学习的流水线并行中的“气泡”问题，但在RLHF中更为严重，因为涉及的是**不同模型**之间的数据传递。
**挑战三：四个模型的调度复杂性**
随着模型规模增长到**700亿参数以上**，四个模型的协同调度变得极其复杂。传统框架（如DeepSpeed-Chat）将所有四个模型**共置（co-locate）** 在同一组GPU上——这会耗尽显存。更先进的框架（如OpenRLHF）则采用**分离部署**策略——将生成相关的模型（Actor）部署在专门优化的GPU集群上，将训练相关的模型部署在另一组集群上。
### 1.4. 系统优化的前沿进展
**RLHFuse：阶段融合（Stage Fusion）**
RLHFuse打破了“将RLHF视为独立任务组合”的传统观念，将每个任务拆分为更细粒度的子任务，通过**阶段融合**提高GPU利用率。具体来说：
- **生成与推理任务的融合**：将生成和评分阶段拆分为样本级子任务，实现**跨阶段重叠**
- **训练任务的融合**：将训练拆分为微批次的子任务，通过**融合的流水线调度**执行，有效缓解流水线气泡
实验表明，RLHFuse可将训练吞吐量提升**最高3.7倍**。
**OPPO：流水线重叠**
OPPO通过两种技术加速PPO训练：
- **步内重叠（Intra-step overlap）**：将上游模型（Actor）的输出流式分块传递给下游模型（Reward），使下游模型可以在上游仍在生成时就开始处理
- **步间重叠（Inter-step overlap）**：自适应地将长生成任务推迟到未来步骤，缓解长尾延迟
OPPO可实现**1.8倍的训练加速**和**2.8倍的GPU利用率提升**。
**OpenRLHF：基于Ray的可扩展框架**
OpenRLHF是基于Ray、vLLM、DeepSpeed和HuggingFace Transformers构建的开源RLHF框架。它的核心设计是**重新设计了超过700亿参数模型的调度策略**——不再将所有模型共置，而是利用Ray的分布式能力在不同GPU集群间协调不同的模型引擎。实验显示，OpenRLHF在不同模型规模上实现了**1.22倍到1.68倍的加速**。
### 2.1. PPO算法的核心思想
PPO（Proximal Policy Optimization）是OpenAI提出的策略梯度算法，因其**训练稳定性**和**灵活性**而成为RLHF的事实标准。

### 2.2. PPO训练的分布式架构
一个典型的PPO训练迭代包含以下步骤：
**步骤1：生成经验（Experience Generation）**
- Actor模型为一批prompt生成回答（response）
- 对每个（prompt, response）对，计算：
- **Reward Model的评分**（奖励分数）
- **Reference Model的log概率**（用于计算KL惩罚）
- **Critic Model的价值估计**（用于计算优势函数）
- 将以上所有数据打包为“经验”存入缓冲区
**步骤2：策略更新（Policy Update）**
- 从缓冲区中采样经验
- 计算优势函数（通常使用GAE，Generalized Advantage Estimation）
- 计算PPO的裁剪目标函数
- 通过梯度下降更新Actor和Critic模型的参数
- 重复多次（通常为mini-batch的多个epoch）
### 2.3. 分布式部署策略
在分布式环境中，四个模型的部署方式决定了训练效率和可扩展性。
**策略一：共置部署（Co-location）**
所有四个模型部署在同一组GPU上，通过ZeRO等分片技术共享显存。这是DeepSpeed-Chat等早期框架的默认方式。
- **优点**：实现简单，模型间通信开销小
- **缺点**：显存压力巨大，超过70B参数时效率急剧下降
**策略二：分离部署（Decoupled Deployment）**
将模型分为两组：
- **生成组（Generation Group）**：Actor模型，部署在专门优化的GPU集群上，配合vLLM等推理加速引擎
- **训练组（Training Group）**：Critic、Reference、Reward模型，部署在另一组GPU集群上，配合DeepSpeed ZeRO进行训练
两组之间通过**Ray**等分布式框架进行协调和数据交换。
- **优点**：每组可以独立优化（生成组用推理优化，训练组用训练优化），资源利用更高效
- **缺点**：实现复杂，跨组通信有额外开销
OpenRLHF是分离部署策略的代表。它支持**70B以上参数模型的完整RLHF微调**，并通过vLLM实现生成加速。

### 3.1. 偏好数据的采集
偏好数据是RLHF的“燃料”。没有高质量的偏好数据，奖励模型就无法学习到符合人类偏好的判断标准。
**数据来源**
偏好数据通常来自**众包标注**——由大量标注者对模型生成的回答进行偏好判断。标注过程通常采用**两两比较（Pairwise Comparison）** 的形式：给定一个prompt和两个候选回答（通常由不同的模型或不同配置生成），标注者选择哪个更好。
**数据规模与质量**
奖励模型的质量直接取决于偏好数据的**规模和质量**。高质量的偏好数据需要：
- **多样性**：覆盖不同类型的prompt和不同的回答风格
- **一致性**：标注者之间的判断需要具有较高的一致性
- **细粒度**：不仅标注“哪个更好”，还要标注“好在哪里”
HH-RLHF数据集是一个典型的大规模偏好数据集，包含涵盖日常帮助、信息查询和安全敏感场景的prompt，以及基于“有用性”和“无害性”判断的偏好标签。
**合成偏好数据**
由于人工标注成本高昂，**合成偏好数据生成**正在成为一个重要的研究方向。West-of-N等方法通过模型自身生成合成偏好数据来增强奖励模型的训练数据集。

DPO的优势在于**显著简化了训练流程**——不需要训练奖励模型，不需要PPO的复杂实现。但DPO目前主要依赖**离线偏好数据**，而PPO可以在训练过程中**在线收集新数据**（模型生成 → 奖励模型打分 → 继续训练），这是PPO仍然在顶尖模型（如GPT-4、Claude）中被广泛采用的原因之一。
**DPO的工程实践**
OpenRLHF等框架已经同时支持RLHF（PPO）、DPO和拒绝采样等多种对齐技术。在实际项目中，DPO常被用作**RLHF的轻量级替代方案**——在资源有限或对训练效率要求较高的场景下，DPO可以在更短的时间内获得与RLHF相当的对齐效果。
