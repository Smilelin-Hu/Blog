# 强化学习训练（RLHF/DPO）

前面讨论的高可用与可观测性，确保训练任务能稳定、高效地运行。但有一个根本问题始终没有涉及：**训练出来的模型，真的「好」吗？**

「好」是一个主观概念。在预训练阶段，「好」意味着语言建模损失低——模型能准确预测下一个 token。但这与「模型能生成有帮助、无害、诚实的回答」是两回事。GPT-3 在预训练后可以续写任何文本，但它可能输出有害内容、编造事实，或者拒绝遵循用户指令。

**RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）** 正是为解决这个问题而生：通过**人类偏好数据**定义「好」的标准，然后用**强化学习**让模型学会生成符合人类偏好的回答。ChatGPT、Claude、DeepSeek-R1 等模型都依赖 RLHF 实现与人类价值的对齐。

然而 RLHF 的训练极其复杂——需要同时维护**四个大模型**，且训练流程包含**生成、评分、训练**三个串行阶段。这种复杂性使得 RLHF 的训练效率远低于普通 SFT，对 AI Infra 工程师提出全新的系统挑战。

## 1. 强化学习训练的系统架构与挑战

### 1.1 RLHF 的三阶段流程

**步骤 1：监督微调（SFT）**。用精选的高质量人工标注数据（问题-答案对）对预训练语言模型做有监督微调，得到一个能遵循指令的基础模型。这一步让模型从「续写文本」转变为「回答用户问题」。

**步骤 2：奖励模型训练（Reward Modeling）**。训练一个**奖励模型（RM）**评估回答质量。训练数据来自人类标注的**偏好对比数据**——标注者对同一问题的多个候选回答排序或两两比较。奖励模型的任务是：给定 prompt 和 response，输出一个标量分数，分数越高表示越符合人类偏好。

**步骤 3：强化学习微调（RL Fine-Tuning）**。用 **PPO（Proximal Policy Optimization）**等算法，以奖励模型分数为优化目标进一步微调 SFT 模型。每轮迭代：模型生成回答 → 奖励模型打分 → PPO 根据分数更新参数。

### 1.2 PPO 训练中的四个模型

| 模型 | 作用 | 是否需要训练 |
|---|---|---|
| Actor | 生成回答的策略模型 | 是（PPO 更新） |
| Critic | 估计价值函数，用于计算优势 | 是（PPO 更新） |
| Reference | 提供 KL 惩罚的参照分布 | 否（冻结） |
| Reward | 给回答打分 | 否（通常冻结） |

其中 Actor 与 Reference 在训练开始时是相同的；Critic 与 Reward 结构可以相同，但用途不同——Critic 产生价值估计，Reward 产生奖励分数。

维持四个模型的**显存压力巨大**。对 70B 参数模型，四个模型全部加载仅参数就需 $4 \times 70\text{B} \times 2\ \text{字节（BF16）} \approx 560\ \text{GB}$ 显存——远超单卡容量，必须用**模型并行（TP/PP）**与 **ZeRO 分片**分布式部署。

### 1.3 三大系统挑战

**挑战一：生成阶段的「长尾」瓶颈**。每个迭代分三个串行阶段：生成 → 评分 → 训练。生成阶段 Actor 需要为一批 prompt 生成回答；由于回答长度差异巨大（长尾分布），少数长回答会**严重拖慢整个批次**——GPU 在等待少数长回答时处于空闲状态。现有 RLHF 系统因此饱受低 GPU 利用率困扰。

**挑战二：流水线气泡（Pipeline Bubbles）**。三个阶段之间存在**数据与权重的依赖关系**，形成天然「屏障」——上游未完成时下游只能空闲等待。这类似流水线并行中的气泡问题，但 RLHF 中更严重，因为涉及的是**不同模型**之间的数据传递。

**挑战三：四个模型的调度复杂性**。模型规模增长到 **700 亿参数以上**时，四模型协同调度极其复杂。传统框架（如 DeepSpeed-Chat）把四个模型**共置（co-locate）**在同一组 GPU 上——会耗尽显存；更先进的框架（如 OpenRLHF）采用**分离部署**——生成相关模型部署在专门优化的集群，训练相关模型部署在另一组集群。

### 1.4 系统优化的前沿进展

**RLHFuse：阶段融合**。它打破「把 RLHF 视为独立任务组合」的观念，把每个任务拆成更细粒度的子任务，通过**阶段融合**提高 GPU 利用率：

- **生成与推理任务的融合**：把生成和评分阶段拆成样本级子任务，实现**跨阶段重叠**。
- **训练任务的融合**：把训练拆成微批次子任务，通过**融合的流水线调度**执行，缓解流水线气泡。

实验表明 RLHFuse 可把训练吞吐量提升**最高 3.7 倍**。

**OPPO：流水线重叠**。通过两种技术加速 PPO：

- **步内重叠（Intra-step overlap）**：把上游模型（Actor）的输出流式分块传给下游模型（Reward），使下游在上游仍在生成时就开始处理。
- **步间重叠（Inter-step overlap）**：自适应地把长生成任务推迟到未来步骤，缓解长尾延迟。

OPPO 可实现 **1.8 倍训练加速**和 **2.8 倍 GPU 利用率提升**。

**OpenRLHF：基于 Ray 的可扩展框架**。基于 Ray、vLLM、DeepSpeed 与 HuggingFace Transformers 构建，核心设计是**重新设计了超过 700 亿参数模型的调度策略**——不再把所有模型共置，而是利用 Ray 的分布式能力在不同 GPU 集群间协调不同模型引擎。实验显示它在不同模型规模上实现 **1.22 倍到 1.68 倍加速**。

## 2. PPO 训练的分布式实现

### 2.1 PPO 算法的核心思想

PPO 是 OpenAI 提出的策略梯度算法，因**训练稳定性**与**灵活性**成为 RLHF 的事实标准。核心思想是：更新策略时**限制每次更新的幅度**，避免策略剧烈变化导致训练崩溃。具体通过**裁剪（Clipping）**目标函数实现：

$$
L^{\mathrm{CLIP}}(\theta) = \mathbb{E}\left[\min\left(r_t(\theta) A_t,\ \mathrm{clip}\left(r_t(\theta), 1-\epsilon, 1+\epsilon\right) A_t\right)\right]
$$

其中 $r_t(\theta) = \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{\text{old}}}(a_t \mid s_t)}$ 是新旧策略的概率比，$A_t$ 是优势函数（Advantage）估计，$\epsilon$ 是裁剪范围（通常为 0.2）。这个目标函数确保策略更新不会偏离旧策略太远。

在 RLHF 场景中，PPO 的优化目标不仅是最大化奖励分数，还要**约束模型不要偏离 SFT 模型太远**（通过 KL 散度惩罚），以保持生成能力与多样性。

### 2.2 PPO 训练的分布式架构

**步骤 1：生成经验（Experience Generation）**

- Actor 为一批 prompt 生成回答。
- 对每个（prompt, response）对计算：Reward Model 的评分、Reference Model 的 log 概率（用于 KL 惩罚）、Critic Model 的价值估计（用于优势函数）。
- 把以上数据打包为「经验」存入缓冲区。

**步骤 2：策略更新（Policy Update）**

- 从缓冲区采样经验。
- 计算优势函数（通常用 GAE，Generalized Advantage Estimation）。
- 计算 PPO 裁剪目标函数。
- 通过梯度下降更新 Actor 与 Critic。
- 重复多次（通常为 mini-batch 的多个 epoch）。

### 2.3 分布式部署策略

**策略一：共置部署（Co-location）**。四个模型部署在同一组 GPU 上，通过 ZeRO 等分片技术共享显存——这是 DeepSpeed-Chat 等早期框架的默认方式。

- **优点**：实现简单，模型间通信开销小。
- **缺点**：显存压力巨大，超过 70B 参数时效率急剧下降。

**策略二：分离部署（Decoupled Deployment）**。把模型分为两组：

- **生成组**：Actor，部署在专门优化的 GPU 集群上，配合 vLLM 等推理加速引擎。
- **训练组**：Critic、Reference、Reward，部署在另一组集群，配合 DeepSpeed ZeRO 训练。

两组之间通过 **Ray** 等分布式框架协调与交换数据。

- **优点**：每组可独立优化（生成组用推理优化，训练组用训练优化），资源利用更高效。
- **缺点**：实现复杂，跨组通信有额外开销。

OpenRLHF 是分离部署策略的代表，支持 **70B 以上参数模型的完整 RLHF 微调**，并通过 vLLM 实现生成加速。

### 2.4 关键工程细节

**KL 散度惩罚**。为防止模型在优化奖励时「走得太远」而丧失语言能力，PPO 在奖励中加入 KL 惩罚：

$$
r = r_{\mathrm{RM}}(x, y) - \beta \, \mathrm{KL}\left(\pi_\theta(\cdot \mid x) \,\|\, \pi_{\mathrm{ref}}(\cdot \mid x)\right)
$$

其中 $\beta$ 是 KL 惩罚系数。含义是：如果 Actor 生成的回答与 Reference 差异过大，即使 Reward 评分很高，最终奖励也会被扣分。

**优势函数的计算**。$A_t$ 衡量「在状态 $s$ 下采取动作 $a$ 相比平均水平好多少」。RLHF 中通常用 **GAE** 计算，它平衡了偏差与方差。

**mini-batch 的多轮更新**。与传统 RL 每批只更新一次不同，PPO 通常**在同一 batch 上多次更新**（3–5 个 epoch）。这提高了样本效率，但要求谨慎控制更新幅度——这正是裁剪机制的作用。

## 3. RLHF 的数据采集与奖励模型训练

### 3.1 偏好数据的采集

偏好数据是 RLHF 的「燃料」，没有高质量偏好数据，奖励模型就无法学到符合人类偏好的判断标准。

**数据来源**：通常来自**众包标注**——大量标注者对模型生成的回答做偏好判断。标注采用**两两比较（Pairwise Comparison）**：给定 prompt 和两个候选回答（通常来自不同模型或不同配置），标注者选择哪个更好。

**数据规模与质量**：奖励模型质量直接取决于偏好数据的规模与质量，高质量偏好数据需要：

- **多样性**：覆盖不同类型的 prompt 与回答风格。
- **一致性**：标注者之间的判断需要较高一致性。
- **细粒度**：不仅标注「哪个更好」，还要标注「好在哪里」。

HH-RLHF 是一个典型的大规模偏好数据集，包含日常帮助、信息查询与安全敏感场景的 prompt，以及基于「有用性」与「无害性」的偏好标签。

**合成偏好数据**：人工标注成本高昂，**合成偏好数据生成**正成为重要方向。West-of-N 等方法通过模型自身生成合成偏好数据，增强奖励模型的训练集。

### 3.2 奖励模型的训练

奖励模型的任务是：给定 prompt $x$ 与 response $y$，输出标量分数 $r(x, y)$，分数越高表示越符合人类偏好。

**训练目标**：最大化偏好排序的似然。对一对偏好数据 $(x, y_w, y_l)$（$y_w$ 是更优回答，$y_l$ 是较差回答），损失函数为：

$$
\mathcal{L}_{\mathrm{RM}} = -\mathbb{E}_{(x, y_w, y_l)}\left[\log \sigma\left(r(x, y_w) - r(x, y_l)\right)\right]
$$

其中 $\sigma$ 是 sigmoid 函数。这个损失鼓励模型给更优回答打更高的分。

**模型架构**：通常与基础语言模型**共享架构**（如 Transformer），但把最后的输出层从词汇表大小的分类头替换为**单一标量输出头**。实践中奖励模型通常从 SFT 模型初始化（而非从零训练），因为 SFT 模型已具备对语言的基本理解。

**训练中的关键考虑**：

- **数据平衡**：确保「选 A 更好」与「选 B 更好」的样本大致平衡。
- **正则化**：防止奖励模型过拟合到训练数据中的特定模式。
- **评估**：用独立验证集评估奖励模型的**准确率**（正确预测偏好的比例）。

### 3.3 DPO：绕过奖励模型的直接偏好优化

**DPO（Direct Preference Optimization，直接偏好优化）**是 RLHF 的重要替代方案，核心创新是**直接基于人类偏好数据优化目标模型参数，而不需要显式构建和训练奖励模型**。

**DPO 的原理**。DPO 的数学基础是：在 RLHF 中，最优策略 $\pi^\*$ 与奖励函数 $r$ 之间存在**闭式关系**：

$$
\pi^\star(y \mid x) = \frac{1}{Z(x)} \pi_{\mathrm{ref}}(y \mid x) \exp\!\left(\frac{1}{\beta} r(x, y)\right)
$$

这意味着**奖励函数可以被表示为策略的函数**：$r(x,y) = \beta \log \dfrac{\pi^\star(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)} + \beta \log Z(x)$。DPO 利用这个关系，把 RLHF 的两阶段优化（训练奖励模型 → PPO 优化策略）**合并为一个单阶段优化**——直接优化策略，使其在偏好数据上的似然最大化：

$$
\mathcal{L}_{\mathrm{DPO}} = -\mathbb{E}_{(x, y_w, y_l)}\left[\log \sigma\left(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\mathrm{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\mathrm{ref}}(y_l \mid x)}\right)\right]
$$

**DPO 与 PPO 的对比**：

| 维度 | PPO（RLHF） | DPO |
|---|---|---|
| 是否需要奖励模型 | 需要 | 不需要 |
| 是否需要 Critic | 需要 | 不需要 |
| 数据 | 可在线采样 | 主要离线偏好对 |
| 训练稳定性 | 对超参敏感 | 相对稳定 |
| 工程复杂度 | 高（四模型 + 三阶段） | 低（类似 SFT） |

DPO 的优势在于**显著简化训练流程**——不需要训练奖励模型，不需要 PPO 的复杂实现。但 DPO 目前主要依赖**离线偏好数据**，而 PPO 可以在训练过程中**在线收集新数据**（模型生成 → 奖励模型打分 → 继续训练），这是 PPO 仍在顶尖模型（如 GPT-4、Claude）中广泛采用的原因之一。

**DPO 的工程实践**：OpenRLHF 等框架已同时支持 RLHF（PPO）、DPO 和拒绝采样等多种对齐技术。实际项目中 DPO 常被用作 **RLHF 的轻量级替代方案**——在资源有限或对训练效率要求较高的场景下，DPO 可以在更短时间内获得与 RLHF 相当的对齐效果。

## 4. 量化补充：策略版本、异步周期与路由重放

**三个策略版本要分开记**：实际行为分布 $\mu$（产生样本）、本轮优化起点 $\pi_{\mathrm{old}}$、当前优化策略 $\pi_\theta$，概率比可分解：

$$
\frac{\pi_\theta}{\mu}=\frac{\pi_\theta}{\pi_{\mathrm{old}}}\cdot\frac{\pi_{\mathrm{old}}}{\mu}.
$$

第一项是本轮参数更新，第二项是采样分布与起点的差异——既含版本滞后，也含跨引擎计算差异。即使每轮先同步权重，第二项也未必为 1：生成端逐 token decode 读 KV，训练端整段并行重算，注意力实现、归约次序、batch 形状、精度都可能让同权重同前缀的 logprob 不同（同一行输入按不同段数归约，平方和可差 166 ULP）。若误用重算的 logprob 代替行为记录值（$-3$ 写成 $-3.25$），比值变 $\exp(0.25)\approx1.28$——**参数没变，样本权重却增约 28%**，还可能错误触发 PPO 裁剪；序列级比值会把各 token 偏差相加，长轨迹积累更多。采样配置也要存：温度、top-k／top-p 变换后的概率才是行为概率，截断排除的 token 无法用重要性权重补回。

**异步收益要扣过期样本**。生成 40 s、学习 16 s、权重同步 4 s：同步周期 60 s，异步（独立资源重叠）稳态 $\max(40,16)+4=44$ s；设保留比例 $q$，异步更快要求 $q>44/60\approx73.3\%$——$q=0.8$ 时有效样本吞吐提约 9%，$q=0.7$ 时反而降约 5%。长轨迹还有长度偏移：中断率 $\lambda$ 下持续 $t$ 的轨迹完整生成概率 $e^{-\lambda t}$，总丢弃重采会系统性偏向短样本；逐 token 记录进度与策略版本可续生成。恢复时 KV 的取舍：同权重可续用已存 KV（Qwen3-8B 8K BF16 占 1.125 GiB，存取消耗空间与传输），换权重则需重执行前缀重建——比取回时间与重建时间再选。

**MoE 把数值差异变成离散路径差异**：top-2 下前三专家分数 0.500、0.301、0.300 选 1、2，第三个因计算次序变 0.302 就改选 1、3，影响沿后续层传播。**路由重放（Routing Replay）**记录生成时选中的逻辑专家 ID，训练时按 ID 选专家、用当前权重算分数与梯度：离散路径一致，数值仍反映当前参数。记录成本很小：Qwen3-30B-A3B 48 层 top-8、8192 token 按 uint16 存仅 $8192\times48\times8\times2=6$ MiB，但 ID 要随 token 原始位置一起经过打包、切分与重计算。NVIDIA R3 验证报告：开启后 logprob 误差中位数下降、每步耗时略增、训练奖励无一致提高——比较时分别看概率误差、训练时间与固定评估任务。更彻底的做法是训推同路径：DeepSeek V4.1 从训练之初就用 64K 稀疏注意力、后训练加入层级候选限制与 FP4 量化感知、模拟解码器 SWA 窗口重放，让模型学习使用部署路径实际提供的表示（状态机制见主题二 41 篇，资源调度见主题四 40 篇）。
