# 训练硬件基础与性能指标

上一篇讨论的核心矛盾是算力需求的指数级增长与硬件供给的相对滞后。要理解这个矛盾、进而找到优化的突破口，首先需要深入理解**「算力」从何而来**。

下面以 NVIDIA GPU 为线索，从微观的 SM（流式多处理器）和 Tensor Core 开始，逐层理解 GPU 的计算与存储体系；然后建立衡量硬件性能的关键指标——FLOPS、显存带宽、MFU/HFU；最后把视野从单卡扩展到集群，理解 NVLink、InfiniBand 和 RoCE 这三种互联技术如何将成千上万张 GPU 连接成一个整体。

本篇要点：

- 读懂一张 GPU 的「性能参数表」，理解每个数字背后的硬件含义。
- 用 MFU 和 HFU 评估一个训练任务的硬件利用效率。
- 理解从单卡到集群的互联层次，为后续的分布式通信打基础。

## 1. GPU 架构速览（以 NVIDIA 为例）：SM、Tensor Core、显存层次

### 1.1 CPU vs. GPU：两种设计哲学

在深入 GPU 架构之前，先理解一个根本问题：**为什么 AI 训练要用 GPU，而不是 CPU？**

CPU 和 GPU 的设计目标截然不同。CPU 擅长处理**复杂的逻辑控制和串行计算**——操作系统调度、数据库查询、分支预测密集的程序，这些都是 CPU 的强项。因此 CPU 的芯片面积中，**缓存单元约占 50%，控制单元约占 25%，运算单元仅占 25%**。

GPU 则走了另一条路。它的设计目标是**大规模并行计算**——同时处理成千上万个相似的计算任务。因此 GPU 将**约 90% 的芯片面积给了运算单元**，缓存和控制单元各仅占 5%。这种「放弃复杂性、追求吞吐量」的设计，使得 GPU 在处理矩阵乘法、卷积等 AI 核心运算时效率远超 CPU。

在实际的大模型训练中，CPU 和 GPU 是**协同工作**的：CPU 负责数据加载、任务调度和指令下发；GPU 负责执行大规模并行计算。理解这个分工，就理解了为什么训练优化既要关注 GPU 的计算效率，也要关注 CPU 与 GPU 之间的数据传输效率。

### 1.2 GPU 的层级化架构：从 GPC 到 SM

以 NVIDIA H100（Hopper 架构）为例，GPU 内部是一个高度层级化的结构：

- **顶层：GPC（图形处理集群）**——H100 包含 **8 个 GPC**，每个 GPC 是一个独立的大型计算单元。
- **中层：TPC（纹理处理集群）**——每个 GPC 包含 9 个 TPC，H100 共计 **72 个 TPC**。
- **核心层：SM（流式多处理器）**——每个 TPC 包含 2 个 SM。GH100 芯片完整版为 **144 个 SM**，而 H100 SXM 实际出货配置为 **132 个 wwASM**（A100 为 108 个）。

SM 是 GPU 执行计算的最小独立单元，理解 SM 的内部结构是理解 GPU 性能的关键。

### 1.3 SM 内部：计算单元与缓存系统

每个 SM 内部主要包含以下计算单元：

**CUDA Core（通用计算核心）**：负责执行标量计算（如加法、乘法）。H100 的每个 SM 包含 **128 个 FP32 CUDA Core** 和 64 个 FP64 CUDA Core。以 132 个 SM 计算，H100 SXM 共有 16896 个 FP32 CUDA Core。

**Tensor Core（张量计算核心）**：专门为矩阵乘法设计的**专用硬件单元**。H100 搭载**第四代 Tensor Core**，每个 SM 包含 4 个，全卡共 528 个（144 SM 版本为 576 个）。Tensor Core 支持 **FP8、FP16、BF16、TF32** 等多种精度格式的混合精度计算，其吞吐量是 A100 的 2 倍。

除了计算单元，SM 还配备了多级缓存：

- **寄存器文件**：每个 SM 有 65536 个 32 位寄存器，总大小 256 KB。
- **L1 数据缓存 / 共享内存**：SM 内部的高速缓存，供同一 SM 内的线程共享。
- **L2 缓存**：所有 SM 共享，H100 的 L2 缓存为 **50 MB**。

### 1.4 显存层次：从 HBM3 到五级缓存

GPU 的存储体系是一个从「快而小」到「慢而大」的金字塔结构：

1. **寄存器**：最快，但容量最小（每 SM 仅 256 KB），由编译器分配。
2. **L0/L1 缓存与共享内存**：可显式控制的片上高速缓存，延迟极低。
3. **L2 缓存**：50 MB（H100），所有 SM 共享，用于缓存频繁访问的全局内存数据。
4. **HBM3 高带宽显存**：H100 SXM 版本配备 **80 GB HBM3 显存**，带宽高达 **3.35 TB/s**；PCIe 版本使用 HBM2e，带宽约 2 TB/s。
5. **CPU 主内存（系统内存）**：通过 PCIe 5.0 连接，带宽仅 128 GB/s，远低于 HBM3。

理解这个五级存储层次，对后续的**显存优化**至关重要——优化的本质，就是在不同存储层级之间寻找最优的数据放置与移动策略。

## 2. 关键性能指标：FLOPS、显存带宽、算力利用率（MFU/HFU）

了解了硬件架构之后，需要建立一套**衡量硬件性能的语言**。日常工作中最常讨论的就是下面这些指标。

### 2.1 FLOPS：硬件的「理论极速」

**FLOPS**（Floating Point Operations Per Second，每秒浮点运算次数）是衡量 GPU 计算能力的最基本指标。不同精度下的 FLOPS 含义不同：

- **FP32（单精度）**：传统科学计算的标准精度，H100 SXM 约 67 TFLOPS。
- **TF32**：专为 AI 设计的精度格式，H100 约 495 TFLOPS（稀疏 989）。
- **FP16/BF16**：混合精度训练的主流格式，H100 约 990 TFLOPS（稀疏 1979）。
- **FP8**：最新的低精度格式，H100 约 1979 TFLOPS（稀疏 3958）。

需要注意的是，这些数字是**理论峰值**——硬件在理想条件下能达到的最高算力。实际训练中几乎不可能达到 100% 的理论峰值，这就引出了后面的关键指标。

### 2.2 显存带宽：往往比算力更先成为瓶颈

在大模型训练中，**显存带宽**（Memory Bandwidth）的重要性不亚于算力本身。

原因在于：大模型训练是**访存密集型**（Memory-Bound）和**计算密集型**（Compute-Bound）的混合体。Transformer 架构中的很多操作（如 LayerNorm、Softmax、Dropout）对算力要求不高，但需要频繁读写显存。当显存带宽不足时，GPU 的计算单元就会「饿死」——等待数据从显存中搬运过来。

H100 SXM 的显存带宽高达 **3.35 TB/s**，是 A100（约 1.55 TB/s）的两倍多。即便如此，在大规模训练中显存带宽仍然常常是主要瓶颈。

一个粗略的判断标准：**如果 GPU 利用率（`nvidia-smi` 查看）低于 90%，但显存带宽利用率接近 100%，说明训练是访存密集型的，优化方向应该是减少显存访问**（如算子融合、减少中间结果的落盘）。

### 2.3 MFU 与 HFU：衡量「算得有多好」的核心指标

FLOPS 衡量的是「硬件能算多快」，但实际训练中硬件往往没有被充分利用。**MFU**（Model FLOPs Utilization，模型算力利用率）和 **HFU**（Hardware FLOPs Utilization，硬件算力利用率）就是用来量化「硬件被用得好不好」的两个关键指标。

**MFU 的定义**：

$$
\mathrm{MFU} = \frac{\text{模型理论需要的计算量（预估 FLOPS）}}{\text{硬件理论 FLOPS}}
$$

这里的「预估 FLOPS」指模型前向 + 反向传播所必需的计算量，**不包括**因优化技术（如激活值重计算）而额外引入的计算量。MFU 衡量的是**算法层面的效率**——模型本身对硬件的利用程度。

**HFU 的定义**：

$$
\mathrm{HFU} = \frac{\text{实际发生的所有计算量（实际 FLOPS）}}{\text{硬件理论 FLOPS}}
$$

HFU **包括**了所有实际发生的计算，包括激活值重计算等优化技术引入的额外计算。因此 **HFU ≥ MFU** 恒成立。

**两者关系的实际意义**：

- 如果 **MFU 和 HFU 都很低**（如都低于 30%），说明硬件本身没有被充分利用，问题可能在数据加载、通信瓶颈或并行策略不当。
- 如果 **MFU 低但 HFU 高**（如 MFU=40%、HFU=70%），说明大量算力被「浪费」在了重计算等额外操作上——这是激活值重计算等显存优化技术的代价。
- 如果 **MFU 和 HFU 都很高**（如都接近 50%–60%），说明训练任务对硬件的利用已经相当充分。

什么样的 MFU/HFU 算「好」？这取决于模型规模和硬件配置。对于千亿参数级别的模型在千卡集群上训练，**MFU 达到 40%–50% 已是非常优秀的水平**；而小规模模型在单卡上训练，MFU 可以达到 60%–70% 甚至更高。

在大厂 AI Infra 团队中，**提升 MFU 是训练优化工程师的核心 KPI 之一**。每一次并行策略调整、每一次通信优化、每一次算子融合，最终都要体现在 MFU 的提升上。

## 3. 从单卡到集群：NVLink、InfiniBand、RoCE

单张 H100 固然强大（3.35 TB/s 显存带宽、近 2000 TFLOPS 算力），但对于千亿、万亿参数的大模型来说，**单卡远远不够**。需要将成百上千张 GPU 连接成一个整体，这涉及三种关键的互联技术。理解它们需要先建立一个**层次化的认知**：

- **NVLink**：GPU 与 GPU 之间的**芯片级直连**，用于服务器内部的多卡互联。
- **InfiniBand（IB）**：服务器与服务器之间的**专用高速网络**，为高性能计算（HPC）而设计。
- **RoCE（RDMA over Converged Ethernet）**：**基于以太网的 RDMA 方案**，成本更低、兼容性更好。

### 3.1 NVLink：GPU 的「专属高速公路」

NVLink 是 NVIDIA 开发的**专有高速互联技术**，用于 GPU 之间的直接通信。

**核心特点**：

- **极高的带宽**：第四代 NVLink（H100）提供 **900 GB/s** 的双向带宽，是 PCIe 5.0（128 GB/s）的 **7 倍以上**。
- **极低的延迟**：延迟在微秒（µs）级别。
- **直接内存访问**：GPU 可以直接读写另一个 GPU 的显存，无需 CPU 介入。
- **范围受限**：NVLink 是**芯片级互联**，通常只能在同一服务器内部（同一物理节点）使用。

在实际的 8 卡 H100 服务器（如 NVIDIA DGX H100）中，8 张 GPU 通过 NVSwitch 实现**全互联拓扑**，总带宽可达 **7.2 TB/s**。

**适用范围**：NVLink 主要用于**张量并行（TP）**和**专家并行（EP）**等需要高频、大量数据交换的并行策略。在这些场景中，GPU 之间每轮迭代都要交换大量数据，NVLink 的高带宽至关重要。

### 3.2 InfiniBand：集群的「专用骨干网」

当需要连接**不同服务器**（不同节点）上的 GPU 时，NVLink 就不够用了——它无法跨越物理节点的边界。这时就需要**集群级互联**。InfiniBand 是专门为高性能计算和 AI 集群设计的**专用网络技术**。

**核心特点**：

- **高带宽**：NDR 规格支持 **400 Gbps**（即 50 GB/s）的单端口带宽。
- **超低延迟**：延迟在 **1 微秒（µs）**级别。
- **无损传输**：通过基于信用的流量控制（Credit-based Flow Control）实现**零丢包**传输。
- **RDMA 支持**：支持**远程直接内存访问**，数据可以直接从一个 GPU 的内存传输到另一个 GPU 的内存，**完全绕过 CPU**，大幅降低延迟和 CPU 开销。
- **GPUDirect 支持**：与 NVIDIA 的 GPUDirect 技术配合，实现 GPU 到 GPU 的直接通信。

**适用范围**：InfiniBand 是构建**大规模 AI 集群**的首选方案，NVIDIA 的 DGX SuperPOD 等参考架构都基于 InfiniBand 构建。局限在于生态相对封闭、配置维护复杂、成本较高。

### 3.3 RoCE：以太网上的 RDMA

**RoCE**（RDMA over Converged Ethernet）是在**标准以太网**上实现 RDMA 的技术方案。

**核心特点**：

- **兼容性好**：基于标准以太网，可以利用现有的网络基础设施。
- **成本较低**：以太网交换机的价格通常低于 InfiniBand 交换机。
- **带宽与 IB 相当**：在相同速率下，RoCE 和 IB 的带宽相同。
- **延迟略高**：RoCE 的延迟通常在 **2 微秒（µs）**左右，比 IB 略高。
- **需要无损网络配置**：RoCE 需要依赖 **PFC（优先级流控制）**和 **ECN（显式拥塞通知）**等机制来实现无损传输。

**适用范围**：RoCE 适合**成本敏感**或**需要与现有以太网基础设施兼容**的 AI 集群部署场景。

### 3.4 三种技术的对比与选型

| 技术 | 覆盖范围 | 典型带宽 | 延迟 | 适用并行维度 |
|---|---|---|---|---|
| NVLink | 节点内 GPU 直连 | 900 GB/s（双向） | 微秒级 | TP / EP |
| InfiniBand | 节点间 | 400 Gbps（50 GB/s） | 约 1 µs | DP / PP |
| RoCE | 节点间（以太网） | 与 IB 同速 | 约 2 µs | DP / PP |

**实际部署中的层次结构**：在一个典型的 AI 训练集群中，这三种技术是**分层协作**的：

1. **服务器内部**：8 张 GPU 通过 **NVLink + NVSwitch** 全互联，实现 7.2 TB/s 的超高带宽。
2. **服务器之间**：通过 **InfiniBand 或 RoCE** 网络连接，实现跨节点的 GPU 通信。
3. **整个集群**：通过 InfiniBand/RoCE 构建的胖树（Fat-Tree）或混合拓扑，连接成百上千个节点。

**选型建议**：

- **追求极致性能**：选择 InfiniBand，它是目前 AI 训练集群的**黄金标准**。
- **平衡性能与成本**：选择 RoCE，在性能损失可控的前提下大幅降低网络成本。
- **单机多卡场景**：NVLink 是**必须的**，没有 NVLink 的多卡训练性能会严重下降。
