# 五个后训练平台项目：从语料到可恢复 RL

第五期最后六个章节是六个工程项目。它们串起来就是一条完整链路：**原始网页 → 可训练语料 → 配方 → 合成与偏好数据 → SFT/DPO/RL → 可恢复的 Agentic RL 平台。**

## 1. 项目全景

| # | 项目 | 交付物 | 一句话验收 |
|---|---|---|---|
| 1 | 从 Common Crawl 到可训练语料 | 语料 Release + 数据卡 | 任一 Token 能追到 WARC 偏移 |
| 2 | 可版本化数据湖与血缘控制面 | 目录 + 血缘 + 发布 + 删除传播 | 正向与反向都能查 |
| 3 | CPT / SFT 数据配方工厂 | 配方 DSL + 不可变 Release | 同配方可重放出同一 Release |
| 4 | 合成 / 偏好 / RM 数据工厂 | 样本 + 验证证据 + 拒绝原因 | 每条样本都能解释「凭什么进」 |
| 5 | 可按显存缩放的 SFT→DPO→GRPO/RLVR 流水线 | 显存预算表 + 降级策略 | 同一配方在不同卡数上都能跑通 |
| 6 | 可恢复的异步 Agentic RL 平台 | 环境 + 控制器 + 恢复工作流 | 杀进程后不双写、不重放错版本 |

## 2. 项目一：从 WARC 到可训练语料

### 2.1 仓库骨架

```text
schemas/source_record.json / document.json / decision.json
src/resolve_snapshot.py / fetch_warc.py / parse_html.py
    / filter_document.py / deduplicate.py / publish_release.py
tests/fixtures/  tests/test_replay.py
artifacts/manifests/  metrics/  data_cards/
```

**三类记录的最小字段**：

| 记录 | 关键字段 |
|---|---|
| source_record | `source_id`、抓取快照、WARC 路径、记录偏移、长度、URL、抓取时间、响应状态、MIME、Payload 哈希、策略版本 |
| document | 稳定 `document_id`、父源记录、标题、正文、语言、结构块、规范化版本、内容哈希 |
| decision | 阶段、动作、原因码、阈值、算子版本、时间、证据摘要 |

一条硬规则：**所有标识都由规范序列化后的确定字段计算，不能用随机 UUID 替代可重算身份。**

Release Manifest 列出：Recipe、上游资产、Tokenizer、分片算法、随机种子、每片哈希、文档数、有效 Token、原因统计、数据卡位置。**训练恢复只接受 Manifest 登记且哈希匹配的分片**——目录里多出一个文件，不能自动进训练。

### 2.2 七个实施步骤

1. **注册来源与快照**：冻结 CC 快照与 WARC 路径范围，为来源域绑定许可、地域、敏感级别、抓取预算与退出方式。**未知策略进隔离，不允许「先抓后补」**；索引查询结果保存原始响应哈希；
2. **Range Fetch**：用偏移 + 长度做 Range 请求，经长度/哈希/记录头/Payload 校验后写内容寻址缓存；重试以源记录身份幂等；**缓存键必须含快照、路径、偏移、长度**，避免不同记录串线；
3. **解析与正文边界**：解压 → 解析 HTTP → 按 MIME 路由 HTML/文本/PDF/拒绝；删导航、脚注、广告时记录规则；**解析失败不是空文档**，要保存 `parse_error` 类别与样本；
4. **规范化与语言路由**：Unicode 归一、控制字符、空白折叠、URL 标准化都要版本化；**原文哈希与规范文哈希同时保存**；语言识别输出分布与置信度，低置信/混合语言进专门桶；
5. **质量、隐私与安全**：规则层（长度、字母比、重复行、模板密度、链接密度）+ 模型层（质量/领域/难度/风险）；PII 分类型处理（删字段 / 局部遮盖 / 整文档隔离 / 升级人工）；分数保留模型版本与校准窗口；
6. **去重与去污染**：先精确哈希 → 再 Shingle/LSH 出候选 → Jaccard 复核成簇 → 代表选择综合来源策略、质量、长度、抓取时间，**并保存「被代表」关系**；去污染用题面/答案/段落/子串多视图，命中后保留基准版本、匹配位置与动作；
7. **Tokenize、分片与发布**：固定 Tokenizer → 有效 Token → 稳定哈希分片 → 片内固定种子排列。门禁检查输入覆盖、Schema、原因守恒、重复簇、PII 红线、污染红线、Token 预算、分片哈希与重放一致性。**通过后写就绪标记，消费者不读半完成目录。**

## 3. 项目二：数据湖与血缘控制面

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l32_01.png" width="78%" alt="数据湖与血缘" />
  <p>图 2：目录、血缘、发布与删除传播构成控制面</p>
</div>

交付能力：

- **资产目录**：资产 ID、版本、Schema、Owner、用途、许可、质量摘要、上下游、发布状态；
- **血缘**：正向（来源→模型）与反向（问题对象→派生资产与模型）都支持；
- **发布**：候选 → 验证 → 发布 → 别名切换 → 回滚，全程有事务与证据；
- **删除传播**：Tombstone、代表重选、派生资产失效与模型影响分析。

验收方式：随机抽一条记录，能正向追到 Release 与训练 Run；随机抽一个 Checkpoint，能反向列出消费过的数据版本。

## 4. 项目三：CPT / SFT 数据配方工厂

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l33_01.png" width="78%" alt="配方工厂" />
  <p>图 3：配方是声明式的，产出是不可变 Release</p>
</div>

一份配方至少包含：

```text
目标能力与评测          ← 决定要什么
来源集合 + 过滤算子      ← 决定选什么
混合比例（按有效 Token）  ← 决定给多少
课程与阶段              ← 决定什么时候给
Token 预算与覆盖 floor   ← 决定下限
```

两条纪律：**配方是声明式配置，不是脚本**（否则不可重放）；**一次配方产出一个不可变 Release**，别名只指向 Release。

## 5. 项目四：合成 / 偏好 / RM 数据工厂

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l34_01.png" width="78%" alt="合成与偏好工厂" />
  <p>图 4：生成—验证—选择三段管线，每段都留证据</p>
</div>

三段式：

1. **生成**：教师版本、prompt 模板、温度/Top-p、采样数全部版本化；
2. **验证**：Schema → 规则 → 执行 → Judge → 人工抽样，**每条样本保存全部状态与拒绝原因**；
3. **选择**：覆盖约束 + 质量排序 + 去重 + 去污染，产出「样本 + 证据 + 分数」。

偏好数据额外要求：同 Prompt 同工具状态、长度控制、位置偏差 AB/BA、曝光上限。

## 6. 项目五：可按显存缩放的流水线

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l35_01.png" width="78%" alt="可缩放流水线" />
  <p>图 5：同一套代码要能在 1 卡、8 卡、多机上都跑通</p>
</div>

要产出的不是「一个能跑的脚本」，而是**显存预算表 + 降级策略**：

| 维度 | 缩放方式 |
|---|---|
| 模型 | 小模型基线 / LoRA / 4-bit |
| batch | micro batch + 梯度累积 |
| 序列 | 长度分桶 / 截断策略 |
| 并行 | DP → DP+ZeRO → DP+TP/PP |
| 显存 | 激活重计算 / offload / 量化 |

验收：同一配方在「1 卡 / 8 卡 / 多机」三种预算下都能跑通，且**记录每种配置的有效 Token 与墙钟**——不记录就无法比较「缩放是否真的有效」。

## 7. 项目六：可恢复的异步 Agentic RL 平台

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l36_01.png" width="78%" alt="异步 Agentic RL 平台" />
  <p>图 6：环境、控制器、权重发布与恢复工作流共同构成平台</p>
</div>

### 7.1 环境契约

每个环境定义：镜像、工具 Schema、网络策略、资源限制、超时、初始化快照、可观察状态、终局判定。工具调用记录**请求、响应哈希、副作用 ID、幂等键**；高风险外部动作在模拟或审批环境执行，**训练策略不直接持有生产凭证**。

### 7.2 Partial 的七种终止

自然 EOS、长度限制、墙钟限制、工具暂停、主动抢占、用户取消、环境故障——七种语义不能混。

可暂停状态包括：对话 Token、KV 或可重建上下文、环境快照、工具副作用、随机状态、Policy 与 Runtime 合同。**无法一致恢复时，Partial 只能用于诊断或特定过程监督，不能伪装成可续跑状态。**

时间截断允许 Critic Bootstrap 的前提是「状态仍合法 + Critic 版本明确」；环境损坏不能无条件 Bootstrap。续跑后要抽样比较「截断估值 vs 最终回报」。

### 7.3 权重发布

`Policy Bundle` = 训练 Checkpoint + 推理权重分片 + Tokenizer + 模板 + 采样默认 + Runtime 兼容 + 量化 + 哈希 + 谱系。

发布流程：临时前缀生成全部分片 → 写 Manifest → 注册 Ready → Worker **在请求边界切换** → 小规模加载验证 → Golden Prompt 桥接。**禁止中途切版**。

记录：发布大小、转换、传输、加载、Warmup、Fleet 完成、旧版本 Drain 时间。增量/共享内存方案必须有完整权重校验回退；**任何 Worker 加载失败，都不能让路由器假设它已切版**。

### 7.4 资源放置

| 方案 | 适用 |
|---|---|
| 时分复用 | 单机、预算有限 |
| 一 Rollout 一 Trainer | 稳定隔离 |
| Colocate | 减少权重传输 |
| Disaggregate | 独立扩缩、故障域隔离 |

决策依据：模型大小、KV、环境等待、网络拓扑、更新频率、故障域、**新鲜有效吞吐**。资源声明按 GPU/显存/CPU/环境槽位/Token 预算/拓扑，而不是只按 Pod 数。

### 7.5 仓库与测试

```text
api/  schemas/{task,experience,policy_bundle}.json
services/{scheduler,rollout,environment,reward,sealer,trainer,publisher,registry}/
workflows/recovery/  deploy/{local,kubernetes}/
tests/{state_machine,fault_injection}/  dashboards/  runbooks/
```

**合同测试必须独立于具体队列**，避免把供应商语义写进算法。

### 7.6 租约、陈旧与幂等

三条最容易踩的坑：

1. **超时不证明旧进程已死亡**——必须有持久化条件阻止双写；
2. `experience_id` / `attempt_id` 的提交要幂等：重复尝试返回 `duplicate_attempt`，同尝试重放返回 `idempotent`；
3. 陈旧 Experience 要按「版本 + 年龄 + Ratio」三重门禁拒绝或降权，**不能只看版本差**。

## 8. 六个项目共享的验收口径

| 口径 | 含义 |
|---|---|
| 可重放 | 同一输入 + 配方 + 代码版本 → 同一输出 |
| 可追溯 | 任一产物能正反向追到来源与消费方 |
| 失败关闭 | 校验不过必须拒绝，不能静默降级 |
| 单变量 | 实验一次只改一个主要因素 |
| 有方差 | 关键结论要多种子/置信区间 |
| 可恢复 | 杀进程后不双写、不重放错版本 |

## 9. 上线清单

- [ ] 每个产物有 Manifest 与摘要，训练只读登记分片

- [ ] 配方声明式，一次配方一个不可变 Release
- [ ] 合成数据每条带验证证据与拒绝原因
- [ ] 显存预算表覆盖 1 卡 / 8 卡 / 多机
