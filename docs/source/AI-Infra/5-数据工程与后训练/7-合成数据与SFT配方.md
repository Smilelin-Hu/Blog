# 合成数据与 SFT 配方：生成、验证与选择

SFT 数据的两大来源是「人写的」和「模型生成的」。后者便宜、量大，但它带来两个新问题：**怎么证明它对**，以及**怎么证明它有用**。

## 1. 合成数据的定位

</div>

一句必须记住的话：**教师生成的是「能力转移」，不是「事实来源证明」。**

学生可能学到教师的解释风格、拒答习惯，也包括错误。验证目标是**产品目标**，不是「与教师越像越好」。

## 2. 指令合成：难度要可观测

难度可以通过这些维度控制：步骤数、干扰信息、信息位置、约束数量、所需工具、证明深度。

两条纪律：

1. 不要只让教师自报「这是困难题」——要保存**可观测难度特征**；
2. 用**学生通过率或执行轨迹**校准难度标签。

过难且不可验证的题只增加噪声。

## 3. 响应合成的五种做法

| 做法 | 强项 | 风险 |
|---|---|---|
| 单教师单响应 | 成本最低 | 无法估计生成方差，不适合开放安全/事实任务 |
| 多采样 Best-of-N | 提升找到好答案的概率 | 成本上升 + **选择偏差**：选择器有漏洞时会主动搜索漏洞 |
| 多教师 | 语言/领域/风格多样性，减少回声 | 需校准教师能力与许可；简单平均会隐藏弱教师 |
| 蒸馏 | 能力转移 | 学生继承教师错误与风格；不能以「像教师」为目标 |
| 拒答 / 澄清 | 高质量数据不止有答案 | 若全部给确定答案，学生会学成过度自信 |

**拒答要分三类**：安全拒答、知识不确定、信息缺失——混在一起会让模型学会「一律拒」或「一律答」。

## 4. 推理轨迹：不是答案的装饰

### 4.1 后验合理化

在正确答案后补一段「看起来合理」的解释，与真实求解过程无关。这种数据会教模型**编理由**，而不是**解题**。

轨迹的价值在于：分解问题、调用工具、验证中间结果、定位错误。

### 4.2 结果监督 vs 过程监督

| 类型 | 判断对象 | 成本 | 适用 |
|---|---|---|---|
| 结果监督 | 最终答案 | 低 | 可验证任务（代码/数学/SQL） |
| 过程监督 | 中间步骤 | 高（标注与 Judge 复杂） | 定位首个错误、长链推理 |

组合方式：执行器先筛结果，再对高价值或边界样本做过程验证。

### 4.3 工具轨迹 = 状态转移

```text
观察 → 选择工具 → 生成参数 → 接收结果 → 更新计划 → 停止
```

轨迹要保存**工具 Schema 版本、调用结果摘要、错误码**。只存最终自然语言，就丢掉了所有可训练的决策边界。

### 4.4 长度偏置

教师常把「更长」当「更好」，学生于是学会无意义展开。评价应是「正确 + 最小充分 + 可验证 + 成本」：简单题保留直接答案，复杂题保留必要步骤。

## 5. 自改进闭环：五阶段都要留痕

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l20_02.png" width="78%" alt="自改进闭环" />
  <p>图 2：生成、批评、修订、验证、回收彼此独立留痕，闭环才有意义</p>
</div>

| 阶段 | 职责 | 关键纪律 |
|---|---|---|
| Generate | 探索候选项 | 温度/Top-p/提示策略版本化；**只负责探索，不宣布正确** |
| Critique | 指出事实/逻辑/格式/安全/证据缺口 | 必须引用可验证位置；同教师自评有盲区，要叠加规则与独立模型 |
| Revise | 依据批评重写，保存父子边 | **修订不继承父候选的通过状态**，全部门禁重跑 |
| Select | 比较候选并给分项理由 | 位置、长度、风格、自偏好都会影响 Judge；交换顺序、多 Judge、执行器、人工抽样估计偏差 |
| Learn | 只有过门禁的样本进 SFT/偏好/评测 | 下一轮生成由**能力缺口与失败分布**驱动，不是无脑扩模板 |

如果这五步不留痕，闭环只是把同一种偏差反复写回数据池。

## 6. 验证器体系：六层，按成本递进

| 层 | 检查什么 | 边界 |
|---|---|---|
| Schema | 字段、类型、角色顺序、特殊 Token、最大长度、必需元数据 | **机器可读 ≠ 语义正确** |
| 规则 | JSON、正则、长度、禁词、引用、单元约束 | 确定、便宜、可复现，但只覆盖已编码条件 |
| 执行 | 代码/数学/SQL/工具调用/形式证明在沙箱跑 | 保存输入、环境、依赖、退出码、资源限制；**单一测试通过 ≠ 完整正确**，要隐藏与变形测试 |
| 模型 Judge | 开放质量、相关性、帮助性、安全 | 有偏差；冻结模型/提示/解析器，用量表与校准集，报告拒判与冲突 |
| 人工 | 高风险、开放边界、Judge 校准、随机审计 | 需指南、培训、双标、仲裁；保存一致率 |
| 组合门禁 | 先便宜规则 → 沙箱 → Judge → 人工抽样 | 顺序要降成本，**但不能让高风险样本绕过**；每样本保存全部状态而非只存「通过」 |

## 7. SFT 数据选择：别让 Top-K 收缩

  <p>图 3：全局 Top-K 会把低资源能力整体挤出</p>
</div>

五步选择：

1. **硬过滤**：权利不清、秘密、无法解析、明显错误、超限、污染、Schema 不兼容——**有版本、有拒绝原因**，不把风险转成连续质量分；
2. **质量排序**：规则 / 执行 / Judge / 人工 / 学生信号；分数只在同一量表内可比，跨任务要校准；
3. **覆盖约束**：为能力、语言、难度、安全边界、工具、长度设置最低覆盖与来源上限——**总体质量上升不能掩盖关键能力样本归零**；
4. **核心集选择**：聚类、设施位置、梯度或表示选择；复杂方法必须与「分层随机 + 简单去重」基线比较；
5. **主动选择**：按目标学生的不确定/错误/损失挑样本；信号依学生版本，不是数据永久属性，要防「只选噪声难例」。

## 8. 混合不是文件比例

| 口径 | 问题 |
|---|---|
| 样本比例 | 受响应长度影响：同样条数的短分类与长轨迹监督 Token 差几个数量级 |
| Token 比例 | 更接近梯度预算，要在 Template、截断、Packing、Loss Mask 之后计算**非 Padding 监督 Token** |

两个进阶做法：

- **来源与能力双层采样**：先选能力桶，再选来源与样本，同时控制产品覆盖与单来源集中；层次权重必须换算成最终概率并验证；
- **静态 vs 课程混合**：课程随 Token 水位改变难度/领域/安全比例，收益必须与「相同总 Token 的静态基线」比较。

还要区分：**重采样改变曝光，损失加权改变单次梯度贡献**——两者不等价，实验一次只改一种因素。

## 9. 去污染

### 9.1 污染单元不只有完整题目

可能是：完整题目、答案、推理路径、代码、测试、关键数字、文档段落、同源模板。**按评测任务定义污染单元，不要用一个字符串规则包打天下。**

### 9.2 四层匹配

- 精确/规范化：抓完全副本，便宜可解释，抓不到释义与结构改写；
- 模糊：n-gram / MinHash / 编辑距离 / 代码结构，阈值需金标校准，短文本易误报；
- 语义：嵌入或模型发现释义；
- 来源谱系：发现「由评测题生成的改写」。

注意：**语义高相似不自动等于污染**，要结合答案与任务判断。

### 9.3 处置

隔离命中样本及其同父后代或整簇，重算覆盖与混合。**若评测集已被用于生成或选择，应把它降级为开发集，并建立新的盲测。**

## 10. 消融：五类设计

| 设计 | 回答 | 注意 |
|---|---|---|
| Leave-one-source-out | 某个来源的条件边际价值 | 来源间有交互 |
| Add-one-source | 小规模筛选 | 加入顺序影响结论，需固定基线或多顺序 |
| 剂量曲线 | 零/低/中/高 Token 的收益饱和与回退 | 必须配合固定总 Token 或明确增量预算 |
| 处理消融 | 去重/质量/污染/长度/课程各自贡献 | 不能全一起上线后无法归因 |
| 多种子 + 置信区间 | 结论是否可区分 | 小模型方差显著；差异小于方差时结论是「无法区分」 |

最后一条最容易被忽视：**没有方差估计的「提升」经常只是随机波动。**

## 写在最后

合成数据这条线的逻辑很清晰：**生成负责多样性，验证负责正确性，选择负责价值。** 三者混在一起，就会出现「数据很多、效果不明、无法复现」。
