# 偏好与奖励：从标注到 DPO 家族

SFT 教「怎么答」，偏好数据教「哪个答得更好」。后者看起来只是换个标签，实际上把问题从「监督学习」变成了「相对比较 + 分布约束」——**错误的关系会被稳定地学进模型**。

## 1. 偏好数据的三种来源

### 1.1 人类偏好

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l22_01.png" width="78%" alt="人类偏好采集" />
  <p>图 1：标注协议、分歧与仲裁共同决定偏好数据的可用性</p>
</div>

- 高风险或难例用**多人独立标注**，分歧进入仲裁；
- **保留原始标签**，不要用多数票覆盖不确定性；
- **分歧率是指南的健康指标**：分歧高说明指南模糊或任务本身不可判定。

### 1.2 AI Feedback

用明确原则让模型批判与修订（Constitutional 类做法），再比较候选。三条纪律：

- **原则要版本化**，冲突处理要记录；原则不是自然法，需要产品、安全、治理共同定义；
- **Pointwise vs Pairwise**：绝对评分便于缓存与多候选排序，但标尺会漂移；成对比较更易判断相对优劣，却受顺序与配对分布影响——两者可组合校准；
- **Judge 有七种常见偏差**：位置、长度、自偏好、风格、引用、语言、权威语气。缓解手段：AB/BA 交换、金标、跨家族 Judge、执行证据、人工审计。

边界很清楚：**AI Feedback 扩展规模与一致性，不能替代真实用户价值、专家事实与严重安全判断。** 多个相关 Judge 一致，也可能一起错。

### 1.3 On-policy 偏好

策略更新后输出分布就变了，**旧候选覆盖不到新策略的失败模式**。所以当前策略生成的候选更接近决策边界，比较信号更有用。

| 概念 | 含义 | 工程要点 |
|---|---|---|
| 严格 on-policy | 生成策略 = 训练当前权重 | 同步昂贵 |
| 近策略 | 允许一定版本滞后 | 记录 Policy Lag 并设上限；**不能把数周旧模型的输出叫「当前策略」** |

三个细节：

- **Prompt 采样**：来自真实受治理流量、能力图、红队、环境任务、历史失败；按风险/难度/覆盖采样；**线上原文不自动进训练**；
- **候选生成**：同 Prompt 从当前策略采多条，控制温度与长度——**太相似没信号，差异太大变成「容易负例」**；
- **标注延迟**：生成、Judge、人工都要时间，标签完成时策略已变；发布要绑定「生成策略水位 + 标注时间」，训练器控制可接受滞后。

## 2. 偏好质量的五个维度

| 维度 | 具体要求 |
|---|---|
| 可判定性 | 上下文充分、评价维度明确；不可判定的数据**不能随机填标签** |
| 一致性 | 用重复对、顺序交换、金标、多标估计；**高一致 ≠ 正确**（可能共享指南偏差） |
| 难度 | 差距过大=易对，过小=难对；训练需要课程与边界，难对噪声更大 |
| 长度控制 | 若 chosen 总更长，模型会学长度而非质量；做长度切片、加「短优长劣」对、用分项指南审计 |
| 去重与来源上限 | 按 Prompt 簇、响应簇、生成策略设曝光上限，否则重复对会放大偏好 |

一个具体机制：单向标注 + 位置偏差会系统性抬高 A 位候选。做法是 AB/BA 双向标注，把聚合规则写进版本化记录，并保留冲突样本。

## 3. 奖励模型与过程奖励

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l23_01.png" width="78%" alt="奖励模型" />
  <p>图 3：RM 学的是「偏好概率」，不是「客观质量」</p>
</div>

- **成对训练**（Bradley–Terry）：\(P(y_w \succ y_l) = \sigma\left(r_\phi(x,y_w) - r_\phi(x,y_l)\right)\)，训练用 \(-\log\sigma(\cdot)\)；
- **RM 的三个风险**：reward hacking（模型学会讨好 RM 而非变好）、分布外打分不可信、对长度/风格敏感；
- **校准很重要**：RM 分数是相对量，跨批次/跨版本不可直接比；要有金标与一致性检查；
- **PRM（过程奖励）** 需要步骤级标签：标注成本高、步骤边界定义难、聚合方式（求和/最小/折扣）会改变行为。它更适合「可验证的长链推理」，不适合所有任务。

## 4. 离线偏好方法族

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l24_01.png" width="78%" alt="DPO 家族" />
  <p>图 4：同一份偏好数据，不同 Loss 写入的是不同的统计关系</p>
</div>

### 4.1 从 KL 正则奖励最大化到 DPO

经典目标：

$$
\max_\pi\ \mathbb{E}_{x,y\sim\pi}\left[r(x,y)\right] - \beta\, D_{KL}\left(\pi(\cdot\mid x)\,\|\,\pi_{ref}(\cdot\mid x)\right)
$$

对固定 Prompt 的最优策略：

$$
\pi^\ast(y\mid x) = \frac{1}{Z(x)}\pi_{ref}(y\mid x)\exp\left(\frac{r(x,y)}{\beta}\right)
$$

反解得「奖励 = \(\beta\) × 对数概率差 + 只依赖 Prompt 的常数」。**两个回答作差时常数消失**，于是不用显式训练 RM 也能拟合 Bradley–Terry。

### 4.2 DPO 的 Loss 与梯度

定义 Pair Margin：

$$
\Delta_\theta = \left[\log\pi_\theta(y_w\mid x)-\log\pi_\theta(y_l\mid x)\right] - \left[\log\pi_{ref}(y_w\mid x)-\log\pi_{ref}(y_l\mid x)\right]
$$

$$
\mathcal{L}_{DPO} = -\log\sigma(\beta\Delta_\theta),\qquad
\frac{\partial \mathcal{L}}{\partial \Delta_\theta} = -\beta\,\sigma(-\beta\Delta_\theta)
$$

三点必须理解：

1. 它约束的是**相对变化**，不保证 chosen 绝对概率上升——「两端都降、rejected 降更多」同样能降 Loss，这正是要**单独监控 chosen NLL** 的原因；
2. 低 Margin/错分的样本梯度大，已分开的样本梯度饱和；
3. \(\beta\) 同时影响输入尺度与梯度幅度，**不能只靠「保守/激进」选值**，要扫参并观察隐式奖励 Margin、KL 代理、chosen/rejected NLL、长度、熵与任务指标。

### 4.3 reference-free ≠ 没有基线

三种说法要分清：

- 参考分数**已缓存**（语义仍依赖固定参考）;
- 参考模型与策略**共享部分权重**；
- Loss **真的没有参考项**（目标已改变，基线退化为隐式常量或其他正则）。

三者在报告里同名，实验就无法比较。

### 4.4 DPO 的数据要求与五种失败

数据要求：同一 Pair 必须同 Prompt 语义、同可见工具状态、同评判标准；**chosen 有额外检索结果而 rejected 没有，模型会学「上下文痕迹」**；保留原始生成概率/温度/策略版本；平局不随机打方向；重复 Prompt 按组切分。

| 失败 | 表现 | 诊断 |
|---|---|---|
| 长度爆炸 | 用冗长提高相对概率 | 看长度分布与「长度-胜率」相关性 |
| chosen 似然下降 | 靠更强压低 rejected 获胜 | 单独看 chosen NLL |
| 参考不一致 | 缓存 log-prob 来自错模板/旧 Tokenizer | 核对参考计算版本 |
| 过度拟合 Judge 风格 | 只讨好某一 Judge | 多 Judge + 人工审计 |
| Pair 噪声被记忆 | 大轮数后训练集准确率虚高 | 看验证集与分切片 |

诊断的铁律：**把 Loss 拆成 chosen reward / rejected reward / Margin / 准确率 / 长度**，而不是只看一条总曲线。

### 4.5 IPO：把 Margin 拉到有限靶值

DPO 在「近乎可分」的数据上会持续推大 Margin，容易过拟合。IPO 改成围绕有限目标做平方误差：

$$
\mathcal{L}_{IPO} = \left(\Delta_\theta - \frac{1}{2\tau}\right)^2
$$

不同库用 \(\beta\) 或 \(\tau\) 且常数不同，**不能只比参数名**，要读实际公式、序列聚合与默认缩放，并用固定 log-prob 做数值对拍。

工程含义：Margin 低于目标时增加 chosen 优势，超过目标后梯度反向拉回——抑制「容易样本被无限强化」，但目标设错也会压制真实强偏好。它不是噪声清洗器：系统性偏差、颠倒标签、模板捷径照样会被学。

### 4.6 KTO：单样本好/坏反馈

真实产品更容易拿到点赞/点踩/接受/重试，**不总能配出严格成对候选**。KTO 允许每条样本带 desirable/undesirable 标签：

$$
z(x,y) = \log\pi_\theta(y\mid x)-\log\pi_{ref}(y\mid x)
$$

对正样本希望 \(z\) 高于某个 KL 基线中心，对负样本希望低于中心，正负用不同权重。直觉与「参考点」有关：人对收益与损失的反应不对称。

它的新问题是**反事实不可观测**：看到某回答被点赞，并不知道同条件下另一个回答会怎样。而且**选择偏差严重**——用户只会评价被展示的回答，展示策略、位置、延迟、人群、界面都会影响标签。数据至少要保存曝光概率、策略版本、路由、用户上下文桶与交互结果，条件允许时做随机化或倾向修正。

### 4.7 ORPO 与 SimPO：两个方向的简化

- **ORPO**：把 SFT 与偏好合并在一次训练里（SFT 损失 + 相对劣势惩罚），省掉单独的参考模型阶段；
- **SimPO**：用**长度归一化的平均 log-prob** 作为隐式奖励，并且**不需要参考模型**。

它们的共同吸引力是「省一个模型/省一段流程」，代价是**语义变了**：没有参考项，就失去对「偏离原始分布」的显式约束，需要靠数据质量、长度归一化与早停来控制。

### 4.8 三个控制面

| 控制面 | 负责 |
|---|---|
| 数据 | Pair Schema、生成策略、标注、清洗、切片、去重、版本 |
| 训练 | 策略、参考模型、Loss、优化器、分布式、检查点、可恢复性 |
| 评测发布 | 离线能力、安全、长度、校准、服务基准、Canary、回滚 |

**算法只占训练控制面的一部分**，三者的版本必须能在一次 Run 里被唯一解析。

## 5. 在线路线：PPO / GRPO / RLOO / DAPO

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l25_01.png" width="78%" alt="在线偏好优化" />
  <p>图 5：在线方法把「采样 → 打分 → 更新」变成闭环，代价是系统复杂度</p>
</div>

| 方法 | 核心差别 |
|---|---|
| PPO | Actor + Critic + Reward + Reference 四模型；用 Critic 估优势，KL 约束参考 |
| GRPO | 去掉 Critic，用**同组内相对优势**（组归一化）代替 |
| RLOO | 用 leave-one-out 基线估计优势，无需 Critic |
| DAPO | 在 GRPO 基础上做采样/裁剪/长度等工程改进（动态采样、clip 范围、长度惩罚等） |

共同点：**它们都依赖「采样质量 + 奖励可靠性」**。奖励错，优化只会更高效地学错。这也是下一篇（Rollout 与奖励系统）要解决的核心。

## 6. 一张诊断清单

- [ ] Loss 已拆成 chosen / rejected / margin / 准确率 / 长度
- [ ] chosen NLL 未持续下降
- [ ] 参考 log-prob 的模板与 Tokenizer 版本一致
- [ ] 长度分布与「长度-胜率」相关性已检查
- [ ] Pair 未把「上下文痕迹」当质量（检索结果/工具状态一致）
- [ ] Judge 偏差已用 AB/BA、多 Judge、人工抽样估计
- [ ] 数据版本、生成策略水位、标注时间三者可唯一解析
- [ ] 训练集准确率与验证集分开报告
