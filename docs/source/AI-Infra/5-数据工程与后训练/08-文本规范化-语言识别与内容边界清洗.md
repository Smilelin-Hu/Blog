# 文本规范化、语言识别与内容边界清洗

## 1. 本文要解决的工程问题

清洗规则删掉了乱码，也顺手改坏了代码缩进、数学符号和多语种文本。最终语料更整齐，却少了原本要训练的结构。

本文围绕一个可执行判断展开：怎样做文本规范化与语言识别，同时保留原文证据和可逆边界？读完应能给出自己的系统边界、输入输出、版本关系和验收证据，而不是只复述工具名称或公式。

## 2. 本文交付物与判定标准

本文的核心决定是：把字节修复、Unicode 规范化、语言识别、正文边界与内容重写分层，并为不可逆动作保存原因和原文定位。

完成学习和实验后，应当交付一份最小可复现记录，至少包含输入快照、配置、代码版本、运行状态、原始输出和结论边界。验收证据是：固定边界集覆盖混合语言、代码、公式、异常编码和短文本；每条变更都能区分修复、保留、拒绝和不确定。

围绕“文本规范化、语言识别与内容边界清洗”的验收不接受三类替代品：把模拟输出写成真实 GPU 结果；只展示成功样本而隐藏失败与 `SKIPPED`；只给总分，不保存能复算总分的对象级记录。

## 3. 前置知识与实验边界

“文本规范化、语言识别与内容边界清洗”的机制实验使用 Python 3.10 及以上版本和标准库，重点验证对象、算法或状态转换。真实硬件路径使用 PyTorch；检测不到 CUDA 时必须输出结构化 `SKIPPED`，不得静默改跑 CPU 后仍标成 GPU 实测。

语言识别分数与规则命中只提供筛选证据，不代表文本事实正确或适合某一训练目标。

### 3.1 业务背景与失败模式

解析层已经把 HTML、PDF、代码和对话变成结构化 Unit，但这些文本仍可能包含不同 Unicode 表示、错误控制符、模板残片、不可见字符、混合语言、乱码、导航/页眉、引用与用户内容边界。清洗的目标不是让所有文本看起来统一，而是生成适合特定训练用途、可逆可审计、不会误伤语言与结构的规范视图。

盲目小写、NFKC、删除标点、合并空白和“非目标语言删除”会造成真实语义损失。兼容归一化可能把上标、圈号、宽度或格式差异折叠；代码大小写和空白重要；阿拉伯、希伯来双向文本、组合附加符与 Emoji 序列不能按 ASCII 直觉；短文本语言识别置信度低；一个网页可能正文中文、代码英语、引用日语。清洗规则必须按内容类型、语言候选和用途分层。

清洗也是血缘变换。每次删除、替换、合并或分段都应产生位置映射、reason code 和 Recipe，使下游去重、隐私删除和训练问题能回到原 Unit。不可逆变化不能覆盖原文；`clean_text` 是派生字段，Raw/Parsed Text 保留受 Policy 管理。

本文建立 Decode/Unicode/Whitespace/Boundary/Language/Boilerplate 六层模型，用 CPU 机制实验展示可逆编辑脚本与语言证据融合，用 CUDA 实验运行小型字符模型数据面并诚实 skipped。最终目标是让“清洗后 Token 更多/更少”能被解释为具体规则、切片和训练价值，而不是黑箱正则堆。

### 3.2 能力目标

理解 Unicode code point、grapheme、combining mark、NFC/NFD/NFKC/NFKD、控制/格式字符、双向与混淆字符；设计按类型的 Whitespace/换行/标点策略；融合 HTML/PDF/对话结构做内容边界；区分文档、段落、Span 语言识别；校准低资源/短文本/代码混合；保存 Edit Map 与诊断。

### 3.3 工程验收

相同输入/Recipe 输出确定；规范化幂等；每个输出 Span 可映射到原输入或明确为插入；删除/替换按 reason 总账；语言模型/Unicode/规则版本固定；关键语言/内容类型切片人工 Golden 通过；无单 GPU 时真实路径输出 `skipped`。生产发布保留原视图与新 Candidate 差异。

### 3.4 边界

本文不把质量评分、去重、隐私与安全全部塞入“清洗”。语言/结构用于路由和边界，不把“不是主语言”自动等价低质量；可疑 Confusable 是安全/质量信号，不盲目改字符；具体版权/个人数据决定由相应 Policy Stage。

### 3.5 原文、规范文与训练文

Parsed Text 尽量保留解析器输出；Normalized Text 做 Unicode/换行等低风险变换；Clean View 按内容边界删除/标注模板；Training View 再按 Tokenizer/样本 Recipe 序列化。四层分别有 ID/摘要，不能只留最终字符串。

### 3.6 Edit Operation

操作类型包括 KEEP、DELETE、REPLACE、INSERT、MOVE/ASSEMBLE。每项保存 input span、output span、reason、rule/model 和 confidence。MOVE 通常用多个 KEEP Span 的输出顺序表达，避免伪造连续原位置。Edit Map 可压缩相邻同类型区间。

### 3.7 可逆性等级

字节→Unicode 若有替换不可逆；NFC 可从原文重算但无法从结果恢复具体原表示；删除模板不可逆；空白折叠丢数量。系统保存原父资产，使派生可重建；“可逆”指通过血缘而非单字符串反函数。数据卡声明变化。

### 3.8 幂等性

同一规范化函数重复应用应不再变化，测试 `f(f(x))=f(x)`；但多个 Stage 顺序可能不交换，如先 NFKC 再 Confusable 与反向不同。Recipe 固定 DAG 顺序。拼接两个已 NFC 字符串也未必仍 NFC，Assembler 后需边界处理/验证。

### 3.9 总账

输入 code point/grapheme/byte、输出、keep/delete/replace/insert 分别计数；操作 Span 覆盖输入且不重叠/有序，输出映射闭合。按 Source、语言、Unit type 和 reason 切片。清洗率突变阻止发布。

## 4. Unicode 规范化

### 4.1 四种形式

NFD 做规范分解，NFC 分解后规范组合；NFKD/NFKC 进一步兼容分解/组合。NFC 通常保留规范等价语义并让二进制表示稳定；NFKC 会折叠宽度、圈号、上标等兼容差异，可能删除重要格式语义，不能对任意文本盲用。

### 4.2 类型化策略

自然语言正文可默认评估 NFC；搜索/去重可另生成 NFKC/Casefold Key 而不替换展示/训练 Text；代码、数学、标识符和历史文本保守保留并只做安全 NFC/诊断；用户名/域名 Confusable 使用安全专用 Skeleton 作信号，不写回原文。

### 4.3 Combining Mark

组合附加符与预组合字符视觉相同但 code point 不同；NFC 统一规范等价。孤立/异常长 combining 序列可能是解析错误/攻击信号，但某些语言合法使用多个，按 script/语言与长度分布判断。删除会损语言。Grapheme 分割用于 UI/长度，不用 Python `len` 替代。

### 4.4 Compatibility 风险

NFKC 可能把罗马数字、数学字母、分数、上/下标、全半宽等折叠。对普通网页去重 Key 可能有价值，对数学公式、代码、型号、密码/标识符会错。生成并行 `comparison_key`，训练字段由规则/消融决定。记录变更类别和比例。

### 4.5 Unicode 版本

规范、Script/Category 和 Confusable 数据随 Unicode 版本发布/稳定规则演进。Recipe 记录 Unicode/运行库版本，Golden 使用官方 Normalization Test 与实验边界样本。升级新 Candidate 对齐，不能只升级 Python 镜像无差异。

### 4.6 Confusable

不同 Script 字符视觉相似可能用于投毒/欺骗；UTS #39 类 Skeleton/混合 Script 检测是风险信号。自然多语、数学与品牌可能合法混合，不能见 Cyrillic+Latin 就删除整文。按 identifier/URL/代码与自然文本分别路由安全审查。

## 5. 控制字符、格式字符与换行

### 5.1 C0/C1 控制字符

NUL、BEL、ESC 等可能来自损坏、终端控制或二进制误解，正文通常删除/隔离；TAB/LF/CR 有结构意义。策略按 Category 和 Unit type 白名单，记录 code point/位置但日志不输出终端控制。代码字符串/协议样本可能合法，保留原文并只在展示转义。

### 5.2 CRLF 与换行

规范视图可将 CRLF、CR、Unicode line/paragraph separator 映射 LF，但 Edit Map 保留原跨度。换行数量/段落边界不能一概折叠：Markdown/代码/诗歌/表格与普通段落不同。先识别 Unit type，再策略。最终序列化明确尾换行。

### 5.3 Zero Width 字符

ZWSP、ZWNJ、ZWJ、BOM/WORD JOINER 在某些语言、Emoji 和排版有意义，也可能作为混淆/绕过滤。按 Script、Grapheme 和上下文检测，不能全删。开头 BOM 作为编码标记与正文中的 U+FEFF 区分。变更生成 reason。

### 5.4 Bidi 控制

RLO/LRO/RLI/LRI/PDI 等影响显示顺序，可用于合法双向文本或隐藏代码。训练自然语言可保留并标 Bidi sequence；代码/URL/标识符出现异常控制进入安全隔离。UI 安全显示转义/指示，不把视觉顺序当存储顺序。

### 5.5 Variation Selector 与 Emoji

Emoji 变体选择、肤色、ZWJ 家庭/职业序列是 Grapheme 的一部分。删除“不可见字符”会改变 Emoji 或断开。训练是否保留 Emoji 由内容策略，不用字符清洗误删。长度/截断按 Grapheme/Token 目的分别计算。

### 5.6 Private Use/未分配

私用区可能来自字体图标、企业编码或 PDF 字体映射错误；未分配 code point 也可能未来 Unicode。统计与 Source 切片，文本质量低时 partial/隔离；不能统一映成问号并 success。若有批准映射表，版本化且保留原 span。

### 5.7 Replacement Character

U+FFFD 通常说明上游解码失败，少量可能原文本就包含。解析阶段应保存 decode diagnostic；清洗统计比例/连段，超过阈值隔离或回 Raw 重解，不用删除后掩盖。训练若保留标记需明确。按语言/Source 校准。

## 6. 空白、标点和排版

### 6.1 空白分类

ASCII space、NBSP、窄不换行空格、全角空格、Tab 与多种 Unicode Space Separator 语义不同。自然正文可将部分间隔映普通空格，法语标点、数字单位、CJK、代码和表格要保守。策略有映射表与 Unicode 版本。

### 6.2 连续空格

普通段落连续水平空白可折叠；代码、ASCII 图、诗歌、表格、Markdown 缩进、对齐数据保留。Unit type 来自解析层，低置信不强洗。折叠记录输入/输出 span。行首/尾去除也按类型。

### 6.3 连续空行

网页解析常产生多空行，普通正文可最大保留 1—2；章节/引用边界用结构 Unit 而非空行猜。代码/诗歌不改。删除多空行可改变位置与去重 Key，Edit Map/Recipe 固定。

### 6.4 标点标准化

全半角/弯直引号/破折号/省略号在不同语言有语义/风格。NFKC 或自定义映射会抹风格，训练可能需要保留。可为搜索/去重生成 punctuation_key，展示/训练原 NFC。OCR 常见标点错另做模型/规则诊断，不盲替。

### 6.5 重复标点

`!!!!!!` 可能情绪、垃圾、代码/正则；统计最长 run/比例作为质量信号，除非明确产品 Recipe 不直接折成一个。删除会改变语气/对话风格。极端上限防资源，但状态 partial。

### 6.6 引号与括号

成对检查可发现 OCR/截断，不表示不成对就删除；自然语言省略、代码/公式嵌套复杂。保持原字符和结构，提供 balance feature。自动补引号是生成新内容，需高证据/明确 insert 操作，基础清洗不做。

### 6.7 断词连字符

PDF 行尾连字符恢复依语言/词典/坐标，解析篇已讨论。清洗不再次全局删除 `-\n`，否则代码、复合词、列表损坏。使用解析器的 `line_break_hyphen_candidate` 属性与模型，低置信保留。

### 6.8 大小写

Lower/casefold 用于比较 Key 可能有价值，训练 Text 通常保留；德语、土耳其语、希腊等映射非 ASCII 简单规则，Locale/Unicode 固定。代码/实体大小写重要。Casefold Key 与原文分字段。

### 6.9 数字

全角/不同 script 数字、千分/小数、日期/单位格式不能一律 ASCII 化。语言模型需要多样表示，去重/检索 Key 可映射并保留脚本证据。混合数字是安全信号。个人/账号数字由隐私 Stage，不在规范化随意删除。

## 7. 内容边界清洗

### 7.1 结构优先

HTML DOM 区域、PDF bbox/页面类型、代码 CST、对话 Message/Part 是边界主证据。文本正则只作辅助。若前一篇已经把 nav/footer/comment/code 分 Unit，本文按 Unit type 决定保留/路由；不要把结构先拼成全文再用关键词切。

### 7.2 页眉页脚

PDF 跨页相近位置/文本模式识别，去除视图保留原 Unit 和 page/bbox。章节标题变化、页码和正文顶部反例。删除规则按 Document 多页统计，单页不套。文本重复去重不是替代，因为语义顺序仍受扰。

### 7.3 网页导航

DOM tag/role、链接密度、跨页模板、文本密度和视觉/类名信号组合；站点专项规则有 Source/时间/Golden。导航可用于站点结构/检索但正文训练视图排除。`nav` 标签不是绝对，旧网页无语义 tag。

### 7.4 Cookie/隐私弹窗

常跨站模板且高链接/按钮/政策词，但语言多样、可能正文讨论相关主题。使用 DOM overlay/form/模板指纹与站点多页证据；低置信标 `consent_banner_candidate`，不按出现“cookie”删除段落。

### 7.5 广告与推荐

DOM 区域、外链/跟踪、重复模块/位置与视觉模型；产品推荐可能正文组成。清洗视图可排除，Source/Policy 另判断。模型分类需训练/校准/版本。广告文本仍可做安全分析但不混正文。

### 7.6 评论与用户内容

评论不是垃圾，可能是对话/观点数据，但作者/权利/质量不同。分区为 comment Unit、保存 thread/reply/author 匿名关系，训练 Recipe 独立选择。不能拼到新闻正文后让模型误判事实来源。

### 7.7 引用与转载

blockquote/引号/引用标记保留引用边界，去重/来源后续处理。不要删除所有引用造成上下文断裂，也不要当作者正文。对话中的引用回复同理。清洗只标类型/序列化标记。

### 7.8 代码块

代码/日志/命令保留空白、大小写、标点与换行，语言识别按 code 而非自然语言。技术文档正文/代码关系保留。Secrets 由安全 Stage 扫描，不能基础清洗执行代码或替换字符后掩盖。

### 7.9 表格

保留 cell/row/header 结构，空白对齐不是语义主载体。训练 Text 序列化另 Recipe，复杂表低置信不硬转自然句。语言可按 cell/row 识别，数字/单位保留。页眉重复与表格 header 区别。

### 7.10 列表

保留有序/无序、item 层级与编号。删除 bullet/序号可能损步骤；重复项目符号/OCR 错误诊断。自然 Text 视图用明确换行/标记。语言识别短 item 可结合父标题/邻项。

### 7.11 签名与模板尾部

邮件/论坛签名、免责声明、版权脚注可能跨文档重复。用结构分隔、位置、多文档模板、短语和身份关系识别；法律/来源证据仍保留冷 Unit。训练正文视图可排除。关键词单点易误删正文讨论。

### 7.12 截断与拼接

文本突然结束、重复页、两文档粘连用结构/标点/语言/Source 异常信号；清洗不自动生成缺失句。可拆分有证据边界并 partial，或隔离。每输出 Document span 映原输入。对话分支不可按时间拼。
