# 隐私、安全、版权、投毒与数据退出机制

## 1. 本文要解决的工程问题

PII、恶意提示或需要退出的来源已经派生出多个数据版本。只在最新文件上删除，旧分片、缓存、索引和检查点仍然保留影响。

本文围绕一个可执行判断展开：怎样把隐私、安全、版权、投毒检测和数据退出做成可传播的控制流程？读完应能给出自己的系统边界、输入输出、版本关系和验收证据，而不是只复述工具名称或公式。

## 2. 本文交付物与判定标准

本文的核心决定是：把隐私、安全、版权、投毒和退出统一为带版本的治理事件，沿血缘冻结新消费并执行影响分析。

完成学习和实验后，应当交付一份最小可复现记录，至少包含输入快照、配置、代码版本、运行状态、原始输出和结论边界。验收证据是：故障演练能从一条治理事件定位所有直接和间接派生物，并记录删除、隔离、下架、重训或风险接受。

围绕“隐私、安全、版权、投毒与数据退出机制”的验收不接受三类替代品：把模拟输出写成真实 GPU 结果；只展示成功样本而隐藏失败与 `SKIPPED`；只给总分，不保存能复算总分的对象级记录。

## 3. 前置知识与实验边界

“隐私、安全、版权、投毒与数据退出机制”的机制实验使用 Python 3.10 及以上版本和标准库，重点验证对象、算法或状态转换。真实硬件路径使用 PyTorch；检测不到 CUDA 时必须输出结构化 `SKIPPED`，不得静默改跑 CPU 后仍标成 GPU 实测。

本文给出技术控制面和证据格式，不提供具体司法辖区的法律结论。

### 3.1 业务背景与失败模式

一条数据即使语言流畅、质量高、独特且对模型有价值，也可能因为包含个人信息、超出授权范围、携带恶意载荷、来自被投毒的供应链，或收到合法退出请求而不能用于训练。治理系统的难点不在于列出几个敏感词，而在于把用途、法域、许可、身份、权限、血缘、检测证据、人工审批、删除证明和已有模型影响组织成可执行控制面。

本文不提供针对任何司法辖区的法律意见。法律基础、例外、保留义务和版权判断应由具备资格的法律与隐私团队结合具体事实完成。工程目标是让组织能够表达并执行这些决定：每条数据为什么可用、能用于什么、谁能访问、何时失效、如何隔离、如何退出、哪些派生资产和 Checkpoint 受影响，以及如何证明动作真的完成。

应能建立 Policy Registry、Rights Record、Sensitive Finding、Poison Risk、Quarantine、Tombstone 与 Impact Graph 的核心 Schema；理解 PII 发现与身份确认的区别，理解版权许可与内容质量的边界，理解数据投毒、后门、供应链篡改和恶意文档的攻击面；完成 CPU 上的策略状态机与影响传播实验，以及通用 CUDA GPU 上的敏感实体批处理骨架，硬件不足时返回 `skipped`。

### 3.2 学习目标与能力清单

### 2.1 用途限制

允许某个用途不能自动扩展到其他用途。

数据“可以保存”不自动等于“可以用于预训练、SFT、评测或公开发布”。Rights Record 应按 purpose 表达 allowed、denied、review 和 expiry，消费方必须声明用途。新用途没有记录时失败关闭。不能把一次授权复制成永久通行证。

### 2.2 数据最小化

只处理完成目标所需字段，只给执行任务所需权限，只保留满足目的和 Policy 所需时间。日志、特征、Embedding、人工截图和教师理由都可能成为额外副本。最小化是数据模型与系统设计约束，不是发布后的清理活动。

### 2.3 可追责性

每个自动或人工决定都有主体、Policy、证据、时间、版本和审批；每个 Release 能证明输入、变换、权限和消费者。仅写“已脱敏”“合法来源”不足以审计。系统必须能回答谁批准了什么以及当时依据什么。

### 2.4 失败关闭

失败关闭针对明确的治理门禁，不是任意异常都删数据。

许可未知、Policy 服务不可用、身份冲突、敏感检测系统性失败或供应链摘要不符时，不将记录默认 accepted。根据风险进入 review、quarantine 或 failed。高可用不能用错误的数据语义交换。

### 2.5 可逆与必须不可逆

普通质量过滤可保留父资产以便回滚；合法退出或安全处置可能要求不可恢复删除。系统需区分技术可逆、政策允许恢复与法律保留义务。不能以“未来可能需要调试”为由无限复制原文，也不能在不确认义务时承诺彻底销毁。

### 3.3 实验准备与责任边界

### 3.1 Policy Registry

每条 Policy 包含 jurisdiction、purpose、data class、action、conditions、effective time、owner、legal approval、priority 和 version。规则编译成规范 IR 与 digest，运行 Worker 只读签名 Artifact。法务文本可链接但不由工程师自行解释成结论；工程 Policy 记录已批准实施逻辑。

### 3.2 Rights Record

Rights Record 描述 source/document 在具体用途上的许可、授权基础、地域、期限、署名、再分发、模型训练、派生物和退出渠道。unknown 与 denied 不同，expired 与 withdrawn 不同。记录证据引用、合同或页面版本和人工 Reviewer。来源级权利可被文档级例外覆盖，但优先级显式。

### 3.3 Data Class

分类可包括 public、internal、confidential、personal、sensitive personal、regulated、restricted benchmark 与 security quarantine。具体定义由组织和法域制定。分类影响存储、加密、日志、跨区、人工访问和保留。质量分不能降低分类级别。

### 3.4 Decision 状态

隔离是限制继续使用，不等于最终删除或已判违规。

推荐 allowed、denied、review、quarantined、withdrawn、expired、invalid 和 skipped。allowed 绑定 purpose 与截止时间，不是全局布尔；review 有 Owner 与 SLO；withdrawn 记录执行范围；skipped 只表示明确路径未运行。所有状态纳入总账。

### 3.5 Policy 优先级

强制删除、法律保留、安全隔离、许可拒绝、隐私限制、质量与采样按已批准优先级解决冲突。法律保留可能要求隔离但不删除，训练仍不可使用。冲突不能由配置文件顺序偶然决定，编译期检查并要求 Owner 签字。

## 4. 隐私发现与处置

### 4.1 PII 发现不是身份确认

正则、NER 和模型可以发现“像邮箱、电话、地址、证件号或姓名”的跨度，但不能证明它属于某个请求人，也不能判断公开事实是否可处理。Finding 保存类型、跨度、confidence、detector 和上下文级别；身份与权利请求由独立流程确认。不要把 NER 预测当法律结论。

### 4.2 精确模式

邮箱、IP、电话、账号和部分证件可用格式与校验位识别。正则必须有资源上限和语言/地区适配，避免把版本号、代码、数学式误判。原始命中不写普通日志，使用 type、hash 和受控 span。检测器版本固定。

### 4.3 模型化实体检测

姓名、地址、健康、财务与上下文身份需要 NER 或 LLM 复核。模型有语言、领域和偏见，confidence 需校准，低资源切片更保守。教师外部 API 不得接触未批准原文。输出带拒识和支持范围。

### 4.4 去标识化

删除、掩码、替换代用标记、泛化、Token 化和合成替代各有用途。仅删除直接标识符不保证匿名，准标识符组合可重识别。原文与脱敏视图分开，映射表更高权限。训练是否可用由 Policy，不因“做过脱敏”自动允许。

### 4.5 代用标记符设计

代用标记应保持类型与结构，例如 PERSON_1、EMAIL_1，避免所有实体同一 Token 导致关系丢失；同文一致、跨文是否一致由隐私需求决定。随机化 seed 与映射受控。代用标记符自身不能含原值 hash 的可逆泄漏。

### 4.6 重识别风险

评估稀有组合、外部可链接数据、长原文、地理时间和工作经历。k-anonymity 等指标只能描述特定攻击模型，不是绝对匿名证明。高风险进入合成/聚合或拒绝。风险评估版本化并定期重做。

### 4.7 日志与样本泄露

异常栈、debug payload、人工截图、模型 Prompt 和监控标签常绕过正文权限。日志默认只记 record、type、reason 与 Trace；查看原文通过受控工作台。敏感哨兵字符串测试所有 Sink。事故按安全流程处理历史副本。

## 5. 版权、许可与来源治理

### 5.1 版权问题不能压成质量分

内容原创、准确或教育性高，不说明训练、复制、再分发或商业使用获得许可。Rights Record 单独表达来源与用途。法律解释随法域、事实和时间变化，应由专业团队评估；工程系统只执行版本化结论并保留证据。

### 5.2 Source Registry

来源记录站点/仓库/供应商、抓取方式、条款快照、robots 或访问条件、许可证、地域、Owner、有效时间和退出渠道。域名级默认可被路径/文件级覆盖。未知条款不默认允许。来源所有权变化触发 Review。

### 5.3 许可证解析

代码与文档许可证名称、版本、例外、NOTICE、署名、传染性和再分发义务结构化。SPDX 类标识有助规范，但文件实际文本和仓库关系仍需验证。多个许可证冲突进入 review。自动检测不替代法律批准。

### 5.4 许可随血缘传播

解析、清洗、去重、Embedding、标签、训练 Manifest 和发布包继承 Rights 引用。派生物是否受相同义务由 Policy 决定，但系统必须能追踪来源。合并多个文档时采用最严格或明确组合规则，不能丢掉父许可。

### 5.5 署名与 NOTICE

若使用条件要求署名或 NOTICE，训练数据和产品发布流程需生成完整清单、去重但不遗漏。代表选择不能导致唯一许可证据丢失。NOTICE Artifact 绑定 Release，消费者知道如何履行。无法履行时拒绝用途。

### 5.6 版权退出

提供可验证请求渠道，记录作品、权利主张、范围、身份、决定和执行。复杂争议进入法务 review，工程不自行判断。批准退出后沿影响图处理父与派生、阻断未来摄取，并评估已有模型。状态与证明不可篡改。

## 6. 安全与投毒威胁模型

### 6.1 攻击者目标

投毒可降低总体能力、植入触发后门、偏置特定实体、操纵评测、窃取秘密或让训练系统耗尽资源。目标不同，检测信号与处置不同。威胁模型写攻击能力、知识、入口、预算和成功条件。NIST 等对抗机器学习分类可作为统一术语参考，具体控制仍需本地风险评估。

### 6.2 供应链入口

来源网页、开放仓库、供应商包、数据标注、模型教师、Tokenizer、规则配置、容器与对象存储都可能被篡改。只扫描正文不够。Artifact 摘要、签名、SBOM、最小权限、审批和不可变 Manifest 形成纵深防御。

### 6.3 后门样本

攻击者在少量样本中关联触发词与目标行为，文本可表面高质量。检测包括异常触发频率、标签/响应一致、来源集中、Embedding 小簇、梯度或模型行为探针。任何单一方法召回有限，需红队与 Canary。高风险来源隔离。

### 6.4 数据可用性攻击

超长组合字符、灾难正则、压缩炸弹、嵌套结构、巨大行与重复候选可拖垮管道。解析前检查字节/压缩比，阶段有字符、Token、时间、内存和边数预算。超限记录 quarantine，不能部分处理后标正常。

### 6.5 提示注入与文档指令

用于 RAG 或 Agent 训练的文本可能包含“忽略规则”“上传秘密”等指令。预训练数据中的指令不必自动恶意，但进入工具轨迹或教师标注时会影响系统。将内容与控制通道隔离，教师 Prompt 明确不执行文档命令，工具访问最小权限。

### 6.6 评测操纵

攻击者可向训练源注入基准答案或针对公开评测优化模板，制造虚高。Benchmark Registry、多层去污染、来源异常和新鲜评测共同缓解。命中不应只从训练移除，还需追踪生成配方与已有 Checkpoint。

### 6.7 检测器投毒

PII、质量或安全分类器本身可被恶意标签、权重或配置影响。训练集血缘、group split、独立 Gold、Artifact 签名和启动 Canary 必需。Detector 升级做状态迁移和关键切片。无法验证的模型不进入强 Policy。

## 7. Quarantine 与事件处置

### 7.1 隔离不是删除

quarantine 表示当前不能进入普通消费，需要受限保存用于分析、法务或安全。它有原因、风险、Owner、访问、保留期和处置 SLO。没有消费路径的隔离会无限膨胀。到期动作由 Policy，不自动放行或删除。

### 7.2 证据封存

事件样本、原字节、摘要、时间、来源、检测器、环境和操作日志以只读证据包保存，访问审计。隐私最小化与法律保留可能冲突，由批准 Policy 决定。普通工程日志不充当法证存储。

### 7.3 爆炸半径

给定 source、record、detector、Policy、Artifact 或时间窗口，Impact Graph 列出派生数据、Selection、训练运行、Checkpoint、评测和发布模型。范围基于不可变标识，不靠全文搜索。事件优先停止扩散，再深入分析。

### 7.4 恢复策略

恢复使用要发布有证据的新状态，不能悄悄抹掉事件历史。

从可信父资产与已验证 Artifact 重建，修复消费者和 Cache，验证权限、总账、敏感/安全 Gold 与训练 Reader。若父资产本身不可信，寻找替代来源而非清洗掩盖。恢复证据与事故证据并存。

## 8. 数据退出与删除证明

![数据退出与删除证明](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l13_02.png)

### 8.1 请求入口

模型影响需要单独评估，删除数据不自动逆转已学习信息。

请求需要可访问渠道、case_id、范围、主体/权利验证、法域、理由、接收时间和 SLA。不要在普通聊天或工单复制更多敏感原文。请求人身份数据独立高权限保存。工程只接收最小化目标标识。

### 8.2 Identity Resolution

把请求映射到 source/document/record 不是简单邮箱搜索。需要验证别名、页面、账户、内容所有权和误伤风险。模糊匹配只生成 candidate，由授权人员确认。错误删除他人数据同样是事故。

### 8.3 Tombstone

批准退出生成不可变 Tombstone，包含目标逻辑 ID、适用范围、原因、effective time、Policy 和 case 引用。所有摄取、重算、Cache 和训练选择在读取时检查。Tombstone 不是把正文再复制一遍，最小标识也受保护。

### 8.4 派生传播

从父记录找到清洗视图、特征、Embedding、重复组、标签、合成派生、训练 Manifest 和 Checkpoint。直接派生可删除/隔离，聚合统计与模型如何处置由 Policy 和法律决定。系统输出影响清单与完成/例外状态。

### 8.5 物理与逻辑删除

逻辑墓碑能立即阻止访问，物理删除按对象存储、备份、索引和保留周期完成。二者时间与保证不同。删除证明列每层状态、时间、执行器、验证和允许例外。不能在尚未清理备份时宣称立即物理消失。
