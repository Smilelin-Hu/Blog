# DPO、IPO、KTO、ORPO、SimPO 与离线偏好系统

## 1. 本文要解决的工程问题

团队把同一份偏好数据依次喂给 DPO、KTO、ORPO 和 SimPO，只比较最后总分，却没有检查每种方法需要的数据形态、参考策略和长度归一。

本文围绕一个可执行判断展开：怎样依据数据形态和参考策略选择 DPO、IPO、KTO、ORPO 或 SimPO？读完应能给出自己的系统边界、输入输出、版本关系和验收证据，而不是只复述工具名称或公式。

## 2. 本文交付物与判定标准

本文的核心决定是：从标签形态、参考模型、隐式奖励、长度偏差与计算预算选择离线偏好目标，并保持可比训练合同。

完成学习和实验后，应当交付一份最小可复现记录，至少包含输入快照、配置、代码版本、运行状态、原始输出和结论边界。验收证据是：候选方法共享数据切片、起始策略和评测预算，报告目标函数、参考策略、有效样本与主要超参数。

围绕“DPO、IPO、KTO、ORPO、SimPO 与离线偏好系统”的验收不接受三类替代品：把模拟输出写成真实 GPU 结果；只展示成功样本而隐藏失败与 `SKIPPED`；只给总分，不保存能复算总分的对象级记录。

## 3. 前置知识与实验边界

“DPO、IPO、KTO、ORPO、SimPO 与离线偏好系统”的机制实验使用 Python 3.10 及以上版本和标准库，重点验证对象、算法或状态转换。真实硬件路径使用 PyTorch；检测不到 CUDA 时必须输出结构化 `SKIPPED`，不得静默改跑 CPU 后仍标成 GPU 实测。

离线偏好优化依赖收集数据的覆盖范围，无法凭目标函数消除数据缺失。

### 3.1 业务背景与失败模式

### 1.1 从 SFT 的局限开始

SFT 把目标回答当作唯一正确序列，最小化逐 Token 负对数似然。它可以教会格式、任务和基本行为，却没有直接表达“回答甲比回答乙更好多少”。当两个回答都合理、差异集中在事实、约束遵循或冗余程度时，只训练 chosen 会丢失 rejected 携带的决策边界。离线偏好优化同时观察两者，通过相对概率改变决策边界，并尽量避免无约束地远离已有模型。

设 Prompt 为 $x$，偏好回答为 $y_w$，非偏好回答为 $y_l$，当前策略为 $\pi_\theta$，参考策略为 $\pi_{ref}$。一个偏好样本不是两个独立文本，而是一条有方向的关系：在给定评审标准和上下文时，$y_w \succ y_l$。数据层必须保存 Pair 来源、选择机制、标注置信、平局、策略版本和长度，否则训练者无法知道这条关系适用于什么分布。

### 1.2 序列对数概率与长度

两者改变优化目标，不能当作纯数值技巧随意替换。

因果语言模型给回答的序列对数概率为：

$$\log \pi_\theta(y|x)=\sum_{t=1}^{|y|}\log \pi_\theta(y_t|x,y_{\lt t})$$

求和会天然随长度变得更负，因此算法对总和、均值和显式长度项的选择会改变行为。使用 Token 均值并不天然正确：它可能奖励长回答中大量容易 Token，也可能削弱关键少数 Token 的影响。应将长度定义为实验维度，报告 chosen 与 rejected 长度差、Loss 对长度的梯度相关、生成长度分布和长度匹配切片，而不是把一种归一化当成普适答案。

### 1.3 参考策略的作用

参考策略通常是 SFT 检查点的冻结副本。它为每个回答提供基线概率，使训练信号关注当前策略相对基线的变化：

$$r_\theta(x,y)=\beta\left(\log\pi_\theta(y|x)-\log\pi_{ref}(y|x)\right)$$

这里 $\beta$ 控制相对概率变化映射到隐式奖励的尺度。参考模型不是普通初始化；它参与 Loss 语义。只要参考权重、Tokenizer、模板、截断或特殊 Token 不同，隐式奖励就改变。因此数据卡必须绑定 reference revision 和输入规范，恢复训练时也要验证它们的摘要。

### 1.4 离线的含义

离线表示训练期间不向当前策略重新采样并获取新偏好，数据由一个或多个行为策略预先产生。优势是流程简单、成本可控、容易重放；局限是覆盖范围固定。随着 $\pi_\theta$ 变化，训练分布之外的回答可能越来越多，原有 Pair 不再约束这些区域。离线算法不能从未见动作中凭空推断人类偏好，它只是利用模型先验和有限比较做泛化。

### 1.5 优化、泛化与因果的边界

Loss 下降说明模型更符合训练目标，Pair 准确率上升说明在给定集合中偏好 Margin 方向更正确，都不能单独证明真实用户满意、安全或事实性提升。Pair 本身可能由长度、格式、模型家族等混杂因素决定。一个完整声明必须区分：数据关系是什么、算法把哪种统计关系写入模型、离线评测观察到什么、线上实验又观察到什么。不要把相关偏好包装成对模型能力的因果证明。

### 1.6 偏好系统的三个控制面

第一是数据控制面，负责 Pair Schema、生成策略、标注、清洗、切片、去重和版本。第二是训练控制面，负责策略、参考模型、Loss、优化器、分布式、检查点和可恢复性。第三是评测发布控制面，负责离线能力、安全、长度、校准、服务基准、Canary 和回滚。算法只占训练控制面的一部分，三者的版本必须能在一次 Run 中被唯一解析。

### 3.2 学习目标与能力清单

### 2.1 从 KL 约束奖励最大化出发

经典目标希望策略获得高奖励，同时不离参考策略过远：

$$\max_\pi\;\mathbb{E}_{x,y\sim\pi}[r(x,y)]-\beta D_{KL}(\pi(\cdot|x)\|\pi_{ref}(\cdot|x))$$

对固定 Prompt，最优策略满足：

$$\pi^*(y|x)=\frac{1}{Z(x)}\pi_{ref}(y|x)\exp\left(\frac{r(x,y)}{\beta}\right)$$

反解得到奖励等于当前与参考策略对数概率之差乘以 $\beta$，外加只依赖 Prompt 的归一化常数。将两个回答作差时，常数消失，因此无需显式训练 Reward Model 也能拟合 Bradley–Terry 偏好概率。

### 2.2 DPO Loss

定义策略相对参考的 Pair Margin：

$$\Delta_\theta=\left[\log\pi_\theta(y_w|x)-\log\pi_\theta(y_l|x)\right]- \left[\log\pi_{ref}(y_w|x)-\log\pi_{ref}(y_l|x)\right]$$

DPO 最小化：

$$\mathcal{L}_{DPO}=-\log\sigma(\beta\Delta_\theta)$$

当当前策略相对参考更偏向 chosen 时，$\Delta_\theta$ 为正，Loss 下降；若方向相反，梯度推动 chosen 概率相对上升、rejected 相对下降。注意它约束的是相对变化，不保证 chosen 绝对概率一定上升。两端概率都下降、但 rejected 下降更多时，Pair Loss 也可能改善，这正是需要单独监控 chosen NLL 的原因。

### 2.3 梯度直觉

对 Margin 求导可得：

$$\frac{\partial \mathcal{L}}{\partial \Delta_\theta}=-\beta\sigma(-\beta\Delta_\theta)$$

错误或低 Margin 样本梯度大，已被正确分开的样本梯度逐渐饱和。$\beta$ 同时影响输入尺度和梯度幅度；在不同实现里它的直觉容易被口头简化。工程上不要仅凭“更保守”或“更激进”选值，而要扫参并观测隐式奖励 Margin、参考 KL 代理、chosen/rejected NLL、生成长度、熵和任务指标。

### 2.4 Reference-free 并不等于没有基线

有些实现通过预计算参考 log-prob 节省显存，有些配置称为 reference-free 并省略显式参考项。前者语义仍然依赖固定参考，只是把推理移出训练 Step；后者改变了目标，基线退化为隐式常量或其他正则。发布文档必须区分“参考分数已缓存”“参考模型与策略共享部分权重”“Loss 真的没有参考项”，否则同名实验无法比较。

### 2.5 DPO 的数据要求

两者相减后进入目标，省掉参考项就不再是标准 DPO。

同一 Pair 必须使用同一 Prompt 语义、相同可见工具状态和相同评判标准。若 chosen 拥有额外检索结果而 rejected 没有，模型可能学会上下文痕迹。Pair 最好保留原始生成概率、采样温度和策略版本，以便识别行为策略偏差。平局不应随机打方向；可丢弃、软标或进入专门目标。重复 Prompt 要按组切分，避免候选近重复泄漏到验证集。

### 2.6 DPO 常见失败

第一类是长度爆炸，模型通过冗长提高相对概率或利用数据偏差。第二类是 chosen 似然下降，训练通过更强压低 rejected 获胜，造成整体语言质量退化。第三类是参考不一致，缓存 log-prob 由错误模板或旧 Tokenizer 计算。第四类是过拟合单一 Judge 风格。第五类是 Pair 噪声在大训练轮数下被记忆。诊断必须把 Loss 拆成 chosen reward、rejected reward、Margin、准确率和长度相关，而不是只看一条总 Loss 曲线。

### 2.7 DPO 适用边界

当有高质量 Pair、参考策略明确、希望用相对简单的监督式训练替代在线 RL 时，DPO 是强基线。它不自动解决数据覆盖、在线探索、可验证长轨迹信用分配和安全硬约束。对于工具环境，若 Pair 只比较最终文本而忽略真实状态，模型可能学到漂亮解释而非成功行为。算法选型必须从可获得的监督单位出发。

### 3.3 实验准备与责任边界

### 3.1 DPO 饱和背后的问题

当偏好数据近乎完全可分时，逻辑回归式目标倾向持续增大 Margin；有限数据、标签噪声和模型容量下，这可能放大过拟合。即使梯度逐渐变小，继续训练仍可能让策略远离合理区域。IPO 从偏好目标的理论分析出发，将优化改成围绕有限目标 Margin 的平方误差，从而显式规定“分开到什么程度算够”。

### 3.2 IPO 的典型形式

使用与 DPO 相同的对数比差，可写出一种常见 IPO 目标：

$$\mathcal{L}_{IPO}=\left(\Delta_\theta-\frac{1}{2\tau}\right)^2$$

不同库可能用 $\beta$ 或 $\tau$ 并采用不同常数，因此不能只比较参数名字。核心含义是把 Margin 拉向有限靶值，而不是无限推大。实现审计要从实际公式、序列聚合和默认缩放读取语义，配置迁移时用一组固定 log-prob 做数值对拍。

### 3.3 有限 Margin 的工程直觉

当 Margin 低于目标，梯度增加 chosen 相对优势；超过目标后，梯度会反向拉回。这能抑制容易样本被无限强化，也可能在目标设得不当时压制真正强偏好。应在噪声率、偏好强度和任务切片上扫目标 Margin，观察泛化而不是训练准确率。若标注含强弱等级，可考虑样本级目标或权重，而不是所有 Pair 使用一个绝对目标。

### 3.4 IPO 与标签噪声

噪声处理先保留来源证据，再决定权重或复核。

有限目标通常对可分数据过拟合更温和，但它不是噪声清洗器。系统性偏差、颠倒标签、模板捷径仍会被学习。训练前要估计标注者一致性、Pair 难度和反事实鲁棒性；训练中比较高置信与低置信切片；训练后用独立来源验证。算法正则只能调整放大程度，不能把错误关系变成正确关系。

### 3.5 选择 IPO 时要问什么

首先确认当前 DPO 是否确有 Margin 持续增大、验证收益回落或 KL 代理失控，而不是优化器、数据重复或参考缓存错误。其次确认实现的 IPO 公式和长度归一化。再次用相同数据、Token 预算和评测协议比较，避免把更多训练或不同 Batch 误当算法收益。最后检查生成行为：有限 Margin 改善了稳健性，还是只是让模型更接近 SFT 基线。

## 4. KTO：从成对偏好转向单样本好坏反馈

### 4.1 为什么需要 Unpaired 反馈

真实产品更容易获得点赞、点踩、接受、重试或投诉等单样本反馈，而不总能为同一 Prompt 准备严格成对候选。KTO 允许每条样本带 desirable 或 undesirable 标签，以当前策略相对参考的对数比和一个 KL 基线构造价值信号。它降低 Pair 采集门槛，却增加了反事实不可观测问题：看到某回答被点赞，并不知道同条件下另一回答会怎样。

### 4.2 KTO 的价值中心

令 $z(x,y)=\log\pi_\theta(y|x)-\log\pi_{ref}(y|x)$，再用批次或分布估计的 KL 项作为参考中心。对正样本希望 $z$ 高于中心，对负样本希望低于中心，并用不同权重处理正负类别。其直觉与前景理论中的参考点有关：人对收益和损失的反应可能不对称。实现细节在不同库中会变化，必须检查 KL 估计是否跨设备聚合、是否停止梯度以及类别权重如何归一。

### 4.3 单样本反馈的选择偏差

用户只会评价被系统展示的回答，展示策略、位置、延迟、用户群和界面都会影响标签。点踩样本可能集中在高风险流量，点赞可能来自更容易任务。数据至少保存曝光概率、策略版本、路由、用户上下文桶和交互结果；条件允许时做随机化或倾向修正。否则 KTO 学到的可能是产品路由和用户群差异，而非回答质量。

### 4.4 正负比例与权重

大量点赞加少量点踩不表示世界上好回答更多，可能只是反馈机制不对称。训练 Batch 若照原比例采样，负类梯度会被淹没；若简单五五采样，又改变了目标分布。应显式定义采样分布与 Loss 权重，分别报告正样本价值、负样本价值、各切片接受率和校准。权重是产品代价函数的一部分，要版本化并参与评审。

### 4.5 KTO 适用与不适用场景

不同目标对标签结构的需求不同，不能仅按算法名换配置。

适合反馈天然非配对、样本量大且有可靠曝光日志的产品闭环；也可把已配对数据拆成正负样本作为基线。不适合把含义不明的点击直接当质量标签，也不适合需要精细比较近邻答案的任务。若可以低成本构造成对候选，Pair 能消除部分 Prompt 难度差异；若不能，KTO 提供可用路径，但必须投入更多因果与偏差控制。

## 5. ORPO：把 SFT 与偏好比值放在同一目标中

### 5.1 为什么希望不保留参考模型

DPO 通常从 SFT 检查点继续并需要参考 log-prob。ORPO 把 chosen 的监督似然与 chosen 相对 rejected 的优势比目标组合，希望在单阶段中既学习目标回答又拉开偏好，不依赖独立参考模型。它可减少一次流水线和参考推理成本，但“无参考”不代表无正则；SFT 项和目标形式共同约束策略。

### 5.2 Odds Ratio 直觉

对一个回答的概率 $p$，odds 为 $p/(1-p)$。序列概率极小，实际实现通常在对数空间并基于平均 Token 对数概率构造稳定形式。ORPO 希望 chosen 的 odds 相对 rejected 更高，同时保留 chosen 负对数似然：

$$\mathcal{L}_{ORPO}=\mathcal{L}_{SFT}(y_w)+\lambda\mathcal{L}_{OR}(y_w,y_l)$$

具体 odds 的计算、序列归一化和数值截断必须以所用实现为准。评审不能只抄论文公式，还要对真实代码输入做单元测试。

### 5.3 SFT 项带来的行为

显式 chosen NLL 能避免训练只靠压低 rejected 取胜，通常也让格式和语言建模更稳定。但如果 chosen 本身质量不高，它会被更直接地模仿；如果偏好数据只表达相对好坏，chosen 未必达到可作为教师答案的水平。数据验收因此要分别判断“比另一个好”和“值得监督学习”。不满足绝对质量门槛的 Pair 可用于纯相对目标，却不一定适合 ORPO 的 SFT 项。

### 5.4 单阶段并不自动降低总成本

省去显式 SFT 后 DPO 两阶段，可能减少检查点和参考推理；但若偏好数据规模小、格式覆盖不足，仍需要独立 SFT 初始化。不同目标混合也可能需要更多扫参和更严格的数据筛选。成本比较应包含数据准备、训练 Token、参考预计算、显存、调参次数和回归风险，而不是只计算一次 Step 的 FLOPs。

### 5.5 ORPO 的诊断

分别记录 SFT Loss、偏好 Loss、chosen/rejected 长度、序列 log-prob、Margin 和生成质量。若总 Loss 下降但偏好 Margin 不升，可能是 SFT 项主导；若 Margin 猛增而 chosen NLL 恶化，检查实现或权重；若输出长度变化，确认序列平均和模板。用与 DPO 相同的 Pair 切片、Token 预算和评测，使比较落在算法而非实验条件上。

## 6. SimPO：参考模型自由与目标 Margin

### 6.1 SimPO 的出发点

SimPO 直接使用策略对 chosen 和 rejected 的平均 Token 对数概率之差作为隐式奖励，并引入目标 Margin，不需要冻结参考模型。平均 Token 概率与生成时的长度归一评分更接近，可降低参考前向和缓存开销。典型形式可写为：

$$\mathcal{L}_{SimPO}=-\log\sigma\left(\beta\left[ \frac{\log\pi_\theta(y_w|x)}{|y_w|}- \frac{\log\pi_\theta(y_l|x)}{|y_l|} \right]-\gamma\right)$$

这里 $\gamma$ 要求 chosen 相对 rejected 超过一个目标间隔。不同实现可能把 $\gamma$ 写成 $\gamma/\beta$，阅读配置时必须还原到括号内的真实数值。

### 6.2 平均 Token 概率的收益与风险

总和强烈受序列长度影响，平均可以让不同长度 Pair 更可比。但平均也会把一个关键低概率错误摊薄到很多普通 Token 中，且生成终止 Token 的处理会影响结果。应明确是否包含 EOS、是否对 Prompt Mask、截断后长度如何计算，并在短回答、长回答、长度相当和长度反转切片上分别评估。任何长度归一都只是建模选择，不是消除长度偏差的证明。

### 6.3 目标 Margin 的意义

没有 Margin 时，只要 chosen 平均 log-prob 略高于 rejected 就可逐渐降低 Loss；引入 $\gamma$ 要求更明确的区分。过小可能学习不足，过大可能持续挤压 rejected 并损害多样性。参数不能脱离 $\beta$ 和 log-prob 尺度讨论。扫参时画实际 Margin 分布、满足率、梯度集中度和任务收益，避免只按训练 Loss 选择。

### 6.4 无参考模型的系统收益

训练时少一套权重或少一份预计算 log-prob，可显著降低显存、存储和流水线复杂度；检查点也不必绑定独立 reference artifact。但可复现性仍需绑定初始化模型，因为所有相对学习从该点开始。没有显式 KL 锚点后，要更认真监控与初始化策略的分布差异、通用能力回归和生成熵。
