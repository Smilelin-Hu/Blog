# 可版本化、可追责的数据湖与血缘控制面

![可版本化数据湖与血缘控制面](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l32_01.png)

## 1. 项目目标与验收问题

项目要构建一个面向 AI 训练的数据资产控制面，使团队可以从任意 Checkpoint 反向回答：它消费了哪些 Release、这些 Release 来自哪些源、经过哪个 Recipe、由谁批准、有哪些删除或风险事件；也可以从任意源数据正向回答：它进入了哪些 Sample、Shard、Run、Checkpoint 和 Serving Candidate。

这里的数据湖不是对象存储目录，血缘也不是文档里画的 DAG。系统必须把资产身份、不可变 Manifest、版本谱系、运行提交、删除传播和证据查询落成可测试协议。CPU 实验验证图与内容寻址；真实路径可以对接 S3 兼容存储、PostgreSQL 和 OpenLineage 兼容事件。依赖缺失时返回 `skipped`，不声称完成外部系统实测。

## 2. 资产模型

核心实体分为 Source、Asset、Recipe、Run、Release、Training Run、Checkpoint、Evaluation 和 Deployment。Source 描述外部来源及其治理合同；Asset 是内容寻址的不可变物理或逻辑数据；Recipe 是算子 DAG 与全部参数；Run 是一次物理执行；Release 是通过门禁的可消费资产；Checkpoint 绑定训练状态与消费清单；Deployment 绑定服务版本和评测证据。

身份分三层。业务身份表达“这是哪个逻辑对象”，版本身份表达“这是该对象的哪个不可变版本”，物理位置只是可替换副本。`asset_version_id` 由 Schema、内容 Manifest、Recipe 和上游版本的规范序列化计算。不能把 `s3://bucket/latest/part-1` 当作版本，因为对象可覆盖、路径可迁移、`latest` 会变化。

边类型包括 `DERIVED_FROM`、`FILTERED_BY`、`TOKENIZED_WITH`、`PACKED_INTO`、`CONSUMED_BY`、`CHECKPOINT_OF`、`EVALUATED_BY`、`DEPLOYED_AS` 和 `SUPERSEDES`。每条边保存产生它的 Run、事件时间、控制面接收时间和合同版本。删除与事故查询依赖边语义，不能只保存无类型父子关系。

## 3. 架构与职责

对象存储保存不可变 Payload、Manifest、统计和证据；元数据数据库保存身份、版本、状态、边与查询索引；事件总线接收阶段提交与训练消费事件；注册服务验证 Schema、哈希、权限和状态机；血缘投影器把事件构造成可查询图；策略引擎执行发布、撤回、保留与多租户规则；审计服务生成时间点快照和影响报告。

服务持有稳定引用，字节不随目录别名变化。

写路径采用“先 Payload、后 Manifest、再注册”的协议。Writer 把分片写到临时前缀并计算哈希，生成引用全部分片的 Manifest，注册服务检查对象存在和哈希后事务性创建 Asset Version，最后写只读就绪标记。消费者只接受注册表状态为 Ready 且 Manifest 哈希匹配的版本。半上传目录、孤立对象和失败 Attempt 由垃圾回收按租约处理。

读路径先解析逻辑 Release 到不可变版本，创建 Consumption Lease 并返回签名 Manifest。训练启动后把实际读取分片、游标和有效 Token 写入消费清单；Checkpoint 提交引用清单哈希。这样“配置计划使用什么”与“训练实际消费什么”可以区分。

## 5. 状态机与提交协议

Asset Version 状态为 Proposed、Verifying、Ready、Quarantined、Withdrawn 和 Deleted。Ready 之后 Payload 不可修改；修复产生新版本并用 `SUPERSEDES` 连接。Withdrawn 立即阻止新租约但保留审计证据；Deleted 只在保留期、治理和引用条件允许后清理物理 Payload。

Run 状态为 Created、Running、Committing、Succeeded、Failed 和 Abandoned。每个 Stage 有逻辑 ID 和 Attempt ID，提交使用比较并交换：只有输入版本、Recipe 版本与预期状态匹配的 Attempt 能成为赢家。重复事件以 `event_id` 去重，投影器游标可恢复，图可由不可变事件重建。

Checkpoint 提交把模型分片、优化器、调度器、随机状态、数据游标、代码、容器、硬件拓扑、训练配置、消费清单和父 Checkpoint 放入 Manifest。只有全部对象哈希验证成功，Checkpoint 才进入 Ready。训练注册表不得在模型文件仍上传时把 `latest` 指向候选。


第一条命令读取固定反例并输出机制检查。第二条只运行单进程 CUDA 基础探针，不是本文完整数据平台或训练算法；没有 CUDA 时输出 `skipped`。通过探针不能证明 DDP、模型质量、集群吞吐或端到端恢复。真实系统扩展需要另外实现正文所列模块，并在自己的模型、数据和硬件上验收。

完整入口脚本保存在实验包同名文件中；阅读时从入口追到共享机制函数，再对照 fixture 与结果检查项。

回溯与撤回传播方向相反，使用相同血缘证据。

```python
import hashlib
import json
from collections import defaultdict, deque

def canonical_hash(value):
    payload = json.dumps(value, ensure_ascii=False, sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(payload.encode()).hexdigest()

class Catalog:
    def __init__(self):
        self.assets = {}
        self.forward = defaultdict(set)
        self.reverse = defaultdict(set)

    def register(self, kind, manifest, parents=()):
        version = canonical_hash({"kind": kind, "manifest": manifest, "parents": sorted(parents)})
        self.assets.setdefault(version, {"kind": kind, "manifest": manifest, "status": "ready"})
        for parent in parents:
            self.forward[parent].add(version)
            self.reverse[version].add(parent)
        return version

    def descendants(self, root):
        seen, queue = set(), deque([root])
        while queue:
            node = queue.popleft()
            for child in self.forward[node]:
                if child not in seen:
                    seen.add(child)
                    queue.append(child)
        return sorted(seen)

    def withdraw(self, root):
        affected = [root] + self.descendants(root)
        for item in affected:
            self.assets[item]["status"] = "withdrawn"
        return affected

catalog = Catalog()
source = catalog.register("source", {"uri": "fixture://source-a", "sha256": "abc"})
document = catalog.register("document", {"recipe": "parse-v1"}, [source])
release = catalog.register("release", {"recipe": "filter-v3", "tokens": 1200}, [document])
checkpoint = catalog.register("checkpoint", {"step": 100, "consumption": [release]}, [release])

assert checkpoint in catalog.descendants(source)
impact = catalog.withdraw(source)
assert catalog.assets[checkpoint]["status"] == "withdrawn"
print(json.dumps({"source": source, "checkpoint": checkpoint, "impact": impact}, indent=2))
```

实验应重复注册同一对象，确认版本身份不变；改变 Recipe 后身份改变；从 Source 能遍历到 Checkpoint；撤回不会删除证据，而是改变可消费状态并生成影响集合。生产系统还需处理亿级边、时间点查询、权限和图投影延迟。

## 7. 真实后端路径

故障注入应覆盖每个相邻步骤的间隙。

真实路径使用对象存储保留策略、关系数据库事务和事件系统。启动前执行依赖探测：

```python
import json
import os
import socket

checks = {
    "object_store_endpoint": bool(os.environ.get("OBJECT_STORE_ENDPOINT")),
    "database_dsn": bool(os.environ.get("LINEAGE_DATABASE_DSN")),
    "event_endpoint": bool(os.environ.get("LINEAGE_EVENT_ENDPOINT")),
}
for key, port in [("database_reachable", 5432), ("object_store_reachable", 9000)]:
    host = os.environ.get(key.upper().replace("_REACHABLE", "_HOST"))
    if not host:
        checks[key] = False
        continue
    try:
        with socket.create_connection((host, port), timeout=1):
            checks[key] = True
    except OSError:
        checks[key] = False

status = "ready" if all(checks.values()) else "skipped"
print(json.dumps({"status": status, "reason": None if status == "ready" else "external_backends_unavailable", "checks": checks}))
```

真实验证先上传两个小分片，故意在 Manifest 注册前中断，确认消费者不可见且垃圾回收可清理。随后完成注册、建立 Release、启动一个只读训练模拟、提交 Checkpoint，再重放事件重建空投影库。最后撤回一个 Source，验证新租约阻断、现有租约策略、影响图和审计导出。

## 8. 血缘覆盖与查询

血缘覆盖率不以“图里有边”为分子，而以必须追踪的业务转换为全集。对每个 Stage 检查输入版本、输出版本、Recipe、Run、代码和决策证据；对训练检查计划 Release、实际清单、游标与 Checkpoint；对发布检查评测、审批、Candidate 和 Serving 版本。

必须支持四类查询：给定 Checkpoint 反查全部 Source；给定 Source 正查全部 Release 与 Checkpoint；给定 Recipe 比较两个版本的影响；给定时间点重建当时可消费版本。查询结果附图快照版本和不完整警告，投影延迟时不能把“没查到”解释为“没有影响”。

## 9. 撤回传播与模型影响

派生检查点需要另外评估，不自动完成遗忘。

撤回请求先经过身份、范围、法律依据和审批验证，生成不可变 Tombstone。策略引擎对匹配 Source 与 Document 标记 Withdrawn，阻断未来 Release 和训练租约；影响服务沿血缘列出分片、训练 Run、Checkpoint、评测和部署。结果按直接包含、重复代表依赖、派生合成和未知影响分类。

模型层动作不是控制面自动删除文件这么简单。组织可依据风险选择停止部署、回滚 Candidate、重新训练、执行遗忘评估或记录例外。系统要提供证据与执行钩子，但不虚构“删除训练行就已经从模型中消失”。

## 10. 指标与验收阈值

关键指标包括资产注册成功率、Manifest 哈希失败、孤立对象数量、事件投影延迟、重复事件阻断、血缘覆盖率、Checkpoint 消费清单覆盖、时间点查询正确率、撤回传播延迟、受影响资产召回率、权限拒绝、备份恢复点和审计导出时间。

确定性只在约定算法与环境边界内成立。

验收 Golden Graph 预先定义来源到 Checkpoint 的全部路径，注册后查询召回必须完整且无跨租户泄漏。随机删除投影库后从事件重建，资产身份、状态和边集合与原库一致。并发提交两个 Attempt 只有一个成功。对象被篡改后读取验证失败。撤回后新训练无法获取租约，影响报告包含目标 Checkpoint。

## 11. 故障注入与排障

在 Payload 上传中、Manifest 写入后、数据库提交前后、事件发送前后、Projector 落库前后和 Checkpoint 切换前后分别杀死进程。每次检查是否出现 Ready 但缺对象、重复边、丢事件、悬空 `latest` 或跨租户可见。网络分区时宁可停止发布，也不能让两个控制器同时批准冲突版本。

查询漏边时，先核对生产事件、总线偏移、死信、Schema 兼容和投影游标，再检查查询方向；不要直接人工补数据库边，因为事件重建会再次丢失。对象哈希失败时立即隔离版本和下游消费，保留副本与访问日志，定位写后篡改、错误 Multipart 或 Manifest 串线。

## 12. 演示与最终交付

演示创建 Source、运行解析 Recipe、发布 Release、模拟训练消费并提交 Checkpoint，然后从 Checkpoint 一键导出来源和配方。接着升级 Recipe 展示不可变谱系，删除投影库并重建，最后提交 Tombstone 展示阻断和模型影响报告。演示要包含一次故障，而不只是顺利路径。

最终交付包括 Schema、API 合同、数据库迁移、部署配置、事件重放工具、Golden Graph、故障矩阵、备份恢复手册、权限矩阵、指标面板、撤回 Runbook 和限制清单。最重要的验收句是：任意训练结果都能由不可变证据解释，任意风险源都能在规定时间内定位影响，而系统不会用覆盖历史换取表面整洁。

## 13. 生产评审十二问

### 13.1 路径与身份是否分离

对象集合和顺序都应由 Manifest 明确。

移动对象、增加副本或切换存储后端不应改变 Asset Version。评审把同一 Payload 复制到新位置，注册表应解析为同一内容身份并记录新 Replica；若版本由 Bucket 路径生成，迁移会破坏全部血缘与 Checkpoint 重放。

### 13.2 Manifest 能否防止半发布

故意只上传部分分片并尝试注册，Registry 必须因对象缺失或哈希不符拒绝。消费者没有权限绕过 Ready 状态直接枚举临时前缀。临时对象带 Run 与租约，垃圾回收只清理已过期且未被成功 Manifest 引用的对象。

### 13.3 事件重复是否幂等

相同事件投递两次不能生成重复边或推进两次状态；不同事件使用同一逻辑提交键时只能有一个赢家。投影器保存去重与游标，但原始事件不覆盖。重建后边集合、状态和版本身份与在线投影一致。

### 13.4 Schema 升级是否双向安全

生产者升级前验证消费者最低版本，未知必填字段不能被旧服务静默忽略。迁移器读取旧事件生成新投影，不篡改历史 Payload。回滚生产者时要处理已经存在的新 Schema 资产，而不是假设队列自动恢复旧格式。

### 13.5 血缘缺口是否可见

查询结果携带覆盖状态、投影水位和未知边界。若某个外部系统未接入，影响报告必须标记不完整，不能输出空集合暗示没有影响。覆盖率按应产生的转换事件计算，并由独立 Golden Run 审计。

### 13.6 权限是否沿资产传播

有文件读取权限不自动等于允许所有训练用途。

派生资产默认继承最严格上游约束，降级权限需要显式策略和审批。评审让低权限租户引用高权限 Source，Registry 应在提交或租约阶段阻断，不能仅靠对象路径保密。审计查询也要防止通过图关系泄露名称与统计。

### 13.7 Checkpoint 记录计划还是事实

训练配置中的 Release 是计划，实际消费清单才是事实。评审模拟分片读取失败与恢复，Checkpoint 应保存实际成员、游标和有效 Token；计划与事实差异触发告警。只引用配置无法判断某个被撤回文档是否真的进入梯度。

### 13.8 Tombstone 是否会竞态

撤回与新 Release 发布并发时，策略引擎必须以一致快照检查上游状态，阻止在 Tombstone 之后发布含风险源的版本。已获得的租约按合同暂停或到期，事件顺序与控制器任期进入审计，不能靠墙钟猜先后。

### 13.9 备份是否可恢复

需核验悬空引用、损坏对象及最新完整 Commit。

有备份文件不等于完成恢复。定期在隔离环境还原数据库、事件与 Manifest，验证对象哈希、时间点查询和权限，再记录真实 RPO/RTO。对象存储、数据库和事件日志的恢复点要协调，否则会出现图引用尚不存在对象。

### 13.10 图查询能否规模化

影响查询按常见方向建立索引，并设置分页、预算和异步导出。深图遍历保存快照与查询条件，避免运行中新增边造成不一致。性能压测使用真实度数与热点分布，不能只测均匀随机图。

### 13.11 人工修复是否可重放

禁止直接在生产数据库补边或改状态。紧急修复通过受审计命令生成补偿事件，包含原因、审批、目标与前置状态；在空库重放时得到同一结果。这样事故处置不会成为血缘重建时再次出现的幽灵差异。

### 13.12 模型影响是否诚实

系统能证明数据进入哪些 Checkpoint，但不能凭血缘自动证明它对参数产生多大影响或已经被遗忘。报告区分直接消费、可能派生、当前部署和模型层未知，把重新训练、回滚或遗忘评测作为治理动作，不制造确定性幻觉。
