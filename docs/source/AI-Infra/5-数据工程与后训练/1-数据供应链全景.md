# 数据供应链全景：对象、版本与规模口径

训练一个模型到底需要什么数据、这些数据现在是什么状态、为什么这版比上版好——如果回答不了这三个问题，「两万亿 Token」只是一个宣传数字。

## 1. 「数据」不是一个文件夹

把下载的文件丢进 `data/`、写个清洗脚本、导出 `train.jsonl`，在一次性实验里能跑。但它隐藏了至少十类信息：

1. 原始内容从哪来、何时取得、依据什么许可；
2. 原始文件是否完整、是否解析失败或编码损坏；
3. 哪一版清洗规则处理过它；
4. 哪些文档被删除、原因是什么；
5. 去重时谁与谁重复、保留了谁、为什么；
6. 属于什么语言、领域、难度与质量区间；
7. 是否与验证集/测试集/红队集重叠；
8. Tokenizer 版本、特殊 Token 与文档边界怎么处理；
9. 训练时的混合比例、采样顺序与随机种子；
10. 哪个检查点消费了哪些 Shard、中断后从哪恢复。

工程里的「数据」至少三部分：**内容 + 元数据 + 血缘事件**。只有内容无法筛选审计；只有内容与元数据无法解释「这版是怎么来的」。

## 2. 数据资产四元组

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l01_01.png" width="78%" alt="数据供应链全景" />
  <p>图 1：内容、元数据、血缘、版本四者共同构成一个可引用的数据资产</p>
</div>

$$
A = (C,\ M,\ L,\ V)
$$

- \(C\) Content：文本、图片、音频、代码或交互轨迹；
- \(M\) Metadata：来源、语言、领域、长度、许可、质量分、安全标签；
- \(L\) Lineage：输入、处理步骤、输出、运行与父子关系；
- \(V\) Version：内容 + 元数据 + 处理关系的**不可变快照**。

**版本不是文件名后缀**（`final_v3_really_final`）。一个有效版本需要：稳定标识、内容校验和、父版本、生成配方、代码版本、参数、创建时间。

## 3. 七个核心数据对象

| 对象 | 是什么 | 关键点 |
|---|---|---|
| Source | 数据为什么进入系统 | 不等于 URL：还要有 source_id、类型、所有者、时间窗、许可、robots/opt-out、保留期、抓取工具版本 |
| Capture | 同一来源的一次取得 | 同一网站在不同月份的抓取是不同 Capture；Source 与 Capture 分开，才能同时表达「同源」与「内容变了」 |
| Document | 保留自然边界的内容单元 | 网页正文、PDF 文章、代码文件、论坛主题、完整对话；要能回到原始字节 |
| Sample | 面向训练目标的语义单元 | 预训练段落、指令对、多轮对话、偏好对、可验证答案、Agent 轨迹 |
| Sequence | Token 序列 | 由固定 Tokenizer 产生，跨越文档边界时要记录 |
| Batch | 一次消费 | 不是新来源，是采样与打包的结果 |
| Trajectory / Experience | 交互轨迹 / 训练经验 | RL 与 Agent 场景的核心对象，带环境状态与奖励 |

两条纪律：

- **派生必须带父子关系**：一个 Document 可以派生出预训练段落、问答、术语解释、代码修复等多个 Sample，血缘不能断；
- **Batch 是消费不是来源**：把 Batch 当新数据会破坏计数与去重口径。

Document 层适合做来源治理、解析质量、文档级去重、语言识别与粗粒度质量判断；它不一定能直接训练——可能太长、含多个任务、需要切段或转成对话结构。

## 4. 三条流与两个流水线

```text
数据流：Source → Capture → Document → Sample → Sequence → Batch → 训练
控制流：门禁、配额、审批、发布、回滚
版本流：资产版本 → 训练运行 → 检查点 → 反馈回流
```

**离线数据流水线**（批处理、可回溯）与**在线后训练流水线**（rollout、偏好采集、在线评估）形态不同，但最终**必须共享同一套资产目录与质量门禁**——否则线上来的数据会绕过所有离线规则。

## 5. 规模口径：先写清对象，再写数字

### 5.1 五个限定字段

| 字段 | 例子 |
|---|---|
| `asset_version` | `cc-2025-06-v3` |
| `object_type` | Source / Document / Sample / Sequence / Trajectory |
| `processing_stage` | Raw / Parsed / Filtered / Deduplicated / Train-ready |
| `count_unit` | 字节 / 字符 / 文档 / 样本 / Token / 有效标签 Token / 训练步 |
| `measurement_recipe` | 解析器、Tokenizer、过滤规则、去重配置、统计代码版本 |

缺任意一项，「2T Token」都不可审计。两个最常见的造假：**用新 Tokenizer 重算旧语料但沿用旧版本名**；**去重后报文档数、去重前报 Token 数**。

### 5.2 四个阶段的公式

**Raw（采集）**：

$$
B_{raw} = \sum_{i=1}^{N_{obj}} \mathrm{bytes}(o_i)
$$

压缩前后必须分开；同时记录对象数、下载成功率、HTTP 状态分布、MIME、抓取时间、内容校验和。**原始字节多只说明采集量大，不代表解析后有多少正文**（PDF 可能是扫描图，网页可能大半是脚本与模板）。

**Parsed（解析）**：

$$
D_p = \{\, p(o) \mid o \in O,\ \mathrm{status}(p(o)) = \text{success} \,\},\qquad
R_{parse}^{doc} = \frac{|D_p|}{|O|}
$$

也要报字符口径的保留率，但分母（「可提取字符估计」）在真实系统里难有全量真值——**只能抽样人工评估召回，不能假装存在精确答案**。

文档成功率高 ≠ 正文完整：解析器可能对每个网页都返回字符串，却只抓到 Cookie 提示、导航栏或第一页。至少要报成功/空/过短文档、异常编码、正文占比、结构块数量与解析器版本。

**Filtered（门禁）**：

$$
D_f = \{\, d \in D_p \mid g_1(d) = 1,\ \ldots,\ g_k(d) = 1 \,\}
$$

每个 $g_j$ 都要可解释：语言、长度、PII、许可、解析完整度、恶意内容风险。**门禁串行时，总保留率无法解释各自影响**——语言过滤先删掉的乱码文档，后续乱码门禁就看不到。

所以要同时记四种口径：顺序口径（在输入上删了多少）、全体口径（在解析全集中命中了多少）、重叠口径（同时命中哪些原因）、主原因（数据卡展示用）。

**Train-ready**：

$$
N_{eligible} = |D_f|,\qquad T_{eligible} = \sum_{d \in D_f} t(d)
$$

$t(d)$ 必须由**固定 Tokenizer 版本**计算。未绑定 Tokenizer 时可以报字符与估算 Token，但**不能把估算值和真实分词混在同一字段**。

## 6. 「独特」至少有四种口径

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l02_01.png" width="78%" alt="语料度量" />
  <p>图 2：规模、质量、独特性、训练价值是四把不同的尺子</p>
</div>

1. **精确独特**：对规范化内容求稳定哈希，同哈希进同簇，每簇计一次：

$$
N_{exact} = \left|\left\{\, h(n(d)) : d \in D_f \,\right\}\right|
$$

规范化是否去空白/大小写/时间戳/模板会改变结果，**必须版本化**。

2. **近似词法独特**：MinHash/LSH/Winnowing 把高 Jaccard 或共享长片段的文档聚簇，取每簇代表文档的 Token 和：

$$
T_{lex} = \sum_{c \in C_{lex}} t(r(c))
$$

依赖 Shingle 大小、相似度阈值、Band/Row 配置与代表选择策略。

3. **语义多样性**：两篇文章可能没有共享句子却讲同一件常识；也可能词面相似但各有增量。语义聚类后可算簇数、簇大小分布、有效簇数与覆盖熵：

$$
H = -\sum_{k=1}^{K} p_k \log p_k
$$

4. **有效训练 Token**：经过质量、去重、去污与打包之后**真正参与梯度**的 Token 数——它和「名义 Token」经常差一倍以上。

## 7. 五组必须承认的冲突

| 维度 | 拉高它的代价 |
|---|---|
| 质量 | 过滤越严，规模越小，长尾/低资源领域先被删 |
| 多样性 | 引入更多来源，噪声与重复随之上升 |
| 独特性 | 去重越狠，可能删掉合法的重复强化信号 |
| 难度 | 只留难题会让模型丢失基础能力，只留简单题学不到东西 |
| 时效 | 追新会牺牲稳定性与可复现性 |

这些冲突不能靠一句「我们重视质量」解决，只能靠**显式的数据配方 + 分域报告 + 可回滚的版本**。

## 8. 一个最小可恢复供应链

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l02_02.png" width="78%" alt="规模口径" />
  <p>图 3：每个阶段都要能回答「剩多少、删了什么、为什么」</p>
</div>

最小要求：

- **可恢复**：任一阶段失败能从上一版快照继续，不需要重跑整条链；
- **可回放**：给定资产版本 + 配方 + 代码版本，能复现同一份输出；
- **可审计**：每个删除/保留都有 Reason 与统计；
- **可删除传播**：来源撤回某条数据时，能追到已发布的数据集、训练运行与检查点，并记录影响范围。

最后一条最常被忽略：**没有删除传播，就没有合规的数据供应链。**

## 写在最后

数据工程的第一性原理是**可追溯**：对象要分层、版本要不可变、口径要带限定、删除要能传播。做到这四点，后面的清洗、去重、混合与配方才有意义。
