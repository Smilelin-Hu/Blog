# 混合与课程：领域、权重与配方优化

数据配方 = **选哪些数据 × 各给多少**。前一篇解决「选」，这一篇解决「给多少」，以及「怎么证明给出去了」。

## 1. 领域不是文件夹名

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l14_01.png" width="78%" alt="领域分类与采样" />
  <p>图 1：四轴本体描述内容，采样桶是它在配方里的投影</p>
</div>

一个网页可能同时是「中文 + 医学 + 问答 + 高质量」。领域至少有四条正交轴：

- 语言与地域（`language=zh`）
- 知识主题（`topic=medicine`）
- 内容体裁（`genre=qa`）
- 来源或质量等级（`quality=tier_a`、`source_family=licensed_forum`）

**压成单一标签会立刻引发争论**：「中文医学问答」到底算中文、医学还是对话？正确做法是保留多轴本体，配方再用规则投影成采样桶（`zh_medicine_qa_a`）——原始属性长期稳定，桶可随实验重建。

每个轴还要写清：是否互斥、是否多标签、父子关系、未知与混合怎么表达。**来源族应来自注册表事实，不要用内容分类器猜。** 标签文档至少给正例、反例、边界例与判定顺序：「`code` 只含源码，还是也含技术解释？」「`math` 是含公式就算，还是必须以数学推理为目的？」——这些边界直接改变权重与预算。

## 2. 三种分布，缺一不可

| 分布 | 含义 | 来源 |
|---|---|---|
| 库存分布 | 有哪些、各多少 | 发布快照 |
| 计划分布 | 经审批的 \(p_i\) | 配方 |
| 实现分布 | 实际消费 | 训练过程按 Token 计量 |

**只保存权重无法证明实现正确**：序列长度、Packing、坏样本跳过、DataLoader 重试都会改变实际比例。

计量以**进入损失计算的有效 Token** 为主，同时保留样本数、序列数与原始字节。不同领域平均长度差异很大，**按样本数对齐 ≠ 按 Token 对齐**；若目标是控制梯度贡献，还要记录 Loss Mask 之后的受监督 Token，不能把模板与填充算进预算。

## 3. 给不确定留位置

- 置信度不足 → `unknown`
- 多主题都重要 → 带概率的多标签
- 元数据与内容预测冲突 → `conflict` 并保留两者

**不要为了让统计图加总到 100% 就把不确定样本硬塞进最近的桶**——那等于把分类错误伪装成事实。

未知率本身是健康指标：突然升高可能意味着新领域出现、解析异常、语言模型失效或上游字段变化。生产配方可以给未知桶小额探索预算，或先隔离——按风险决定，而不是按分类器默认值决定。

## 4. 本体要版本化

团队把 `science` 拆成物理/化学/生物时，**旧快照不能被静默重标**：发布本体新版本、固定分类器与规则、对历史候选集做可重放迁移，并输出**旧桶 → 新桶的流量矩阵**。

否则指标趋势会出现假变化：能力「提升」可能只是桶定义变窄，某来源占比「下降」也可能只是标签移动。版本化让团队能区分「数据变了 / 分类器变了 / 定义变了」。

## 5. 分类流水线的四层

| 层 | 做法 | 边界 |
|---|---|---|
| 可靠元数据 | 合同、栏目、仓库语言、出版物分类、人工标注 | 不能因 URL 含 `medical` 就判医疗；要监控覆盖率与冲突率 |
| 轻量规则 | 扩展名、AST 解析成功、符号密度、对话角色结构 | 便宜可解释，但覆盖有限、易被模板欺骗 |
| 监督分类器 | 从真实候选池分层抽样训练 | 随机抽主流网页会得到很高总体准确率，却保不住数学/法律/低资源语言 |
| 层级 + 拒识 | 先大类再子类；低置信回退扁平或人工 | 父类错则子类永无机会；联合概率 \(P(child)=P(parent)\cdot P(child\mid parent)\) 不能直接用条件概率当全局置信度 |

规则输出要带**标签、置信度、证据、规则版本**。例如 `genre=code` 的证据是「解析器识别为 Python 且成功生成 AST，代码字符占正文 80%」，而不是「出现了大括号」。

软标签（物理 0.6 / 数学 0.3 / 计算机 0.1）比硬标签更适合预算分析——但它**不自动真实**：未校准模型会对错误预测非常自信，必须用可靠性曲线、ECE、类别条件校准与拒识质量来验证。

人工复核要按**价值**调度（Token 量、目标桶稀缺度、不确定性、来源风险），并让结论进入金标集、真正改进规则或模型——否则会永远重复同类工作。

## 6. 分类质量如何传导到采样

### 6.1 总体准确率不是关键指标

假设通用网页占 95%，把所有样本都预测成通用类也有 95% 准确率，却完全抹掉了数学与代码。

要看的指标：每类 Precision/Recall、混淆矩阵、宏平均、**按 Token 加权**的指标，以及**对最终预算的偏差**（估计库存 \(\hat N_i\) 与真实 \(N_i\) 的误差）。

### 6.2 用混淆矩阵做预算压力测试

设 \(C_{ij} = P(\hat y = j \mid y = i)\)，真实分布向量 \(q\)，则预测桶分布：

$$
\hat q = qC
$$

按预测桶给权重后，就能模拟「计划给数学 10%，实际只有 6%，其余来自误判网页」的风险。

**不要直接用矩阵求逆修正全部权重**：长尾类别下矩阵噪声大，逆矩阵会产出负数与极端权重。更安全的是置信区间 + 保守下界 + 场景压力测试，再用抽样审计与小规模代理训练验证。

### 6.3 标签漂移 ≠ 库存漂移

新批次领域占比变化，可能因为世界真的变了，也可能因为分类器/规范化/解析器变了。发布报告要同时做：**旧分类器评新数据**、**新分类器重评稳定基准**、以及交叉差分。

如果线上分类器自动更新而配方不变，等于**悄悄改变了数据分布**。分类器升级必须像过滤策略一样走 Shadow → 差分 → 审批 → 版本发布。

## 7. DoReMi：用「超额损失」定权重

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l15_01.png" width="78%" alt="DoReMi 与代理优化" />
  <p>图 2：参考模型定义「基准」，代理模型只优化自己相对基准落后最多的领域</p>
</div>

### 7.1 为什么需要参考模型

直接最小化「最差领域损失」会偏向熵高、噪声大或不可学的领域。DoReMi 先按参考分布训练参考模型 \(\theta_{ref}\)，再看代理模型**相对参考多出来的损失**：

$$
R_i(\theta) = \mathbb{E}_{x \sim D_i}\left[\ell(\theta; x) - \ell(\theta_{ref}; x)\right]
$$

一个领域绝对损失高但已达参考水平，不该继续吸走权重；另一个绝对损失低但明显落后，仍有优化空间。

### 7.2 极小极大与指数梯度

$$
\min_\theta \max_{\alpha \in \Delta^K} \sum_i \alpha_i R_i(\theta)
$$

$$
\tilde\alpha_i^{t+1} = \alpha_i^{t}\exp\left(\eta \hat R_i^{t}\right),\qquad
\alpha_i^{t+1} = \frac{\tilde\alpha_i^{t+1}}{\sum_j \tilde\alpha_j^{t+1}}
$$

要点：

- \(\eta\) 太大权重会在噪声领域间跳，太小几乎不离开初始分布；
- 数值上用减去最大 logit 的 LogSumExp 防溢出；
- **必须平滑**：\(\alpha' = (1-\epsilon)\alpha + \epsilon q\)，再加每域上下限。某领域权重归零后就没法估计超额损失，闭环无法自我纠正；
- **聚合方式要选**：全程平均、烧入后平均、EMA、分阶段平均——早期波动大，后期更接近目标，不能把某一种当唯一答案。

### 7.3 三阶段与成本

1. 训参考模型并冻结；
2. 训代理模型、在线更新领域权重并记录轨迹；
3. 把聚合权重投影到生产约束（库存上限、最小覆盖），重采样全量数据训目标模型。

**参考与代理的成本必须计入总成本**，不能只报目标模型省了多少。

### 7.4 参考模型的五个设计点

- 参考分布决定「超额」相对什么，选择理由必须记录，并至少比较一个替代参考；
- 参考**充分但不必最强**：太弱则超额不稳，太强则代理长期落后；
- 参考损失**不能从训练批次泄漏**（冻结参考或预计算样本级损失）；
- 预计算省算力但增存储与版本耦合；在线双前向准确但吃 GPU，需 Profile 决定；
- 参考模型本身也可能被污染，要检查训练数据重叠。

## 8. 代理优化的五个陷阱

| 陷阱 | 表现 |
|---|---|
| 单域直觉 | 提高一个领域必然挤掉别的领域，忽略替代关系与领域交互 |
| 高质量 ≠ 边际价值 | 模型已掌握的高质量领域，追加 Token 收益很低 |
| 损失 ≠ 该上采样 | 高损失可能是噪声、Tokenizer 不适配或乱码；低损失可能是重复泄漏 |
| 赢家诅咒 | 从上百候选中挑最好，容易选中噪声极端；要多种子、交叉验证、Top-k 平均 |
| 代理信噪比不足 | 代理噪声大到排序近似随机时，扩大搜索只会制造虚假精确 |

RegMix 一类做法是先跑一批小规模混合实验，用回归模型拟合「混合比例 → 性能」，再在候选空间搜索。它的前提正是**代理信噪比**：先验证「小实验的排序能否预测大训练」，再扩大候选数。

## 9. Tokenization 与 Packing

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l16_01.png" width="78%" alt="Tokenization 与 Packing" />
  <p>图 3：Tokenizer 版本与打包方式都会改变「有效 Token」的口径</p>
</div>

三条与配方直接相关的规则：

1. **Tokenizer 必须版本化**：同一语料在 v1 与 v2 下 Token 数不同，混用会让「预算」失真；
2. **Packing 会改变注意力边界**：把多篇拼进一个序列，要么用块对角 mask 隔离文档，要么接受跨文档注意力（可能泄漏）；
3. **Padding 是纯浪费**：按最长样本补齐会浪费大量算力，应按长度分桶或 packing。

另外两件常被忽略的事：

- **EOS/边界符**：文档边界缺失会让模型学不到「何时停」；
- **长度分布**：配方按 Token 计量，但长度分布决定 packing 效率与 batch 内浪费。

## 10. 数据课程：从易到难值得做，但要证据

课程学习（curriculum）常见做法：先短后长、先易后难、先通用后专业。

三条纪律：

1. **定义要可操作**：「难度」必须来自可测量的代理（长度、困惑度、领域评分、通过率），不能用主观标签；
2. **别破坏覆盖**：只按难度排序会让长尾领域在早期缺席，后期补不回来；
3. **要有对照**：同预算、同终态混合比例下的 A/B，而不是「感觉收敛更快」。

## 写在最后

混合这件事有三层证据：**本体与分类**（你以为什么）、**计划分布**（你打算给什么）、**实现分布**（实际消费了什么）。三层对不上，配方就无法解释。
