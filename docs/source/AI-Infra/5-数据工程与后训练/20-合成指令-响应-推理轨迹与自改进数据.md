# 合成指令、响应、推理轨迹与自改进数据

## 1. 本文要解决的工程问题

Teacher 批量生成指令和推理轨迹，过滤器又由同一模型评分。看板上的通过率很高，错误模式、措辞和推理捷径也被成批复制。

本文围绕一个可执行判断展开：怎样生成和筛选指令、响应与推理轨迹，又不把模型偏差批量复制进数据？读完应能给出自己的系统边界、输入输出、版本关系和验收证据，而不是只复述工具名称或公式。

![合成数据生产闭环](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l20_01.png)

## 2. 本文交付物与判定标准

本文的核心决定是：分离任务生成、响应生成、验证和选择角色，并记录 Teacher、Prompt、采样参数、验证器与失败原因。

完成学习和实验后，应当交付一份最小可复现记录，至少包含输入快照、配置、代码版本、运行状态、原始输出和结论边界。验收证据是：合成数据按难度、来源、验证方式和重复模式切片；抽样能回放生成链路并复现筛选决定。

围绕“合成指令、响应、推理轨迹与自改进数据”的验收不接受三类替代品：把模拟输出写成真实 GPU 结果；只展示成功样本而隐藏失败与 `SKIPPED`；只给总分，不保存能复算总分的对象级记录。

## 3. 前置知识与实验边界

“合成指令、响应、推理轨迹与自改进数据”的机制实验使用 Python 3.10 及以上版本和标准库，重点验证对象、算法或状态转换。真实硬件路径使用 PyTorch；检测不到 CUDA 时必须输出结构化 `SKIPPED`，不得静默改跑 CPU 后仍标成 GPU 实测。

模型评审可以扩展筛选规模，不能消除共享偏差或替代可验证任务的程序检查。

### 3.1 业务背景与失败模式

合成数据不是把一次模型调用放大为无限训练资源，而是把业务能力缺口转化为可生成、可验证、可选择、可追责的监督资产。指令合成扩展任务意图，响应合成提供候选行为，推理轨迹合成暴露中间步骤，自改进让模型依次生成、批判、修订和选择。它们能降低人工从空白开始写样本的成本，却会继承教师模型的知识截止、偏见、风格、错误和安全边界。

生产系统的核心问题不是“能生成多少”，而是“每个生成样本为什么存在、由谁产生、经过什么验证、对哪个能力缺口负责、训练后带来什么边际收益”。若不建立父样本谱系、提示版本、生成参数、验证器结果和数据退出路径，规模越大，错误回声越强。合成流水线应被理解为一个带有测量和控制的生产系统，而不是一个批量 API 脚本。

### 3.2 Seed

Seed 是生成起点，可以是人工指令、真实文档、任务定义、工具 Schema、失败案例或能力标签。它不必直接成为训练样本，但必须有来源、权利、时间和敏感性状态。无来源 Seed 会让所有后代失去治理基础。

### 3.3 Candidate

Candidate 是一次生成的候选，包括指令、响应、轨迹、批判或修订。候选保存生成模型、提示摘要、采样参数、随机种子、父对象和时间。未验证候选只属于隔离区，不能因为格式合法就进入训练。

### 3.4 Verified Example

Verified Example 通过格式、规则、执行、Judge 或人工验证，并记录每道门禁的结果。通过不代表绝对正确，只表示在指定验证器版本和范围内满足要求。验证器不足必须作为风险字段保留。

### 3.5 Released Dataset

Released Dataset 是冻结、可复现、可训练的样本集合，包含清单、摘要、Schema、采样权重、父系覆盖、质量画像、污染报告和退出映射。训练只能引用发布 ID，不能直接消费生成任务不断变化的输出目录。

### 3.6 从能力图而不是随机主题开始

先定义能力、领域、难度、输入形态、约束、语言和风险的多维覆盖。例如代码任务不只分语言，还要分理解、生成、调试、测试、重构、性能与安全。随机让教师“再想一些问题”会集中到常见模板，制造数量而不是覆盖。

### 3.7 Self-Instruct 范式

Self-Instruct 从少量种子生成新指令、判断其有效性、生成实例并过滤相似项。关键思想是让模型参与扩展任务空间，而非逐条人工写作。工程上必须控制种子偏置、相似度阈值、生成批次和人工抽检；教师容易重复熟悉任务，长尾覆盖不会自动出现。

### 3.8 文档条件指令

以受治理文档为证据生成问答、抽取、改写或推理任务，可以提高事实可验证性。每个问题保存证据片段和文档版本；验证时检查答案是否被证据蕴含、是否需要外部知识、是否泄漏无关秘密。文档条件生成仍可能把歧义变成虚构确定答案。

### 3.9 无种子指令诱导

某些已对齐教师在只给模板边界时会隐式生成用户指令，可用于探索任务分布。它降低 Seed 准备成本，也更容易复制教师的默认偏好与高频风格。生产使用时应与明确能力覆盖对照，并限制教师自我偏好的支配。

### 3.10 反事实与约束变体

同一任务可变换实体、数值、语言、长度、工具、输出 Schema 或安全约束，形成边界样本。变体必须保持语义和可解性；机械替换可能破坏单位、因果或事实。使用执行器和不变量检查比纯文本相似度更可靠。

### 3.11 难度生成

难度可以通过组合步骤、干扰信息、信息位置、约束数量、所需工具和证明深度控制。不要只让教师自报“这是困难题”，而应保存可观测难度特征，并用学生通过率或执行轨迹校准。过难且不可验证的题只增加噪声。

## 4. 响应合成

### 4.1 单教师单响应

成本最低，但无法估计生成方差或比较质量。适合格式严格、可执行验证的任务，不适合开放安全与事实任务。即使只有一个候选，也要保存验证证据。

### 4.2 多采样 Best-of-N

对同一指令生成多个候选，再由规则、执行器、Reward Model 或 Judge 选择。N 增加会提升找到好答案的概率，也增加成本和选择偏差。选择器若存在漏洞，Best-of-N 会主动搜索漏洞而非真实质量。

### 4.3 多教师

不同教师可提供语言、领域和风格多样性，减少单一模型回声。需要校准教师能力、许可和输出风险，并防止简单平均隐藏弱教师。训练发布保存教师占比与实际晋级率。

### 4.4 蒸馏响应

强教师为弱学生生成答案，是能力转移而非事实来源证明。学生可能学到教师的解释风格、拒答和错误。验证应针对产品目标，而不是“与教师越像越好”。

### 4.5 拒答与澄清响应

高质量数据不仅包含直接回答，还包含证据不足、冲突、危险或需求不清时的拒答和澄清。若合成数据全部提供确定答案，学生会学习过度自信。拒答必须区分安全拒答、知识不确定和信息缺失。

## 5. 推理轨迹

### 5.1 轨迹不是答案的装饰

推理轨迹应帮助分解问题、调用工具、验证中间结果或定位错误，而不是在正确答案后补一段看似合理的解释。后验合理化可能与真实求解过程无关。轨迹质量需要过程级检查。

### 5.2 结果监督与过程监督

结果监督只判断最终答案，成本低且适合可验证任务；过程监督评价中间步骤，能定位首个错误但标注与 Judge 更复杂。二者可以组合：执行器先筛结果，再对高价值或边界样本做过程验证。

### 5.3 可见轨迹与隐藏轨迹

训练资产可以保存详细推理、压缩解释、工具事件或仅最终答案。产品是否展示完整轨迹是单独策略。本文讨论数据与训练机制，不假设模型必须向用户暴露内部推理。

### 5.4 工具轨迹

工具任务的核心是状态转移：观察、选择工具、生成参数、接收结果、更新计划、停止。轨迹需要保存工具 Schema 版本、调用结果摘要和错误码。只保存最终自然语言会丢失可训练的决策边界。

### 5.5 轨迹长度与啰嗦偏置

教师常把“更长”误当“更好”，学生因此学会无意义展开。评价应考虑正确、最小充分、可验证和成本。对简单题保留直接答案，对复杂题保留必要步骤，形成长度校准。

## 6. 自改进闭环

![自改进闭环](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l20_02.png)

自改进只有在生成、批评、修订、验证和回收策略彼此独立留痕时才有意义；否则系统只是在把同一种偏差反复写回数据池。下面按阶段展开完整闭环。

### 6.1 Generate

生成多个候选并保留完整元数据。生成阶段只负责探索，不负责宣布正确。温度、Top-p 和提示策略决定探索空间，应版本化。

### 6.2 Critique

批判器指出事实、逻辑、格式、安全和证据缺口。批判必须引用可验证位置，避免泛泛而谈。使用同一教师自评时会有盲区，可结合规则和独立模型。

### 6.3 Revise

修订器依据批判生成新候选，保存父子边。修订并不保证提升，需重新执行全部门禁，不能继承父候选通过状态。

### 6.4 Select

选择器比较候选并给出分项理由。位置、长度、风格和自偏好会影响 Judge。交换顺序、多 Judge、执行器与人工抽样可以估计偏差。

### 6.5 Learn

只有通过发布门禁的样本进入 SFT、偏好学习或评测候选。训练后用能力缺口和失败分布决定下一轮生成，而不是无条件扩大旧模板。

## 7. 验证器体系

### 7.1 Schema 验证

检查字段、类型、角色顺序、特殊 Token、最大长度和必需元数据。Schema 通过只证明机器可读，不证明语义正确。

### 7.2 规则验证

适合 JSON、正则、长度、禁词、引用、单元和输出约束。规则确定、便宜、可复现，但只覆盖已编码条件。

### 7.3 执行验证

代码、数学、SQL、工具调用和形式证明可在沙箱或验证器中执行。保存输入、环境、依赖、退出码、资源限制和结果摘要。单一测试通过不能证明完整正确，需要隐藏与变形测试。

### 7.4 模型 Judge

Judge 处理开放质量、相关性、帮助性和安全，覆盖广但有偏差。冻结模型、提示和解析器，使用量表与校准集，报告拒判和冲突。Judge 分数是测量，不是真理。

### 7.5 人工验证

用于高风险、开放边界、Judge 校准和随机审计。标注者需要指南、培训、双标与仲裁，并受到隐私和内容安全保护。人工也会犯错，因此保存一致率。

### 7.6 组合门禁

先用便宜确定规则剔除明显失败，再执行沙箱、Judge 和人工抽样。顺序应降低成本而不让高风险样本绕过。每个样本保存全部状态而不是只存最终通过。

## 8. 多样性、去重与污染

文本不同不保证新增学习信号。

### 8.1 指令多样性

按意图、领域、结构、语言、长度、难度与工具覆盖。嵌入距离只能表示语义近似，不能替代能力标签。高多样性也不保证有训练价值。

### 8.2 响应多样性

开放任务需要风格与策略多样性，格式任务则需要稳定。多样性目标必须服务产品，不能为了距离而保留低质答案。

### 8.3 父样本去重

不同表面问法可能来自同一文档事实。仅对最终文本去重会高估独立证据。沿父样本和事实单元限制派生数量。

### 8.4 评测污染

生成模型可能记得公开基准并产生相似题目。对指令、解答、代码和关键数字做精确、模糊与语义检查，记录命中。训练集与最终盲测来源严格隔离。

## 9. 选择与混合

### 9.1 质量分不等于采样权重

全选最高分会集中到简单、主流、Judge 偏好的样本。训练混合应同时考虑能力缺口、多样性、难度和来源上限。高质量长尾需要保留。

### 9.2 有效率

有效率等于通过门禁且进入发布的候选占生成候选比例。它帮助估算成本，但低有效率可能来自探索困难长尾，高有效率也可能来自题目过易。必须按桶查看。

### 9.3 边际训练价值

对候选桶做小规模增量训练或 Influence 代理，观察相对基线提升。生成分数只是输入质量，最终价值由学生模型决定。

### 9.4 真实与合成混合

真实样本提供实际分布和可信锚点，合成样本扩展覆盖。比例需消融，并按来源、教师和父事实设置上限。不能把所有合成统一当一类。

### 10.1 实验目标

设置预算和停止条件，不能无限重试到偶然通过。

下面程序用确定性算术任务模拟合成闭环。它生成候选、注入可控错误、执行验证、修订失败候选、按正确性与简洁性选择，并输出父子谱系、有效率和覆盖。它不调用大模型，结论只覆盖流水线机制。

```python
import json
import random
from dataclasses import dataclass, asdict

@dataclass
class Candidate:
    cid: str
    seed_id: str
    parent_id: str | None
    prompt: str
    response: str
    stage: str
    valid: bool = False
    score: float = 0.0
    reason: str = "not_checked"

def expected(a: int, b: int, op: str) -> int:
    return a + b if op == "add" else a * b

def verify(candidate: Candidate, answer: int) -> Candidate:
    try:
        value = int(candidate.response.split("答案=")[-1].strip())
        candidate.valid = value == answer
        candidate.reason = "passed" if candidate.valid else "wrong_answer"
        candidate.score = (1.0 if candidate.valid else 0.0) - 0.001 * len(candidate.response)
    except Exception:
        candidate.reason = "parse_error"
        candidate.score = -1.0
    return candidate

def main() -> None:
    rng = random.Random(20260822)
    seeds = []
    candidates = []
    for index in range(40):
        op = "add" if index % 2 == 0 else "mul"
        a, b = rng.randint(2, 30), rng.randint(2, 12)
        answer = expected(a, b, op)
        seed_id = f"seed-{index:03d}"
        seeds.append({"seed_id": seed_id, "op": op, "a": a, "b": b, "answer": answer})
        generated = []
        for sample in range(3):
            wrong = rng.random() < 0.28
            value = answer + rng.choice([-2, -1, 1, 2]) if wrong else answer
            text = f"先识别运算{op}，计算后得到答案={value}"
            item = Candidate(f"{seed_id}-g{sample}", seed_id, None,
                             f"计算 {a} {op} {b}", text, "generate")
            generated.append(verify(item, answer))
        candidates.extend(generated)
        if not any(item.valid for item in generated):
            parent = max(generated, key=lambda item: item.score)
            revised = Candidate(f"{seed_id}-r0", seed_id, parent.cid, parent.prompt,
                                f"重新执行并校验，答案={answer}", "revise")
            candidates.append(verify(revised, answer))
    selected = []
    for seed in seeds:
        pool = [item for item in candidates if item.seed_id == seed["seed_id"] and item.valid]
        if pool:
            selected.append(max(pool, key=lambda item: item.score))
    payload = {
        "status": "passed",
        "claim_boundary": "deterministic arithmetic synthesis mechanism only",
        "seed_count": len(seeds),
        "candidate_count": len(candidates),
        "valid_candidate_rate": sum(x.valid for x in candidates) / len(candidates),
        "released_seed_coverage": len(selected) / len(seeds),
        "revised_count": sum(x.stage == "revise" for x in candidates),
        "lineage_edges": [
            {"parent": x.parent_id, "child": x.cid}
            for x in candidates if x.parent_id is not None
        ],
        "sample_release": [asdict(x) for x in selected[:3]],
    }
    print(json.dumps(payload, ensure_ascii=False, indent=2))

if __name__ == "__main__":
    main()
```

### 10.2 结果解释

应看到候选有效率小于发布覆盖率，因为同一 Seed 可生成多个候选，修订使原本没有正确候选的 Seed 恢复。选择分数同时惩罚无意义长度，展示“正确且简洁”的多目标选择。真实系统需替换为受治理 Seed、模型服务、执行沙箱和版本化 Judge。

## 11. 通用 CUDA 真实生成与学生训练路径

### 11.1 实验边界

CUDA 实验使用小型因果语言模型或本地可用模型，Rank 零生成或读取候选发布，一个或多个 Rank 做短 SFT 并聚合 Token。没有可用 CUDA GPU 或模型资产时输出结构化 `skipped`。实验验证分布式训练和数据发布消费，不宣称大模型能力。

```python
import json
import os

try:
    import torch
    import torch.distributed as dist
    from torch import nn
except Exception as exc:
    print(json.dumps({"status": "skipped", "reason": f"torch unavailable: {exc}"}))
    raise SystemExit(0)

def skip(reason: str) -> None:
    print(json.dumps({"status": "skipped", "reason": reason}))
    raise SystemExit(0)

def main() -> None:
    if not torch.cuda.is_available():
        skip("CUDA unavailable")
    if torch.cuda.device_count() < 1:
        skip(f"requires at least one CUDA device, found {torch.cuda.device_count()}")
    if int(os.environ.get("WORLD_SIZE", "1")) < 1:
        skip("launch with torchrun --nproc_per_node=1")
    dist.init_process_group("nccl")
    rank = dist.get_rank()
    local_rank = int(os.environ["LOCAL_RANK"])
    torch.cuda.set_device(local_rank)
    device = torch.device("cuda", local_rank)
    torch.manual_seed(20260822)
    vocab, hidden, length = 512, 192, 96
    model = nn.Sequential(nn.Embedding(vocab, hidden), nn.LayerNorm(hidden),
                          nn.Linear(hidden, vocab, bias=False)).to(device)
    model = nn.parallel.DistributedDataParallel(model, device_ids=[local_rank])
    optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)
    consumed = torch.zeros(2, dtype=torch.long, device=device)
    try:
        for step in range(80):
            generator = torch.Generator(device=device)
            generator.manual_seed(10_000 * rank + step)
            tokens = torch.randint(0, vocab, (2, length + 1), generator=generator, device=device)
            logits = model(tokens[:, :-1])
            loss = nn.functional.cross_entropy(logits.reshape(-1, vocab), tokens[:, 1:].reshape(-1))
            optimizer.zero_grad(set_to_none=True)
            loss.backward()
            optimizer.step()
            consumed[0] += tokens[:, 1:].numel()
            consumed[1] += 1
        dist.all_reduce(consumed)
        if rank == 0:
            print(json.dumps({
                "status": "passed",
                "consumed_tokens": int(consumed[0]),
                "optimizer_steps_across_ranks": int(consumed[1]),
                "peak_allocated_bytes": torch.cuda.max_memory_allocated(device),
                "claim_boundary": "synthetic two-GPU SFT control path only",
            }))
    except torch.cuda.OutOfMemoryError as exc:
        if rank == 0:
            print(json.dumps({"status": "skipped", "reason": f"CUDA OOM: {exc}",
                              "suggestion": "reduce hidden, sequence length, or micro batch"}))
    finally:
        dist.destroy_process_group()

if __name__ == "__main__":
    main()
```
