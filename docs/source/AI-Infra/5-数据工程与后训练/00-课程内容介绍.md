# 课程内容介绍

## 1. 课程内容介绍

大厂 AI Infra 训练营（第五期）：大模型数据工程与后训练基础设施

从原始语料到可训练的数据，从一次模型交互到可用的学习信号，再到能够持续运行的后训练系统。本系列沿着这条工程路径，串联数据工程、后训练方法与平台设计，便于理解各个环节如何协作，以及问题发生后应该从哪里查起。

全系列包含 7 个学习阶段、30 篇图文笔记、30 个机制实验和 6 个综合工程项目，配套独立实验代码包。内容按“问题与原理 → 工程分析 → 实验验证 → 项目应用”展开；复杂关系辅以机制图，其余内容通过推导、实例和代码讲解。

## 2. 解决什么问题

数据规模增长，训练效果却没有同步提升；SFT 样本看起来正确，模板与 Loss Mask 却改变了训练目标；强化学习流程能够运行，策略版本、奖励或恢复状态却悄悄错位。这些问题横跨数据、算法与系统，需要把整条链路放在一起分析。

内容围绕四类实际问题组织：

- 数据是否值得训练：区分规模、质量、独特性与有效 Token，分析过滤、去重和数据混合的取舍。
- 样本是否表达了正确目标：追踪原文、模板、Token、Packing 与 Loss Mask，检查数据进入梯度计算前的每一步。
- 后训练信号是否可靠：理解偏好数据、奖励模型、可验证奖励与策略更新之间的关系，识别污染、奖励投机和评估偏差。
- 系统是否能够持续运行：分析权重同步、异步采样、断点恢复、版本追溯与成本，建立可以检查和重放的工作流程。

## 3. 适合谁学习

适合希望向大模型方向延伸的数据工程师、负责训练与推理基础设施的后端或平台工程师，以及希望理解数据和系统实现的算法工程师。已有训练经验、但知识集中在某个框架或算法上的人，也可以通过本系列建立更完整的工程视角。

学习前应能阅读 Python、处理 JSON 与文件路径，并会在命令行运行脚本；同时了解训练集、验证集、Token、Batch、Loss 与 Checkpoint 的基本含义。正文会解释数据与后训练中的关键机制，Python 编程和机器学习基础需要提前具备。

## 4. 能力目标

- 数据资产设计：将来源、处理配方、样本、发布版本与模型检查点关联起来，追查数据从哪里来、被谁使用。
- 训练数据加工：选择解析、清洗、去重与质量评估方法，分析误删、污染、多样性损失和吞吐瓶颈。
- 后训练数据设计：组织 SFT、合成数据与偏好数据，解释模板、掩码、奖励和采样如何影响优化目标。
- 系统诊断与恢复：定位策略陈旧、版本混用、重复提交和恢复不一致，设计相应的观测与故障实验。
- 工程方案评估：结合工作负载、硬件条件与实验结果，说明方案的适用范围，并形成可复查的设计和验收记录。

## 5. 内容与配套资料

30 篇笔记按知识依赖分为 7 个阶段，覆盖数据来源与治理、训练样本加工、后训练数据、奖励与强化学习，以及分布式系统协作。每篇围绕一个工程问题，包含机制解释、实现分析、实验、排障、练习与代码说明。

30 个机制实验便于用小规模输入检查关键算法和状态变化。6 个综合项目将多篇知识组合成更完整的工程方案，覆盖语料流水线、数据血缘、数据配方、偏好与奖励工厂、后训练算法衔接和异步平台恢复。

配套代码包含可运行的机制实验入口、CUDA 基础探针，以及供阅读和扩展的正文代码。项目中的完整生产架构是进阶实现目标，需要结合目标模型、数据与运行环境继续开发和验收。

## 15. 如何安排学习顺序

系统学习：按第 01–30 篇推进，每完成一个阶段整理输入、输出与关键判断，再选择相关项目验证。首次接触数据与后训练系统时，建议采用这条路线。

侧重数据工程：先学第 01–17 篇，结合项目一、二、三理解语料加工、数据血缘和配方管理，再进入第 18–22 篇，学习持续预训练、SFT 与偏好数据。

侧重后训练平台：先学第 01–03 篇建立对象与版本模型，再学第 16–30 篇，重点结合项目四、五、六。样本构造、分片和断点续读会影响训练复现与恢复，应与算法和调度一起学习。

## 16. 怎样把知识变成项目成果

阅读时先明确本篇要解决的问题，再梳理对象、公式和因果关系；进入实验后，记录输入与配置，检查结果是否符合预期。随后改变一个条件，观察结果或失败方式如何变化，并回到正文解释原因。

项目练习应逐步积累可复用的成果：数据处理规则与数据卡、版本和血缘记录、样本与配方配置、训练目标对照、故障记录及恢复方案。正文提供设计与实验依据，具体项目的完成范围应以实际实现和验证的部分为准。

## 17. 如何检查学习效果

完成一篇后，尝试回答三个问题：这个机制解决了什么问题？什么条件下会失效？用哪项实验观察支持自己的判断？能运行代码之后，还应能解释输入、指标和结果之间的关系。

完成综合项目时，保留可重放的输入、环境配置、版本信息、运行结果与失败记录。性能比较需要同时记录设备、精度、Batch 和序列长度；恢复实验需要说明故障发生的位置，以及恢复后如何检查一致性。

## 18. 实验环境与运行范围

没有 GPU 也可以先学习正文并运行 CPU 机制实验，验证数据结构、算法关系、状态转换与故障处理。CPU 模拟结果用于理解机制，不能据此推算真实模型吞吐或显存表现。

CUDA 基础探针需要 PyTorch 与可用的 NVIDIA CUDA GPU，具体依赖和参数以各目录的 README 为准。探针检查基础执行条件；完整模型训练还取决于模型、数据、精度和显存。多卡与集群方案需要在相应环境中实施和测量。

实验结果中的 passed 表示当前输入满足该实验的检查条件，failed 表示需要排查，skipped 表示运行条件不足。三者分别记录，便于区分代码问题、环境缺口与已经验证的结果。

## 19. 配套实验包与开始方式

配套实验包后续单独整理补充。解压后先阅读根目录 README，再运行环境检查；之后从第一篇开始进入对应文章。项目代码按项目独立组织。

根目录的 `check_environment.py` 用于检查环境，`run_all_simulations.py` 用于批量运行机制实验，`run_all_gpu.py --check-only` 用于检查 GPU 条件。具体命令和参数在实验包与各篇代码说明中提供。

建议先完成第 01 篇：画清数据对象之间的关系，运行机制实验，再带着结果进入后续章节。
