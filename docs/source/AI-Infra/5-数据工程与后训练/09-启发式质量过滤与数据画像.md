# 启发式质量过滤与数据画像

## 1. 本文要解决的工程问题

团队把低困惑度、长正文和少广告组合成一个质量分，阈值一收紧，网页模板少了，短回答、诗歌和代码说明也一起消失。

本文围绕一个可执行判断展开：怎样用可解释画像和灰区机制校准启发式质量门槛？读完应能给出自己的系统边界、输入输出、版本关系和验收证据，而不是只复述工具名称或公式。

## 2. 本文交付物与判定标准

本文的核心决定是：先做可解释的数据画像，再用分桶、灰区和抽样复核校准启发式规则，避免把单一文体偏好写成通用质量。

完成学习和实验后，应当交付一份最小可复现记录，至少包含输入快照、配置、代码版本、运行状态、原始输出和结论边界。验收证据是：每条过滤规则都有命中分布、保留样本、误删样本和切片影响，门槛变化可以从报告复算。

围绕“启发式质量过滤与数据画像”的验收不接受三类替代品：把模拟输出写成真实 GPU 结果；只展示成功样本而隐藏失败与 `SKIPPED`；只给总分，不保存能复算总分的对象级记录。

## 3. 前置知识与实验边界

“启发式质量过滤与数据画像”的机制实验使用 Python 3.10 及以上版本和标准库，重点验证对象、算法或状态转换。真实硬件路径使用 PyTorch；检测不到 CUDA 时必须输出结构化 `SKIPPED`，不得静默改跑 CPU 后仍标成 GPU 实测。

启发式过滤能稳定处理已知模式，无法覆盖事实性、任务价值和所有新型垃圾内容。

### 3.1 业务背景与失败模式

经过解析、规范化和边界清洗，文本已经“能读”，但它还不一定值得消耗训练 Token。网页抓取中仍会出现关键词堆砌、自动生成目录、残缺句子、广告列表、搜索结果、乱码残余、重复段落、模板化商品页和极短信息；代码与对话数据也各有低价值形态。启发式质量过滤的任务，是用成本低、含义清楚、可大规模执行的统计信号描述这些现象，并在有证据的范围内做保留、降权、隔离或删除。

这不是为文本定义一个永恒的“好坏”。同一份电话号码列表对通用语言建模价值有限，对信息抽取却可能有用；口语化论坛对百科问答不够整洁，却承载真实对话与方言；短代码片段不能用自然语言句末标点规则衡量。因此，本文把质量定义为“相对于数据用途的可观察适配度”，把启发式规则定义为有版本、有范围、有误伤预算的决策组件。

完成后应能从零设计一套质量特征 Schema，解释长度、词形、符号、重复、熵、句法代理和结构特征的含义；能用数据画像而非直觉设置阈值；能建立保留、拒绝和灰区三路输出；能在 CPU 上复现特征计算与规则执行；能在至少一张可用 CUDA GPU 上验证批量张量特征路径，并在无 GPU 时诚实返回 `skipped`；还能把一次删除率异常追到具体规则、来源和样本。

### 3.2 学习目标与能力清单

### 2.1 上游输入合同

质量过滤读取的是已经完成基础解析和低风险规范化的 typed unit。每条记录至少需要稳定 record_id、source_id、unit_type、clean_text、父视图摘要、语言证据、结构元数据和权限域。过滤器不能重新猜编码、重新解析 HTML 或把对话展平成普通正文；上游若缺少这些字段，应返回 invalid_contract，而不是用默认值继续。质量分布强烈依赖解析方式，因此 parser_recipe 也是画像切片的重要维度。

### 2.2 下游输出合同

输出不应只有一个布尔值。至少包含 feature_vector、rule_hits、quality_status、decision_reason、policy_id 和运行版本。quality_status 推荐区分 accepted、gray、rejected、invalid 与 skipped。accepted 表示通过当前用途的硬门禁，不表示绝对高质量；gray 表示证据矛盾或靠近阈值，需要模型评分、人工抽样或下游降权；rejected 表示命中经过验证的排除条件；invalid 表示特征无法可靠计算；skipped 表示硬件或依赖路径未执行。

### 2.3 与模型化质量评分的边界

启发式规则回答可解释的局部问题，例如“字母词占比是否异常低”“最长重复行是否过高”“文档是否主要由项目符号组成”。模型化评分学习多个信号之间的非线性关系，可能发现规则难表达的教育价值、连贯性和领域风格。两者不能互相冒充：规则层适合做安全护栏、低成本预筛和画像；模型层适合排序与软选择。下一篇会专门讨论模型层，本文只在实验中使用最小可解释组合，不把它包装成训练质量真值。

### 2.4 与去重的边界

重复特征关注单文档内部的行、段落、n-gram 和字符运行，用于发现模板与关键词堆砌；跨文档近似重复属于去重系统。内部重复高的诗歌、代码生成文件和法律条款不一定该删除，跨文档唯一的垃圾页也不因此变好。规则要保存重复发生在哪些跨度，并让 unit_type 与用途参与决策。去重标识可以作为画像特征，但过滤器不应自行改写集群代表。

### 2.5 与安全和版权的边界

质量差不等于有害，质量高也不等于许可可用或安全。成人、隐私、恶意代码、版权退出和投毒需要独立策略与权限。把它们塞进 quality_score 会导致下游只看到一个数字，无法执行强制 Policy。质量系统可以接收安全状态作为先决条件，也可以把异常统计送安全侧输出，但不能用“低质量”掩盖治理决定。

### 3.3 实验准备与责任边界

### 3.1 为什么没有单一客观质量

设文档为 $d$，用途为 $u$，质量可以写成一组条件向量，而不是一个自然常数：

$$Q(d,u) = \left[q_{read}, q_{structure}, q_{information}, q_{language}, q_{diversity}, q_{task}\right]$$

可读性、结构完整、信息密度、语言一致、多样性和任务适配可能互相冲突。教育文章在知识任务上高分，口语对话在交互任务上更重要；高结构化列表不适合普通语言建模，却适合实体学习。工程上可以为特定 Release 定义组合策略，但必须保留原始特征，不能只存组合后的单值。

### 3.2 硬门禁、软分与灰区

软分不能豁免硬约束；排序还须受覆盖预算限制。

硬门禁只用于证据强、误伤代价经过验证的情形，例如空文本、严重解码损坏、超过资源上限或几乎全部为单一标点。软分用于连续权衡，例如长度、平均词长、句子比例、重复度和停止词覆盖。灰区承接阈值附近、规则冲突与新来源。一个典型决策可以表达为：先检查 invalid 与 Policy，再执行少量 hard reject，随后根据 soft score 和不确定性进入 accepted 或 gray。

### 3.3 规则的逻辑形式

固定抽检集帮助比较版本，但还需要新增来源样本。

每条规则 $r$ 应包含适用域 $A$、特征函数 $f$、阈值区间 $T$、动作 $a$ 和原因码 $c$：

$$r(d)=\begin{cases} a,& d\in A \land f(d)\in T,\\ \text{no-op},& \text{otherwise}. \end{cases}$$

适用域至少可约束来源、语言、长度、unit_type 和 Recipe。动作不是只能删除，还可标注、降权、隔离或请求更强评估。规则冲突由显式优先级和风险级别解决，不能依赖配置文件偶然顺序。

### 3.4 选择函数与保留预算

当 Token 预算 $B$ 有限时，过滤实际上是一个选择问题：

$$\max_{x_i\in[0,1]}\sum_i x_i V(d_i,u),\quad \text{s.t.}\quad \sum_i x_i T_i\le B.$$

启发式特征只能近似价值 $V$，而且某些语言与领域会系统性低估。因此不要仅按一个分数从高到低截断。生产配方通常先分层保障覆盖，再在层内按质量与重复度采样，同时为长尾语言、来源和内容类型设置最小预算。过滤与混合虽是两个阶段，但画像必须为后续约束优化提供足够维度。

### 3.5 误删比漏删更难恢复

漏过一些低价值文本会消耗 Token，误删稀有高价值文本则可能永远失去覆盖。两者成本依模型规模、数据稀缺度和重新抓取能力而变。规则评审应分别估计 false reject 与 false accept，而不是只报 accuracy。在强不平衡数据中，一个看似百分之九十九准确的规则仍可能误删大部分少数语言。默认策略应保守保留父资产，先以灰区或采样降权观察下游影响。

## 4. 数据画像：在设阈值之前先理解分布

### 4.1 画像不是一张均值报表

总体阈值可能系统性排除长尾切片。

平均长度、平均符号率很容易被极端值支配。可靠画像要给分位数、直方桶、零值率、缺失率、最大值和代表样本，并按来源、抓取时间、语言、unit_type、解析器版本和权限域切片。对高基数域名，可以离线保存 TopK 与长尾桶，在线监控只使用受控标签。画像产物应绑定父 Manifest 和特征 Recipe，使阈值决策能够复现。

### 4.2 基线、候选与差分画像

基线描述已发布版本，候选描述新配方，同父数据差分描述每个特征和状态的迁移。若输入集合也变化，应另做 cohort 报告。差分不仅比较总体拒绝率，还要展示规则新增命中、旧命中消失、accepted 到 rejected、语言与来源切片变化，以及按训练采样权重计算的暴露量。稳定 Hash 样本让评审者能连续观察同一批文档。

### 4.3 分布漂移与来源漂移

特征分布变化可能来自真实内容变化、抓取源变化、解析器变化或过滤器故障。监控要同时观察输入画像和输出画像，并保留 source cohort。可以使用 Population Stability Index、Jensen-Shannon 散度或分位差作为告警信号，但它们只提示“变了”，不说明“坏了”。告警后必须结合样本和上游版本判断，不能自动把新分布拉回历史分布。

### 4.4 条件分布比全局分布更有用

中文、英文和泰文的字符/词比不同，代码与自然语言的标点率不同，标题与正文的长度不同。全局阈值会把少数群体当异常。画像应至少估计 $p(\text{feature}\mid\text{language},\text{unit\_type},\text{source\_class})$，并在数据足够时加入长度桶。低样本切片可以使用父层阈值或贝叶斯收缩，但必须标记支持度，不能根据几个样本产生极端规则。

### 4.5 画像中的守恒关系

输入记录应等于 accepted、gray、rejected、invalid 和 skipped 之和；输入字符可分解为各状态字符量；每条规则的命中可以重叠，因此不能直接相加当作拒绝总数。画像系统要区分独占最终原因与非独占 rule hit。重复尝试必须按逻辑 record_id 去重。守恒断言失败时，整批画像不可用于发布决策。

## 5. 基础长度与结构特征

### 5.1 字节、字符、字素簇、词与 Token 长度

至少同时记录 UTF-8 字节、Unicode 代码点、字素簇近似、空白切分项和目标 Tokenizer Token 数。不同语言的词边界并不统一，空白词数不能跨语言直接比较。Token 长度直接关系训练成本，却受 Tokenizer 版本影响。短文本门禁应按 unit_type 制定：标题十个字可能完整，正文十个字通常信息不足，代码函数也不能用句子长度判断。

### 5.2 行、段落与句子统计

记录行数、非空行数、段落数、句子数、最长行、行长分位和空行率。单行超长网页可能是解析器丢失换行，逐词一行可能是错误 DOM 抽取；大量短行可能是诗歌、字幕或菜单。句子切分器必须语言感知，并允许失败状态。质量规则使用这些统计时要结合结构类型，不能把“每行一个短语”一律当垃圾。

### 5.3 截断与残缺代理

文档以逗号、未闭合括号、半个 HTML 实体、孤立列表项或未闭合代码围栏结束，可能提示抓取截断。可计算括号与引号平衡、末尾标点类型、围栏配对和解析器 truncated 标志。自然语言存在故意省略，代码片段也可能本就不完整，因此这些更适合进入 gray 或形成连续分，不宜单独硬拒绝。上游字节范围和 HTTP 长度证据比文本猜测更强。

### 5.4 列表与目录密度

项目符号、编号前缀、短行与链接组合可以识别目录或导航。特征包括列表行比例、相邻编号连续性、平均列表项长度、链接密度和正文段落比例。教程步骤和法律条款也是列表，是否有训练价值取决于项内完整性与上下文。FineWeb 一类管道会探索 list-like 过滤，但生产复用时必须在自己的语言与领域上重新消融。

### 5.5 结构多样性

高质量长文通常包含一定的句长和段落变化，但“越多样越好”不是定律。可以计算行长变异系数、段落长度熵、句型代理与标题正文比，作为画像而非硬规则。模板生成页可能每段长度完全相同，OCR 错序也可能表现为异常高变异。结构特征的价值主要在与重复、符号和来源证据联合，而不在单独阈值。

## 6. 字符、词形与符号特征

### 6.1 字符类别比例

按 Unicode 类别统计字母、数字、标点、符号、分隔符、控制与标记字符比例，并额外统计 replacement character、私用区和不可见格式字符。分母必须明确是代码点还是字素簇。数学、代码和表格天然符号多，商品与金融数据数字多，不能套自然语言门禁。异常比例先用于路由和抽样，再结合 unit_type 做决定。

### 6.2 字母词与停止词覆盖

英文 Web 过滤常用 alphabetic word ratio、stopword presence 等代理判断是否像连贯语言。多语言系统必须为每种语言维护合适词表和 Tokenizer，并记录覆盖版本。停止词少可能是关键词堆砌，也可能是标题、专业术语或黏着语分词失败。词表不支持的语言返回 not_applicable，绝不能按零分处理。

### 6.3 平均词长与超长词比例

乱码、无空格拼接或 Base64 片段常产生极长空白 Token。记录平均、P95、最大词长，以及超过阈值的 Token 比例。URL、哈希、化学式、代码标识符和某些语言正常词也可能很长。可以先识别 URL/代码/编码块，再计算自然语言词特征；高超长词比例更适合隔离检查，而非单规则删除。

### 6.4 数字与标点密度

数字率高可能是价格表、日志、统计数据或垃圾关键词；标点率高可能是代码、公式、ASCII 图或乱码。除了总体比例，还应记录连续运行、不同字符数和局部窗口最大值。自然语言正文中的长标点运行比总标点率更可疑。中文等语言句末标点与英文不同，终止标点规则需要本地化，并注意标题通常无句号。

### 6.5 大小写与全大写词

英文全大写词比例可提示广告、标题或机器生成噪声，但缩写、法律文件、代码常见大写。应在语言为拉丁脚本且 unit_type 为自然语言时适用，排除短缩写和句首效应。大小写信息在清洗层未被折叠才能计算。最终保留原始特征与归一化分母，避免未来规则无法重算。

### 6.6 特殊代用标记符与模板 Token

“lorem ipsum”、变量代用标记、CMS 错误、登录提示、Cookie 文字、模板花括号和连续下划线可作为站点噪声信号。关键词列表不能成为全局删除规则，因为教程正文可能讨论这些词。更可靠的特征是代用标记符密度、位置、跨页面重复与结构角色。匹配规则需要语言和来源范围，命中原文保存在受控证据中。

## 7. 重复与信息密度特征

重复比例是代理特征，合法列表和代码也可能高重复。

### 7.1 行重复率

设规范化非空行为 $l_i$，出现次数为 $c(l)$，可以计算重复行字符占比：

$$R_{line}=\frac{\sum_l \mathbb{1}[c(l)\gt 1]\cdot c(l)\cdot |l|}{\sum_i |l_i|}$$

分母使用字符量比使用行数更能反映长模板的影响。还应记录最高频行、唯一行率和连续重复。诗歌副歌、法律声明和代码生成文件可能合法重复，因此 rule hit 必须携带类型与代表跨度。

### 7.2 段落重复率

段落级重复对网页模板、拼接错误和内容复制更敏感。规范键可做 NFC、空白折叠和有限大小写处理，但不能用过强 NFKC 改变语义。对很短段落，碰撞和自然重复高，应设置最小长度。可同时计算完全重复和近似指纹，但跨文档聚类仍交给去重阶段。段落重复高可降权或切掉明确模板，而非必然拒绝整篇。

### 7.3 n-gram 集中度

将词或字符 n-gram 计数为 $c_g$，总数为 $N$，可用 Top-K 质量占比、重复 n-gram 比例或 Herfindahl 指数：

$$H=\sum_g\left(\frac{c_g}{N}\right)^2$$

关键词堆砌和循环生成会产生高集中度。$n$ 取值、分词方式和文本长度强烈影响结果，短文不稳定。中文可使用字符 n-gram 或经过验证的分词，代码则需 Token 级特征。画像应按长度桶展示分布。

### 7.4 字符熵与压缩率

字符分布熵为：

$$E=-\sum_c p(c)\log_2 p(c)$$

极低熵可能是单字符重复，极高熵可能是加密、压缩、Base64 或多脚本乱码，但自然语言的熵受语言和长度影响。压缩比提供另一种重复代理，模板和重复文本更易压缩。两者都只能做异常检测；高信息密度并不等同高训练价值，随机字符的熵也很高。

### 7.5 唯一词比例

type-token ratio 随长度增长自然下降，不能使用统一阈值。可以按长度桶比较，或使用移动平均 TTR、根号修正等稳定形式。关键词堆砌可能唯一率低，术语表可能很高。对没有可靠词边界的语言，使用字符 n-gram 多样性。特征名称必须写明 Tokenizer 与大小写策略，避免不同实现同名。

### 7.6 局部重复与全局平均

一个文档可能只有尾部百分之十发生无限循环，总体重复率仍不高。滑动窗口计算局部最大重复、熵和符号率，可以定位异常跨度。窗口大小用字符或 Token 表达并记录版本。若异常只在明确尾部，边界清洗可切除；若散布全文，整篇降权更合理。输出最大窗口值与位置，方便人工验证。

## 8. 可读性、连贯性与信息代理

### 8.1 句末标点比例

统计非空行或句子是否以适合该语言的终止标点结束，可发现菜单、关键词列表和提取断行。它曾被一些 Web 数据流程采用或消融，但不能盲目复制。标题、列表、聊天短轮次、代码和诗歌不遵守句末规则。特征应只对适用块计算，并保留 not_applicable 比例。是否作为过滤条件由目标数据的模型消融决定。

### 8.2 功能词与连贯文本代理

功能词覆盖、代词/介词/助词比例能区分自然句子与随机关键词，但对专业术语、公式和低资源语言偏差显著。词表来源、词形变化和分词器都影响结果。比起“至少包含两个停止词”的硬规则，更稳健的是作为连续特征进入画像，并对极短文本不计算。人工抽样需覆盖方言和非标准书写。
