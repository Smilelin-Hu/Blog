# 去重与安全：删得对，也删得可解释

去重是数据流水线里最容易被「一句已去重」糊过去的环节；安全与合规则是最容易被工程当成法务问题甩出去的环节。两者其实是同一件事的两面：**你必须能证明「保留了谁、删除了谁、依据是什么」。**

## 1. 「重复」是一种关系，不是属性

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l11_01.png" width="78%" alt="去重分层" />
  <p>图 1：从字节摘要到语义复核，成本逐层上升，规模逐层缩小</p>
</div>

两个压缩文件字节不同，解压后正文可能相同；两个网页只差一个日期，从训练语义看近似重复；两篇独立新闻描述同一事件，语义相近但事实细节不同，**未必该删**。

所以每条去重规则必须回答四个问题：

1. **比较什么表示**（字节 / 规范化文本 / Shingle 集合 / 语义向量）；
2. **在哪个粒度比较**（对象 / 文档 / 段落 / 子串）；
3. **用什么相似函数**（哈希相等 / Jaccard / 编辑距离 / 余弦）；
4. **什么阈值算同簇**。

缺任一项，「已去重」都不是可复现结论。

## 2. 五类去重与用途差异

| 类型 | 适合发现 | 主要风险 |
|---|---|---|
| 字节级 | 完全相同的原始对象（省解析与存储） | 只能抓完全一致 |
| 规范化文本 | 编码/换行/Unicode/标点差异 | 规范化过强会合并不同内容 |
| 模糊文档 | 大部分内容重合 | 阈值难定，跨站转载与同题不同文混淆 |
| 段落/子串 | 文档内或跨文档的局部拷贝 | 长文档里的引用与模板难区分 |
| 语义 | 改写与同义表达 | 误删知识互补内容的风险最高 |

**用途会改变判断**：

- 预训练：想删大段转载，但保留同一概念的多种自然表达；
- SFT：可能要保留同题的不同高质量解法；
- 偏好数据：**必须保留同 Prompt 的不同响应**——差异正是监督信号；
- 评测去污染：宁可提高召回，再对命中受控复核。

## 3. 级联：成本从低到高

```text
字节摘要 → 规范化精确哈希 → 模板/段落统计 → Shingle + MinHash 候选
        → 少量候选做 Jaccard / 编辑距离 / 长子串 / 语义复核
```

两个理由：全量两两比较是 \(O(N^2)\)，规模一大就不可行；昂贵算法**不一定更可靠**——把所有文档直接丢进语义 Embedding，既贵，又可能把主题相近但内容互补的文档错并。

每层都要记录：输入量、候选量、确认簇、删除量、耗时、资源、抽检结果。**只存最终保留集，就无法判断某条文档在哪一层消失**，阈值调整时也不能复用上游特征。

还要写清短路条件与例外：精确哈希相同可直接同簇，但若许可/来源优先级要决定代表，仍需把全部成员送进代表选择；**低质量文档不应在记录重复关系前删掉**——它可能有助于识别其他来源的模板簇。

## 4. 比较视图与训练视图

去重通常对文本做规范化：Unicode 归一、大小写折叠、空白合并、控制字符删除、数字与 URL 代用标记。规范化越强越容易发现形式重复，也越容易误合并。

铁律：**比较视图是训练文档的派生字段，不能覆盖原文。** 代码大小写、数学符号、空格缩进、标点都可能有语义；为了指纹方便去改训练内容，等于把「去重」变成「不可逆清洗」。

规范化 Recipe 必须版本化，至少记录：Unicode 形式、语言相关大小写规则、空白定义、标点处理、HTML 实体、数字与 URL 策略。**哈希必须绑定 Recipe ID**，否则两套规范化的摘要不可直接比较。

异常输入也要防：超长重复字符、混合方向文本、非法代理字符、零宽字符、组合字符，都可能让「看起来相同」产生不同表示，或让正则耗时异常。要设长度与时间上限，失败时保留状态，**不要把异常统一映射成空串**。

## 5. 精确哈希的正确用法

- 加密摘要：碰撞风险极低，适合跨系统稳定标识；
- 高速哈希：吞吐高，适合分区与内存表；可用它做候选键，再用长度、第二摘要或原文比较确认；
- **不要用语言运行时的默认哈希当持久 ID**：很多实现会随机化种子，不同进程结果不同；
- 完全相同的摘要也不代表代表样本可以随便选：同一内容可能出现在原创站、聚合站、低质量镜像、许可未知来源。簇内要保存所有成员元数据，再按来源可信度、许可、解析质量、时间、结构完整性选代表；
- 分布式实现先按摘要前缀分桶，让相同摘要必进同分区；**警惕空文档/通用模板造成的超大热桶**，否则单个 Worker 会成长尾。

### 5.1 外部排序 vs 哈希聚合

- 摘要能进内存：哈希表聚合简单高效；
- 超内存：分区写盘或多路归并外部排序（相同摘要相邻，内存只需保存当前组）；
- 选择取决于数据规模、带宽、分区数与是否需要有序输出；
- **任务重试必须幂等**：输出路径由「输入版本 + Recipe + 分区 ID」派生，写完校验再提交；全局 Manifest 只引用全部通过计数校验的分区。

## 6. Bloom Filter：只回答「肯定不存在」

$$
p \approx \left(1 - e^{-kn/m}\right)^k,\qquad k^\ast = \frac{m}{n}\ln 2
$$

三条纪律：

1. **有假阳性，无假阴性**（实现正确前提下）——适合在昂贵查询前挡掉「明显新键」；
2. **命中后仍需查精确摘要**：把「可能存在」当重复删除，假阳性就会变成永久数据损失；
3. **容量超设计值会迅速饱和**，要监控插入数与位密度；普通 Bloom 不支持安全删除，删除需求用 Counting Bloom 或重建。

## 7. Shingle 与 Jaccard

把文本切成连续 Token/字符 N-gram：

$$
J(A,B) = \frac{|S_A \cap S_B|}{|S_A \cup S_B|}
$$

- Shingle 太短：常见短语产生大量偶然重叠；太长：对微小编辑过敏；
- 词级对自然语言直观但依赖分词，字符级跨语言统一但受空白/编码影响；
- **集合会丢频次**：一段模板出现十次与一次贡献相同；若频次有意义，用 Multiset Jaccard、加权 MinHash 或单独模板比例特征；
- 短文档（如几个词的标题）Shingle 不足，估计方差大，应改用规范化精确匹配或单独阈值。

### 7.1 为什么不能全量算

\(N\) 个文档有 \(N(N-1)/2\) 对，百万文档就接近五千亿对。必须先做**候选生成**，并同时报告两个指标：**候选缩减率**与**候选召回**。只报最终簇 Precision，会掩盖分桶/LSH 参数造成的盲区。

分桶要谨慎：按长度过滤有数学依据（集合大小差太多不可能高 Jaccard），但**按域名分桶会漏跨站转载，按语言分桶会漏翻译与语言识别错误**。安全分桶应来自相似度上界，或仅用于资源规划，并保留跨桶策略。

## 8. MinHash 的概率含义

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l12_01.png" width="78%" alt="语义去重" />
  <p>图 2：签名碰撞是概率证据，不是「两篇相同」的证明</p>
</div>

对同一随机排列，两集合最小元素相同的概率等于 Jaccard。实践用一组近似独立哈希，每个哈希取所有 Shingle 哈希的最小值，组成签名；**相等位置的比例是 Jaccard 的无偏估计**。

若真实相似度为 \(s\)，每个位置近似是成功概率 \(s\) 的 Bernoulli，方差 \(s(1-s)/h\)——增加签名数降低方差，但线性增加计算/存储/比较成本。**参数应由目标阈值附近的允许误差反推，不能照抄默认值。**

三个实现级坑：哈希独立性不足、整数溢出、Shingle 预哈希碰撞。

## 9. 安全与合规：工程要执行的是「已批准的结论」

### 9.1 四类记录

| 记录 | 内容 |
|---|---|
| Policy Registry | jurisdiction、purpose、data class、action、conditions、生效时间、owner、法务批准、优先级、版本；编译成规范 IR + digest，Worker 只读签名产物 |
| Rights Record | 来源/文档在具体用途上的许可、授权基础、地域、期限、署名、再分发、模型训练、派生物、退出渠道 |
| Data Class | public / internal / confidential / personal / sensitive / regulated / restricted-benchmark / security-quarantine；**质量分不能降低分类级别** |
| Decision | allowed / denied / review / quarantined / withdrawn / expired / invalid / skipped |

注意语义差别：**unknown ≠ denied**，**expired ≠ withdrawn**；`allowed` 绑定用途与截止时间，**不是全局布尔**；**隔离是限制使用，不等于已删除或已判定违规**。

冲突解决走「已批准优先级」：强制删除 > 法律保留 > 安全隔离 > 许可拒绝 > 隐私限制 > 质量与采样。**法律保留可能要求隔离但不删除，且训练仍不可用。**

### 9.2 PII 发现 ≠ 身份确认

正则、NER、模型能发现「像邮箱/电话/地址/证件号/姓名」的跨度，但**不能证明它属于某个请求人**，也不能判断公开事实是否可处理。Finding 要存类型、跨度、confidence、detector 与上下文级别；身份与权利请求走独立流程。**不要把 NER 预测当法律结论。**

去标识化的手段（删除/掩码/替换/泛化/Token 化/合成替代）各有用途，但要记住：**只删直接标识符不保证匿名**，准标识符组合可重识别。代用标记保持类型（`PERSON_1`、`EMAIL_1`）以免关系丢失；映射表权限更高；**「做过脱敏」不自动等于允许训练**。

日志是常见泄露口：异常栈、debug payload、人工截图、模型 Prompt、监控标签都可能绕过正文权限。默认只记 record/type/reason/trace，看原文走受控工作台；用敏感哨兵字符串测试所有 Sink。

### 9.3 版权、许可与退出

- **版权不能压成质量分**：内容原创、准确、教育性高，不说明训练/复制/再分发/商用获得许可；
- **许可随血缘传播**：解析、清洗、去重、Embedding、标签、训练 Manifest、发布包都要继承 Rights 引用；合并多个文档时按「最严格」或显式组合规则；
- **署名与 NOTICE**：若条件要求署名，发布流程要生成完整清单，代表选择不能导致唯一许可证据丢失；
- **版权退出**：提供可验证请求渠道，记录作品/主张/范围/身份/决定/执行；批准后沿影响图处理父与派生、阻断未来摄取、评估已有模型。

### 9.4 投毒威胁模型

攻击目标不同，检测与处置就不同：降低总体能力、植入触发后门、偏置特定实体、操纵评测、窃取秘密、耗尽资源。威胁模型要写清攻击能力、知识、入口、预算与成功条件。

供应链入口不止正文：来源网页、开放仓库、供应商包、标注、Teacher 模型、Tokenizer、规则配置、容器、对象存储都可能被篡改。纵深防御靠**Artifact 摘要 + 签名 + SBOM + 最小权限 + 审批 + 不可变 Manifest**。

## 写在最后

这一篇的结论可以压缩成两句话：**去重要说清「比较什么、怎么算、为什么保留这一个」；安全要说清「谁批准、依据什么、删了之后影响谁」。**
