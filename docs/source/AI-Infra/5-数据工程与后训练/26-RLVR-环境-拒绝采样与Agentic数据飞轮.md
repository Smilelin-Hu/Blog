# RLVR、环境、拒绝采样与 Agentic 数据飞轮

## 1. 本文要解决的工程问题

代码任务用单元测试做奖励后，模型发现测试漏洞；Agent 任务用环境成功做奖励后，环境状态又无法稳定复现。可验证奖励仍可能被投机。

本文围绕一个可执行判断展开：怎样为 RLVR 与 Agentic RL 设计任务、环境、验证器、拒绝采样和数据回流？读完应能给出自己的系统边界、输入输出、版本关系和验收证据，而不是只复述工具名称或公式。

## 2. 本文交付物与判定标准

本文的核心决定是：把 Task、Environment、Verifier、Trajectory 和 Rejection Reason 版本化，给验证器做对抗测试并保留失败轨迹。

完成学习和实验后，应当交付一份最小可复现记录，至少包含输入快照、配置、代码版本、运行状态、原始输出和结论边界。验收证据是：任务集覆盖正常、边界和诱骗样本；同一轨迹在固定环境和验证器版本下能复算奖励与终止状态。

围绕“RLVR、环境、拒绝采样与 Agentic 数据飞轮”的验收不接受三类替代品：把模拟输出写成真实 GPU 结果；只展示成功样本而隐藏失败与 `SKIPPED`；只给总分，不保存能复算总分的对象级记录。

## 3. 前置知识与实验边界

“RLVR、环境、拒绝采样与 Agentic 数据飞轮”的机制实验使用 Python 3.10 及以上版本和标准库，重点验证对象、算法或状态转换。真实硬件路径使用 PyTorch；检测不到 CUDA 时必须输出结构化 `SKIPPED`，不得静默改跑 CPU 后仍标成 GPU 实测。

程序奖励降低主观标注成本，不保证验证器无漏洞，也不覆盖开放域行为的全部质量。

### 3.1 业务背景与失败模式

### 1.1 可验证奖励

给定任务实例 $x$、策略轨迹 $\tau$ 与环境 $E$，验证器 $V$ 输出奖励、终止、证据和原因：

$$(r, done, evidence, reason)=V(x,\tau,E)$$

奖励可以是二值成功、测试通过比例、约束满足向量或分阶段得分。真正重要的不是标量，而是证据是否能重放：测试输出、最终状态摘要、资源用量、错误类型、环境版本和验证器版本都应保留。一个裸 `reward=1` 无法审计，也无法在验证器升级后重新解释。

### 1.2 任务实例

任务不是一段 Prompt，而是带版本的契约：初始状态、允许动作、工具 Schema、资源限制、成功条件、隐藏测试、超时、随机种子、数据许可和安全等级。相同文字在不同依赖、文件系统或网络条件下可能有不同答案。任务注册表为每个实例分配不可变 ID，公开描述与私有验证资产分离，防止训练过程读取隐藏答案。

### 1.3 环境

环境接收动作并返回观察，维护状态与副作用。代码环境包含文件、依赖、编译器和测试；浏览环境包含页面状态、会话和网络策略；科学环境包含模拟器、初值与随机过程。环境镜像、工具版本、网络、时钟、随机源和资源配额共同决定语义。只固定容器标签而不固定镜像摘要，仍无法复现。

### 1.4 轨迹

缺失处理须预先定义，不能随意用新策略补齐旧组。

轨迹是观察、思考或计划、动作、工具回执、奖励与终止的有序记录。训练数据通常不应保留不必要的私密内部信息，但必须保存足以验证行为的状态。每步有 step_id、parent、timestamp、action schema、observation hash、token usage 和错误码。分支搜索还要记录树关系和选择原因，不能只保存最终胜者。

### 1.5 验证器

验证器由解析、规范化、执行、比较和聚合组成。解析失败与答案错误不同，超时与逻辑失败不同，环境故障更不能当策略负奖励。原因码决定重试、数据用途和训练权重。验证器本身有测试、版本、所有者、权限和红队；它是生产代码，不是临时评测脚本。

### 1.6 奖励与证据分离

同一证据可按不同产品代价聚合成奖励。例如十个测试通过九个、一次危险文件写入，简单平均可能仍很高；安全门控应先判失败，再计算功能分。保存原始向量让聚合规则可以升级。训练消费的标量必须绑定 aggregation_version，不能在历史轨迹上静默重算后仍使用旧数据版本。

### 1.7 RLVR 与 Reward Model

闭环优化的是验证信号，验证器正确性必须独立检查。

可验证奖励通常在覆盖范围内更客观，但不一定稠密，且验证器可能不完整。Reward Model 覆盖开放风格与人类价值，但易受偏差和 Goodhart。系统可组合：硬验证决定可行与安全，学习型 Reward 在通过集合中排序；或用验证结果训练过程模型提供稠密信号。两者职责清楚，不能让软分抵消硬失败。

### 1.8 RLVR 与离线偏好

验证器可以从同一 Prompt 的候选中自动构造 chosen/rejected，也可以直接提供在线 RL 奖励。前者便宜、稳定，受离线覆盖限制；后者能探索新轨迹，成本和方差更高。拒绝采样介于两者之间：大量生成，通过验证筛选，再用于 SFT 或偏好训练。本文把三者视为同一数据飞轮的不同消费方式。

### 3.2 学习目标与能力清单

### 2.1 数学与形式答案

最终数值、代数式或选项可规范化后比较。解析器要处理等价表达、单位、精度、区间和多答案，避免只接受字符串完全相等。对于证明题，最终结论正确不代表过程有效，可增加定理检查或步骤验证。隐藏答案必须与 Prompt 存储隔离，策略容器不能读取评分文件。

### 2.2 代码任务

编译、单元测试、静态检查、性能和安全规则形成奖励向量。公开测试提供反馈，隐藏测试防止硬编码；随机生成测试扩大覆盖。沙箱限制 CPU、内存、磁盘、进程、网络和系统调用。测试通过证明覆盖范围内行为，不证明不存在未测错误，异常高分提交优先人工审计。

### 2.3 结构化输出

JSON Schema、语法树、SQL 解析和类型检查可以稳定验证格式与局部语义。只验证 Schema 会奖励语法正确但内容虚假的输出，因此再检查字段关系、数据库只读执行或业务约束。解析器需区分多余文本、编码和截断，避免模型用包装绕过检查。

### 2.4 工具调用

验证最终环境状态而非模型自述。例如日历事件是否真实存在、文件是否生成、数据库事务是否满足约束。使用模拟或隔离账户，所有副作用可回滚。工具返回必须由环境签名或可信通道写入轨迹，禁止策略伪造“调用成功”的文本获得奖励。

### 2.5 搜索与浏览

目标可能是找到正确证据、完成多页导航或提取结构化信息。验证器检查引用是否存在、页面状态和最终答案；网络内容随时间变化，任务需要快照或时间戳。机器人限制、登录和隐私边界由环境控制。不能为了训练绕过站点权限或把真实用户凭据注入轨迹。

### 2.6 游戏与模拟器

环境直接给分，适合长程策略。随机种子、物理版本和帧步定义影响结果；高分可能来自模拟器 Bug。分离训练种子与评测种子，保存动作和状态摘要，设置物理不变量与异常检测。策略发现漏洞时，先修环境并重标数据，而不是庆祝奖励提升。

### 2.7 科学与工程任务

可用数值残差、约束满足、仿真结果或实验计划检查。近似误差、单位和边界条件必须显式。若验证成本昂贵，可先用廉价代理筛选，再对候选运行高保真验证；训练账本保留两级分数和选择概率，防止代理取代真实目标。

### 2.8 Agentic 工作流

任务跨多个工具和状态，成功标准既含最终结果，也含权限、成本、步骤与恢复。验证器检查不变量，例如不修改禁区、所有外部写入可追踪、失败后状态一致。长轨迹奖励稀疏，需要过程证据或层级任务，但任何稠密奖励都不能改变最终硬约束。

### 3.3 实验准备与责任边界

### 3.1 环境镜像

以内容摘要固定基础镜像、依赖锁、测试资产和启动脚本。构建过程生成 SBOM 与漏洞报告，镜像只读，任务工作区使用临时层。标签仅作人类别名。环境注册表记录兼容的任务 Schema 与验证器，升级通过桥接任务比较旧新成功率。

### 3.2 状态初始化

每次 Episode 从声明的快照恢复，包含文件、数据库、浏览器、工具凭据替身和随机种子。初始化失败属于基础设施错误，不给策略负奖励。状态 hash 在首步记录，结束时保存差异摘要。批量环境池要防止上一个 Episode 残留影响下一个。

### 3.3 隔离

执行不可信代码时采用最小权限、无特权容器、系统调用限制、网络默认关闭、资源配额和超时。高风险工具使用模拟端点。密钥由环境代理代持，策略只获得短期作用域句柄，不接触真实凭据。日志脱敏并限制下载。安全隔离是任务基础设施，不由模型提示保证。

### 3.4 确定性

固定种子并不保证确定，线程、GPU Kernel、网络、时钟和外部服务都可能变化。将可控随机源注入环境，外部内容用快照或录制回放，时间使用虚拟时钟。对无法确定部分做多次运行与统计验收。文档明确“逐位复现”还是“结果分布复现”。

### 3.5 超时

不同原因对应不同训练语义，不能全部映射为零奖励。

超时分为动作、工具、Episode 和验证四层。策略等待与基础设施拥塞要区分；前者可作行为成本，后者应重试或作废。使用单调时钟，记录排队和执行时间。超时后强制清理进程与副作用，验证环境没有泄漏，再进入池中复用。

### 3.6 网络

默认禁止任意外网，按任务允许域名、方法和流量，响应可录制。真实网络任务需要遵守权限、速率和数据使用边界。DNS、证书和重定向也纳入策略。验证器不信任模型提供的页面文本，只信任环境观测。网络失败有独立原因码，不与答案错混合。

### 3.7 工具 Schema

工具参数使用严格类型、枚举、范围和幂等键，返回结构化状态与错误。Schema 版本进入 Prompt 和轨迹，旧模型调用新工具前做兼容层。危险动作要求确认或双阶段提交。验证器检查真实调用日志与最终状态，不从自然语言猜测是否调用。

### 3.8 环境池

冷启动成本高时可预热环境，但每次分配验证镜像、状态和清洁度。池控制器记录租约，Episode 结束清理并运行 Canary；失败实例销毁。不同安全等级使用独立池。利用率优化不能跨任务泄漏状态，缓存只保存公开、不可变依赖。

### 3.9 可观测性

关联 task_id、episode_id、policy_revision、environment_digest、verifier_version 和 trace_id。记录每步延迟、Token、工具错误、资源、奖励向量与终止原因。正文与敏感状态使用权限受控对象，指标只引用 hash。可从一次异常奖励下钻到验证证据和环境日志。

### 3.10 故障分类

至少区分策略错误、格式错误、验证失败、环境初始化失败、工具暂时失败、资源超限、安全阻断和取消。只有策略可归因错误进入负样本；基础设施失败重试且不训练。原因分类器要抽样人工校准，否则错误归因会把平台故障教给模型。

## 4. 验证器设计

### 4.1 先写规范再写代码

规范列出输入、允许等价、成功条件、失败优先级、容差、资源和证据。测试用例覆盖正例、近似正例、明显错、边界、攻击和环境故障。没有规范的验证器会在迭代中随意移动目标，历史奖励不可比。规范版本与代码摘要一起进入任务。

### 4.2 规范化

数学表达可化简、排序或单位转换，JSON 可解析后比较，文本答案可抽取限定区域。规范化必须保守，避免把含义不同的答案折叠。保留原始输出、规范化输出和规则链。任何规则命中率异常变化触发审计，防止策略专门生成解析器喜欢的包装。

### 4.3 隐藏测试

公开测试帮助探索，隐藏测试估计泛化。两者覆盖相同规范而实例不同，隐藏资产不进入 Prompt、镜像可读层或错误消息。测试泄漏检测扫描轨迹和输出。反复训练使用同一隐藏集也会适配，应保留最终盲集并周期生成新变体。

### 4.4 部分奖励

测试通过比例提供稠密信号，但可能奖励只修容易测试、忽略关键不变量。按测试重要性分层，致命项门控，剩余项再加权。权重在训练前固定。报告原始通过向量，不只保存聚合分数。部分奖励的单调性要用反例测试。

### 4.5 多验证器仲裁

解析器、执行器、安全器和 Judge 可能冲突。先定义优先级：环境无效则作废，安全失败则阻断，功能执行决定可行，软 Judge 只在可行集合排序。仲裁返回每个子结果与最终原因。平均所有分数是最危险的默认，因为严重失败会被稀释。

### 4.6 验证器测试

单元测试覆盖解析与容差，集成测试在真实镜像运行，变异测试修改正确答案关键部分应失败，模糊测试探索异常输入，红队尝试路径遍历、资源耗尽、伪造回执和读取隐藏文件。发布前在冻结任务桥接旧新版本，解释每个翻转。

### 4.7 验证器 Hacking

字符串命中可以被绕过，反例应保存在回归集。

策略可能输出特殊浮点、利用未检查字段、读取测试、缓存前次结果、触发超时默认通过或制造日志解析错误。高奖励、低行为合理性和异常资源样本优先审计。发现漏洞后冻结受影响轨迹，修复验证器，重新判分并评估已训练模型，而不是只修未来任务。

### 4.8 版本升级

验证器新版本不应覆盖旧奖励。对历史轨迹可生成新的 evaluation record，保留旧记录和关系。训练数据版本明确选用哪个结果。若新规则改变成功语义，创建任务主版本；若只是修复实现 Bug，也要标记受影响范围。纵向报表避免混合不可比版本。

## 5. 拒绝采样

### 5.1 基本过程

对每个任务从行为策略采样 $N$ 条轨迹，经验证器筛选成功或高质量轨迹，用于 SFT、Pair 构造或轨迹蒸馏。若单次成功概率为 $p$ 且样本独立，至少一条成功的概率为：

$$P(\text{success})=1-(1-p)^N$$

独立假设常不成立，同一策略错误高度相关，因此实际收益可能更低。必须实测 N—成功—多样性—成本曲线。

### 5.2 选择偏差

只保留成功轨迹会让数据集中于策略已会的任务和容易的解法，困难任务消失。训练后平均质量可能提高，却没有扩大能力边界。发布数据时保存每个任务的尝试数、成功数和采样概率，按任务宏观控制权重，并保留失败与无成功任务用于诊断和课程设计。

### 5.3 成功轨迹不一定可学

偶然猜中、利用漏洞、冗长搜索或依赖隐藏状态的成功不适合监督。筛选还需检查过程合法、成本、可解释证据、重复和稳定重放。对随机环境重复运行，只有成功稳定才进入高置信集。最短轨迹也不总最好，过度压缩可能省略必要推理。

### 5.4 失败轨迹的价值

失败包含首错、恢复和边界信息，可构造 Pair、过程监督、错误分类和课程学习。不能把所有失败当 rejected：环境故障和不可判应隔离，近成功与无意义失败价值不同。按原因和距离成功的证据采样，控制负样本难度。保留原始分布避免只训练“漂亮成功”。

### 5.5 候选多样性

提高 $N$ 若只是重复同一路径，收益和数据独特性很低。通过温度、提示变体、策略集成、工具计划和随机环境增加多样性，并用动作序列、状态访问和语义嵌入测量。多样性必须在安全和任务规范内。选择时兼顾成功、成本与覆盖，而非只取最高分同簇样本。

### 5.6 预算分配

固定每题 $N$ 简单但浪费在极易或极难任务。可先少量探索估计成功率和不确定性，再向处于学习边界、价值高的任务追加预算。策略要记录选择概率，防止自适应采样导致评测偏差。生产配额按任务、租户和风险限制，异常高重试触发熔断。

### 5.7 轨迹蒸馏

成功轨迹可转为 SFT 样本，但要决定保留全部工具回执、压缩无效步骤还是提取关键决策。压缩器本身可能改变因果顺序，需重放验证最终行为。保留原轨迹与蒸馏轨迹的父子血缘，训练评测比较直接模仿与压缩版本。

### 5.8 构造偏好

同一任务的稳定成功可作 chosen，策略可归因失败作 rejected；若两个都成功，可按成本、步骤或软质量比较；两个都失败时可按进展形成弱 Pair，但标签不确定。硬成功与软风格分开。Pair 必须来自相同环境初态，否则结果不可比较。

## 6. 稀疏奖励与信用分配

### 6.1 终局奖励的困难

长轨迹最终失败时，不知道早期计划、某次工具参数还是恢复策略负责。把同一个零奖励分给所有 Token 会产生高方差和错误归因。先从环境证据中定位首个不可恢复错误、关键状态变化和仍可恢复节点，再决定过程标签。无法因果判断时保留不确定，不用自动 Judge 强行补齐。

### 6.2 过程验证

每步验证局部合法、状态前置条件、工具结果和进展。例如代码任务可在关键提交运行测试，导航任务检查是否到达子目标。过程信号提高密度，也可能鼓励刷局部分。最终成功和安全不变量保持门控，过程奖励只在其下提供学习形状。

### 6.3 潜势函数

若能定义状态潜势 $\Phi(s)$，可用 $\gamma\Phi(s')-\Phi(s)$ 塑形，理论上在适当条件下不改变最优策略。生产潜势常由启发式或模型估计，条件未必成立。验证插入空动作、绕路和倒退是否获得正分，监控潜势高但最终失败的轨迹。

### 6.4 首错归因

首错不是第一个非理想步骤，而是首次使成功路径显著丧失的动作。需要完整前态、动作、回执和可行恢复分析。多标注者或执行回放给置信。训练可聚焦首错前后对比，后续连锁错误降低权重，避免重复惩罚同一根因。

### 6.5 分层任务

将长任务拆成可验证子目标，如理解需求、建立文件、实现功能、通过测试和清理状态。子目标必须保持与最终目标一致，不能让模型完成形式检查却破坏整体。任务图记录依赖、可选路径和验收，课程难度按子目标组合而非仅按轨迹长度增长。

### 6.6 反事实重放

固定某一步之前状态，替换动作并重放后续，可估计该动作的因果影响。环境必须支持快照，后续策略也需控制。成本高时只对高分歧和关键错误抽样。反事实结果形成 Pair 或过程标签，同时记录重放策略与随机种子，避免把不同后续混为动作效果。

### 6.7 成本奖励

Token、工具调用、延迟和外部资源都可作为成本，但只有在成功与安全集合内优化。过早加大成本惩罚会让策略拒绝或跳过必要验证。先画成功—成本 Pareto，再定义预算与超限门控。不同任务按复杂度设基线，不用统一步骤数惩罚。

### 6.8 不确定奖励

验证器可能返回区间、置信或不可判。训练可丢弃低置信、降低权重、用保守下界或请求高保真验证。最危险的是把不可判转零，因为环境故障就会成为负信号。日志分别报告策略失败率、环境作废率和验证不确定率。
