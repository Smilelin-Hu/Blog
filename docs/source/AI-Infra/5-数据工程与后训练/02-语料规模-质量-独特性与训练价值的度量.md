# 语料规模、质量、独特性与训练价值的度量

## 1. 本文要解决的工程问题

两份语料都写着一万亿 Token：一份重复率高、模板页多，另一份更短却覆盖了更多独特文档。只看名义规模，团队会把存储量当成训练价值。

本文围绕一个可执行判断展开：怎样区分名义 Token 规模与真正影响训练的有效、独特和高价值数据？读完应能给出自己的系统边界、输入输出、版本关系和验收证据，而不是只复述工具名称或公式。

![语料规模与训练价值度量](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l02_01.png)

## 2. 本文交付物与判定标准

本文的核心决定是：把规模拆成名义 Token、有效 Token、独特 Token、可消费 Token 和边际训练价值，并固定每个指标的分母与估计方法。

完成学习和实验后，应当交付一份最小可复现记录，至少包含输入快照、配置、代码版本、运行状态、原始输出和结论边界。验收证据是：同一快照在过滤、去重和分词前后能够复算 Token 总账，代理训练的比较也使用相同预算和切片。

围绕“语料规模、质量、独特性与训练价值的度量”的验收不接受三类替代品：把模拟输出写成真实 GPU 结果；只展示成功样本而隐藏失败与 `SKIPPED`；只给总分，不保存能复算总分的对象级记录。

## 3. 前置知识与实验边界

“语料规模、质量、独特性与训练价值的度量”的机制实验使用 Python 3.10 及以上版本和标准库，重点验证对象、算法或状态转换。真实硬件路径使用 PyTorch；检测不到 CUDA 时必须输出结构化 `SKIPPED`，不得静默改跑 CPU 后仍标成 GPU 实测。

Token 统计可以解释供给结构，不能单独证明某份语料会带来目标能力提升。

### 3.1 业务背景与失败模式

一家团队说自己已经收集了十万亿 Token，另一家团队说只有两万亿 Token。仅凭这两个数字，无法判断哪一方的数据资产更有价值。十万亿 Token 可能包含大量网页模板、镜像站、采集重试、机器翻译副本和重复代码；两万亿 Token 也可能经过严格去重、覆盖多个能力域，并且与训练目标高度匹配。名义规模只是进入流水线的字节或 Token 数，不等于模型真正看到的新信息，更不等于对目标能力产生正向梯度的训练信号。

数据工程最容易出现的管理错觉，是把“存储量增加”“文档数增加”和“模型可学习的信息增加”当成同一件事。一次抓取任务新增一百 TB 原始文件，可能只是采集到了更多压缩包、附件和导航页；去重前 Token 增加一倍，独特内容可能只增加百分之十；训练读取了一万亿 Token，优化器真正消费的有效标签 Token 还要扣除 Padding、被 Mask 的模板、损坏样本、重复样本和训练失败后没有提交的 Batch。

因此，本文不寻找一个万能的数据质量总分，而是建立一套可审计的度量体系。它需要同时回答五类问题：

1. 规模：各处理阶段到底有多少文档、字符、字节、Token 和序列。
2. 独特性：其中多少内容是新的，多少是精确重复、近似重复、模板重复或语义冗余。
3. 质量：内容是否完整、连贯、可信、可用、安全，并符合目标训练阶段。
4. 覆盖：数据是否覆盖目标语言、领域、能力、难度、时间和人群切片。
5. 价值：在固定计算预算下，增加或删除某一批数据，是否改善目标模型和目标评测。

这五个问题不能压缩成一条“保留率越高越好”的指标。高保留率可能表示过滤器没有工作；低保留率也可能表示数据源选择很差，或者过滤器误删了长尾内容。高困惑度可能代表罕见而有价值的知识，也可能代表乱码；低困惑度可能代表语言流畅，也可能代表训练集重复。衡量数据的过程必须保留多个维度，并把所有数字绑定到明确的对象、版本、口径和时间窗口。

### 3.2 学习目标与能力清单

完成后应当能够：

1. 区分原始规模、解析规模、合格规模、独特规模、可训练规模、已消费规模和有效训练规模。
2. 解释为什么字节数、字符数、文档数、样本数、序列数和 Token 数不能互相替代。
3. 为名义 Token、唯一 Token、有效 Token、贡献 Token 建立可计算的口径。
4. 区分精确独特性、词法独特性、语义多样性和能力覆盖，避免把“没有重复”误认为“足够多样”。
5. 从完整性、自然度、可信度、教育价值、安全性和目标相关性等维度描述数据质量。
6. 使用分布、分位数、切片、置信区间和基线比较，而不是只汇报一个平均分。
7. 理解计算最优规模、数据受限训练、重复训练和边际收益递减之间的关系。
8. 设计数据消融、代理训练与固定评测，估计某个数据来源的边际训练价值。
9. 通过 CPU 机制实验计算多阶段数据账本，通过 CUDA 实验比较相同名义 Token 下不同数据配方的训练结果。
10. 明确小模型、短训练和合成数据实验能够证明什么，不能外推什么。

### 3.3 实验准备与责任边界

本文需要基本的 Python、JSONL、概率统计和语言模型训练概念。应当理解平均数、分位数、方差、抽样、交叉熵和训练/验证集的区别。公式会逐步解释，不要求预先掌握统计学习理论。

机制实验只依赖 Python 3.9 以上版本和标准库，用一个可控语料演示文档计数、Token 计数、重复簇、质量权重、覆盖权重、Bootstrap 置信区间和边际价值排序。这个实验验证指标如何计算以及口径怎样变化，不声称模拟数据等价于真实网页分布。

真实硬件实验使用 PyTorch DistributedDataParallel，在至少一张可用 CUDA GPU 上训练一个小型自回归 Transformer。实验会为高重复、含噪和较高独特性三种语料构造相同的名义 Token 预算，比较训练损失、保留集损失、独特 Token 消费量、有效 Token 比例和吞吐。没有至少一张 CUDA GPU、PyTorch 版本不满足或显存不足时，程序必须输出结构化 `skipped`，不能在 CPU 上运行后把结果称为 CUDA 单卡实测。

这个真实实验能够证明：在相同代码、模型和名义 Token 预算下，数据构成会影响优化轨迹和保留集指标。它不能证明某种配方在十亿参数模型、真实网络语料或生产集群上保持同样的收益幅度。规模效应、Tokenizer、领域分布、训练时长和模型容量都会改变结果。

## 4. 数据规模应该沿哪几个阶段计量

### 4.1 第一条原则：先写清对象，再写数字

“有五亿条数据”中的“条”可能指 URL、原始对象、解析文档、切分段落、SFT 对话、偏好对或 Token 序列。对象不同，数字相差几个数量级也很正常。任何规模指标至少要带上五个限定字段：

- `asset_version`：统计的是哪个不可变数据版本。
- `object_type`：Source、Object、Document、Sample、Sequence、Trajectory 还是 Experience。
- `processing_stage`：Raw、Parsed、Filtered、Deduplicated、Train-ready 或 Consumed。
- `count_unit`：字节、Unicode 字符、文档、样本、Token、有效标签 Token 或训练步。
- `measurement_recipe`：使用哪个解析器、Tokenizer、过滤规则、去重配置和统计代码。

如果缺少这些限定，一句“语料有 2T Token”不可审计，也无法与另一版数据比较。最常见的错误是用新 Tokenizer 重新统计旧语料，却仍沿用旧版本名称；或者在去重后汇报文档数、在去重前汇报 Token 数，形成不可能同时成立的宣传数字。

### 4.2 原始规模不是训练规模

原始规模描述采集系统取得了多少字节和对象。它主要用于存储预算、网络带宽、解析吞吐与来源覆盖分析。可以定义：

$$B_{raw}=\sum_{i=1}^{N_{obj}} \operatorname{bytes}(o_i)$$

其中 $o_i$ 是原始对象，$B_{raw}$ 是压缩前或压缩后的字节总量。二者必须分开，因为压缩率会受文本、图片、归档格式和重复程度影响。压缩后 1 TB 的 HTML 与压缩后 1 TB 的视频不能用同一处理成本估算。

Raw 层还应记录对象数、成功下载率、HTTP 状态分布、MIME 类型、抓取时间和内容校验和。原始字节很大，只说明采集或导入工作量大，不说明解析后能得到多少正文。一个 PDF 数据源可能包含大量扫描图片；一个网页源可能大部分是脚本、样式和重复模板。

### 4.3 解析规模回答“成功得到多少可解释内容”

解析规模从原始对象进入 Document 层之后计算。设原始对象集合为 $O$，解析函数为 $p$，成功产生的文档集合为 $D_p$：

$$D_p=\{p(o)\mid o\in O,\;\operatorname{status}(p(o))=success\}$$

解析保留率可以按对象计算：

$$R_{parse}^{doc}=\frac{|D_p|}{|O|}$$

也可以按正文字符计算：

$$R_{parse}^{char}=\frac{\sum_{d\in D_p}\operatorname{chars}(d)}{\sum_{o\in O}\operatorname{extractable_char_estimate}(o)}$$

第二个分母在真实系统里往往难以精确获得，所以通常需要抽样人工评估解析召回，而不是假装存在一个准确的全量真值。文档成功率高也不代表正文完整。解析器可能对每个网页都返回字符串，却只提取到 Cookie 提示、导航栏或第一页。

解析规模至少要同时报告成功文档、空文档、过短文档、异常编码、正文占比、结构块数量和解析器版本。对于 PDF，还要区分原生文本、OCR 文本、公式、表格和图片说明；对于代码仓库，要区分文件、提交、Fork 和 Vendor 依赖。

### 4.4 合格规模来自一组门禁，而不是一个分数

过滤后规模 $D_f$ 是通过用途相关门禁的文档集合：

$$D_f=\{d\in D_p\mid g_1(d)=1, g_2(d)=1,\ldots,g_k(d)=1\}$$

每个 $g_j$ 代表一个可解释门禁，例如语言属于目标集合、正文长度在可接受范围、PII 已处理、许可允许该用途、解析完整度达到阈值、恶意内容风险未超过上限。门禁需要分别统计命中与删除原因。

当多个门禁串行执行时，总保留率不能解释各门禁的真实影响。若语言过滤先删除了一个乱码文档，后续乱码过滤就看不到它。应该同时记录：

- 顺序口径：在当前门禁输入上删除了多少。
- 全体口径：在解析后全集中命中了多少。
- 重叠口径：一个文档同时命中了哪些原因。
- 主原因：为了数据卡展示而选择的单一主要删除原因。

保留集合的规模为：

$$N_{eligible}=|D_f|,\qquad T_{eligible}=\sum_{d\in D_f}t(d)$$

这里 $t(d)$ 必须由固定 Tokenizer 版本计算。若尚未绑定 Tokenizer，可以先汇报字符数和估算 Token，但不得把估算值与真实分词计数混在同一字段。

### 4.5 独特规模至少有四种口径

不同粒度回答不同问题，文档唯一不保证段落唯一。

第一种是精确独特规模。对规范化后的内容计算稳定哈希，相同哈希进入同一簇，每簇只计一次：

$$N_{exact_unique}=|\{h(n(d)):d\in D_f\}|$$

其中 $n(d)$ 是规范化函数，$h$ 是内容哈希。规范化是否移除空白、大小写、时间戳和模板会改变结果，所以必须版本化。

第二种是近似词法独特规模。MinHash、LSH、Winnowing 或子串算法会把 Jaccard 相似度高、共享长片段的文档聚为重复簇。可以用代表文档 Token 数之和作为近似独特 Token：

$$T_{lexical_unique}=\sum_{c\in C_{lex}}t(r(c))$$

其中 $C_{lex}$ 是重复簇集合，$r(c)$ 是每簇的代表文档。这个值依赖 Shingle 大小、相似度阈值、Band/Row 配置和代表选择策略。

第三种是语义多样性。两篇文章可能没有共享句子，却讲述完全相同的常识；也可能词面相似但分别包含关键增量。语义聚类后可以计算簇数、簇大小分布、有效簇数和覆盖熵。设簇占比为 $p_k$，则 Shannon 熵为：

$$H=-\sum_{k=1}^{K}p_k\log p_k$$

为了让熵更直观，可以计算有效簇数：

$$K_{eff}=\exp(H)$$

若数据均匀分布在十个簇中，$K_{eff}$ 接近十；若绝大多数数据集中在一个簇，即使名义上存在十个簇，$K_{eff}$ 也会明显下降。

第四种是能力独特性。数据可以在词法和语义上多样，却只覆盖简单问答，缺少代码调试、数学证明、长文归纳、工具调用或多轮澄清。能力独特性需要基于目标能力标签、任务分解、难度和验证集覆盖来描述，不能仅靠 Embedding 聚类代替。

### 4.6 可训练规模取决于样本构造与 Tokenizer

通过治理和去重的 Gold 数据还不是最终训练数据。样本构造会切分长文档、拼接短文档、生成对话模板、设置最大长度和特殊 Token；Tokenizer 会把字符转换为 Token；Packing 会改变序列数和 Padding 比例。

设构造后的样本集合为 $S$，Tokenizer 为 $\tau_v$，则名义训练 Token 数为：

$$T_{trainable}=\sum_{s\in S}|\tau_v(s)|$$

对于 SFT，还需要区分输入 Token 和参与损失的标签 Token：

$$T_{label}=\sum_{s\in S}\sum_{j=1}^{|\tau_v(s)|}m_{s,j}$$

其中 $m_{s,j}\in\{0,1\}$ 是 Loss Mask。若只对 Assistant 响应计算损失，User、System、工具描述和 Padding 不属于有效标签 Token。用总输入 Token 当作 SFT 的监督规模，通常会高估真正的监督信号。

### 4.7 已消费规模必须由训练运行确认

重试、Mask 和失败更新会使实际分母偏离名义预算。

Train-ready Manifest 声明数据“可被训练”，但不代表训练真正消费了全部数据。分布式训练可能在中途失败；某些 Shard 因读取错误被跳过；动态采样可能多次访问一部分数据；梯度累积过程中发生 OOM 时，已经完成前向的 Token 未必产生一次成功优化器更新。

定义成功提交的全局 Step 集合为 $U$，每个 Step 的有效输入 Token 为 $b_u$，则已提交 Token 为：

$$T_{committed}=\sum_{u\in U}b_u$$

如果训练有数据并行度 $d$、每卡微批大小 $m$、梯度累积步数 $a$、序列长度 $l$，且所有位置有效，则理论每次更新 Token 为：

$$T_{step}=d\times m\times a\times l$$

真实值还要乘以非 Padding、非 Mask 的比例，并扣除因故障未提交的微批。正确做法是在训练端聚合 `input_tokens`、`label_tokens`、`non_padding_tokens`、`optimizer_committed` 和数据游标，而不是只用配置文件相乘。

### 4.8 七级 Token 漏斗

![七级 Token 漏斗](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l02_02.png)

沿箭头依次看各个对象，箭头表示本节讨论的依赖或处理顺序。每一级单独记数；这些阶段不是可直接相加的独立收益。

为了避免团队各说各话，可以把 Token 规模固定成七级漏斗：

1. `raw_estimated_tokens`：从原始字节或字符估算的 Token，只用于容量规划。
2. `parsed_tokens`：成功解析正文按固定 Tokenizer 统计的 Token。
3. `eligible_tokens`：通过许可、安全、语言和基础质量门禁的 Token。
4. `unique_tokens`：按声明的去重策略保留后的 Token。
5. `trainable_tokens`：完成样本构造、模板和截断后的输入 Token。
6. `label_tokens`：真正参与损失计算的 Token。
7. `committed_tokens`：进入成功优化器更新、可由 Checkpoint 游标证明的 Token。

每一级都应同时记录相对于上一级和相对于 Raw 的比例。例如：

$$R_i^{local}=\frac{T_i}{T_{i-1}},\qquad R_i^{global}=\frac{T_i}{T_{raw}}$$

局部比例帮助定位哪个步骤损失最大，全局比例帮助估算从采购或抓取规模到训练规模的总体转换效率。若只看最终比例，无法判断损失发生在解析、许可、质量、去重还是样本构造。

## 5. “有效 Token”应该怎样定义

### 5.1 有效 Token 不是行业统一常数

“有效 Token”常被用来表达过滤、去重、Packing 或数据选择后的有用规模，但不同团队的定义可能完全不同。有的团队把非 Padding Token 称为有效 Token；有的把去重后的 Token 称为有效 Token；有的用质量分加权；还有的根据训练收益反推数据有效性。若不声明公式，这个术语比名义 Token 更容易造成误解。

本文把有效性拆成三个层次：计算有效、数据有效和任务有效。

计算有效 Token 指真正进入损失并完成更新的 Token：

$$T_{compute_effective}=\sum_i m_i\cdot c_i$$

其中 $m_i$ 表示该 Token 是否参与 Loss，$c_i$ 表示所在更新是否成功提交。这个指标用于系统吞吐和训练账本，通常可以精确统计。

数据有效 Token 是对重复、损坏和质量风险加权后的统计量：

$$T_{data_effective}=\sum_i m_i c_i q_i u_i$$

其中 $q_i\in[0,1]$ 表示质量权重，$u_i\in[0,1]$ 表示独特性权重。它是一种管理和比较指标，依赖评分模型与去重定义，不能被误称为客观真值。

任务有效 Token 进一步考虑目标相关性与边际训练贡献：

$$T_{task_effective}=\sum_i m_i c_i q_i u_i r_i v_i$$

其中 $r_i$ 是目标相关性，$v_i$ 是在当前模型、当前配方和当前预算下的边际价值估计。这个量最接近“对模型目标有多少用”，但也最难可靠估计。它必须依赖训练实验或经过校准的代理模型，不应由一个语言模型随意打分后就当成事实。

### 5.2 为什么权重相乘需要谨慎

质量、独特性、相关性和价值直接相乘看似简洁，却隐含多个假设：各权重已经在同一尺度上校准；它们近似独立；零分确实意味着 Token 完全无用；相同 Token 的权重可以线性相加。真实数据通常不满足这些假设。

例如，一条低流畅度的代码错误日志，通用文本质量模型可能给低分，但它对故障诊断任务非常有价值。一个在全局语料中重复的 API 示例，对入门能力可能仍有教学作用。一篇高质量数学论文如果重复训练过多次，边际价值会下降，但并非第一次出现就只值固定权重。

因此，加权 Token 更适合作为可解释的比较工具，而不是训练效果的替代指标。工程上需要同时保留每个维度的原始分数、分布和切片，并用数据消融检查加权公式是否与目标评测一致。
