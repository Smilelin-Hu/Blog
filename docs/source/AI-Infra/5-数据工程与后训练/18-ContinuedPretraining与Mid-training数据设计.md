# Continued Pretraining 与 Mid-training 数据设计

## 1. 本文要解决的工程问题

领域数据继续预训练后，目标域评测上升，通用能力和安全行为却退化。团队只保留最终平均分，无法判断是数据混合、学习率还是训练阶段造成。

本文围绕一个可执行判断展开：怎样为持续预训练与 Mid-training 设计数据目标、配方、污染控制和能力验收？读完应能给出自己的系统边界、输入输出、版本关系和验收证据，而不是只复述工具名称或公式。

## 2. 本文交付物与判定标准

本文的核心决定是：为 Continued Pretraining 与 Mid-training 分别定义能力目标、通用回放、污染边界、停止条件和回滚基线。

完成学习和实验后，应当交付一份最小可复现记录，至少包含输入快照、配置、代码版本、运行状态、原始输出和结论边界。验收证据是：同预算候选配方同时报告目标域、通用域和安全切片，并保存起始检查点、数据版本与学习率轨迹。

围绕“Continued Pretraining 与 Mid-training 数据设计”的验收不接受三类替代品：把模拟输出写成真实 GPU 结果；只展示成功样本而隐藏失败与 `SKIPPED`；只给总分，不保存能复算总分的对象级记录。

## 3. 前置知识与实验边界

“Continued Pretraining 与 Mid-training 数据设计”的机制实验使用 Python 3.10 及以上版本和标准库，重点验证对象、算法或状态转换。真实硬件路径使用 PyTorch；检测不到 CUDA 时必须输出结构化 `SKIPPED`，不得静默改跑 CPU 后仍标成 GPU 实测。

小模型和短训练可筛选明显错误配方，不能完整预测目标模型的遗忘与涌现能力。

### 3.1 业务背景与失败模式

企业常已有一个通用基础模型，希望它掌握专业术语、组织文档、新语言、代码库、长上下文或特定推理结构。从头预训练成本过高，直接 SFT 又主要学习输入—输出行为，难以充分吸收大规模无标签知识。Continued Pretraining 在原检查点上继续语言模型目标，使用目标领域与通用重播数据改变模型分布；Mid-training 则常指处在基础预训练与最终后训练之间的一段能力塑形，可组合领域知识、长上下文、代码、数学与结构化目标。

这条路线看似只是“再训一些 Token”，却有多个系统风险：目标域过强会灾难性遗忘通用能力；学习率过高会破坏旧表示，过低又无法吸收新知识；Tokenizer 与模板不兼容会制造伪适配；新数据含评测污染会让能力虚高；重播池可能包含已退出数据；只看目标域 Loss 会把模型变成狭窄专家；模型继续训练后还要重新验证后续 SFT、对齐和推理兼容。

本文建立从基线诊断、目标数据与重播、Token 预算、优化日程、能力课程、检查点、评测和回滚的完整 CPT 数据工厂。重点不是背诵某个重播比例，而是能用目标收益、通用护栏、成本和风险曲线选择配方，并在至少一张可用 CUDA GPU 上诚实验证小规模机制。

### 3.2 学习目标与能力清单

### 2.1 Continued Pretraining

目标不同会改变数据 Schema 与 Loss 口径。

从已有语言模型检查点继续使用自监督语言模型目标训练。数据可以是新增通用语料、某个专业域、多语语料、代码或时间更新。它改变基础表示和知识，输出新的 Base 或 Intermediate Checkpoint。

### 2.2 Domain-Adaptive Pretraining

DAPT 是 CPT 的一种，重点用目标领域无标签语料适配，如法律、医学、金融或企业产品。它通常混入通用重播以减缓遗忘。领域定义、质量和许可边界决定结果，不是把含关键词的网页放大。

### 2.3 Task-Adaptive Pretraining

TAPT 使用与目标任务输入分布接近的无标签文本继续预训练，规模更小、更贴近任务。它与 SFT 不同，因为不需要输入—标签对；但若任务文本与评测过近，污染风险更高。

### 2.4 Mid-training

Mid-training 不是统一行业标准术语。工程上可把它定义为基础预训练之后、最终 SFT 与偏好优化之前，用较大规模数据塑造长上下文、推理、代码、工具格式或领域能力的阶段。项目必须写明具体目标和 Loss，不能用一个名称掩盖多种训练。

### 2.5 Continual Learning

模型按时间接收多个领域或版本数据，既要学新又要保留旧。它比一次 DAPT 多了顺序、累积遗忘、旧数据可用性与长期检查点治理。重播、正则、参数隔离和蒸馏都可作为工具。

### 2.6 SFT 的边界

SFT 学习指令、角色和期望响应，样本监督 Token 通常只覆盖助手输出。CPT 学习下一 Token 分布，正文大多参与 Loss。知识可以经两者进入，但优化信号、数据 Schema 和能力风险不同，不能把未配对文档硬套 Chat Template 称 SFT。

### 3.3 实验准备与责任边界

### 3.1 目标域 Loss

在独立、去污染的目标域验证集计算 Token 平均交叉熵与长度、来源切片。高 Loss 可能表示缺知识、Tokenizer 低效、格式异常或数据噪声。先抽查与对比通用模型，不自动开始 CPT。

### 3.2 通用能力护栏

冻结语言理解、推理、代码、多语、安全和产品关键评测。CPT 成功至少要求目标能力提升且护栏不越界。护栏选择反映模型未来用途，不只用一个总体榜单。

### 3.3 记忆与污染基线

在训练前测目标语料复述、成员推断、评测重叠和敏感探针。继续训练后变化要相对基线解释，避免把原模型已有问题归给新数据或漏掉新增风险。

### 3.4 Tokenizer 诊断

按目标域统计字符每 Token、回退、长专业词、代码和结构格式。若极度膨胀，CPT 相同 Token 看到更少原文；但升级 Tokenizer 成本巨大，应单独评估，不在 CPT 中无记录热换。

### 3.5 知识截止与版本冲突

目标数据是否包含比基础模型更新的事实、多个冲突版本或企业内部规则。构建时间和版本切片，评测模型能否区分当前、历史与不确定，而不是只看平均问答。

## 4. CPT 数据组成

### 4.1 目标域核心语料

高质量、可追踪、与能力目标相关的无标签文档。按主题、体裁、来源、版本和难度分桶。核心不是数量最大，而是独特信息、结构和任务覆盖。

### 4.2 通用重播

增加领域权重需要同时观察通用能力回退。

从基础分布或合法代理分布选择通用样本，维持语言与世界知识。重播池要有来源、版本、去污染和退出能力；不能因为基础模型曾训练过就永久获得使用权。

### 4.3 桥接语料

连接通用与专业表达的教材、综述、教程、问答和术语解释，能降低分布突变。桥接质量需要验证，过度简化材料可能只改善表面术语。

### 4.4 结构能力语料

代码、数学、长文档、表格线性化和多文关系可作为 Mid-training 能力数据。它们与领域知识正交，配方用多轴约束，不把所有“专业”压一个桶。

### 4.5 合成扩展

从真实文档生成解释、题目、推理或反事实可扩展覆盖，但生成器错误会放大。合成来源单列，验证可从证据推出、去重和无评测模板，不能取代真实核心语料。

### 4.6 负面与冲突数据

历史版本、错误主张和相互冲突文档若无标记混入，会让模型平均化事实。可以排除，或构造成有时间、来源和可信度上下文的显式任务。CPT 普通下一 Token 目标不擅长自动消解无标记冲突。

## 5. 重播设计

### 5.1 重播不是越多越安全

提高通用重播通常减缓遗忘，却稀释目标域学习并增加成本。最佳比例取决于基础模型、目标数据、Token 预算和护栏。需要比例网格与 Pareto 曲线，不能复制他人固定数值。

### 5.2 随机通用重播

从合格基础池按原分布抽样，简单无额外选择偏差，是重要基线。缺点是许多样本对当前护栏边际价值低。

### 5.3 核心集重播

按多样性、影响或能力覆盖选择较小核心集，降低 Token 成本。核心集可能过拟合固定护栏或漏掉长尾，必须和随机同规模基线比较，并持续复核。

### 5.4 损失或梯度驱动重播

选择当前模型遗忘风险高、损失上升或梯度冲突大的通用样本。闭环更高效，也可能追逐噪声。动态决定要保存观测、算法、种子和实际样本，保证重放。

### 5.5 生成式重播

用旧模型生成代表性通用文本，避免保存原始数据，但会放大模型偏差、缺少真实长尾并产生合成闭环。生成内容仍需治理、质量和去重。

### 5.6 Logit 或表示蒸馏

在重播样本上约束新模型接近旧模型，可以比只拟合真实下一 Token 更直接保留行为。需要保存教师模型、温度、目标和额外前向成本；也可能保留旧错误。

## 6. 数据配方数学

### 6.1 静态混合

设目标域比例 $p_t$，重播比例 $p_r=1-p_t$，总预算 $B$，则目标与重播 Token 分别为 $Bp_t$ 和 $Bp_r$。如果目标独特 Token 为 $N_t$，平均曝光 $e_t=Bp_t/N_t$。比例必须与绝对预算共同评估。

### 6.2 多域混合

企业 CPT 常有多个目标子域与多类护栏。向量 $p\in\Delta^K$ 受保底、封顶、曝光和治理约束，可用上一阶段的温度、DoReMi 或 RegMix 研究，但目标从零预训练变成“相对基础检查点的增量价值”。

### 6.3 遗忘—适配目标

可把目标选择概念化为：

$$\min_p L_{target}(\theta_B(p)) \quad\text{s.t.}\quad L_{guard,j}(\theta_B(p))-L_{guard,j}(\theta_0)\le\delta_j$$

$\theta_0$ 是基础模型，$\theta_B(p)$ 是预算 $B$ 后模型。护栏是硬约束时不能由目标收益补偿。

### 6.4 边际收益

在多个 Token 里程碑评估目标改善与护栏回退，寻找收益递减和遗忘拐点。只比较零与最终预算，无法知道更短训练是否更经济安全。

## 7. 优化器与学习率

### 7.1 是否重置优化器

若只有基础权重、没有原优化器状态，CPT 从新优化器开始。即使有状态，原预训练末期动量与学习率可能不适合新分布。比较重置、部分恢复和 Warmup，并记录检查点契约。

### 7.2 学习率通常更谨慎

CPT 在已形成表示上更新，过高学习率可能快速遗忘或发散。较低峰值和短 Warmup 是常见候选，但必须通过小规模网格验证，不能作为绝对规则。

### 7.3 Warmup

从零或低学习率升到峰值，缓解新优化器和新数据分布冲击。Warmup 按有效 Token 定义，目标与重播混合在早期是否变化要明确。

### 7.4 学习率衰减

余弦、线性或常量影响目标吸收和后期稳定。若 Mid-training 后还要 SFT，输出检查点需要处于可继续优化的状态；极低学习率终点不等于不能后续训练，但优化器状态通常重新设置。

### 7.5 Weight Decay 与正则

沿用基础预训练设置未必最优。参数距离、EWC 式重要性、Layer 冻结或低秩更新可以减缓遗忘，但会限制适配。每种方法增加模型状态与复杂性，应先与数据重播基线比较。

### 7.6 梯度裁剪与异常

新领域长序列或代码可能提高梯度峰值。记录裁剪率、非有限值和领域切片，先查数据与 Loss 归一，不通过缩小所有更新掩盖坏批。

## 8. 阶段课程

每个阶段保留输入与模型谱系，失败时能回到明确基线。

### 8.1 过渡阶段

早期以通用重播和桥接为主，逐渐增加目标核心，降低分布突变。是否有效需与静态打散对照；它会与 Warmup 耦合。

### 8.2 核心吸收阶段

目标域占主，维持护栏重播和小额全域探索。按主题、长度与难度平衡，避免单一来源支配。

### 8.3 能力塑形阶段

提高长上下文、代码、数学或结构任务，保留核心领域和通用护栏。Mid-training 可在这里定义特定 Loss 或 FIM，但每个改变独立版本。

### 8.4 稳定阶段

末期可提高高质量通用与桥接，降低目标过拟合，或保持静态。需用目标能力证明不会冲掉新知识。不要把“回温”当无需验证的固定做法。

### 8.5 按模型反馈调整

动态重播或难度课程可基于验证损失，但要限制增益、保存决策和保留探索。第一版更适合离线窗口更新，不让线上评测直接高频控制数据。

## 9. 灾难性遗忘的测量

### 9.1 绝对变化

对每个护栏计算 CPT 检查点相对基础模型的差，包含置信区间和多种子。不同任务量纲不能随意平均。

### 9.2 最大遗忘

终点可能恢复，但中间检查点曾大幅回退。记录训练全程最差差值、发生 Token 位置与恢复速度，帮助设置在线停止。

### 9.3 平均遗忘

在多个旧任务上汇总可提供概览，但关键护栏单独门禁。宏平均受任务拆分粒度影响，报告向量。

### 9.4 表示漂移

在固定探针上比较隐藏表示、Logit KL 或参数距离，可提前发现变化，但与能力不一一对应。它是诊断，不替代行为评测。

### 9.5 通用验证 Loss

稳定、频繁、便宜，适合作为在线护栏。总体 Loss 不一定捕捉推理和安全，应和任务评测结合。

### 9.6 目标过拟合

目标训练 Loss 持续下降而独立目标能力不再提升、复述增加，说明继续训练边际价值低。设置停止条件，不用完成预定 Token 当唯一成功。

## 11. 模型合并、知识编辑与机器遗忘

### 11.1 模型合并：task arithmetic、TIES 与 DARE

合并把多个同源微调模型的权重直接组合，免训练获得多能力：task arithmetic 对任务向量（微调权重 − 基座权重）加减；TIES 先 trim 小幅值参数、再 elect sign 解决符号冲突、最后不相交合并；DARE 随机 drop 大部分增量参数并按比例 rescale，依赖深度网络的冗余性。前提硬约束：同一基座、同一架构、同一 tokenizer，否则权重不可对齐。

合并是 CPT 多领域能力的低成本替代，但大规模实证（What Matters for Model Merging at Scale）表明收益随模型规模与任务组合波动，不能默认「合了就涨」：每次合并走 37 的评测回归，目标能力涨幅与通用能力回退成对报告。合并也不豁免遗忘测量——§9 的通用能力护栏同样适用。

### 11.2 知识编辑：ROME 与 MEMIT

编辑不重训而直接改权重中的事实关联：ROME 定位 FFN 中存储目标事实的层做 rank-1 更新，MEMIT 批量编辑多层。三个评估维度缺一不可：specificity（目标事实改对）、locality（无关事实不变）、generalization（换问法仍生效）。已知局限：编辑会累积退化（多次编辑后通用能力下降）、涟漪效应（改一个事实牵连相关推理链），适合少量高价值事实修正，不适合大规模知识更新——后者仍回 CPT 数据管线。

### 11.3 机器遗忘：方法与评估

unlearning 目标是让模型「忘掉」特定数据的影响（隐私退出/版权请求的模型层响应，接 13 §8.6）。方法谱系：梯度上升（直接反向优化遗忘集，易伤通用能力）、NPO/SimNPO（把遗忘集当负样本做偏好优化，稳定性更好）；2026 年的实证（Editing as Unlearning，AAAI）表明 ROME/MEMIT 加 query merging 在长序列遗忘上是强基线——编辑与遗忘在方法层合流。

评估用三组对照：forget set（目标内容残留率，含换问法探测）、retain set（相邻知识保留）、通用能力基准（37 的回归集）。只看 forget set 下降就宣布遗忘成功是常见误判——模型可能只是「变笨了」。与 32 §13.12 的结论一致：血缘与删除证明不能替代模型层验证，遗忘声明必须附三组评估证据。

### 11.4 工程定位与验收

合并/编辑/遗忘都是「低成本补丁」，不是数据治理的替代：主路径仍是配方重播与重训，补丁用于时效性要求高或重训代价不可接受的场景，且每次补丁后进版本血缘（32）与评测门禁。验收：合并/编辑前后目标与通用能力成对报告、遗忘三组评估达标、补丁操作全部进血缘与审计、补丁累积次数有上限（超限触发重训）。
