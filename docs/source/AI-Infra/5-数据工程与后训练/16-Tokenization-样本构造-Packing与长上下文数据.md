# Tokenization、样本构造、Packing 与长上下文数据

## 1. 本文要解决的工程问题

同一批 SFT 样本换了 Chat Template、Tokenizer 或 Packing 实现后，训练 Loss 仍然正常，但标签错位、跨样本注意力和截断位置已经改变。

本文围绕一个可执行判断展开：怎样把 Tokenization、样本构造、Packing 与长上下文边界编译为确定性数据产物？读完应能给出自己的系统边界、输入输出、版本关系和验收证据，而不是只复述工具名称或公式。

## 2. 本文交付物与判定标准

本文的核心决定是：把 Tokenizer、模板、边界标记、Loss Mask、截断与 Packing 编译成可测试的数据产物合同。

完成学习和实验后，应当交付一份最小可复现记录，至少包含输入快照、配置、代码版本、运行状态、原始输出和结论边界。验收证据是：黄金样本逐 Token 比较 input_ids、labels、mask 与边界；Packing 前后有效监督 Token 守恒。

围绕“Tokenization、样本构造、Packing 与长上下文数据”的验收不接受三类替代品：把模拟输出写成真实 GPU 结果；只展示成功样本而隐藏失败与 `SKIPPED`；只给总分，不保存能复算总分的对象级记录。

## 3. 前置知识与实验边界

“Tokenization、样本构造、Packing 与长上下文数据”的机制实验使用 Python 3.10 及以上版本和标准库，重点验证对象、算法或状态转换。真实硬件路径使用 PyTorch；检测不到 CUDA 时必须输出结构化 `SKIPPED`，不得静默改跑 CPU 后仍标成 GPU 实测。

格式正确只证明训练目标按预期编码，不能证明答案内容正确或配方有效。

### 3.1 业务背景与失败模式

清洗后的文档只有变成 Token、训练样本、位置与注意力结构，才会影响模型梯度。同一份正文可以被不同 Tokenizer 切成完全不同长度；同一组 Token 可以按文档内连续、跨文档拼接或滑动窗口构造；同样的 Packing 利用率，既可能正确隔离文档，也可能让无关文档互相注意；同样声称支持长上下文，可能只是把大量短文塞满窗口，没有提供真实长程依赖。

这一层常被当作训练器中的小工具，实际却同时决定语义边界、算力利用、领域预算、退出粒度和可复现性。Tokenizer 变化会使全部 Token 预算失效；EOS 漏插会让文档跨界；Loss Mask 偏一位会训练模型预测错误目标；恢复时 Packing 缓冲丢失，会使后续所有样本顺序变化。性能工程不能只看 Padding 减少了多少，也要证明训练语义没有污染。

本文从 Tokenizer 资产治理开始，覆盖 BPE、Unigram、字节回退、规范化与特殊 Token；随后定义预训练、持续预训练和对话样本的构造；再讨论截断、滑窗、拼接、在线与离线 Packing、隔离注意力、位置 ID、文档边界、长上下文长度分布和至少一张可用 CUDA GPU 上的真实验证路径。最终输出是一份可签名的数据编译产物，而不是不可解释的 Token 二进制。

### 3.2 Tokenizer 流水线

Tokenizer 与特殊 Token 配置必须绑定模型版本。

完整 Tokenizer 通常包含输入规范化、预分词、子词模型、后处理、特殊 Token 和解码。任何环节变化都会改变 ID 序列。规范化可能统一 Unicode 或大小写；预分词决定空格与标点边界；BPE、Unigram 或 WordPiece 学习词表；后处理插入 BOS、EOS 或段落标记；解码器定义 ID 如何返回文本。

工程清单不能只保存 `vocab.json`。需要保存完整配置、合并规则、规范化实现、特殊 Token 表、库版本、未知与字节回退策略、输入编码和内容摘要。训练、评测、推理和数据统计必须引用同一不可变资产。

### 3.3 BPE 的工程直觉

BPE 从较小符号集合开始，反复合并高频相邻对，直到达到词表或规则预算。高频片段用较少 Token，长尾由更小单元组合。词表越大，平均序列可能更短，但嵌入和输出矩阵更大，稀有 Token 训练不足，跨语言分配也可能更不公平。

BPE 合并规则依赖训练语料与规范化。若 Tokenizer 训练数据被网页主语言支配，代码、中文、日文或专业术语会被切得更碎。不能只用总体字符每 Token 评估，应按语言、领域、体裁、Unicode 类别和长尾切片。

### 3.4 Unigram 的工程直觉

Unigram 从较大候选子词集合出发，以概率模型逐步裁剪对似然贡献较小的单元。编码时可以选择最高概率切分，也可做子词正则采样。它与 BPE 的训练和分词目标不同，不能只比较词表大小。

若开启随机分词，训练可获得分词多样性，但可复现与离线缓存更复杂。必须保存随机算法和种子，评测与推理通常使用确定性编码。随机 Tokenizer 输出会使相同记录 ID 对应不同 Token 摘要，需要在数据产品中显式版本化。

### 3.5 WordPiece 与词级边界

WordPiece 常在预分词后的词内构造子词，通过其打分规则选择合并。词边界对空格语言较自然，对无空格语言、代码和混合文本需要不同处理。任何“词”假设都可能把 URL、标识符、Emoji 和复合脚本切成意外模式。

### 3.6 字节级与字节回退

字节级编码能覆盖任意 UTF-8 输入，减少真正未知字符；代价是非主流脚本、乱码或二进制片段可能膨胀成很多 Token。字节回退只在子词无法覆盖时退到字节，兼顾常见片段效率与开放词表。

覆盖不等于质量。一个字符永远能编码，但若每个字节都是单 Token，长文本成本和上下文有效内容会变差。监控每字符 Token、每字节 Token、回退率和连续回退长度，发现编码异常与低资源语言不公平。

### 3.7 特殊 Token 的身份不可随意变化

BOS、EOS、PAD、UNK、MASK、系统、用户、助手、工具和文档边界等 Token 都有稳定 ID。添加 Token 会扩大嵌入与输出层，改变模型权重形状；重排 ID 更会让现有检查点语义完全错误。新增特殊 Token 要创建 Tokenizer 新版本，并规定旧检查点如何扩展和初始化。

特殊字符串若与普通文本冲突，需要 Added Token 行为或转义策略。用户正文恰好包含 `<|assistant|>` 时，不能未经处理就被解释为控制边界。训练和推理的转义必须相同。

### 3.8 Encode 与 Decode 不必逐字节恒等

规范化、不可逆字符替换或空格处理可能使 `decode(encode(text))` 不同于原文。应定义需要满足的是规范化后文本相等、语义相等还是字节相等。对代码、JSON、表格和标识符，空格与大小写常有语义，不能套用自然语言规范。

Tokenizer 若提供 Offset Mapping，应抽样验证每个 Token 映射到原始字符区间。退出、错误定位和 Loss Mask 对齐会依赖这条映射。

### 3.9 压缩率

常见指标包括字符每 Token、字节每 Token、词每 Token 或 Token 每字符。必须明确分母和规范化，不同语言的字符信息量不同。总体平均会由主流语言支配，应报告切片分布、分位和最差区域。

### 3.10 未知与回退

统计 UNK 率、字节回退率、连续回退长度和包含回退的记录比例。UNK 率为零不代表无问题，字节级系统可能用很长序列掩盖覆盖缺陷。

### 3.11 词表利用率

在目标语料上统计 Token 频次、从未使用比例、低频尾部和各领域独占 Token。大词表中大量从未出现单元浪费参数；但稀有控制 Token 或特定脚本单元可能有明确价值，不能只按频次删除。

### 3.12 边界质量

检查代码关键字、标识符、数字、日期、URL、数学表达、Emoji 组合和无空格语言是否产生合理片段。边界质量不一定有唯一金标，可以通过下游代理损失、编辑稳定性和人类抽查共同判断。

### 3.13 编辑稳定性

在文本开头插入一个字符后，后续 Token 是否大范围变化。局部稳定对增量缓存、差分和错误定位有利。BPE 与规范化可能让改变传播到相邻边界，需按实际内容测量。

### 3.14 公平与成本

同样语义长度在不同语言的 Token 数差异，会直接影响训练预算、推理价格和上下文容量。评估跨语言相对膨胀，并在混合配方中以 Token 而非文档数核算。改 Tokenizer 可能改善一部分语言却损害代码或英文，需要 Pareto 比较。

### 3.15 模型质量

最终通过固定模型与 Token 预算的代理训练比较验证损失和能力。若按 Token 预算对齐，压缩更好的 Tokenizer 能看到更多字符；若按原始文本对齐，则计算量可能不同。两种实验回答不同问题，报告必须说明。

## 4. Tokenizer 训练数据设计

### 4.1 不是把全部预训练数据再读一遍

Tokenizer 训练通常只需代表性子集，但要覆盖语言、代码、数学、特殊格式和长尾字符。按原始库存抽样会忽略小领域；均匀抽领域又可能过度影响词表。先定义 Tokenizer 目标权重，与预训练混合可以相关但不必相同。

### 4.2 控制重复

模板和重复文档会让合并规则浪费在站点导航或许可证样板上。使用去重后的代表集，限制来源集中度。某些重复结构如代码语法确有价值，需通过领域覆盖保留，而非保留全文副本。

### 4.3 控制规范化

Tokenizer 训练与使用必须采用同一规范化。若先在原始文本训练词表，却在编码前转小写或 Unicode 归一化，许多词表单元永远不可达。将规范化配置作为 Tokenizer 资产的一部分，并对代表字符串生成测试向量。

### 4.4 特殊 Token 先规划

预训练边界、对话角色、工具调用、多模态代用标记和填充需要提前规划稳定区间。不要为了未来可能需求无限预留；可以保留有限扩展区，但每次启用仍需新版本和检查点适配。

### 4.5 训练与验证切分

Tokenizer 也需要独立验证语料，比较压缩、回退和切片。验证不用于反复挑词表而无限过拟合；保留盲测脚本与语言。Tokenizer 训练数据同样受许可、隐私和血缘约束。

## 5. 从文档到因果语言模型样本

### 5.1 基本移位目标

给定 Token 序列 $(t_0,...,t_{L})$，输入是 $(t_0,...,t_{L-1})$，标签是 $(t_1,...,t_L)$。Loss Mask 决定哪些标签参与交叉熵。这个简单移位最容易出现偏一错误：BOS、EOS、Padding 和文档边界都要在移位后验证。

### 5.2 文档内样本

每个文档独立 Tokenize，插入边界，再按最大长度切块。短文档产生 Padding 或等待 Packing；长文档产生多个块。优点是血缘清晰，缺点是若块间没有重叠，跨边界知识只在一侧出现。

### 5.3 连续 Token 流

把多个文档 Token 串联后按固定长度切块，利用率高。必须插入 EOS 或文档标记，并决定是否允许跨文档注意。若普通因果 Mask 允许跨文档，后一文档可以看到前一无关文档，这是一种训练语义，不应因实现便利被默认。

### 5.4 文档截断

只取前 $L$ 个 Token 简单但系统丢失结论、附录和后半部代码。可随机裁剪、按段落抽样或多窗口覆盖。每种策略改变内容分布，需要报告位置覆盖与文档曝光。

### 5.5 滑动窗口

窗口长度为 $L$，步长为 $S\lt L$，相邻窗口重叠 $L-S$。它保留跨边界上下文，却重复训练重叠 Token。Loss 可以只落在每窗新增区域，前缀作为上下文而不重复监督；这样需精确 Mask 和 Token 账本。

### 5.6 前缀与目标分离

对条件任务，前缀 Token 提供上下文但不计 Loss，目标 Token 参与 Loss。预训练通常所有非边界 Token 都参与，但文档续写、FIM、长文问答或 SFT 会有不同 Mask。样本格式必须携带显式 `loss_mask`，不能让训练器根据字符串猜。

## 6. 边界 Token 与跨文档语义

### 6.1 EOS 既是内容也是控制信号

EOS 告诉模型文档结束，并提供从结尾预测结束的目标。若每篇文档不加 EOS，模型可能学习无缝续写到下一篇；若连续多个 EOS，又会放大无意义模式。规则明确空文档、已有 EOS 和截断块怎样处理。

### 6.2 BOS 是否每文档重置

有的模型只在整条训练序列开头放 BOS，有的每个独立文档放。每文档 BOS 能强化边界，却增加 Token 和与推理模板的耦合。选择应与预训练架构和推理行为一致。

### 6.3 文档分隔符不能替代注意力隔离

加入 EOS 并不会阻止后文 Token 关注前文，只提供学习信号。若要求数学等价于独立样本，需要块对角因果 Mask、分段注意力或支持 Packed Sequence 的内核。语义分隔和计算隔离是两件事。

### 6.4 位置 ID 重置

Packing 多个文档时，可每文档从零重置位置，也可在物理包内连续增长。重置更接近独立训练，但需要注意力实现支持分段位置；连续位置让后文出现在任意绝对位置，有时用于长度泛化，却会与跨文档隔离组合产生不同分布。

### 6.5 边界 Loss Mask

如果不希望模型学习从一篇文档 EOS 预测下一篇 BOS，就将跨边界的标签位置 Mask 掉。要画出输入索引、标签索引和 Mask 逐位测试，文字描述很容易产生偏一。

## 7. 截断、窗口与文档覆盖

长度满足不代表对话和工具调用仍然完整。

### 7.1 Head 截断偏差

文档开头常含标题、摘要和导航，长期只取 Head 会让模型少看结论与尾部。代码文件开头是导入，末尾才有核心实现。监控原始位置分位的 Token 覆盖。

### 7.2 Tail 截断偏差

只取尾部会失去定义与上下文。某些日志尾部含结果，适合任务，但不能作为通用预训练默认。任务特定抽样与通用语料分开。

### 7.3 随机窗口

每轮从长文随机起点取一窗，长期提高位置覆盖，但同文档曝光随机，复现需保存种子和文档轮次。退出时仍能按记录 ID 追踪所有窗口。

### 7.4 确定性多窗口

按稳定步长生成窗口 ID，易缓存与审计。重叠增加 Token 预算，窗口清单应记录原文 Token 区间、重叠和 Loss 区域，避免把上下文 Token 反复计入有效预算。

### 7.5 语义边界切分

优先在章节、段落、函数或对话轮边界切分，减少语义断裂。若段落超过最大长度，再退到 Token 切分。解析边界本身有版本和置信度，不能假设 HTML 标签总准确。

### 7.6 保留前后文桥

构造块时保留少量前文作为不计 Loss 上下文，帮助跨章节连续；也可保存文档内块 ID 与前驱关系，让长上下文阶段重新组合。桥长度会增加计算，需通过跨边界评测决定。

## 8. Padding 与长度分桶

EOS 作为 Pad ID 时仍需独立 Attention 与 Label 边界。

### 8.1 Padding 浪费

一个批次 Pad 到最大长度，有效利用率为有效 Token 总数除以 `batch_size × max_length`。长度分布重尾时浪费很大。按相近长度分桶能减少 Pad，但会改变数据顺序和批次同质性。

### 8.2 长度分桶的随机性

先按长度排序再固定批次会让课程按长度排列。更安全的是划粗桶，桶内随机，领域调度后在可接受窗口组批。桶边界、Shuffle 缓冲和种子进入加载器状态。
