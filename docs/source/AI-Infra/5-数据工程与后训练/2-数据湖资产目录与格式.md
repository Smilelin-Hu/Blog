# 数据湖、资产目录与格式：让字节变成可引用的资产

训练脚本需要的是「一个确定的字节集合」。中间需要三层东西：**存字节的地方、解释字节的目录、描述字节怎么来的血缘**。它们混在一起，就会退化成「一堆文件 + 一个没人敢改的脚本」。

## 1. 五种设施各管一段

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l03_01.png" width="78%" alt="数据湖与资产目录" />
  <p>图 1：对象存储存字节、Lakehouse 给表加事务、目录负责发现、血缘负责解释</p>
</div>

| 设施 | 职责 | 关键限制 |
|---|---|---|
| 对象存储 | 保存字节（WARC、Parquet、JSONL、Token Shard、Checkpoint） | **不是 POSIX**：目录 rename 可能是复制+删除；小对象 list 昂贵；原子性以单对象为界 |
| 数据湖 | 保存不可逆处理**之前**的证据，便于重算 | 没有目录与治理会退化成 Data Swamp |
| Lakehouse | 给表加原子提交、Schema 演进、时间旅行 | 适合元数据/特征/索引；**别把二进制硬塞进表** |
| 资产目录 | 回答「组织拥有哪些数据、能不能用」 | 描述可变，**版本事实不可变**，两者要分开 |
| 血缘 | 回答「怎么来的、影响谁」 | 真实图是多对多，不能把一条示意链当全貌 |

两条容易踩的坑：

- **对象 Key 是位置，不是身份**：同一内容可复制到多个 Key，同一 Key 可被覆盖。训练只记路径，事后无法证明当时读的是哪些字节——必须记内容哈希、大小、对象版本与 Manifest；
- **元数据不是把全文复制一遍**：对象存储放大内容，表/索引放可查询元数据，图放血缘边，日志放事件，靠稳定 ID 关联。

## 2. 资产身份：六种 ID 不要混

| ID | 含义 |
|---|---|
| `blob_id` | 内容哈希 + 算法，标识一段不可变字节 |
| `object_id` | 来源对象或逻辑文档，可跨内容修订 |
| `asset_id` | 一类数据产品，如「中文技术文档 Gold」 |
| `version_id` / `commit_id` | 该资产的一次不可变提交 |
| `snapshot_id` | 表/视图在某时刻的一致快照 |
| `alias` | `candidate` / `stable` / `production`，指向某个提交，可原子切换 |

**训练配置写 `asset_id + commit_id`，不能只写 alias。** Alias 在启动前解析，解析结果连同 commit 写入运行记录；运行中 alias 变了，不应影响已启动任务。

## 3. 格式栈的七层

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l07_01.png" width="78%" alt="训练数据格式" />
  <p>图 2：逻辑样本 → 编码记录 → 物理 Shard → 索引 → Manifest → Reader Plan → 消费回执</p>
</div>

| 层 | 是什么 | 不变量 |
|---|---|---|
| Logical Sample | 训练语义单位（预训练片段/SFT 对话/偏好对/轨迹） | 有稳定 `sample_id`，**物理重分片不改 sample_id** |
| Encoded Record | Schema 映射后的可序列化记录（JSON/Arrow 行/Tar 成员/Token 数组） | Null、类型、Unicode、嵌套、版本必须明确 |
| Physical Shard | 存储/并发/重试/缓存/分发单位 | **不可变**：新增样本生成新 Shard，不 append 已发布对象 |
| Index | `sample_id/ordinal → Shard + offset`，或 Shard → 统计 | 派生资产，绑定 Dataset/Shard 摘要与版本 |
| Dataset Manifest | Schema + Recipe + 全部 Shard/Index + 总账 + 顺序规则 + 父 Release + Policy | Manifest 自身内容寻址或签名；**Reader 不列目录、不猜最新版** |
| Reader Plan | 给定 world_size/rank/worker/epoch/seed 的分配与预取 | 可重建；不依赖进程到达顺序或默认 Hash |
| Consumption Receipt | 实际打开的 Shard、校验结果、样本/Token 数、跳过/错误、Checkpoint 位置 | 与 Manifest 对账，发现少读、重复、损坏 |

**验收标准**（可以直接当 checklist）：Manifest 不可变且带 Schema/Recipe/索引版本；每个 Shard 可独立校验；多 Rank/Worker 在约定 Epoch 内不重不漏；断点恢复后消费序列或统计语义一致；损坏/缺失/版本漂移**失败关闭**；缓存命中仍验证 Dataset 身份与 Source Policy。

## 4. Schema 设计的六条硬规则

1. **强制字段**：`sample_id`、payload（或结构化字段）、source references、schema/recipe 版本、逻辑长度。只存 text/token 而无身份，退出、去污、故障定位都做不了；
2. **嵌套与扁平**：对话/偏好/轨迹天然嵌套，完全扁平会重复 conversation 元数据并破坏关系；过深嵌套又让引擎难处理。**逻辑 Schema 保真，训练热视图单独序列化成扁平 Token 样本**；
3. **Null 与 Unknown**：Null 是「已知为空」，缺失是「Schema/来源未提供」，Unknown 最好显式枚举。不要把空串、0 与 Null 混用；
4. **数字类型**：Token ID 最大值决定 `uint16/int32/int64`——太宽浪费 IO，太窄溢出；文件超 4 GB 时 32 位 offset 危险；
5. **字符串与二进制**：原文规范 UTF-8，非法输入在上游留状态；图片/音频用 binary 或对象引用，**不要 Base64 塞 JSON**（约 1/3 放大 + 额外解码）；
6. **演进与冷热**：新增可选字段向后兼容，改语义/类型/必填要新主版本；Reader 声明支持范围，未知主版本失败。冷路径留完整 Text/结构/血缘，热路径留 Token/Mask/紧凑引用，**热数据必须可重建**。

## 5. JSONL 的定位

优点是可读、生态广、调试方便，每行一个记录、顺序扫描、分段恢复与流式写入都简单——适合早期数据交换、失败样本、Manifest 与中等规模 SFT。

局限也很明确：无强制 Schema、体积大、随机访问差、嵌套表达弱。**它是「能跑」的默认，不是「能规模化」的默认。**

## 6. 来源与许可：先登记，再采集

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l04_01.png" width="78%" alt="数据源登记" />
  <p>图 3：来源登记表决定「能不能用、能用到什么程度」</p>
</div>

一个 Source 记录至少要包含：

- 稳定 `source_id`、来源类型、所有者；
- 获取时间与时间窗口；
- **许可、使用范围、再分发条件**；
- robots / opt-out / 合同约束；
- 保留期、删除联系人、撤回策略；
- 抓取工具版本、原始对象清单与校验和。

三条实践原则：

1. **Source 与 Capture 分开**：同一站点不同月份抓取是不同 Capture，才能同时表达「同源」与「内容变了」；
2. **许可按用途判定**：研究可用不等于可商用、可再分发；许可矩阵要能回答「这个用途能用哪些 Source」；
3. **撤回要能传播**：来源要求删除时，要能追到派生 Sample、Dataset Release、训练运行与检查点，并产出影响报告。

## 7. 解析与数据流引擎

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l05_01.png" width="78%" alt="数据解析" />
  <p>图 4：WARC / HTML / PDF / 代码 / 对话各有不同的解析风险</p>
</div>

| 输入 | 主要风险 | 必须记录 |
|---|---|---|
| WARC | 记录边界、重复抓取、压缩分块 | WARC 位置、record offset、抓取时间 |
| HTML | 模板导航、脚本样式、正文抽取失败 | 正文选择器版本、正文占比 |
| PDF | 扫描页、公式表格、乱序 | 页码、坐标、OCR 状态、文本/图像比例 |
| 代码 | Vendor、生成文件、许可证 | 仓库、Commit、路径、语言、LICENSE 关联 |
| 对话 | 角色/边界、工具调用结构 | 模板版本、角色序列、截断位置 |

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiinfra_y5_l06_01.png" width="78%" alt="数据流引擎" />
  <p>图 5：批处理引擎负责吞吐，分布式执行负责弹性，两者常组合使用</p>
</div>

引擎分工的实用判断：

- **DataTrove / NeMo Curator**：面向 LLM 语料的专用流水线，内置常用过滤器与去重；
- **Ray**：弹性任务编排，适合大规模异构处理与在线/离线混合；
- **Spark**：成熟的批处理与表生态，适合结构化清洗与统计。

选型不看「谁更强」，看三件事：**是否能断点续跑**、**是否能按 Shard 并发**、**是否能把每步的血缘与统计落盘**。

## 8. 一张选型速查

| 需求 | 建议 |
|---|---|
| 存大对象（WARC/权重/Token Shard） | 对象存储 + 内容哈希 + Manifest |
| 需要时间旅行/增量读 | Lakehouse 表格式 |
| 需要「有哪些数据集、能不能商用」 | 资产目录（描述与版本分离） |
| 需要回答「这版由什么生成、影响谁」 | 血缘（正反向都查） |
| 训练读取 | Manifest 驱动 + Index + Reader Plan + Receipt |
| 中等规模 SFT 交换 | JSONL（但要带 schema 版本与 sample_id） |

## 写在最后

这一篇的关键词是**身份**：Key 不是身份、路径不是身份、文件名不是身份；只有内容哈希、commit_id 与 Manifest 是。
