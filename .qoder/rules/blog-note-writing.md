# 博客笔记编写规范

适用于 博客（docsify 站点，内容位于 docs/source/）新增、迁移或改写任何文章时，必须遵守以下规则。

## 1. 笔记口吻（非教程）

- 正文一律为「笔记」风格，禁止教程讲课式表达：
  - 章节自指：「这一章 / 本章 / 本节课 / 本节 / 本篇教程 / 你将学到 / 你将收获」→ 改用「本文 / 内容概览 / 下面」等中性表述。
  - 第二人称指令式：「你可以先… / 如果你想… / 帮助你… / 推荐你的…」→ 改为去主语表述「可以先… / 若要… / 便于… / 推荐的…」。
- 属内容而非口吻的第二人称必须原样保留：代码块内的 prompt 模板、引用的用户话术与示例问句（如访谈问题对照表、Mom Test 问句）。
- 通用解释性叙述中的「我们（笔者）」可留。
- 批量改写时先用正则定位候选、逐条 Read 取原文精确匹配（注意全角引号），改后复扫计数验证归零。

## 2. 分篇与顺序

- 整理自外部教程的内容不做整篇搬运，也不写成单篇大汇总：按来源主题提炼，一个主题重写成独立一篇。
- 篇目编号顺序必须与来源教程原章节顺序一致（以源站侧边栏 / 学习路径为准），不得按主观重排。
- 文章内章节标题一律用阿拉伯数字编号（`## 1.`），禁止中文数字（`## 一、`）。
- 文章正文不以「笔记缘起」类引用块开场（已废弃）；来源信息仅在系列 README 的一行引用块体现。篇末「写在最后」用相对链接承接下一个主题。
- 调整篇目顺序时，用 git mv 保留历史，并同步更新全部篇间互链及「前两篇」类指代。

## 3. 开源教程来源注明

- 专栏或子系列 README 只用一行引用块注明出处，格式固定：
  `> 内容整理自开源教程 [名称](链接)，作为参考笔记。`
- 位置固定：紧跟系列主题简介之后、`## 目录` 之前，即「标题 → 主题简介 → 来源行 → 目录」；不得放在目录之后，也不得放在主题简介之前。
- 不写「关于本专栏」式多段说明，不罗列借鉴的章节标题，不写「已适配本站排版」「非原文搬运」等过程性细节。
- 正文文章内不写来源说明与「笔记缘起」类话术，出处只在系列 README 体现。
- 内容整理自本地或付费课程讲义时不写出处行，也不写「原始讲义共 N 讲、按主题合并为 M 篇」这类结构说明；正文里「讲义里…」「第 N 课…」等指向原课的表述改为中性说法（如「常见资料里…」「前面的原理…」），技术结论本身保留。
- 不保留「篇目与原课映射」类表格：原课编号属于本地比对信息，不入站；覆盖核对放本地脚本。

## 4. 配图与提交

- 图片统一经 PicGo 上传图床，正文使用其返回的在线链接（当前图床为 gitcode `weixin_42917352/image-host`，链接形如 `https://raw.gitcode.com/weixin_42917352/image-host/blobs/<sha>/images/<文件名>`；历史图片在 GitHub 图床 `https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/<文件名>`，两者并存，不迁移）；删本地图前校验 `\]\(images/` 与本地 assets 引用计数为 0。
- 每批内容改动校验（无本地图片、无断链、口吻合规）后提交；每解决完一个问题（一项独立改动），无需等待另行指示，直接按功能分组 git 提交，提交信息遵循仓库规范 `<模块>: <祈使句摘要>`；推送仍须用户单独下达指令。
- 推送代理等本机环境信息一律不写进本规则：本仓库代理已配置为 git repo-local（`git config --local http.proxy`，随 `.git` 目录走，整目录拷贝即恢复）；需要代理端口、直连/强推命令时，从本机 `.env.local` 或 `git config --local -l` 查询，若 `.env.local` 缺失则按下文「换机恢复」重建。

## 5. 绘图规范：单主题图

- 课件优化优先评估配图：接到课件优化、改写或扩写需求时，先评估内容是否涉及流程说明、机制原理等需辅助理解的场景，优先补齐单主题图便于理解，再打磨文字；已有图若为多主题堆砌大图，顺手拆分为单主题图。
- 需配图场景：流程说明、架构与组成、机制原理、状态/时序演变、对比关系等辅助理解的内容应配示意图；纯公式推导、表格罗列、代码清单不强制配图。
- **单主题原则（硬性）**：一张图只表达一个核心概念、一个步骤或一条流程；严禁把整篇内容或多个独立主题堆砌在一张「全景大图」里。文章含多个独立主题时，拆成多张单主题图，分别紧跟各自对应的正文段落。
- 粒度控制：单条流程节点超过约 7 个、或跨越多个边界清晰的阶段时，按阶段拆分为多张图；每张图脱离其他图也能独立读懂。
- 图随文走：插图紧跟其解释的段落之后，alt 文本一句话点明图的主题；不在文首集中堆图，不用一张大图替代各节展开。
- 居中显示：插图单独成段，由 `src/styles/global.css` 全局样式（`.prose p > img:only-child, .prose > img`）统一居中，正文不写对齐标签或居中包装。
- 绘制与风格：用 `.qoder/excalidraw-diagram/` 下的 excalidraw-diagram skill 绘制，颜色遵循其 `references/color-palette.md`；渲染 PNG 后必须目检文字溢出、箭头错位与元素重叠，修到合格为止。
- 命名与存放：图片命名 `<系列前缀>_y<主题号>_l<篇号>_<图序>.png`（如 `aiinfra_y1_l05_01.png`）；excalidraw 草稿与渲染产物放 `.tmp/bookfigs/`（不入库），入库的只有正文里的在线链接。
- 存量 ASCII 流程块：代码块中属于流程说明的 ASCII 示意图，改写时替换为单主题图，不保留 ASCII 块与图重复表达同一内容；日志、命令输出等非流程 text 块不动。

## 6. 站点架构与换机恢复

- 前端为 Astro（脚手架与视觉风格源自 llm-gpu 站点）：配置在仓库根 `astro.config.mjs`（base `/Blog`），组件/布局在 `src/`；内容仍在本目录 `source/`，路由与目录同构（`/source/<原路径>`，README 即目录索引）。
- 内链由 `src/utils/rehype-blog-links.mjs` 统一加 base 前缀并去 `.md` 后缀；正文继续写 `/source/...` 或相对 `.md` 链接，不手写 base。提示框 `> [!TIP]` 由 `rehype-alerts.mjs` 渲染；mermaid/数学/代码复制/图片放大/暗色/搜索均为站点内置能力。
- 机器无关的信息都在仓库里，clone 即得：内容在 `docs/source/`、图床地址见本规则第 4 节、远程地址见 `git remote -v`；课程原始工作区归档在仓库根 `courses/`（不入站）。
- 若使用 GitHub HTTPS 推送且需免密，可将认证嵌入 repo-local 的 remote URL 或改用 SSH remote，二者均不进入跟踪文件；个人访问令牌等凭据只放本机 `.env.local`（已被忽略），严禁写入任何入库文件。
- `.env.local` 为本机开发备注，缺失时重建，至少记录：代理软件本地 HTTP 端口、`git config --local http(s).proxy` 设置命令、临时直连推送命令（`git -c http.proxy= -c https.proxy= push`）。
- 本地预览：仓库根 `npm install && npm run dev`（入口 http://localhost:4321/Blog）；或 `npm run build && npm run preview` 验证产物（含 pagefind 搜索索引）。部署由 `.github/workflows/deploy.yml` 在 push master 时构建 dist 上 GitHub Pages。
